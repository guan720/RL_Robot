## 1. 先给判断

**当前最值得选择的是一个可核验的系统组合：学习器 + 自动奖励 + 场景复位/失败恢复 + 持续运行 harness。没有查到一套公开方案已经在广泛机械臂和移动操作任务上证明全程零人工、并完整开源到可以直接复现。** 这是本次证据范围内的结论，不是证明世界上不存在这种系统。

建议首轮保留四条路线，先按任务和现有策略筛选，不宜用一张跨论文成功率榜选冠军：

| 路线 | 建议保留 | 为什么贴合本次目标 | 首轮必须解决的缺口 |
|---|---|---|---|
| 固定机械臂、从少量示范开始 | HIL-SERL 基座 + SERL 正反任务思想；MEDAL++ 作自主学习对照 | 真实控制与训练代码可读，正反任务能把成功后的场景恢复纳入学习 | 人工标奖/异常救援；对象离开可达工作区；恢复策略自身失败 |
| 已有扩散/流/VLA 基础策略 | DSRL；有适配资源时 PLD + ENPIRE | 用小策略改进基础能力，或通过 RL 采集更好数据再蒸馏；ENPIRE 对接代码与模型两类更新 | DSRL 真机例程仍逐回合人工标奖/等待复位；PLD/ENPIRE 依赖预先做好的循环工位 |
| 自动替代动作接管 | AutoSERL、UniIntervene | 前者示范与规则恢复，后者价值判断与恢复记忆，直接针对接管 | AutoSERL 仍人工奖励且有源码可用性疑点；UniIntervene 只发布离线组件，真机集成不在包内 |
| 移动拾取/整理与移动操作 | ReLMM；Spot 持续操作系统作架构参考 | 显式设计导航、抓取、目标循环、复位和探索 | 换电、死角物体、补给、地图/外部相机；Spot 系统完整代码未核到 |

以上是我的工程判断；各项原文证据和保留意见见后文及专项报告。[HIL-SERL](https://github.com/rail-berkeley/hil-serl)、[MEDAL++](https://github.com/rehaanahmad2013/self-improving-robots)、[DSRL 真机例程](https://github.com/nakamotoo/dsrl_pi0)、[ENPIRE](https://github.com/NVlabs/ENPIRE)、[ReLMM](https://github.com/charlesjsun/ReLMM)。

## 2. “自学习”需要逐环节记账

一个策略训练后能独立执行，不等于它的训练过程无人值守。论文中的 autonomous、reset-free、self-improving 也不能互相替代。建议分开记录以下人工来源：

| 环节 | 要核查什么 | 常见被省略的人工 |
|---|---|---|
| 冷启动 | 基础模型、离线数据、示范和失败样本来自哪里 | 大量预训练数据、遥操作、人为制造失败 |
| 任务与课程 | 谁选下一任务、起始分布、难度和切换时刻 | 人工分阶段、设计任务对、挑恢复点 |
| 奖励与成功判定 | 来自状态规则、分类器、VLM，还是按键 | 每回合人工判断成功；持续修标签 |
| 正常复位 | 成功/超时后，物体和机器人能否回到可训练状态 | 只写 `env.reset()`，物理操作实际由人完成 |
| 失败恢复 | 卡住、掉物、出界、抓取失败后如何重新开始 | 人把物体放回、解缠、重抓、现场接管 |
| 运行维护 | 连续多久，故障/电量/料箱耗尽怎么办 | 换电、补物、相机重启、控制器恢复 |
| 更新与发布 | 数据如何进入训练，谁验收新版本 | 人工筛选最好 checkpoint、修改判据、手动批准部署 |

“免复位”常指不在每个 episode 强制回到指定初始状态；它仍可能需要周期性的 hard reset。一个系统也可能把劳动由现场移到远程标注，或由人转给第二台机器人。这些都可以有价值，但账要分开。

本报告不采用一个主观总分压平所有差别。41 项候选各自保留技术、人工依赖、实验、代码、许可、机构和适用性字段。3 项奖励模型和 2 项基准只是组件/评测；SOAR、REVOLVE、GEAR 的策略学习机制另作说明，不能统称 41 个 RL 算法。

## 3. 学习算法究竟更新什么

| 方法族 | 主要代表 | 更新对象与数据使用 | 优点 | 对少人化的真实作用 |
|---|---|---|---|---|
| 小模型离策略 actor–critic | RLPD、SERL、HIL-SERL、MEDAL++ | 用奖励和下一状态更新价值与策略；成功、失败、次优轨迹都能进入回放 | 真实交互昂贵时可反复利用数据；可混入演示与接管 | 减少试错和后期接管；复位/奖励要另配 |
| 冻结基础策略 + 动作残差 | ResFiT、PLD 的 RL 探索阶段 | 在 BC/VLA 输出附近学习纠正动作；PLD 再把所得数据用于策略更新 | 利用强先验，降低探索难度与大模型在线更新负担 | 有利于闭环实践，但环境可循环是前提 |
| 冻结扩散/流策略 + 噪声空间 RL | DSRL | RL 选择生成过程初始噪声，改变基础策略产生哪种动作 | 无需全量更新基础模型，适合已有好策略 | 提升技能的接口较轻，不能代替 reset |
| 冻结 VLA 表征 + 小 actor/critic | RLT | 通过 RL token 压缩表征，在线更新小控制策略 | 将基础模型能力用于精细动作优化 | 原工作仍保留人类奖励、阶段交接等 |
| VLA/通用策略后训练 | ConRFT、RECAP、RL-100 等 | 连续动作价值引导、优势条件策略提取或离线到在线更新 | 可把实践经验沉淀回通用策略 | 每种方法的人力与开放性差异很大 |
| 世界模型 RL/MPC | DayDreamer、TD-MPC2、MoReFree | 从真实/模拟轨迹学习动力学和价值，再想象训练或规划 | 可能提高交互效率，支持恢复目标选择 | 模型不自动提供可逆世界；MoReFree/TD-MPC2 原证据主要是仿真 |

这些方法与此前 RoboRSI 讨论的关系是：**成功轨迹微调只是模型更新的一种。真正的 RL 通常还从失败、奖励、状态转移和反事实价值中学习。** 外层 code skill 可以调度学习器、复位器、验证器；内层可以更新 VLA、小 actor/critic、噪声策略或残差策略。保留统一能力接口，不意味着所有能力都必须是代码或同一种模型。

算法和实现出处：[RLPD](https://proceedings.mlr.press/v202/ball23a.html)、[DSRL](https://diffusion-steering.github.io/)、[RLT](https://www.pi.website/research/rlt)、[PLD](https://arxiv.org/abs/2511.00091)、[RECAP](https://www.pi.website/blog/pistar06)、[DayDreamer](https://danijar.com/project/daydreamer/)。

## 4. 免复位、自动恢复与长期运行是三个不同问题

**正反任务循环。** SERL 搬运、MEDAL++、MTRF、ReLMM 都利用“完成后还能自然继续”的任务结构。移过去再移回来、拿起后重新放下、关闭再打开，比完成一次后让人重摆场景更接近持续学习。技术难点是反向策略覆盖差、对象出界、初始分布塌缩，以及训练了很久却只会一种狭窄循环。

**失败前中止或失败后恢复。** Leave No Trace、FARL 用可恢复性/风险估计决定何时退回；AutoSERL 用少量示范和恢复点；UniIntervene 学会何时介入并检索恢复经验。它们减少错误进入不可救状态的概率，但不能复原损坏、掉到够不着的位置或耗尽的物料。[Leave No Trace](https://github.com/brain-research/LeaveNoTrace)、[FARL](https://failure-aware-rl.github.io/)、[AutoSERL](https://autoserl.github.io/)、[UniIntervene](https://denghaoyuan123.github.io/UniIntervene-project/)。

**运营闭环。** ReLMM 仍要约每 5 小时换电，某些物体需要人工挪出死角；Spot 持续操作系统用环境约束、感知服务和任务循环，扫地还用第二台机器人复位。机械臂能反向摆物，并不意味着移动平台能自主完成充电、重新定位和全场景恢复。[ReLMM 正文](https://proceedings.mlr.press/v164/sun22a/sun22a.pdf)、[Spot 系统](https://continual-mobile-manip.github.io/)。

## 5. 几项最容易被高估的自主性声明

| 方案/数字 | 本次核验后的准确含义 | 选型影响 |
|---|---|---|
| MEDAL++ 每任务约 30h 学习 | 初始正反各 50 示范；最初 30min 人工 reset，后续平均约每小时仍有一次 | 是降低人工频率的证据，不是 30h 连续零人工 |
| RoboFuME autonomous fine-tuning | 仍每约 15–35 回合人工复位；官方项目代码 Coming Soon | 不宜列“完整开放无人训练基座” |
| AutoSERL 无在线动作示范接管 | 二值奖励仍人工；异常重抓取仍等用户；代码恢复分支存在静态疑点 | 自动接管减少了一个环节，现场劳动尚未消失 |
| UniIntervene 干预减少约 57% | 人工动作步占比 34.3%→14.6%；成功率 81%→88%，即 +7 个百分点 | 不能解释成人类工时、接管事件或人员数量少 57% |
| PLD ≥1h 连续操作 | 这是学习后的连续部署演示；训练有工装、循环任务，某些任务仍需人移动孔位 | 需按具体任务核对训练无人时长 |
| ENPIRE 99% | 每个子任务最多 8 次上下文重试的 pass@8 口径，并非独立同分布试验 | 不能与单次尝试成功率横比 |
| RLinf-USER 支持 VLA 学习 | 原论文 π0 示例为 HG-DAgger；多项真机任务仍人工标奖和 reset | 系统支持学习，不等于每个例子都是无人 VLA RL |
| SimpleVLA-RL 真机成绩 | 原论文真实部署来自仿真 SFT/RL；后续 README 声称真机 RL，但开放细节要分开核 | 不能用原论文证明真机持续自学习 |
| Robometer 自动奖励 | 奖励、成功检测、阶段切换可自动，物理场景复位仍人工 | 可作组件，不能单独解决用户主要瓶颈 |
| OWMM 开门 50%→95% | 该主要结果用人工奖励；CLIP 自动奖励是另一组较小实验 | 不把人工奖励结果贴成完全自主效果 |

逐项原文、附录和实际源码链接见 [复位与自主运行专项](research/reset_autonomy.md)、[真机 RL 专项](research/real_rl_stacks.md)、[VLA 与自动奖励专项](research/vla_self_learning.md)。没有把网站演示视频当作独立实机复现。

## 6. ENPIRE 与 harness + RSI + RL 的直接关系

ENPIRE 应作为外层系统候选单独考虑。其四模块分别负责环境、策略改进、并行采样和实验演化；编码代理可据试验结果调整代码策略、参数与学习流程。这和此前 RoboRSI 的“代码能力 + 学习能力”划分相近，但不表示二者的实现可直接互换。[ENPIRE 项目](https://research.nvidia.com/labs/gear/enpire/)。

开放性核查有实质进展：官方仓库除了 CaP，确实提供真实 RL actor/learner 的入口。PLD runtime 说明从 `minimal_policy@81988f0` 迁移；因此，原 PLD 论文项目没有完整训练仓库链接，不能再笼统改写为“现在没有官方相关 PLD 实现”。该 runtime 明确不包含数据和模型权重；相机标定、station、感知/控制服务与任务环境仍需搭建。[仓库](https://github.com/NVlabs/ENPIRE)、[PLD runtime](https://raw.githubusercontent.com/NVlabs/ENPIRE/main/enpire/policy/pld/runtime/README.md)。

论文把人参与的工位准备和之后的自动优化分为阶段。多机器人缩短墙钟的成绩同时使用更多机器人；代码代理也引入额外模型调用成本。选择它应考察每机器人小时的有效改进、人工分钟及费用，不能仅看“代理自主”或一个最高成功率。[论文](https://arxiv.org/html/2606.19980v1)。

**本次判断：** 如果目标是搭具身 harness 与 RSI 的研究系统，ENPIRE 的优先级很高；如果目标是先把一台机械臂稳定训练起来，HIL-SERL 生态和一个简单可逆任务更适合承担基础对照。两者是不同层次的选择。

## 7. 开源审核不只看有没有 GitHub

我按以下项目分别核查：算法实现、训练入口、真机控制接口、自动奖励、reset/recovery、数据、权重、许可、维护/依赖、实际复现证据。当前结果可概括为：

| 开放范围 | 代表 | 关键限定 |
|---|---|---|
| 官方训练与真机接口可读 | HIL-SERL、SERL、ConRFT、MEDAL++、DSRL π0 版、ENPIRE | 不代表所有论文任务数据/权重/自动复位完整随附 |
| 原算法公开，主要入口为仿真或需迁移旧栈 | RLPD、TD-MPC2、FLaRe、MTRF、ReLMM、RISC、MoReFree | 分清真实分支、历史硬件、软件版本和 sim-to-real 边界 |
| 新组件公开，整套系统缺失 | UniIntervene；部分奖励模型/策略学习组合 | UniIntervene 明确不包含在线 RL 与机器人部署 |
| 源码公开但许可受限/未核明 | ResFiT；AutoSERL、DayDreamer、DSRL 通用仓库的许可需补核 | ResFiT 是 CC BY-NC 4.0；未见根 LICENSE 不能推为宽松商用 |
| 原项目完整训练开放未核到 | RECAP、GR-RL、RAMP、RLT 原作、RoboFuME、FARL、Spot 持续操作系统 | 开放基座/第三方复现不得算成目标方案官方整套发布 |
| 权重/数据与训练代码开放不一致 | DenseReward | HF 资源存在，而官方 GitHub 代码链接为一个空仓 |

上述“未核到”是访问和核验结论；不等于断言作者永远不会发布。主分支链接也会变化，真正复现时需锁定 commit、数据版本和模型 revision。本次不宣称做过全仓安全审计或运行通过。

## 8. 影响力怎么审核

影响力分三类看：①学术出处与方法继承；②官方代码生态；③模型/数据实际分发。机构和顶会是背景信号，不能抵消人工劳动与复现缺口。

本次抓取了 GitHub 官方页、OpenAlex 元数据及 Hugging Face 官方资源页，快照日期均为 2026-09-22。GitHub 的 `k` 保留近似形式；模型/数据下载为平台的 **Downloads last month**，不是总下载、独立用户或真实使用团队数。OpenAlex 对机器人论文覆盖不完整，同一工作预印本与正式版本可能拆成多个条目；**只列选定且匹配标题/作者/DOI的条目计数，不相加，也不称全网总引用量。** 搜索 RL-100 返回的药物材料同名结果已排除。

代表性生态快照：HIL-SERL 约 1.5k stars，SERL 862，TD-MPC2 969，SimpleVLA-RL 约 1.9k，RLinf 约 5.3k；后两者的大生态不等于无人真机能力。MEDAL++ 19、MTRF 7 等旧方法关注较少，仍可能比大规模 VLA 仿真框架更贴合复位研究。[HIL-SERL](https://github.com/rail-berkeley/hil-serl)、[SERL](https://github.com/rail-berkeley/serl)、[TD-MPC2](https://github.com/nicklashansen/tdmpc2)、[SimpleVLA-RL](https://github.com/PRIME-RL/SimpleVLA-RL)、[RLinf](https://github.com/RLinf/RLinf)、[MEDAL++](https://github.com/rehaanahmad2013/self-improving-robots)、[MTRF](https://github.com/facebookresearch/MTRF)。

奖励组件分发快照：RoboReward-4B / 8B 分别为 291 / 514 次月下载，Robometer-4B 为 1,961；RoboReward 数据集为 10,714，DenseReward 数据集为 261。模型与数据集不是同一口径，不排序成一个总榜。[RoboReward-4B](https://huggingface.co/teetone/RoboReward-4B)、[8B](https://huggingface.co/teetone/RoboReward-8B)、[Robometer-4B](https://huggingface.co/robometer/Robometer-4B)、[RoboReward 数据](https://huggingface.co/datasets/teetone/RoboReward)、[DenseReward 数据](https://huggingface.co/datasets/densereward/DenseReward)。

完整计数、版本、来源 URL 和未知项见 [影响力快照](03_影响力与开放性快照.md)。不以未知替代 0；单个 2026 新条目的 0 次收录引用也不意味着没有影响。

## 9. 我建议你按这些条件筛选

1. **任务能否形成物理循环？** 若不能自动把场景恢复到可训练状态，先考虑夹具、收集区、可逆子任务和 recovery；换优化器通常无法消掉现场劳动。
2. **现有策略接口是什么？** 无强基座，选小模型离策略 RL；有扩散/流策略，重点 DSRL；有黑盒 ACT/BC，考虑残差；有可微调基础策略时比较 ConRFT/PLD，大规模通用 VLA 路线另看 RECAP。
3. **剩余人工是否命中你的痛点？** 有人遥控的高成功率可做上限对照；逐回合标奖或摆物的系统不应直接胜出。
4. **能否复现关键闭环？** 至少核到 actor、learner、实际执行动作记录、reward、reset/recovery 与机器人控制接口；论文页和演示视频不足以回答这一点。
5. **再看算力、机构与社区。** 社区成熟度帮助排障，机器人任务适配和人工预算决定是否真的合适。

下表是进入下一轮的建议，不是已经替你定案：

硬件适配要先核对：HIL-SERL/ConRFT 的公开真机栈主要面向 Franka；如果使用 ARX 等不同本体或多机器人，可把 RLinf-USER 纳入基础设施比较。换底座意味着重新适配控制、数据和环境接口，不只是修改模型名称。[ConRFT](https://github.com/cccedric/conrft)、[RLinf-USER](https://arxiv.org/abs/2602.07837)。

| 选项 | 我会保留的用途 | 暂不把它当成什么 |
|---|---|---|
| HIL-SERL + 自主 reset/recovery | 首个稳定真机基座；测出有人工时的可达性能 | 现成无人训练系统 |
| MEDAL++ | 验证正反任务、自动奖励与小时级少值守 | 最新易维护的通用VLA栈 |
| DSRL | 已有扩散/流策略时的低成本在线改进 | 场景恢复方案 |
| PLD + ENPIRE | 模型更新、代码迭代与物理试验的一体化研究 | 全部准备工作零人工、所有资源齐备的成品 |
| AutoSERL / UniIntervene | 两种自动接管机制的研究对照 | 已完成全部异常和普通复位的闭环 |
| ReLMM | 地面移动拾取任务的持续自学习参考 | 任意双臂移动操作的通用解 |
| Robometer / RoboReward | 奖励和成功识别模块比较 | 解决复位和故障维护的独立系统 |

## 10. 下一阶段验证方案（本次仅设计，未执行）

选定 2–3 个匹配硬件的方案后，建议保持同一初始策略、示范预算、任务分布、控制频率、奖励标准和机器人小时。把算法与 harness 的改进分开做消融：基础策略；基础 RL；RL+自动奖励；RL+自动复位；再加失败恢复。更换奖励模型时，另设不参与训练的评测判据，防止模型学会钻奖励空子。

主指标建议：

- **人工分钟 / 机器人运行小时**，另报冷启动与部署准备人时；无需持续盯屏才算减少现场值守。
- 最长连续无人工时长、每小时人工复位/动作接管/标奖次数、物料与维护事件。
- 单次任务成功率与允许重试的最终完成率并列，保留样本数和置信区间。
- 不可恢复失败率、掉物/越界/急停、自动恢复成功率与耗时；不能只统计被成功恢复的案例。
- 包含 reset、推理、训练、等待的墙钟；另报真实交互步、GPU时、机器人台数、外部模型费用。
- 固定测试集上更新前后表现、旧技能回退和跨物体/位置泛化；保留失败轨迹，避免只挑最好 checkpoint。

建议首先选一个可逆桌面任务和一个容易产生恢复需求的接触任务。移动操作单列换电/充电、重新定位与物体补给。由短时有人监护的调试逐步延长无人时长是评测流程设计，不能把未做过的运行写成结果。
