# 较新 RL 基线与 π0.5 选型补充

> **当前推荐以[12 低成功率策略再评估](12_低成功率策略的RL再评估与自主练习路线.md)为准：单臂抓放、VLA-only、可少量 SFT，成功率偏低包括零成功率；ConRFT／EXPO 按实际适配成本竞争，STEAM 在混合数据阶段评估。本文件原 RLT 首选排序和早期 ACT 范围均不再作为当前推荐；下面保留当时的来源与实现审查。**

核验日期：2026-09-22。适用条件：松灵 ALOHA 类双臂，已有 π0、ACT、遥操作和人工接管 DAgger。用户允许选择 π0.5 等其他 VLA。本文是公开资料与实现审查，未安装训练栈、未复现论文、未运行机器人。

## 1. 选型结论与此前建议的修订

**本轮原建议（现已被 07 按新条件修订）：不锁定 π0；在已具备有用任务行为的前提下，以 π0.5 + RLinf RLT 为在线 RL 候选，保留 DSRL 对照；STEAM + CFGRL 作为 VLA 离线后训练候选。不能将这一排序用于未经任务适配、几乎不产生有效动作的策略。**

这是根据公开接口和真机证据作出的工程判断，不是这些方法在松灵双臂上已有统一比较的结论。RLT 与 DSRL 在线阶段均冻结 VLA；“反复练习后基础模型本身进步”的长期路线，需要另接数据回流更新。PLD 是这一层最贴近的研究参考。

修订依据是新核实到：**RLinf 已开放 π0.5 的 RLT 两阶段训练与 Franka 真机配置。** 此前“未找到 PI 原作者完整 RLT 训练仓库”依然准确，但不能由此推成“没有可审查的 RLT 开源实现”。框架代码属于 RLinf 团队；PI 原论文性能不能直接当成这个实现已复现的成绩。[RLT 框架文档](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/rlt.html)

三层选择应分别确定：基础策略选 π0.5／已有 π0／其他 VLA；学习方法选 RLT／DSRL／CFGRL 等；自主运行层负责正反切换、成功验证、失败恢复及数据记录。框架提供多种模型和算法，并不自动证明任意组合已在指定机器人上验证。

### 机构可信度与影响力怎么使用

PI 的原作、清华等团队的真实双臂实验、PLD 的 ICLR 正式发表、RL-100 的期刊发表，提供了不同层次的积极证据；它们不能担保移植后的效果。更重要的是代码是否有训练入口、模型与硬件是否匹配、人工劳动是否记账。

RLT 的 RLinf 实现和社区 `Yyshadow/openpi-RLT` 必须分别归属，不能把框架总 stars 当成 RLT 的影响力。ZPRL 官方仓库本次网页快照为 51 stars / 2 forks；RL-100 为 363 stars / 22 forks，均仅表示当日关注度。本轮没有取得各新论文口径一致的引用量或模型下载量，不据此排名。[ZPRL 仓库](https://github.com/ManUtdMoon/ZPRL)、[RL-100 仓库](https://github.com/Lei-Kun/RL-100)

## 3. 为什么 π0.5 + RLT 更值得先做在线基线

OpenPI 公开 π0.5 基座权重、训练和推理代码；当前公开 π0.5 接口采用 flow-matching 动作头。因此 π0.5 是具体可获取的选项。不过，已有 π0 在本机上的成熟程度可能更有价值，应以同一批数据进行冷启动比较，不能用模型版本代替任务评测。[OpenPI 官方说明](https://github.com/Physical-Intelligence/openpi)

RLT 提供的关键接口是：VLA 产生内部表征与参考动作块，将表征压缩为 token；小 actor/critic 根据 token、本体状态和参考动作块学习控制。它不是直接叠加动作残差，也不是在生成噪声里选动作。对已有接管数据，这种物理动作空间回放更直接；但只有 observation/action 的旧 DAgger 样本仍不能无条件变成完整 RL transition。

RLinf 文档及实际 YAML 已核实：Stage 1 有 π0.5 + token 联合训练；Stage 2 冻结特征模型；真实配置是 `Franka`、`pi05_franka_state`、7 维动作。当前 actor 目标结合 Q 与 BC，普通数据约束到 VLA 参考动作，人工接管数据约束到人工执行动作；文档明确它不是标准最大熵 SAC。[训练文档](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/rlt.html)、[真实配置](https://raw.githubusercontent.com/RLinf/RLinf/main/examples/embodiment/config/realworld_rlt_stage2_ac_mlp.yaml)

两个必须保留的边界：

- **RLT 原论文使用 π0.6，RLinf 实现使用 π0.5。** 方法出处与复现实例的基座不同，不直接继承原文数字。PI 的原实验包含双臂任务，但这不意味着 RLinf 的现成配置也是双臂。
- **RLinf Piper 当前只提供硬件检查，尚无受支持的真机任务或训练工作流。** 真实 RLT 示例还要人工按 `b` 切入 RL 控制阶段。`Piper` 或 `Agilex` 名字出现在仓库里，不等于用户的松灵双臂已兼容。[Piper 说明](https://raw.githubusercontent.com/RLinf/RLinf/main/docs/source-en/rst_source/examples/embodied/piper.rst)、[切换代码](https://raw.githubusercontent.com/RLinf/RLinf/main/rlinf/envs/real/wrappers/episode/policy_switch.py)

因此，“首选”指值得首先适配和验证的公开在线学习实现，不表示一定胜过已有 DSRL，也不表示可以立刻取消值守。

## 4. 如果更重视 VLA 本身学习：STEAM 与 PLD

**STEAM 的吸引力是利用已有的混合质量数据。** 它用成功示范中的帧对时序学习局部进度，多个预测器保守聚合，为示范、失败 rollout 和人工修正数据生成优势/优劣标签，再通过 CFGRL 后训练策略。论文真实任务包括 ARX 双臂叠毛巾、扫码装袋、可乐补货，政策基座是 π0。RLinf 当前的后训练管线提供 π0.5 配置，这属于公开实现支持，不能改写成论文已经验证 π0.5。[论文](https://arxiv.org/html/2606.29834v1)

它主要减少逐帧人工评奖，不替代物理恢复。尤其要避免误读论文中的“反向”：其反序帧对用于构造相对于当前任务的退步样本，**不是机器人执行反向恢复任务**。若我们要训练“放入”和“取回”，应按语言目标分开示范、评估优势，不能用正向进度下降惩罚有价值的反向行为。公开默认配置与论文的专家数据、ensemble 设置也需逐项对齐，见[专项补核](research/new_real_vla_stacks.md)。

**PLD 的吸引力是明确闭合“局部 RL 改进 → 基础模型改进”。** 在线残差专家帮助基础 VLA 产生原本不会的恢复行为，采集时还考虑基础策略实际会访问哪些状态，再把数据回流 SFT。其双 YAM GPU 插拔包含循环任务，作者报告训练后可连续运行至少一小时；这是受限任务的部署证据，不是全训练过程零人工。[论文](https://arxiv.org/html/2511.00091v1)

NVlabs/ENPIRE 中已出现 PLD 真机 actor/learner runtime，不能再笼统说完全无代码；但本次未确认原论文全部数据、权重和完整训练—蒸馏流程作为独立包交付。把这套思路接到 π0.5/RLT 上是我们的组合设计，不能称为官方已验证的 PLD+RLT 算法。[开放 runtime](https://raw.githubusercontent.com/NVlabs/ENPIRE/main/enpire/policy/pld/runtime/README.md)

## 5. 建议的实现顺序与判断关口

| 阶段 | 具体工作 | 进入下一阶段的证据 |
|---|---|---|
| 1. 选基础模型 | 复用同一批正向、正常反向、失败恢复数据，对比已有模型与 π0.5 SFT；不同时更换机器人控制栈 | 同一固定评测集上的双方向成功率、恢复覆盖率、推理时延；π0.5 至少没有破坏现有基本能力 |
| 2. 跑通冻结策略循环 | 外层状态机调度正向与恢复，定义可继续练习的 Ready 状态集合；把人工标奖、切换、复位逐项记录 | 能区分成功、超时、恢复失败和不可恢复状态；测得真实人工分钟数与有效循环数 |
| 3. 建立在线 RL 基线 | 先只训练正向 RLT，小范围接入 RLinf actor/learner；恢复器固定。保留 DSRL 对照 | 在相同交互预算下带来正向改善，而非仅靠更多恢复调用；确认 chunk 截断和接管数据正确 |
| 4. 双向共同学习 | 两方向都采样、都学 Q；目标进入 VLA 指令、token/actor/critic。先独立双策略，再尝试共享目标条件参数 | 在相同机器人小时和人工预算下，共享是否优于独立策略，且失败覆盖没有缩小 |
| 5. 将经验回流 VLA | 比较普通混合数据 SFT、PLD 式部署分布采样、STEAM/CFGRL 后训练；保留原始技能数据 | 关闭在线适配器后，更新后的 VLA 在独立起点与扰动测试中仍有收益，其他能力没有明显退化 |

第 3 阶段到第 5 阶段无需一次叠满。先得到能明确归因的基线，再加入共享和模型回流，否则很难知道收益来自换了模型、增加了数据、恢复器变强还是 RL。

每轮 VLA 回流更新后，token 表征、参考动作分布和旧 actor/critic 可能不再兼容。应重新校准或训练 token 与适配器，从原始观测重算特征或隔离旧缓存和 replay，并重新评测；不能直接把旧冻结模型的特征缓存接到新 VLA 上继续学习。

松灵双臂适配至少包含：具体关节/末端动作语义与单位、双臂和夹爪顺序、动作归一化、相机映射、动作块中断、接管后的实际执行动作与时间戳、奖励/终止语义。不能把 7D 配置改成 14D 就称为适配完成。算力与具体型号未确认，因此不承诺 GPU 数量、工期或成功率。

报告指标至少同时给出：独立测试的正向成功率、失败状态恢复率、人工主动分钟/机器人小时、最长无干预时长、有效自主循环数。完整对照沿用[双向动机审查](05_双向练习动机审查与松灵双臂实现路线.md)：固定恢复器 + 只学正向、独立双向学习、共享双向学习；如要检验自主循环本身，再控制人工初始化条件。
