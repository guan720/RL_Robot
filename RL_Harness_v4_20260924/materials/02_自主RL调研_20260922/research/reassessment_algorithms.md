# 低成功率条件修订后的候选补漏与机制评估

核验日期：2026-09-22。输入条件：松灵 ALOHA 类平台，首任务单臂抓放；允许少量示范、SFT 和人工接管；基础策略成功率偏低，包括零成功率，尚未达到任务可用标准；不限定整模型更新或保留 VLA 表征后重学动作头，不考虑 ACT。本文件仅做原始资料与公开代码静态审查，未安装、训练或操作机器人。

已参考本会话 10、11 报告及 research 中既有候选，避免将 RLinf-USER、RECAP、QC-FQL 等重复包装成新发现。本轮深入补漏三项：RedFlow、HABC、UniIntervene；TEMPO、EXIMO、Dejavu 和 Q-Planning 只做范围与开放状态预筛。

## 1. 对原排序的实际影响

**没有找到足以凭公开可复现性直接替换 ConRFT／EXPO-FT 的新增完整训练系统；但找到两项会改变实施设计的补强：HABC 的接管归因，UniIntervene 的自动恢复。** 这不是断言它们算法表现更差，也不是按不同论文的初始成功率排序。

| 候选 | 与本项目的主要关系 | 当前建议 |
|---|---|---|
| RedFlow | 从失败片段提取有方向的动作纠正，原生 flow VLA | 保留为积累混合数据后的离线研究升级，暂不承担第一条在线训练主线 |
| HABC | 直接利用示范／接管和成功经验，明确处理接管边界 | 数据归因规范应立即借鉴；双价值头整体方案等待实现与预算核验 |
| UniIntervene | 将常见人工救援训练成“检测停滞＋检索恢复目标＋自动纠正” | 在基础正反循环及接管数据形成后，作为减少值守的第二阶段候选 |

个人判断：当前不宜把“新算法”作为唯一进步方向。先保证实际执行动作、接管边界、奖励、正反目标和成功经验回流正确，再决定是否换优化器；这些因素足以掩盖跨算法差异。没有发生自主成功时，成功示范和有效人工纠正仍可作为学习入口；没有任何成功支持的全零稀疏回放则不能靠换论文名称解决。

## 2. RedFlow：值得借鉴失败纠正，尚非首个在线基线

**原始事实。** 香港科技大学团队，2026-07-30 预印本。方法以进度模型和本体状态聚类，从同类上下文的正向经验生成动作纠正目标，再以加权吸引、失败抑制和纠正项更新 flow VLA。它是固定数据上的离线改进。真机使用松灵 Cobot Magic／π0；三任务分别有 600／200／100 条示范，再收集 200／100／100 条 rollout；每任务评估 100 次。附录给出 8 个 FSDP device，回合间人工复位。这是作者配置，不是最低算力要求。[论文方法与附录 D](https://arxiv.org/html/2607.27782v1)

**开放与可信度。** 本轮检索论文、项目相关搜索，没有定位到完整官方训练仓库及许可证，不能标为已开源；也未核实正式会议接收或独立机器人复现。机构背景与同品牌硬件提升相关性，不能替代源码和同协议复现实验。[arXiv 记录](https://arxiv.org/abs/2607.27782)

**我的判断。** 它解决的是“失败应该往哪里改”，和本项目担心的永久靠近坏参考动作不同：纠正来源是实际经验中的正向支持。但下面三项应成为采用门槛：

- 在物体位置、朝向、抓持状态变化后，相似本体状态与进度值是否仍对应同一动作需求？对抓放尤其要防止“机械臂状态接近，物体状态不同”的假匹配。
- 检索得到的动作集合是否多模态？从物体两侧绕行的平均动作可能指向障碍物。应检查匹配可靠性及物理可执行性，不能把经验质心当成真实反事实最优动作。
- 没有匹配成功支持的失败应留作负面证据或请求示范，不能强造纠正标签。正反方向也必须分别聚类或明确以目标条件区分。

因此，起始成功率低本身不是排除理由；**当前更直接的限制是代码未定位、数据前置成本和纠正标签可信度**。若首轮在线系统能稳定产生成功、失败、接管数据，可把该思路作为离线增益对照，而非同时引入到首版控制闭环。

## 3. HABC：最值得吸收的是归因协议，不能夸大现成程度

**原始事实。** ACE Robotics／清华深圳国际研究生院／香港中文大学，2026-06 预印本。HABC 用“能否完成”和“完成效率”两类价值信号给 flow-matching 监督加权。失败自主样本训练价值判断，但其 actor 权重为零；示范和接管可直接监督 actor。混合控制回合仅将最终结果标给最后一段自主执行，避免把接管后的成功归功于前面的错误。真机为 ARX X5、π0.5；每任务 200 条示范，每轮 100 rollout；作者采用 8×A800。附录另写从 π0.5 IQL checkpoint 初始化、action-expert training disabled，具体参数更新边界需源码解释，不能直接称为完整动作专家 RL 更新。[论文 §3、§4、附录 E–F](https://arxiv.org/html/2606.17043v1)

**开源审核。** 官方仓库目前仅 README、1 次提交，明确表示代码稍后发布；页面快照为 6 stars／1 fork。这是占位仓库，不是可复现训练代码。未核实正式会议发表或独立复现。[官方仓库](https://github.com/ACERobotics-VLA/HABC)、[README](https://raw.githubusercontent.com/ACERobotics-VLA/HABC/main/README.md)

**对结果的阅读边界。** 作者项目页给出的 92%／88%／38% 是其任务结果，不应与 ConRFT 等跨任务比大小；正文区分初始等预算比较和继续更多轮后的最佳 checkpoint，不能把后者当等预算胜利。项目页仍可支持其三项真机及作者归属。[作者项目](https://acerobotics-vla.github.io/HABC-Website/)

**我的判断。** 用户现有 DAgger 接管能力使这一归因机制很相关，而且无需等待完整 HABC 开源才能改进日志。但不能机械地把“接管前全部丢弃”规定成所有 off-policy RL 的通用规则：

1. 对实际执行的人类动作，仍可记录有效的一步转移并进入相应 critic；保留控制来源和时长。
2. 对“当前自主策略成功概率”或成功回合监督，不能把人类救援成果无差别反向贴给原策略。
3. 如果跨接管边界构造动作块或多步回报，必须明确截断、mask 或行为条件，保证学习目标与声明一致。

HABC 的双头更适合同时关注成功与效率的后续阶段。首个单臂抓放若还主要缺少可靠抓持／释放，先验证成功学习和正确数据流，未必需要立即引入第二个效率价值头。

## 4. UniIntervene：最贴近“减少接管”，但它是附加系统

**原始结果口径。** NTU／北京邮电大学团队；项目和仓库标示 CoRL 2026 接收，本轮未进一步核对正式 proceedings。UR7e 五任务中，作者报告 HIL-SERL 加该模块后平均成功率由 81% 到 88%，接管率由 34.3% 到 14.6%；后者是接管步数／总交互步数，相对减少约 57%。不是人工分钟减少 57%，也不是长时无人复位结果。π0.5 是文中的 SFT 对照，不应将 HIL-SERL＋该模块的结果称作 π0.5 在线 RL。[作者项目与结果表](https://denghaoyuan123.github.io/UniIntervene-project/)、[论文 §4](https://arxiv.org/html/2606.12372v1)

**实现比单个 recovery policy 复杂。** 公开流程包含离线进度标签、proxy value、停滞片段挖掘、Qwen3-VL 的未来／价值／触发头、恢复记忆以及 FAST 动作恢复头。代码 MIT；GitHub API 本轮取得 HEAD：`40f461f97573383c9cc8fdba43df56f9eb5bbea1`。页面快照为 2 stars／0 forks，不能据此推断性能，当前也不能宣称广泛验证。[固定版本](https://github.com/Denghaoyuan123/UniIntervene/tree/40f461f97573383c9cc8fdba43df56f9eb5bbea1)

README 明确公开的是离线训练 pipeline，**不含机器人部署和 HIL-SERL 集成，也不含轨迹、checkpoint 和记忆库**。当前 Fold Towel 样例使用 32 步恢复目标跨度、输出 8 步 7D 动作，夹爪包含在第七维；这只是数据契约，不自动适配松灵控制语义。[官方 README](https://raw.githubusercontent.com/Denghaoyuan123/UniIntervene/40f461f97573383c9cc8fdba43df56f9eb5bbea1/README.md)、[数据契约](https://raw.githubusercontent.com/Denghaoyuan123/UniIntervene/40f461f97573383c9cc8fdba43df56f9eb5bbea1/docs/DATA_FORMAT.md)

静态核对 `run.py` 确实连接七个离线阶段；未看到它启动真机或在线 RL。作者自己也将公开包与内部实验／部署存储区分；模块冒烟测试不能算本机器人闭环验证。[启动器](https://raw.githubusercontent.com/Denghaoyuan123/UniIntervene/40f461f97573383c9cc8fdba43df56f9eb5bbea1/run.py)、[发布来源说明](https://raw.githubusercontent.com/Denghaoyuan123/UniIntervene/40f461f97573383c9cc8fdba43df56f9eb5bbea1/CODE_PROVENANCE.md)

**我的判断。** 这条线值得上调为“减少人工的系统候选”，但不替代主 RL 优化器。主学习器成功率偏低时，初期仍需要人提供有价值的恢复经验；模型只是在随后逐步替代重复救援。把 VLM、价值模型、检索和恢复头全在首版引入，可能先增加集成和标定成本。

建议阶段顺序：

1. 保留接管起止状态、纠正动作、恢复后结果，构建可审查的常见失败分类。
2. 先给最常见的一两类可恢复故障实现可测的自动重试／恢复，单独统计每类命中率、误触发和恢复失败。
3. 当异常类型足够多、规则不再合算时，再比较 learned trigger 和目标条件恢复。触发器先以旁路方式评估，不立即控制机器人。
4. 只有恢复后下一段自主策略成功率和总体人工时间确实改善，才扩大自动接管范围。自动救援次数下降或上升本身都不是最终目标。

特别注意：论文 proxy value 将成功回合时间位置用作进度监督；本项目不能默认“越到后面越好”。反复犹豫、回退后再成功的轨迹会破坏该近似。应将抓持、物体目标位置和释放状态作为独立核验，并测试误触发。该风险是针对方法假设的分析，未在本机器人复现。

## 5. 其余预筛：为何没有继续扩成新长名单

| 线索 | 一级来源核到的范围 | 本轮结论 |
|---|---|---|
| TEMPO（2026-08） | FLOWER 结构，冻结 VLM，语义投影／动作专家分别 TD3、不同更新频率；两项 Synria 单臂真机，每任务 60 条示范；匿名项目页未定位训练代码 | 方法上符合“不限定动作头”，但还不是更成熟交付。不是 π0.5 的即用插件。[论文](https://arxiv.org/html/2608.07314v1)、[项目](https://anonymous.4open.science/w/tempo-page/) |
| EXIMO（2026-08） | 明确假设基础抓放等原子技能可靠，VLM 编排数据→SFT→残差 off-policy；22 项 ALOHA 仿真，使用 GROD | 适合研究“已有技能却不会组合”，当前抓放执行能力不足时不一定解决主瓶颈；未核到完整开放训练栈。[论文](https://arxiv.org/html/2608.19891v1) |
| Dejavu（CVPR 2026） | 冻结 VLA＋检索经验＋SAC 残差，成功经验增加到记忆；作者项目仍写 Code Coming Soon | 正式发表可信度较好，但冻结残差和发布缺口仍在；暂不能凭更新年份优先于完整开放 HIL 路线。[CVF 正式论文目录](https://openaccess.thecvf.com/CVPR2026?day=2026-06-07)、[项目](https://dejavu2025.github.io/) |
| Q-Planning（2026-08） | 冻结 BC，只更新 Q，对候选动作加权；作者明确候选中不可产生的行为无法依此学会；真机仍依赖人工逐回合成功标签 | 若错误主要是动作选择可作对照；当前允许零成功率时需先核候选行为覆盖，不能把“无遥操作纠正”误写成无人训练。[作者项目](https://q-planning.github.io/)、[作者实验室](https://www.pair.toronto.edu/publications/) |

上述筛选依据是机制、数据／硬件／代码与人工成本，**不是按跨任务起始成功率设 20% 或 50% 门槛**。50% 以下可作项目沟通中的粗略“尚不可用”描述，但不会决定候选准入；同任务、同协议的改进和最终自主可靠性才用于选择。

## 6. 可以立刻写入方案的改进，而非再加新算法名字

- **首轮候选保留 ConRFT 与 EXPO-FT，按同预算实测竞争。** 新增方法尚未提供“用户这套硬件上一定更好”的证据。
- **接管数据分层。** 区分成功示范、成功自主片段、成功救援、失败自主片段、失败但局部有效的人工动作；不是简单按整个 episode 成败删除全部数据。
- **成功回流和失败价值学习分别核验。** 系统有 replay 不代表成功经验一定进入 actor，有接管按钮不代表实际动作正确入库。
- **正反正常循环之外保留第三类恢复。** A→B 和 B→A 都不是任意失败状态的保证；常见故障恢复应单独学习／评估。
- **以减人工验收。** 除成功率外，记录人工接管秒数、场景复位分钟、人工标奖分钟及必须在场待命时间；自动模块的维护劳动也计入。

这是一份可行性评估与研究路线；没有把论文报告指标、仓库 stars、机构署名或静态代码审查写成已完成的真实机器人验证。

## 7. AutoSERL 最新复核：简单自动救援值得借鉴，但不替代 VLA 主线

AutoSERL 已在早期 41 项目录覆盖，此处是一次有界更新核验，不计作新发现。2026-09-22 通过 GitHub API 锁定官方提交 `978f11a9a25cbb6c13ad691df4e6f3156568c378`；只读论文与源码，未运行完整仓库或机器人。

**结论：它不是 VLA 后训练方案，也没有完成本项目完整抓放及正反自主复位。** 作者来自中科院自动化所、智源、北大／PKU-PsiBot 等，项目与 README 标示 ECCV 2026。方法将单条示范变为滑动窗口引导、停滞恢复和终止干预机制。六任务均为手中已持物／工具与单一目标交互；还需指定两处恢复点及几何阈值。基础实验无场景随机化，另做插头初始位置变化。训练奖励明确由人工标注。[原文 §3–4](https://arxiv.org/html/2607.01651v1)、[作者项目](https://autoserl.github.io/)

源码进一步界定了条件：`plug_insert/config.py` 使用 `resnet-pretrained` 和 `single-arm-fixed-gripper`；`train_rlpd.py` 选择像素 SAC agent，并非含语言表征的 VLA。示范引导当前只处理 6D 末端位姿，不能把“一条示范”外推为从桌面定位、抓取、搬运到释放的完整 pick-and-place。[任务配置](https://github.com/autoserl/AutoSERL/blob/978f11a9a25cbb6c13ad691df4e6f3156568c378/examples/experiments/plug_insert/config.py)、[学习入口](https://github.com/autoserl/AutoSERL/blob/978f11a9a25cbb6c13ad691df4e6f3156568c378/examples/train_rlpd.py)

**人工与复位必须拆开记录。** 自动干预 wrapper 仍读取 SpaceMouse 按键决定奖励。插头环境有程序化抬起／回初始位姿；特殊重新抓持分支则由 F1 触发，并要求人工放置物体和回车。由此不能说所有回合都要人复位，也不能宣传全程无人：常规机械臂回位、异常重新抓持和人工判奖是三种不同劳动。[干预实现](https://github.com/autoserl/AutoSERL/blob/978f11a9a25cbb6c13ad691df4e6f3156568c378/serl_robot_infra/franka_env/envs/wrappers.py)、[插头复位实现](https://github.com/autoserl/AutoSERL/blob/978f11a9a25cbb6c13ad691df4e6f3156568c378/examples/experiments/plug_insert/wrapper.py)

**代码确已发布，但可运行性没有验证通过。** 仓库包含学习器、机器人基础设施和自动干预 wrapper；README 让用户沿用 HIL-SERL 环境。公开例程仍有作者本机示范路径，需自己采集和配置。另有一个明确应预检的静态问题：`intervened_slide_idx_buffer` 的值初始化为 list，恢复分支却直接将该值 `+ 1` 用作切片上界；依照当前数据类型，该分支会产生类型错误。这里只完成源码路径分析，未在真实恢复执行中复现，也不据此否定论文实验。项目级 `LICENSE` 未在固定提交文件树中找到；README 有 Apache-2.0 徽章，树中仅检索到控制器子目录许可证，因此应记录为“README 声明 Apache-2.0，项目级许可证文件待补核”，不夸大许可完备性。[README](https://raw.githubusercontent.com/autoserl/AutoSERL/978f11a9a25cbb6c13ad691df4e6f3156568c378/README.md)、[固定仓库](https://github.com/autoserl/AutoSERL/tree/978f11a9a25cbb6c13ad691df4e6f3156568c378)

**对推荐的影响。** 保留 ConRFT／EXPO-FT 的 VLA 主学习器比较；AutoSERL 可以支持更轻的自动救援先行方案：对固定工装、已抓持且对象关系已核验的局部阶段，先尝试轨迹引导及退出条件，再决定是否需要 UniIntervene 的学习式恢复。完整抓放中物体可能移位、脱落、旋转，不能只因末端接近示范轨迹就假定场景已恢复。将该 wrapper 接到 VLA 是新的工程组合，须独立验证，不是论文已经交付的功能。
