# 正反任务的自主运行可行性：状态、数据和验收

2026-09-22。用户已确认首任务只使用一只机械臂，另一臂暂不参与；GPU 未确定。本文为拟议工程设计与数学分析，不是已实现系统或真机结果。

## 1. 为什么单次成功率不足以选型

假设固定策略、每次独立、正反各成功概率 p，而且任何失败都需人帮忙，没有自动重试。一个完整往返成功概率 q=p²；连续 20 往返成功概率 p⁴⁰；首次失败前完整往返数的期望 q/(1−q)。

| 每方向成功率 p | 连续 20 往返全部成功 | 首次失败前完整往返数期望 |
|---|---:|---:|
| 90% | 1.48% | 4.26 |
| 95% | 12.85% | 9.26 |
| 98% | 44.57% | 24.25 |
| 99% | 66.90% | 49.25 |
| 99.5% | 81.83% | 99.25 |
| 99.9% | 96.08% | 499.25 |

同一模型下，要以 90% 概率完成连续 20 往返，每方向需约 99.737% 成功。这只是说明连乘效应，**不能把论文成功率代入后当作本机器人预测**。实际状态相关、策略更新和场景漂移都违反简单假设；若可自主重试或救援，任务失败也不再等于人工介入。实际主指标应为“需人工介入的事件率”和“连续无人介入运行的存活曲线”。

## 2. 状态集合而非轨迹倒放

- A：物体处于源区允许范围、可抓姿态；夹爪释放、机械臂位于下一任务允许的起始范围。
- B：物体处于目标区允许范围，满足同样的可继续执行条件。
- H：物体已经抓起／仍夹持；不是 A 或 B。
- R：失败但可自主恢复，例如物体仍在可达桌面、夹爪空抓、抓取姿态偏离。
- U：当前系统无法自动处理，例如物体离开可达范围或需要人工排障。

正常任务是 A→B 与 B→A。逆向策略能从 B 回 A，不代表能从任意 H/R 回 A。目标切换由物体释放、位置、稳定性等实际成功判据触发；超时只触发诊断，不能无条件翻转方向。末端回到预备位可以用确定性控制，不要求所有恢复步骤都由 RL 学习；但必须显式记录这一自动操作。

关键闭环条件是：正向实际终态被反向起始分布覆盖，反向实际终态被正向起始分布覆盖。只在人工摆好的固定位置分别测高成功率，不能验证这一条件。

SERL 的官方系统已展示 reset-free object relocation，可作正反调度参考；它不直接证明任意 VLA、机器人和失败状态均能自主恢复。[SERL](https://serl-robot.github.io/)

CRONOS 的仿真研究提示，减少复位会改变分布并显著影响策略表现；末端恢复和复位课程本身是实验变量。它是仿真基准证据，不是当前松灵真机性能预报。[CRONOS](https://embodiedai-ntu.github.io/cronos/index.html)

## 3. 第一版的数据与调度契约

使用一个持有机器人控制权的调度器；两个方向各自有策略头、critic、replay 和目标成功判据。可以共享冻结 VLA 模型实例来节约推理资源，但模型封装必须支持两套头；这是开发项，不是假设现有脚本自动支持。

每条数据至少保存：run_id、episode_id、goal_id、policy_version、observations、proposed_action、executed_action、controller_owner、executed_steps、reward、success_source、termination_reason、next_observation、time_stamps。逆向正常搬运也属于有效训练任务，不能与事故后的 reset 标记混用。

目标边界：若训练的是每目标 episodic Q，完成 A→B 后终止该目标的回报，再开始 B→A；不要把正向奖励与反向 Q 拼在同一条 Bellman target 中。另一种可行设计是把调度器状态和未来目标转换显式纳入继续型 MDP，但这比首版复杂。

动作块边界：以实际执行前缀构造 transition。执行了 k 步，折扣和下一观测对应这 k 步；不能用未执行动作算完整 H 步动作块。真正终止、时间截断和人类接管要分别表达，mask 依据所定义的 MDP 决定，不能一概 done=1 或 done=0。

人类数据：可以进入离策略价值学习和监督池，但自动成功率只统计无接管的完成。是否让 Q 跨接管边界 bootstrap 要明确定义；截断可以避免虚假归功，却会丢失接管后的奖励传播。保留实际动作和控制权才能比较这两种选择。

## 4. 首版实验回答三个不同问题

1. **RL 是否有额外价值？** 同一种 VLA／同一初始化，比较继续 SFT／DAgger 与加入 RL；同成功示范、同接管分钟、同机器人时间。不同 VLA 对比回答系统选型，不能归因于优化算法。
2. **正反循环是否节省人力？** 同学习器，比较人工恢复场景和自动反向恢复；把训练反向的示范成本、失败救援、算力等待全部计入。训练早期总人工可能增加，应比较累计人力的交叉点。
3. **反向学习是否促进正向？** 在已经可以循环后，再比较独立双头与共享目标条件模型；同总数据、同正向数据量／预算，报告反向是否占用更多正向训练机会。不要把“多采了一倍数据”解释为共享理解。

首轮可以先做前两项，第三项是后续研究，不必同时实现所有消融。

## 5. 评测与验收建议

- 初筛每方向 20 个预先指定起始状态，固定 checkpoint，不接管计成功；这只能发现明显问题。
- 再测试“另一方向真实产生的终态”，不能仅测人工复位状态。
- 连续运行按多个独立 run 报告完成往返数、自动重试数、人工介入原因和时刻。人工介入后重新计 run，不能把多个片段拼成一次无人值守。
- 在循环工位之外保留独立起点／朝向评测，防止只会重复一条狭窄轨迹。不要混合这两种成功分母。
- 人工主动劳动分钟与必须现场待命分钟分别记录：接管只需数秒，但等待接管可能占用整小时。
- 成功检测单独留出正负例，检查误报、漏报、遮挡和“到位但未释放”。高误报会制造虚假的自学习进步。

在独立同分布、固定策略的二项假设下，20/20 成功的精确单侧 95% 下界仅为 0.05^(1/20)≈86.1%；若要以同口径下界至少 99%，且零失败，需要 299 次。**这不是要求第一轮做 299 次，也不能将相关循环机械计作 299 个独立试验。** [NIST 置信区间原理](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)

GPU 尚未确定。先用实际相机数、图像大小、动作长度、batch 和训练参数集合测峰值显存与端到端延迟，再决策配置；冻结大模型也要负担其推理。并行 learner 不能抢占控制所需的延迟预算。作者硬件配置与 GitHub 用户显存报告均不是本项目的最低配置保证。
