# VLA 弱行为先验下 RLT 与 HIL-SERL 组合的独立审查

核验日期：2026-09-22。范围：松灵双臂、VLA-only、可少量遥操作示范与接管、A/B 两处往返抓放；不讨论 ACT。以下没有真实机器人实验结论。

## 判断

组合具有技术可行性，也比把原版 HIL-SERL 当作现成 VLA 后训练方案更贴近用户约束。但是，建议命名为“VLA 表征与参考动作驱动的 HIL 离策略学习”，明确保留哪些 RLT 组件、借用哪些 HIL-SERL 工程组件。它是需要验证的整合方案，不能把两个已发表方法的效果相加。

尤其要修正“加 HIL-SERL 才让 RLT 能接管”的理解：RLT 本来已经接收人工干预和示范。真正新增的价值，应落在可靠的接管数据链路、示范回放配比、弱参考动作下的学习目标、奖励和循环调度上，而不是重复添加已有机制。

## 已核实的原论文边界

RLT 使用 VLA 表征压缩 token 和参考动作条件的 actor，输出完整动作块，并非固定幅度的加法残差。原实验逐任务先用 1–10 小时遥操作数据微调 VLA 并训练 token，再执行 400–1000 个 RL episode；机器人数据用时不含复位开销。算法已把接管动作写入回放，并作为该样本的参考动作。Ethernet 消融中，token 换 ResNet-10 后吞吐下降约一半，移除 BC 正则跌幅最大；移除参考动作输入能最终追平，但学习更慢、失败更多。这证明其组件在已适配任务的先验上有用，没有证明近零行为先验可以直接冷启动。[RLT 原论文，§IV、§VI、附录 B/C](https://arxiv.org/html/2604.23073v1)

HIL-SERL 的公开训练脚本将示范/接管缓冲与在线缓冲按 1:1 采样，记录实际执行的人工动作，采用 actor/learner 异步结构；示例创建的是像素 SAC 等 agent，不是直接更新 π0.5 权重的训练器。以上数据流程可以移植，但 VLA/token 和动作块接口需要实现。[训练脚本](https://raw.githubusercontent.com/rail-berkeley/hil-serl/main/examples/train_rlpd.py)、[仓库说明](https://raw.githubusercontent.com/rail-berkeley/hil-serl/main/README.md)

## 低成功率需要拆成三个问题

1. **动作先验差，视觉语言表征可用。** 例如能识别物体和目标，但当前机器人动作尺度、夹爪时机尚未适配。此时 VLA token 支撑小 actor 从示范和接管学习，有合理依据；参考动作可以弱依赖。
2. **部分行为可用。** 能接近并抓起，放置总失败。应按阶段评价参考动作，不因整条任务成功率低就把所有参考抛弃。先校正放置，往往比从头扩大探索合理。
3. **表征和动作都不适配。** 若相机/遮挡/语言条件导致目标或接触状态无法辨别，接上 HIL-SERL 不会自动修复。应先处理输入、示范覆盖和 VLA 任务适配。

“成功率为 0”只是结果统计，不能推出“表征无用”或“表征一定可用”。token 重建损失低也不等于对抓取/目标区分足够。可先在留出的物体位置和视角上检查：token 是否可预测物体/目标区域、抓取阶段、持物状态；再看小 actor 在留出示范上的动作误差和受限闭环结果。探针只用于排障，不能替代实际策略评价。

## 冷启动建议：保留表征，避免被错误动作锁住

以下属于设计建议，并非 RLT/HIL-SERL 已证明的组合效果。

- 首批 A→B、B→A 示范共同用于任务 SFT（可参数高效微调）、训练 token readout，以及小 actor 的行为克隆初始化。不要求先达到高任务成功率，但至少先验证动作坐标、尺度和夹爪语义正确。
- 冻结这一版 VLA 与 token 后进入在线离策略 RL；优先沿用 RLT 的动作块 TD 和小 actor/critic，接入 HIL-SERL 式示范/接管/在线回放与日志机制。不要把 SAC 与 TD3 的损失拼在一起却不说明具体算法。
- 人类示范/接管样本的监督锚应是实际执行的人类动作，不是同状态下错误的 VLA 动作；保留失败转移供 critic 学习，不要把所有接管片段都标成成功。
- 非接管样本的参考动作正则可以弱化或按已验证任务阶段分配；保留 reference dropout。不要一开始完全删掉锚定，也不要用尚未校准的 Q 值直接判断“参考可信度”。
- 弱先验的最简单版本是一个固定较低参考 BC 权重，加稳定的人类动作 BC 权重；先证明它优于标准 RLT，再尝试自动门控。若权重改动太多，很难判断哪个机制有效。
- 正反目标必须进入 actor/critic 与 VLA 条件。原 RLT 单任务固定指令下可省略语言 embedding，不宜照搬到两目标共享策略中。
- 若随后更新 VLA/token，旧缓存特征会过期：保留原始图像、状态、指令、动作和模型版本，离线重新编码或清楚分隔版本。

可以表达为两个不冲突的监督项：人类样本向实际动作靠拢，其他样本按可信度向 VLA 参考靠拢；actor 同时优化 critic 给出的回报。这是混合设计，不应冒充原版 RLT 公式。

## 这是否会成为“VLA 编码器＋小 RL 策略”

会。如果参考动作几乎不起作用、VLA 在线完全冻结，主要改善发生在小 actor，该系统本质上就是 VLA 表征驱动的任务 RL 策略。这不是失败，也满足使用 VLA 的工程约束，但不能宣称基础 VLA 本体学会了新技能，更不能自动继承大模型在所有语言指令/物体上的泛化。

应分别报告三种结果：组合策略成功率、去掉小 actor 后基础 VLA 成功率、未训练布局/物体/指令泛化。只有将可靠轨迹回流更新 VLA，并在相同测试条件下确认裸 VLA 提升，才能说基础模型本身变强。冻结 VLA 阶段可称“基于 VLA 的组合策略提升”。

## 最小三组实验

三组共享初始 VLA、首批示范、对象布局分布、累计人工分钟和机器人在线预算；人工接管时间计入总成本，评估回合禁用接管，救援即记失败。

| 组 | 方法 | 回答的问题 |
|---|---|---|
| A | VLA 任务 SFT＋DAgger，保持同等人工预算 | RL 是否比继续利用接管做监督学习更划算？ |
| B | 标准 RLT 路线：相同初始 SFT/token，原参考正则和原有 HIL 机制 | 原版在当前弱先验上已经足够吗？ |
| C | RLT 表征/动作块＋示范/接管强化回放，actor 冷启动、人类 BC 与弱参考 BC 分开 | 针对弱动作先验的改动是否改善学习与人工成本？ |

这三组先回答“系统路线值不值得继续”，不能分离 C 的每个贡献；若 C 明显胜出，再逐项撤去 actor BC、回放改动、参考松绑。token 是否必要也需要额外消融，不能从 C 胜过 B 推出。

先在 A→B 和 B→A 分别评估，再接共同的循环调度器。评价：独立布局成功率、完整往返成功率、每小时成功搬运数、每 100 次搬运人工分钟、连续无人循环长度、掉落后恢复率，以及累计示范/接管/复位人工。复位动作成功不等于恢复所有失败状态。

## 预先约定的停止与调整条件

下列数字属于建议实验关口，不是论文保证，应在启动前固定，避免看到结果后改标准。

- 接口离线回放和受限动作验证不通过，停止 RL，先修坐标/时间戳/动作覆盖；不能用采更多数据掩盖接口错误。
- 比较到双方约定的首轮预算（例如每方向 100 个在线回合）时，连续两个评估检查点都没有无接管完成，且接管占比不降：暂停自主探索，补最薄弱阶段的示范/任务 SFT，再评估。100 回合是检查点，不是宣判算法失败的通用阈值。
- C 相对 B 只增加 Q 预测值，实际无接管成功率不升，或动作明显偏离数据覆盖而失败增加：先恢复更强的人类动作锚/缩小更新，排查 critic 外推；不能以 Q 上涨宣称进步。
- C 在相同累计人工预算下不优于 A/B，且推理与维护成本更高：不继续堆叠新机制，保留更简单方案。
- 两方向尚不能分别稳定完成，或失败后仍频繁需要人工摆回：暂缓无人长循环。训练阶段允许更多接管，不能把有人救援的长录像计作自主闭环。
