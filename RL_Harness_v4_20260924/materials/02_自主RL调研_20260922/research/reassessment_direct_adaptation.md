# 新条件复评：实时 EXPO、原子技能自学习与分阶段诊断

2026-09-22。基础策略可少量 SFT，成功率偏低，包括零成功率；不固定初始百分比，也不要求原生动作专家。首任务松灵单臂抓放。本文补充本轮根代理直接核查的原始来源和工程推断，不是模型训练／真机实验。

## 1. Real-Time EXPO-FT：更新，但解决的是时延，不自动解决复位

Stanford，2026-09-16 预印本，作者 Perry Dong、Kuo-Han Hung、Dorsa Sadigh、Chelsea Finn。相较普通 EXPO-FT，它把慢 VLA 的候选动作生成与较快的最新观测条件 edit 分开，并按延迟对齐执行动作、价值学习和 flow 监督。四项真机实验面向动态抓取、平衡、传递和踢球。[论文](https://arxiv.org/html/2609.18207v1)、[作者项目](https://pd-perry.github.io/real-time-expo-ft/)

对自学习审核最重要的是措辞边界：论文说训练没有人工 intervention，但讨论节明确实验仍由人复位。前者是动作接管，不能改写为训练全流程无人。初始示范、任务奖励检测和人类独立核验也应计入系统成本。平均 42%→97% 是其任务协议内结果，不与 ConRFT 等跨论文排名。

附录明确 base 通过成功回合的 flow-matching 继续学习，训练参数含 LoRA 和非冻结语言主干之外的模块，包括 SigLIP 视觉塔。**这份后续论文的设置不能反过来证明普通 EXPO-FT 旧论文或当前全部配置采用同样冻结边界。** 它提示采用时必须按最终版本核对实际参数，而非只看名为 freeze_encoder 的配置。

**工程判断：** 当前静态抓放首先比较普通 EXPO-FT；若端到端延迟成为失败主因，再采用实时分支。不因更近期就多引入异步延迟、候选噪声筛选等模块。项目链接指向同一 EXPO-FT 官方代码库；不把该库的 stars 重复计作两个独立生态。[官方仓库](https://github.com/pd-perry/expo-ft)

## 2. InSight：公开的自学习邻近方案，但不是当前 RL 优化器替代

原文 v2 为 2026-09-21，Stanford／Princeton／JPL 作者合作。先从已有示范训练可按原子动作指令执行和停止的 π0.5；VLM 识别缺失的动作片段，用参数化控制器尝试，成功片段回流监督训练。真实 xArm 抓放基础数据为 50 条示范，再学习旋转／倾倒等新原子动作。因此“目标技能零示范”不等于“没有基础数据或基础技能”。它主要是自动数据采集＋监督回流，不能冒充 SAC／Q-learning 已开源。[原文](https://arxiv.org/pdf/2606.24884)、[作者项目](https://insight-vla.github.io/)

官方仓库有 real、sim、training 和推理入口，Apache-2.0；README 明确数据及任务 checkpoint 未随仓库交付，公开下载链接仍待补充。网页快照 45 stars／2 forks，1 次提交，仅说明当前关注及发布状态，不说明独立复现数量。[官方仓库](https://github.com/insight-vla/insight)

**工程判断：** 值得借鉴的不是重新做一整套 VLM 规划，而是区分“接近／抓起／搬运／释放”的能力缺口，并让成功片段改善对应能力。首个单物体抓放已有遥操作可用，额外引入 VLM 分段、动作参数提议和视觉 oracle 未必节省总工程；因此不列首轮 RL 基线。作为后续技能增长参照保留。

## 3. 本轮不再按初始百分比筛选，而按失败机制筛选

下表为本项目的工程诊断建议，不是上述论文的实验结论。

| 观察到的失败 | 优先验证的学习方式 | 真正需要检查的条件 |
|---|---|---|
| 抓取姿态、夹爪或路径基本不会；成功主要由人提供 | ConRFT 式完整动作头＋示范／接管，或继续直接监督基础 VLA | 正确动作是否能学入，表征是否包含物体与目标信息；不是只调 Q |
| 已会接近／抓持，执行不稳或局部纠正能完成 | EXPO-FT 的候选选择、edit 和基础模型回流 | 正确动作是否在当前候选／修正可达范围，成功经验是否真正更新 base |
| 已有重复采集的混合质量数据，在线更新调试／资源成本高 | STEAM／优势条件等分轮离线后训练候选 | 进度估计能否评价真实失败和恢复，是否真的减少人工标注 |
| 单次能成功，接着往返却不断卡住 | 正反调度、可继续练习状态覆盖和恢复课程 | 不先归因于 RL 优化器；检查对方终态是否落入下一方向起始覆盖 |
| 主要败在观测变旧、闭环反应慢 | 延迟建模／实时执行，再考虑 Real-Time EXPO-FT | 用传感器到动作的端到端延迟和失败轨迹证实，而非只看网络 forward |

首轮可以只实现一个学习器。数据采集、独立成功检测和正反状态契约要保持可复用，以便后来替换算法，不必为了比较候选重复搭建全部机器人系统。
