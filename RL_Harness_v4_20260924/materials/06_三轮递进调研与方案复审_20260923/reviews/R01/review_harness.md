### Q1. GPT-6 主观察是否被写成已验证的万能感知／实时控制器？

- **定位：**01 §6.1（119–123）、§6.2（133–135）、§7；03 §2.3（63–72）、§3.3；接口附录 §4.1、§4.4、T02/T22/T43。

- **是否足够：**足够。多图按时序输入、独立留出校准、unknown、源时间新鲜度、单位和参考系检查均明确；本地保护不等远端逐电机周期返回。专家汇报没有把结构化输出或 DONE 当真值。

- **必要修订：**无；工位校准和时延预算保持待实验状态。

### Q2. 没有强上游 policy，自动 DAgger 是否仍被不当承诺一定启动？

- **定位：**01 §1（31）、§2（43–45）、§6.3、§10.2；03 §1.2（29）、§2.3（68）、§3.3（166）。
- **一手证据：**S1 的 Algorithm 3.1 与理论条件。
- **是否足够：**足够。两份文档均把 Harness 作为需验证的纠正来源；允许局部原语、几何和程序提供启动信息，不要求另造强 policy，也未把未知质量教师等同原论文专家。
- **反例核对：**所有真实回合零成功、奖励无区分、纠正也无效；反复聚合只会复制错误。现文明确这种条件不能保证启动，并要求局部纠正和小样本 BC 预检。
- **必要修订：**无。

### Q6. H3 能否识别程序积累的训练贡献，而非只测救场？

- **是否足够：**足够。主实验从同一初始 policy 分叉为固定库／允许扩展库，后者生成与试验成本纳入预算；两组最后撤辅助。旧新 policy × 旧新 Harness 四组另冻结、不训练，并加两个无辅助试次。图、图注和正文一致。

### Q12. RPent/OpenETA/Phy 的比较是否公平，是否因品牌或无现成 RL 排除竞争者？

- **定位：**01 §10.2（295–303）、§10.5；03 §2.5（92–105）；调研 §6、§9.2、§11.2、§12；接口 T38。
- **一手证据：**S3、S4、S5。三者所读路径有不同可复用职责，不能以任一工具框架名称代替完整执行与学习栈。
- **是否足够：**足够。RPent 是先联调者，不是已胜者；同 GPT、tool schema、模拟 adapter、故障记录、入口／模式比较观察、交接、日志和工时。OpenETA 未有本项目 RL 与 RPent 需补学习链同等处理；Phy 持久意图的优点与缺少完整实体 Gateway 的边界均保留。品牌只影响部署成本。
- **反例核对：**给 RPent 自有 Gateway，却用 OpenETA 原生入口直接比取消；或以 Phy 有 HTTP tool API 推出硬件执行闭合。统一契约、具体入口记录和需替换路径的成本统计排除了这类不对等结论。
- **必要修订：**无。本轮未重新审计三个仓库的全部执行路径，不将局部阅读升级为全面性能排序。
