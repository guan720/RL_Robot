## 逐问审查

### Q1：成功纠正是否一定能教会部署 policy？

**定位：**01 §6.3、§6.7、§10.2；03 §2.3–2.4；接口 T53。**来源：**DAgger Algorithm 3.1、DIDA 式(3)与 E.1。

**反例：**教师额外相机看见物体在遮挡物左侧或右侧，学生输入完全相同，却分别收到相反横移动作；增加可靠标签仍可能使确定性 BC 学到居中的无效动作。即使两种教师动作都真实成功，也不说明学生可识别。

**充分性：**01 L141–145 已要求冻结快照、记录实际依赖观测、禁止 live sensor 偷读未来，并用相同起点不同后续反馈检查标签依赖；对不可辨识情况明确增加部署历史／视图或收窄范围。§10.2 又把表达能力、编辑可达、Q 选中和独立迁移分别验收。03 未把 DAgger 名称包装成可靠性保证。**必要修订：无。** 同信息限制只消除一类信息差，不能承诺 Harness 正确；文本已将质量和闭环验证另立门槛。

### Q2：反馈程序产出的动作是否会被错写成早先一次预测？

**定位：**01 §6.2–6.3、§6.6、§8.3；03 L80–86；异步附录 §4.2–4.3；接口 T32。**来源：**DIDA 的延迟状态／教师标签区分，Code as Policies 的反馈程序机制。

**反例：**帧100生成接近动作，帧107才看到滑落而改为撤离；把最终重抓成功路径整体当作 `U_100`，会把未来反馈隐含写进普通 BC，也会伪造宏动作行为身份。反过来，因其含事后信息而删除所有数据也不合理。

**充分性：**冻结稿保留微步事实，普通同协议 U 要求同一快照与队列；反馈轨迹须重建新决策点，特权／事后 BC 单列候选。孤立一步标签不得重复填满 n 步，flow／diffusion 未知位置不能只靠末端 loss mask 掩盖。真实 request 与纯 shadow 建议另分，后者不能配他者后果做 TD。**必要修订：无。** 这些资格尚需回放验证，不能以“全部存入 buffer”代替分支正确。

### Q3：RPent 主骨架能否在长工具期间观察并及时接管？

**定位：**01 §10.1–10.2、§11；03 §2.3、§2.5；接口 §1.3、T38。**来源：**RPent `execute_tool`、`cancel_active_and_wait`、`_build_tools`；OpenETA 的上下文与观察义务路径。

**反例：**motion 工具卡住，观察调用排在同一串行工具队列后；远端超时触发取消，但旧线程仍在运行。即便换成另一个认知框架，若继续沿用相同阻塞设备入口，风险仍在。

**充分性：**接口 L58 明确观察服务订阅独立只读图像／遥测，并要求长工具卡死时仍送达多批新观测、能发起取消及本地保持；RPC 取消不充当设备回执。选型固定同 GPT、工具、模拟本体、入口、模式及故障记录，按改造成本可更换骨架。RPent 的优先级是联调顺序，未称现成最优；OpenETA、Phy 被纳入相同契约比较，且没有因缺某品牌适配直接淘汰。**必要修订：无。** 真机停止耗时和观察能力仍待验收。

### Q4：一个 Gateway 是否就足以保证物理排他？

**定位：**01 §11 L333–339；接口 §3.2–3.4、T31、T42、L423、L433；03 L41、L70。**来源：**ROS2 资源 claim 与 Phy `start_action`／`reconcile_nonterminal`。

**反例：**`move_eef` 和 `move_joint` 按工具名分别获锁，实际争用同一机械臂；夹爪由 reset 间接操作却不在资源集合内。又如 POST 已到设备、ACK 丢失，旧任务在会计层结案，新任务重新发送同一增量命令。

**充分性：**文档明确资源按物理部件及依赖闭包登记，多资源未齐不动作；policy、试验、恢复和 reset 使用同一入口。unknown 不释放实体所有权，跨任务仍须对账；重启抬高代次，驱动不支持 epoch 时由唯一进程持连接并确认在途命令。Phy 的局部去重被正确限定为参考，没有被误当全局物理保证。**必要修订：无。** 多资源请求、进程重启及未知回执的故障注入是已写明的开发义务。

### Q5：迟到评分、旧图像和换向是否仍可能污染当前控制？

**定位：**01 §6.4、§11；接口 §4.2–4.3、T42–T44、L433；03 L72、L86。**来源：**OpenETA `_current_vision_evidence`，Phy `observe_action`。

**反例：**A→B 成功回复在 B→A 开始后才到达；同调用 terminal 先于旧 running 返回；源图像很旧但接收时间很新；reset 清队列时旧前向线程仍读取可变处理器。仅有 request ID 或丢弃最终输出都不足以排除这些情况。

**充分性：**历史评分、历史监督和当前控制分别判资格；缓存键包含目标、证据区间及评分版本。回执按调用身份、序号和代次单调处理；冲突终态对账隔离。新鲜度按源采样时间与同步误差；换向／发布设置读写屏障或不可变请求快照，旧结果隔离不代替状态屏障。**必要修订：无。** 这组联合边界在开发文档中已闭合，专家汇报按篇幅概括并链接附录是充分的。

### Q6：程序试验失败或标签被撤销后，能否停止污染扩散？

**定位：**01 §6.5、§9、§11；接口 §4.5、§6.1、§6.3、T23、T27；03 §3.3。**来源：**Phy 的持久意图／任务记录，以及 Code as Policies 的程序执行机制；撤回要求属于本项目工程推论，并非两者已提供的完整功能。

**反例：**新恢复程序修改评分标准，使错误释放被视为成功；撤销标签只更新 replay，但此前已训练的 checkpoint 继续发布；代码回滚后误认为持物状态也回到试验前。

**充分性：**TRIAL 限定权限、动作域、预算和停止条件，候选不能修改 rubric／保护／分母；候选数据隔离后再获训练资格。标签撤销沿样本—视图—checkpoint—后继版本追踪并暂停晋级，必要时回退可信包重训；物理场景须重新观察恢复。部署包包含 normalizer、动作和依赖版本，不只保存权重。**必要修订：无。** 文档没有强加逐次人工确认，也没有把静态检查称为物理验证。

### Q7：程序积累的训练贡献与 A–D 阶段是否足以支持最终目标？

**定位：**01 §6.7、§12、§13.1–13.4；03 §2.1、§3.1–3.2；图6与图3。**来源：**DAgger 的聚合训练机制、Rliable 的有限重复不确定性提示，以及本轮因果设计推论。

**反例：**新 Harness 只把困难起态摆得更简单，或替 policy 多做一步，四种冻结组合的系统成功都提高；这仍不能证明程序扩展使 policy 在共同任务分布上学得更好。多测同一个模型也不等于多个训练重复。

**充分性：**H3 主实验从相同初始 policy 分成固定库／可扩展库两条训练链，生成、试验、恢复成本全部记账，之后关闭动作辅助，在共同留出起态测试；四组合只解释运行配合，另有标签用途及练习机会机制消融。三条收益路径允许某程序只恢复练习，不强迫其全部被学生模仿。H1 使用持续纠正 BC 对照；H2 分开循环与共享；统计预先固定样本、实际增益、允许回归、停止规则与独立训练预算。03 对应 A=P0–P2、B=P3–P4、C=P5、D=可选P6，并允许当前任务达标直接验收。部署复合 policy 的必要模块一起冻结，未把编辑器收益冒称原生 VLA 全部内化。**必要修订：无。** H3 若只提高辅助表现，按现有标准只能得出系统收益；最终稳定性、双向表现和人工成本仍需独立实证。

尚待实测的核心不确定性没有因以上回答消失：固定槽内生成纠正是否来得及、独立观察能否覆盖关键接触事件、解释器给出的动作是否与学生输出空间一致、频繁接管后还有多少合格学习样本，以及程序改进是否能在相同总成本内转化为双向独立能力。冻结稿均将它们交给预检或实验处理。首轮实施应保存失败和未知的完整轨迹，并按方向、错误类型、接管原因检查覆盖；成功案例录像不能替代这些证据。

本轮也没有独立复现任何候选框架的性能排名。源码审查只支持所列函数具有某种行为，不能据此断言其他路径全部缺失某能力。通用性在当前范围内指可替换本体、动作定义和训练组件的接口设计；两个模拟适配器通过仍不构成跨机器人实测。阶段验收须先填入具体任务允许的误报、回归、时延和独立能力标准，当前硬件与工位尚未确定时不宜由审查者代填任意数值。上述限制与文档的现有主张相容。
