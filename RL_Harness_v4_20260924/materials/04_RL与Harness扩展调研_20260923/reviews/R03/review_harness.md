## 1. 先从冻结输入提取技术点

以下技术点先从输入提取，再据此阅读第一方资料、提出反例；并非先接受选型结论再补引用。

1. 系统需要让一个目标条件 policy 同时学习 A→B 和 B→A；Harness 负责观察、评分、动作纠正及有限代码恢复，不预设另一个强 policy。
2. RPent 是暂定认知骨架；Strands 等是工程底座挑战者；Show-Harness 是动作解释器候选；VoLoAgent 是冻结 policy 的辅助系统对照。不同层不应混成单一排行榜。
3. 通用接口依赖能力描述、动作／观测 schema、坐标和时间语义；通用软件不保证同一权重跨本体直接工作。
4. 语义解释器只能生成意图和规范动作，所有实体动作经唯一 Gateway，包括初始化、reset、主动观察、TRIAL 和评测。
5. GPT 观察要脱离长动作工具锁独立获得带时间戳的事实；GPT 的数值动作和程序需要时效、参考系与前置条件检查。
6. 请求取消、模型结果丢弃、程序返回、物理停止分别记录；控制权交接需要当前代际的 quiesce 凭证。
7. 保存原提案、学习边界动作、驱动命令和实测状态；反馈后重规划的整条轨迹不能倒填成最早观测下的一次动作块。
8. DAgger 是对访问状态的纠正聚合；未执行标签可长期用于 BC，但不能借他者动作后果生成真实 TD。实际同协议控制决策还须满足队列时序。
9. 换 goal 时结束旧 episode、清除旧动作／请求资格、重新观察及 prime；迟到结果只按其原始目标归档。
10. 数据、标签、模型、normalizer、调度、任务定义、Harness 代码与评分配置共同版本化；撤销标签要追踪权重，软件回滚后仍须恢复真实场景。

### Q04：长动作工具卡住时，GPT 是否还有新观察？

**反例：** observe 在同一 Toolkit 操作锁后排队；异步 API 可保持连接，却没有新相机事实。

**定位与回应：** T2:47、54–58、87–89、150–154、303–307；H:129。设计让观察订阅 Gateway 的只读图像／遥测事件，并规定长工具运行及卡死时继续送达多批新观测、触发本地保持。

**充分性：充分。** S4–S5 证实原锁限制；S9 证实 await 线程处理不自动形成独立物理观测。方案补的是明确独立路径，未把开异步选项当通过。当前没有实际独立观测结果，仍需按该门槛实现。

### Q05：GPT 能给动作是否被误写为能可靠落地所有动作？

**反例：** 单幅 RGB 的像素位置直接变为三维末端坐标；合法 JSON 数值被当成可达轨迹；多图遗漏瞬时掉落却给成功。

**定位与回应：** T1:115–131；T2:152–163、185–201、338、350。接受数值、轨迹和程序，但要求坐标／时效／前置状态、可表达性及输入证据；无深度或平面约束不把像素当三维。多图抽帧规则、未知结果及工位校准均独立记录。

**充分性：充分。** 文档保留 GPT 主观察与直接纠正能力，同时承认准确率、延迟和调用预算未实测；未借结构化输出声称事实正确，也未强制增加另一个语义模型。模型接入和工位质量是明确待测项。

### Q06：Harness-DAgger 是否继承了不存在的完美专家保证？

**反例：** GPT 低熵但一致犯错；只保存纠正而没有聚合训练；把“自动接管”本身称为标准 DAgger 已收敛。

**定位与回应：** T1:39–41、133–141、243–247；T2:7、201、209–215；A:82–90、177–182。输入明确借用访问状态标注与长期聚合思想，可靠性另审，且配置同预算动态 BC／DAgger 对照。

**充分性：充分。** S11 说明原算法及保证需要额外假设；当前文字不继承这些保证。弱 policy 可用局部工具纠正启动，不要求另一个完整强 policy，但也没有承诺无可用教师和探索时必然改善。

### Q07：RPent、Show 和训练 env 会不会各有一条设备通道？

**反例：** policy 经 Gateway，解释器自行发 ROS/CAN，训练 env 的 reset 又绕开 Gateway；测试进程声称只是评测而同时写机械臂。

**定位与回应：** T1:161–169；T2:29–37、115、140、197、297、378；R:179、195–197。唯一硬件连接、设备级独占、逐帧唯一来源覆盖 reset、主动观察、候选和评测。

**充分性：充分。** T31 明确注入三方同时请求，要求不存在额外写通道。上游能独立运行不意味着可以并排运行，接入责任已经落到接口和验收；具体权限隔离实现仍属后续开发。

### Q08：取消成功能否误取代 quiesce 与交接确认？

**反例：** 协程结束但驱动还有在途命令；旧请求重复到达导致增量重放；Gateway 重启后旧 owner 复活。

**定位与回应：** T2:113–146、323–325、380；T6:245–267。明确封新命令、撤未生效队列、对账在途动作、取得保持凭证再交接；处理中／完成／未知分别处理；重启提代际，ACK 丢失不得重放未知增量。

**充分性：充分。** S2 的模型结果丢弃和 S4 的工具等待均不含本项目物理凭证，输入已明确拒绝代用。保持模式还要考虑持物而非一律断电；T07–T09 覆盖关键竞态，尚未执行不会自动变成逻辑缺陷。

### Q09：中途持物接管是否会被上游初始化 RELEASE 掉物？

**反例：** 启动纠正 runner 自动张开夹爪或双臂 home，尚未取得显式初始化授权就运动。

**定位与回应：** T1:167；T2:77、391；H:108、213。默认初始化被禁用；活动臂、非参与肢体保持和夹爪前置条件显式声明；T38 专门检查持物和未参与肢体。

**充分性：充分。** S1 的启动 RELEASE 是具体反例，已被直接纳入方案。只讨论动作主循环而遗漏构造／启动副作用的问题在本版已有门槛，不要求先完成真机才能认可设计回应。

### Q10：目标切换后旧回复会不会更新新任务？

**反例：** A→B 的成功答复迟到覆盖 B→A 的评分；旧正向 VLA chunk 在反向生效；Q 跨目标 bootstrap。

**定位与回应：** T1:90–94、143–151；T2:87–93、165–183、261–265、334、336–337；T6:265–267。goal/episode/版本绑定所有请求；当前命令资格和历史标签分开；换向 flush／reprime，旧结果仅按旧目标补历史。

**充分性：充分。** 控制和奖励两条链都处理，缓存不使用全局最近分数，终局事件去重；不是只给语言指令换字符串。与单参数双向学习保持一致。

### Q11：正向成功是否能自动成为反向可训练起态？

**反例：** 物体虽在 B 且释放，却位于边缘无法抓取；系统仍按奇偶强行换向，最后删去困难试次。

**定位与回应：** T1:94、109；T2:263–265、289、335、345。反向 init-set 独立检查，整理／恢复计成本，不合法则记录中断；拒绝和困难复位按预定分母留存。

**充分性：充分。** 共享反向 policy 和额外异常恢复被分开，不将恢复成功返送旧任务成功奖励，也不承诺两方向边际成功率简单相乘就是循环可靠性。

### Q12：解释器投影后的动作如何与 Q 保持同一意义？

**反例：** 原末端位移被 IK／限速截断，却仍用截断前数组配真实后继；或者反过来把只移动一半的实测位移倒填为命令。

**定位与回应：** T1:163、245；T2:64–85、319；H:106、210。输入分开 proposed_action、a_rl、driver_command 和 measured_state，先选 learner–environment 边界，再决定投影在接口内还是环境内部。

**充分性：充分。** S3 显示这类变换真实存在。T2 允许不同边界但要求训练／部署一致，避免把“凡投影都必须换 Q 动作”当普遍规则；未知回执留未知，不按计划补齐。

### Q13：反馈式纠正是否被事后拼成起点已知的动作块？

**反例：** t+7 新图发现滑落，t+8 改抓取，却把最终 n 步路径整体贴到 t 时刻 X；或把孤立一步复制成完整 U。

**定位与回应：** T1:137–141、165；T2:379；T6:165–190、233–255、337；H:121–123。起点冻结信息下的同协议 U、应急反馈轨迹、特权／事后标签分开；孤立动作不补齐冒充固定槽。

**充分性：充分。** 低层伺服闭环作为环境，与 Harness 读新图改上层队列有明确区别。反馈轨迹保留，不被一刀切删除，但需要相容监督分支或另定义微步 RL。当前完整头能否获得足量合格 BC／TD 是有明确报告要求的待验证问题。

### Q14：未执行标签与真实请求的终局例外是否混淆？

**反例：** GPT 影子建议 A 未进入控制，却借 policy 动作 B 的后果训练 Q；又或一见“未激活 U 也可 terminal TD”就给所有建议补 request ID。

**定位与回应：** T2:209–215、237–255、327、331、369；T6:63–95、192–231、300–302。普通建议仅 BC；终局分支限定事前真实 admission、冻结输入的原在途结果和当前 C 的实际终局，不事后新查询、不激活已取消结果。

**充分性：充分。** 三类事件和终局例外有直接边界；“保存进 buffer”与“允许哪一种 loss”没有混为一谈。具体 Bellman 数学正确性仍由 RL 专项审查，本项通过的是 Harness 数据来源和资格接口。

### Q15：执行过、成功过或接管过是否自动成为好标签和负奖励？

**反例：** 成功重抓前夹到障碍的所有步骤均获高 BC 权重；因网络超时接管就惩罚前一条动作；flow 部分标签仅末端 loss mask 却从未知输入泄漏。

**定位与回应：** T1:131、175、247；T2:193–201、243–267、330、382；A:94–98、177–181。执行事实、监督质量、TD 资格分开；保留接管理由和时间；局部好动作不要求整回合成功，失败也不自动排除真实 RL。

**充分性：充分。** 不以 GPT 自称、熵或接管事件当正确性；监督 mask 和 Q 梯度范围分别定义，未知 token 的加噪／attention 问题也被覆盖。质量标定和监督可学性仍需实验，不等同于已有可靠教师。

### Q16：数据／代码回滚能否真正追踪到已污染权重？

**反例：** 撤销错成功标签后只改 replay，线上模型继续包含污染；只回退 actor，却沿用新 normalizer、动作 schema 或生成的恢复程序；误以为 Git 回滚撤销机械臂运动。

**定位与回应：** T2:269–297、342–343、360–367、385；T6:259–270；P:86–88。相容版本包含 policy/Q/target/优化器、预处理、调度、任务、Harness 程序、模型／提示／rubric、奖励视图及 replay；撤销可追后继发布并回退重训。

**充分性：充分。** 记录路径不代替内容身份；边界原子切换并重新观察／prime，表征变更重算或隔离缓存，物理场景另行恢复。具体 manifest 传输格式尚未落代码，不影响已经给出的必要语义完整性。

### Q17：代码进化是否可以偷偷更改评测或获得另一设备连接？

**反例：** 候选恢复程序扩大预算、改 rubric 或直接创建 SDK，靠重命名成功／删除失败让自己晋级。

**定位与回应：** T1:153–157；T2:193–199、287–291、339；H:214–216。TRIAL 使用受限 API、有限范围与预算；不能改保护、成功定义、原始事实或分母；真机新行为有独立验证和回归。

**充分性：充分。** 自动试验不默认逐次人批，仍遵守预授权边界；独立审计资料转开发资料后要补新审计实例。该设计满足自动化目标，也没有借同模型多角色构造虚假独立真值。

### Q18：待测门槛是否被当成已测成功，或者缺数值就无条件失败？

**反例：** T37 两模拟 adapter 被写成跨本体能力已实证；Harness 一直代做但总成功率提高就宣称 policy 学会；或要求设计阶段立即交付任意硬件的统一时延阈值。

**定位与回应：** README:3、9、25–31；T1:27–31、309–330；T2:279–291、309–352、374、389；R:187、207、226–232；H:235–244。所有测试明确待实现／待执行，硬件时延和容差在预检中测定；自主窗口开始前必须填入预算与门槛，先固定试次和回归标准。

**充分性：充分。** 已有明确验证对象、失败处置与预先固定要求，不能因没有实测而宣布方案失败，也不能因此宣告系统性能通过。分别评 policy、辅助系统、自主学习与人工工时，足以防止当前文档中的过度结论。
