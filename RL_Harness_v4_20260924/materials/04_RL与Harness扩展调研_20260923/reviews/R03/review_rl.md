# R03 独立审查：RL、异步执行与数据因果兼容

审查日期：2026-09-23。审查对象仅为本轮 `input/` 冻结的技术 README／01／02／06、研究总报告与四份专题，共 9 份文件。未读取或沿用历史审查结论，未修改正文、输入快照或科学家知识库。本文是独立文档与第一方来源审查，不代表运行训练或真机验收。

## 1. 先列技术点

1. 同一个目标条件 actor 参数 θ、Q、target、BC、reward、replay 是否贯穿两个方向；正常反向是否仍是学习任务。
2. 弱 base 的必要动作覆盖、有限编辑可达性、完整头冷启动之间的取舍，是否有可推翻的选择门槛。
3. RT-EXPO、原生头与自定义完整头是否分别保持时间协议，并接受同任务、示范、纠正、实体时间与计算成本约束。
4. 固定槽中旧 C、新 U、下一队列和回报区间是否形成一决策 Bellman 递推；C/E/D 的执行资格与梯度是否混淆。
5. request admission、commit、physical activation 是否为独立事实；当前 C 提前终局、请求未激活时是否存在合法训练样本。
6. terminal、外部截断、迟到评分、抢占、失联及任务换向是否按实际发生顺序处理。
7. 反馈纠正、纯查询标签、真实同协议纠正和遥操作是否按信息集与学习边界分流。
8. 默认 SAC worker 的概率、熵温度、backup 与确定性完整头的 Q＋BC 目标是否明确分离。
9. 纯标签长期池、奖励版本、撤销与 checkpoint 依赖是否保留；框架 replay 是否反向决定数据事实。

## 3. 反例问题、定位与判定

定位简称：`技01/技02/技06` 为技术目录对应文件；`总报告` 为研究总报告；`RL专题/自主专题/Harness专题/平台专题` 为四份 research 文件。行号均对应本轮冻结输入。

### Q01：同一物理状态，在两个目标下价值相反，会不会串奖？

**反例。** 物体已稳定释放在 B：对 g=B 已终止，对 g=A 才是起态。若 actor 换语言而 critic 不换目标，Q 会把“留在 B”同时学成成功与起点。

**定位。** 技01 90–109；技02 219–225、261–265，T17/T18/T24。

**判定：通过。** actor/Q/target/BC/reward/replay 统一 goal 身份；换向结束旧 episode、flush/reprime，同一 θ 双向发布。两方向分层采样和实际梯度／行为验收已明确，未把 shape 相同当语义正确。共享是否产生正迁移留给已列消融，不要求本轮训练出结论。

### Q02：正向成功，但反向不可抓，还能自动作为下一起态吗？

**反例。** 物体被放在 B 边缘，满足正向区域判据，却超出反向抓取可达域；强行按奇偶回合换向会令反向长期失败，并隐含增加人工复位。

**定位。** 技02 259–265、T19/T29；技01 94、109、311–320；自主专题 169–175。

**判定：通过。** 下一方向有独立 `init_set`，拒绝、整理及中断保留记录并计成本。正常反向没有被异常恢复程序替代；循环可靠性也未用两个边际成功率未经检验相乘。

### Q03：零成功 base 从来不闭合夹爪，有界编辑能否凭空补齐？

**反例。** 所有候选在抓取阶段都保持开爪，合法编辑边界不足以跨越必要夹爪命令；仅增大候选数仍不能获得有效抓取。

**定位。** 技01 223–225、264–277；RL专题 125–132、271–282；总报告 80–84。

**判定：通过。** 文档要求在典型失败状态、关键维度和可执行动作上检查候选＋编辑覆盖；不以零成功率单独推断支持不足。还检查加入可靠纠正后 base 的 BC 更新能否扩展分布；放大残差边界不再冒称原方法。完整头也必须通过小样本可学性，而非默认获胜。

### Q04：RT-EXPO 得到更多数据或较新图像，完整头比较是否失真？

**反例。** RT-EXPO 获得更多示范、纠正或更宽 GPU 预算；另一支只读槽起点旧图，却将收益全部归于动作参数化。

**定位。** 技01 266–277；技02 T34；总报告 199–207；RL专题 134–154、273–282。

**判定：通过。** 已固定任务、初始双向数据、实体小时、Harness 调用／执行纠正预算，并记录计算与停机成本；自然推理、网络、队列、sleep、旧帧注入分别报告。不同信息时刻被作为各自完整协议的差异，而非共用 replay 的同公式实现。机制归因可再做匹配信息时刻的消融，但不妨碍先比较整个可部署路线。

### Q05：把 RT-EXPO 约 97% 当作零成功弱起点证据，会不会误选？

**反例。** 用摘要的 42%→97% 宣称 RTC 起点为 42%、零成功也能十分钟无人学会，并省去人工复位和评测成本。

**定位。** 总报告 74–84；RL专题 109–115、150–154。

**判定：通过。** 冻结材料分别写明普通 SFT、RTC-SFT、RT-EXPO 的比较对象；记录 online 前约 30% 或以上的示范微调条件，十分钟指在线机器人数据；人工复位／独立人类评价和延迟实验条件均保留。第一方原文支持这些边界，本项目没有把作者启动阈值强加为自己的统一门槛。

### Q06：当前 R 来自旧 C，而 Q 的动作是新 U，是否错误配对？

**反例。** n=6，在帧100发起 U，100–105执行旧 C，U从106开始。若把100–105回报配 U 后，仍把 next state 设为112，会漏掉或重叠一个槽。

**定位。** 技06 44–85、105–148，例1；技01 199–209；技02 229–237。

**判定：通过。** 当前环境包括队列，普通转移为 `(X,U,R_n,X_next)`，`X_next.C=U`，next在106，折扣 `γ^6`。物理状态主要随 C 变化并不否定 U 对下一队列的作用；U 的物理收益从下一条转移传播。这是闭合的一决策递推，未混成原 SmoothRL 的2n目标。

### Q07：新网络改动 C 预测或未执行 D，能否骗取 Q 梯度？

**反例。** 固定实际 C 和当前 E，仅改变同一 proposal 的前 n 步预测或尾部 D，actor Q loss 却改善。

**定位。** 技06 150–163、例2；技02 243–257、T13/T14。

**判定：通过。** Q读真实 C；当前 Q 动作梯度只经 E，D不进入本次价值动作。文档还区分“该路径梯度为零”与“共享参数更新后其他输出永远不变”。BC mask 不强制等同执行 mask，避免把可信非E标签一并丢掉。

### Q08：当前 C 提前成功，尚未激活的 U 是否必须全部丢弃？

**反例。** 槽起点已有真实请求，C执行第三步时终局，原请求此后返回 U。如果一律以“未物理执行”排除，terminal奖励链可能系统性丢失；若任取一个离线建议充当 U，又伪造行为事实。

**定位。** 技06 63–95、192–219；技02 229–239、T11。

**判定：通过。** 仅允许事前接纳、冻结输入／参数／随机性下原在途计算的真实结果；terminal target为实际 `R_L`、无bootstrap。结果不可取得时保留事实、不补动作。没有request的PRECHECK与shadow标签不能套用该例外。这是延迟决策遇到终止的结果，不是宣称 U 导致旧 C 的成功。

### Q09：终局行不更新 actor，会不会被误称为等价无偏目标？

**反例。** 同一个 X/C 有50%提前终止概率，过滤这类行会让 actor 更常看到存活状态；共享参数时可能改变状态间折中。

**定位。** 技06 211；技01 213。

**判定：通过。** 冻结设计已把该选择明确限定为 actor 的工程采样，承认存活概率对状态权重的影响，要求按目标／状态类记录比例并保留消融。critic仍保留真实terminal。不存在把筛选后的actor梯度宣称为未经筛选目标等价梯度的逻辑跳步。

### Q10：后继成功时回填更长回报，未成功时普通 bootstrap，是否可靠？

**反例。** 后继状态以1/2概率得1并终止，其余回报为0，真值0.5。成功样本回填1，未成功样本保留无条件值0.5，均值却成为0.75。

**定位。** 技06 213–217、例3；技01 215。

**判定：通过。** 已明确禁止按未来终局决定前驱采用哪种target。审查独立数值核对：`0.5×1+0.5×0.5=0.75`；γ=0.9、n=6、下一槽第三步奖1时，terminal回报0.81，前驱收敛后的目标为 `0.9^6×0.81=0.43046721`。这只是数值核对，不是声称训练已收敛。

### Q11：成功裁决晚到，能否抹去已有 commit 或回溯到接触时刻？

**反例。** 稳定释放须连续视频才成立；GPT晚到回复成功，此时 U 已有commit。实现若把commit改成“从未发生”，或将终局回溯到首次触桌，日志与target都会被改写。

**定位。** 技06 221–231；技02 165–183、T18/T20/T21。

**判定：通过。** 事件时间和服务返回时间分开，已发生commit保留；终局依据充分成立时刻划分，时刻不能确定则pending。先超时／抢占后成功不追认为原合法槽terminal；多次查询终局按事件去重。后续处置动作独立记账。

### Q12：106开始的槽在108被接管，100–105的前驱必须一起删吗？

**反例。** 前驱有准确106边界snapshot、队列确为U；后一槽108才被抢占。按整episode删除会浪费有效数据；反过来把后来的纠正写入106队列会制造假转移。

**定位。** 技06 245–257、例5；技02 241、T07/T12。

**判定：通过。** 已成立前驱保留原一步目标，被改写C的槽隔离；边界自身并发不明时才扩大隔离到前驱。删失不作为吸收失败，也不把辅助成功贴给旧U。文档同时承认可用TD密度和干预选择偏差，不声称隔离即可无偏。

### Q13：Harness在107看到滑落，纠正轨迹能否标到100的完整chunk？

**反例。** GPT／解释器多次读新图并重规划，事后拼出的n步动作被当成100时刻冻结X下已选择的U。

**定位。** 技01 135–141、159–169；技06 182–190、237–255；技02 T32；Harness专题 121–123。

**判定：通过。** 同协议开放环纠正、反馈微步与事后特权监督分别处理。普通BC须匹配当时信息集及C；微步不重复填充为n步，未来图像不进入部署输入。特权BC被保留为待独立定义的扩展，不被错误宣布原理上完全不可用。

### Q14：未执行建议长期入池，会不会被 framework mixer 补成真实 transition？

**反例。** Harness标签B未执行，实际执行A；旧replay要求reward和next_observation，adapter就给B填入A的后继与奖励，或填全零假字段。

**定位。** 技02 205–217、255–257、365–369、T15/T16/T36；技01 235–243；平台专题 29–31；RL专题 156–168。

**判定：通过。** 纯标签长期独立池及采样支路已要求，内存环形replay不是唯一存储，BC不需要伪造后继。真实纠正跨多个视图共享ID，不虚增交互次数。默认demo mixer混真实transition，不等于已提供显式BC，也不等于能容纳纯标签。

### Q15：确定性完整头复用SAC，只返回 `log_pi=0` 是否可行？

**反例。** 状态／队列schema已经补齐，worker仍执行SAC entropy backup、actor entropy项或alpha更新；开发者为了满足签名为确定性输出编一个常量概率。

**定位。** 技01 227–233；技02 395（T36补充）；平台专题 21、92–100。

**判定：通过。** 技02已明确禁止假概率，要求首版使用确定性Q＋BC，不继承默认熵温度及entropy backup；随机actor／最大熵是另一个必须完整定义的模式。独立读到的RLinf固定worker确有log_pi与alpha路径，支持该适配要求。平台专题35的Gaussian措辞可澄清，见可选项O1；不推翻技术契约的明确限定。

### Q16：只有一个正确动作标签，能否填零后给flow loss乘mask？

**反例。** 未知动作位置虽在最终loss置零，却已经参与加噪输入或attention，污染了有标签位置；或者复制最后一帧，凭空造完整动作窗。

**定位。** 技06 188–190；技02 257、T14/T16。

**判定：通过。** 明确要求所选头支持相应粒度，或采用完整可信窗口；未标注输入、注意力、目标与推理都要验证。孤立微步不能冒充主宏动作标签。这里是已定义的实现验收，不要求本轮先开发模型。

### Q17：Harness接管或低熵建议是否自动意味着policy错误／专家正确？

**反例。** 因网络超时、补图或主动观察发生接管；另一个Harness稳定输出错误抓取位置，行为熵很低。若统一前帧负奖并强BC，模型会追随错误标签。

**定位。** 技01 279–283；技02 261、T35；自主专题 84–98、177–184。

**判定：通过。** 接管reason、证据与真正动作时段分开；不自动赋failure reward。真实同协议次优动作仍可训练Q，BC质量另判，critic不可信时不得独自定义纠正真值。未把低熵或整回合成功当动作正确的充分条件。

### Q18：动作被IK／投影改变，或normalizer、n更新，旧replay还能混用吗？

**反例。** actor输出末端增量，IK或限幅后机器人只走一半；采集器用实测位移反写行为动作。另一种情况是normalizer或n已变，但shape未变，旧数据继续混入。

**定位。** 技02 64–85、273–277、T03/T26；技06 99–101、163、267–270。

**判定：通过。** 学习边界可在变换前或后，但actor、Q、采纳命令与部署定义必须统一；实测状态不倒填成动作。跨边界投影要进入动作定义／优化路径，保护性改写审查资格；normalizer、调度和表征变更采用版本视图／明确迁移，不能仅靠字符串或shape断言兼容。

### Q19：错误标签撤回后，模型权重是否自动变干净？

**反例。** 同一成功误判或错误BC已经影响多个checkpoint；仅从当前buffer删样本，却继续发布其后继版本。

**定位。** 技01 243、291–293；技02 293–297、T27、TrainingView/ReleaseBundle。

**判定：通过。** 标签撤销追踪至视图、checkpoint及后继，暂停晋级，必要时回退重训；原始事实追加保存，回滚后重查实际物理状态。没有把重标replay等同清除参数影响。

## 4. 必要修订

**无。** 本轮19个具体反例未发现尚未处理的必要事实、逻辑或学习契约缺口。尤其不能将“新头尚未训练”“接口尚未编码”“真机覆盖尚未测量”单独升级为修订原因：冻结方案已给出阶段门槛、待执行用例、失败处理和路线可推翻条件，并明确不宣称已验证。
