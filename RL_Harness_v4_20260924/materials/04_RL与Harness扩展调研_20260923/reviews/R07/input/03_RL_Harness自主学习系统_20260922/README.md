# RL＋Harness 真机自主学习：开发者入口

2026-09-23｜修订版 v3｜设计与源码审核，尚未实施模型训练或真机实验。

**同一个目标条件 VLA policy 练习 A→B 与 B→A；GPT-6＋Harness 负责观察、评分、纠正和恢复；BC＋在线 RL 持续吸收纠正与真实后果。** 首个任务是松灵 ALOHA 类平台的一臂抓放，另一臂不参与，初始策略成功率偏低，包括零成功率。

先读主文理解完整流程，开发时查接口和异步附录，核选型时看证据。无需先读全部调研记录。

当前优先验证：**通用接口＋RPent 认知骨架＋GPT-6 观察纠正＋语义动作解释器＋唯一真机网关＋共享双向完整动作头 BC／队列 RL**。训练运行时先检查 RLinf，LeRobot 为轻量备选；RT-EXPO 与原生 π₀.₅ TD3＋BC 是竞争路线，OpenETA、Strands 等参加 Harness 接口预检。以上是待验证的组合，不是已集成产品或已证最优方案。框架通用性优先，AgileX 适配只计首次部署成本。

三个关键区别：

- Harness 是整个观察与纠正系统，不预设外部高成功率策略。未执行建议可长期入池用于 BC，不能伪造环境后果。
- 异步 RL 区分实际控制请求、队列提交和物理生效；当前槽仍执行旧动作，新决策通过队列影响后续。不是在原同步 loss 上多乘一个 mask。
- 分别验证 policy 独立能力、系统辅助表现与在线人工成本。系统代做成功、文档检查通过，都不是 policy 已学会的证据。

首个开发迭代：接口和时间预检→共享 BC→GPT 观察与局部纠正→数据和目标手算核验→短时真机 BC＋RL→同一 checkpoint 双向评估。代码进化、稠密奖励与动态延迟随后独立验证。
