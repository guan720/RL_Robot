# 异步动作时间轴与学习目标

2026-09-23｜修订版设计附录｜**拟议实现，尚未编码或运行真机训练。**

本文解决一个具体问题：VLA 还在推理时，机器人继续执行旧动作；新 chunk 到达后只执行中间一段。此时，什么是 RL 的状态和动作，Harness 接管的数据怎么学，必须重新定义。不能直接沿用“取观测、执行完整 chunk、再取观测”的同步训练代码。

**首版选择：固定时间槽＋显式动作队列的离策略 RL。** 将已经承诺执行的旧动作纳入状态，把运行时实际接纳的下一槽动作决策作为本轮动作。严格区分“决策请求已接受、动作结果已提交、物理动作已激活”三个阶段。学习器按一个时间槽构造 TD，Harness 的纠正也使用同一接口；实际控制决策、物理动作和仅供监督的建议分别记账。

这一目标由本项目根据并发控制原则提出，**不是原版 SmoothRL，也不是原版 ARLI**。SmoothRL 提供动作分区和价值梯度限制的直接启发，ARLI 提供已承诺动作与延迟状态建模的依据。文末说明两者原实现及本项目未直接采用的部分。

## 1. 先看一次真实执行

以下数字只为解释，控制周期和时间预算必须实测。设每次推理输出 20 个控制步，固定预算为 6 个控制步。以帧 100 取到的观测发起一次推理：

| 绝对控制帧 | 当前 proposal 的索引 | 机器人实际执行什么 | 对本次输出的含义 |
|---|---|---|---|
| 100–105 | 0–5 | 上一次推理已经承诺的旧动作 | **C：committed 区间。** 当前 proposal 对这些时刻的预测不会执行；但机器人并没有停住 |
| 106–111 | 6–11 | 本次推理准时完成并获准入队的动作 | **E：execution 区间。** 正常情况下它是本次 chunk 对真实环境的有效贡献 |
| 112–119 | 12–19 | 后续推理到达后提供的新动作 | **D：discarded 区间。** 当前 proposal 的这些预测被替换 |

因此，`executed_length=6` 远远不够。还必须知道它是**索引 6–11**，绑定哪些绝对控制帧，以及每一帧的命令来自哪次推理。

```text
绝对时间           100            106            112
                   │              │              │
本轮观测/推理       ●──────────────►准时提交 E      │
机器人             [ 旧 C 执行    ][ 本轮 E 执行  ]
下一轮观测/推理                    ●──────────────►新 E
本轮 proposal      [预测已错过 C  ][有效 E       ][被替换 D ...]
```

这里的 C 应读取**已承诺的真实命令队列**，不能读取新 proposal 自己预测的前 6 步。命令与最终机械臂位移也不是同一量：实际是否达到目标，由环境反馈记录；不能用实测位移反填成策略发出的动作。

一般运行日志仍支持不等长的三段：当前推理延迟为 `d`，下一次替换前执行 `c` 步，则有效索引是 `[d,d+c)`。首版训练目标只接收满足固定时间槽契约的数据；支持一般日志不等于已经支持任意可变延迟 RL。

## 2. 首版 RL 的状态与动作

### 2.1 固定时间槽

一个时间槽长 `n` 个底层控制步。普通运行时每隔 `n` 步开始新推理，新推理最迟在槽尾完成。提前完成则等待既定交接点；超时按照第 7 节处理。

在槽起点 `t_k`，定义：

\[
X_k=(h_{t_k},\ g_k,\ C_k,\ \xi_k)
\]

- `h` 是此时已经可用的图像、本体状态及必要历史；不含未来帧。
- `g` 是当前目标，例如把目标物从 A 放到 B，或者从 B 放回 A。
- `C_k` 是接下来这个槽内已经承诺执行的 `n` 步命令。
- `ξ` 是影响转移的调度阶段、动作契约和必要控制状态。固定配置通过数据视图隔离；不能仅把版本字符串作为神奇的动力学修复手段。

共享的目标条件 policy 基于 `X_k` 产生完整动作空间中的下一段：

\[
U_k=\pi_\theta(X_k)=E_k\in\mathbb{R}^{n\times d_a}.
\]

`d_a` 是选定单臂学习动作接口的维度。这里的“完整”指可以学习该接口的全部动作，而不是只能输出靠近旧 VLA 参考动作的小残差；仍保留物理动作范围和连续性约束。

生成器可以继续输出 `H≥2n` 的 chunk，但 RL 决策只取其 `[n,2n)` 段。C 作为固定条件传入，D 不进入这个 RL 动作。实现也可以让新动作头直接输出 `n` 步 E，再由运行时组装计划；必须在模型配置中写清是哪一种。

### 2.2 request、commit、activate 是三个不同事件

在槽起点，运行时接纳一个真正用于本次控制的 `decision_request`，绑定不可变的 `X_k`、目标、策略权重、随机性和下一槽位。对于异步 policy，计算可能到槽内较晚时刻才结束，但输出必须仍是这个冻结输入的 `U_k=π(X_k)`，不能在计算中偷偷读取未来图像或新参数。

| 阶段 | 事件含义 | 需要的证据 |
|---|---|---|
| request accepted | 运行时接受实际的下一槽动作选择流程 | request ID、起点观测、C、目标、权重与随机性、预定槽位、控制租约 |
| result committed | 原请求结果准时、合法地被提交到下一槽队列 | 该请求的真实 U、提交回执、对应 next queue |
| physically activated | 该命令开始作用于真实机器人 | 逐步生效区间、驱动反馈、实际采用与部分生效状态 |

RL 的动作是**真实决策请求产生的 U**。接受请求不代表已经物理执行 U；物理执行的延迟是环境定义的一部分。普通非终止样本必须同时获得正常提交证据；真实终止发生在当前 C 内时，已接受请求的 U 可以因任务结束而不再提交，这仍是实际决策流程遭遇的环境结果，按第 5 节构造 terminal TD。

仅供讨论、评分或离线查询的 Harness 建议没有进入这个实际控制请求，不是这个 MDP 的行为动作。不能事后给建议补一个 request ID，伪装成曾被运行时接纳。

### 2.3 队列是环境的一部分

当前时间槽内，机械臂执行 C。U 在槽尾准时获准入队后，形成下个状态：

\[
X_{k+1}=(h_{t_k+n},\ g_k,\ C_{k+1}=U_k,\ \xi_{k+1}).
\]

**正常情况下，当前 U 的环境作用先表现为改变下一槽队列；它的物理效果从下一槽开始。** 队列入队回执和下个状态的队列快照，都是必须核验的环境事件。真实终止则转入吸收终局，不强行制造 next queue。

这解释了为什么以下两者不能混同：

| 数据 | 是否是这个队列 MDP 的真实动作 |
|---|---|
| 实际 request 已接受，U 按固定调度提交，下一状态队列确为 U；物理执行将在下一槽开始 | 是。它已有可验证的队列状态后果 |
| 实际 request 已接受并有原请求结果 U，但当前 C 先触发任务真终止，U 未激活 | 是实际决策的 terminal 样本；不伪称 U 已物理执行 |
| Harness 只提出离线建议，没有进入实际控制 request | 否。它是可长期保存、可用于监督的动作标签 |

不会因为第一类动作尚未开始物理执行，就把它误删成“未执行建议”；也不会因为第二类建议数值合理，就为它编造入队事件和后继状态。

### 2.4 状态充分性的实际边界

这个定义修复的是遗漏队列导致的并发状态问题。图像本身仍可能不能观察接触、遮挡或物体速度，必要时需要历史、状态估计或额外传感器。文档不把 `X` 自动宣称为完整物理 Markov 状态。

动作解码、限幅、IK 和低层反馈控制必须采用固定、可追溯的接口语义。低层位置控制器根据关节误差闭环工作属于环境动力学；Harness 在槽中依据新图像改变上层命令队列，则属于本节未允许的动作改写。

## 3. 一条普通训练样本怎样形成

### 3.1 奖励和 TD 目标

令底层每个控制步的折扣为 `γ`。当前槽的回报为：

\[
R_k=\sum_{j=0}^{n-1}\gamma^j r_{t_k+j}.
\]

普通样本是：

\[
(X_k,U_k,R_k,X_{k+1}),
\]

相应的一决策 TD 目标为：

\[
y_k=R_k+\gamma^n Q_{\bar\phi}
\big(X_{k+1},\pi_{\bar\theta}(X_{k+1})\big).
\]

双 critic、ensemble 或 target smoothing 可选，但不能改变上述时间对应关系。若代码把一个时间槽当作折扣单位，应明确保存 `γ_slot=γ^n`，避免再对它做一次 `n` 次幂。

当前 R 主要由旧 C 产生，这没有错误。U 的贡献通过下个状态中的 `C_next=U`，再通过后续价值传回。不能为了“让动作立即配上自己的物理奖励”，把下一槽的回报挪进当前样本，却仍保留上述 next state 和折扣。

### 3.2 为什么不直接套原版 2n 目标

在本项目定义中，下一次决策发生在 `t+n`。下一状态的队列是**本次真实接纳的 U**，而目标动作由目标 policy 在这个完整状态下生成。这样不需要跳过一次行为决策，也不需要用中间行为 policy 的新 commitment 代替目标 policy 的决策。

这是一决策的队列增广目标。它与 SmoothRL 论文的 2n chunk-skip 公式不同，不能在代码、图表或实验名称中写成“原版 SmoothRL，仅把折扣改成 n”。

### 3.3 普通样本的准入条件

同时满足以下条件，才发布到普通 TD 视图：

1. C 在整个槽内按选定学习动作边界执行，原始反馈可追溯。
2. 控制 request 在该槽起点真实接纳；其 U 只依赖 `X_k` 及明示随机性，准时、合法且完整入队。
3. next observation 与**当时的 next queue**成对记录，且 `C_next=U`。
4. 目标、动作配置、控制租约和调度模式相容，没有未建模的中途队列替换。
5. 本槽奖励已经归入固定奖励视图；`pending` 不默认作零。

本槽动作结果、当前槽回报与边界快照齐全后，即可 finalized；不需要先偷看后一槽是否成功。若奖励异步到达，可保持 pending，但 next observation／next queue 仍使用原槽边界快照。

如果后一槽发生 Harness 抢占，那是后一槽的事件。当前已经成立的一步转移不因后来被抢占而改写成成功、失败或零价值；更不能把后来的实际动作倒填成当前 next queue。下一槽的不相容样本按第 6 节隔离。

## 4. actor 的 Q 梯度和 BC 各学习什么

### 4.1 Q 的计算图

critic 可以写成 `Q(h,g,C,U,ξ)`。C 是已经承诺的状态，不是本轮可以优化的输出。actor 的价值损失为：

\[
\mathcal L_Q^{actor}=-\mathbb E_{X\sim D}
Q_\phi(h,g,\operatorname{sg}(C),\pi_\theta(X),\xi).
\]

因此 Q 的动作梯度只经过 E／U。当前 chunk 的 C 预测和 D 预测不获得这条 Q 动作梯度。共享网络参数仍可能因 E 的训练更新而改变其他输出；“只经 E”描述的是当前计算图的因果路径，不是承诺其他输出数值永久不变。

动作连续性需要显式依赖旧 C 的末端。首版不在网关背后做未记录的跨 chunk temporal blending。若输出在学习动作边界前被投影，投影必须纳入同一个动作定义与优化路径；不可微的保护性改写触发专门记录与训练资格审核，不能假装实际执行了未改写的 actor 输出。

### 4.2 Harness 的纠正监督

主训练配方为**离策略 Q 学习＋质量受控 BC**。BC 的目标是 Harness 提供、且与输入状态及动作时刻正确对应的纠正。它不是把所有自主失败动作无条件克隆一遍，也不是固定惩罚所有动作偏离旧 VLA 参考。

对于本节的动作头，最直接的标签是 `(X_k,U_k^H)`：Harness 在相同目标、同一 C 和同一调度语义下，为下一时间槽产生的动作段。满足实际 request 和结果契约的纠正可以兼有真实 TD 与 BC 资格；只查询而未进入控制 request 的可信纠正也可以长期存储并参加 BC。第 5 节的真实终局例外不能扩大为“所有未提交建议都可写 TD”。

至少分开四个概念：

| 名称 | 回答的问题 |
|---|---|
| 物理执行记录／mask | 哪条命令在什么时间真正被采用或部分生效 |
| 普通 TD 资格 | 队列动作、区间反馈、next queue 和目标是否满足所选 MDP |
| 动作监督 mask／权重 | 哪些纠正标签在该输入条件下可信、可学 |
| Q 梯度适用区间 | 本轮 actor 哪些输出构成这个决策的 U |

不能用“是否成功”代替四者。失败仍可能是正确 TD 数据，未执行建议也可能是正确 BC 数据。

### 4.3 不能把晚看到的纠正挪到早先状态

例如 Harness 直到帧 107 才看到物体滑落，再生成纠正动作。这不是帧 100 状态下已经承诺的完整 E。不能把它倒填为 `U_100`，声称策略在帧 100 选择了整段纠正。

这限制的是行为事实与首版普通 BC 的标签定义，不是禁止一切事后监督。DIDA 研究了用更丰富信息提供动作标签的延迟模仿；此类特权 BC 可另行建模和验证，但不能把未来观测作为部署时输入。首版将它单列保留，详细边界见 [07 第 10.5 节](07_共享策略与异步RL联合选型证据.md)。

这类片段仍全部保存：真实微步记录保留物理事实；有正确输入时刻的标签可以训练相容的监督分支。要用于首版队列动作头，须重新建立一个当前状态下的决策点，或获得在相同 `X`、同一 C 条件下有效的标签。**若当前 learner 只吃 n 步固定动作段，孤立的一步标签不能重复填成 n 步。**

对 flow／diffusion 动作头，不能只在 loss 最后乘 mask 就假定部分标签兼容：未知动作可能已经进入加噪输入和 token 交互。首版完整原始动作头的具体实现必须明确支持它采用的监督粒度；否则部分标签保留，暂不进入这一分支。

## 5. 终局提前发生：当前 request 使用普通 terminal TD

假设本槽 C 原计划执行 n 步，但在第 `L≤n` 步已达到该目标的真实终止条件，例如物体已释放、稳定，并满足任务契约的终止核验。实际控制 request 已在本槽起点接受，但它产生的 U 因任务结束不再激活。

### 5.1 保留原请求结果，而不是补一个动作

若原请求已经产生 U，保存该结果；若计算尚未完成，可让**同一个在途计算**继续完成，仅用于日志与训练，不再获得硬件执行权限。输入观测、权重、随机性、目标与 C 仍保持原冻结版本，不能在终局后重新查询当前场景生成“合适的动作”。

如果原请求已取消且其真实结果无法取得，或者请求输入与输出无法追溯，则该条样本的动作未知：保留终局事实，但不给它伪造 U。工程上应把“撤销物理执行资格”与“取消所有计算和日志”分开，避免系统性丢失终局训练数据。

这个样本的 reward 与 target 为：

\[
R_{k,L}=\sum_{j=0}^{L-1}\gamma^j r_{t_k+j},\qquad
y_k=R_{k,L},\qquad terminated=true.
\]

这是一条 `(X_k,U_k,R_{k,L},absorbing_terminal)` 的真实**延迟决策**样本，不是 U 的物理执行轨迹。它记录实际控制决策遇到任务终止的结果；没有声称 U 造成了当前 C 的成功，也没有虚构后继队列。

首版在这种取消激活的 terminal 行上只更新 critic，不从该行产生 actor 的 Q 动作梯度；BC 仍按各自标签资格处理。这是显式工程采样选择，不声称与未筛选 actor 的状态权重完全等价：若同一 X/C 有随机提前终止概率，筛除这些行会让 actor 的状态采样额外受存活概率影响，共享参数下可能改变状态间折中。记录按目标／状态类的筛除比例，必要时以单独消融检查；critic 仍保留真实 terminal 样本，不能为校正 actor 权重而篡改 Bellman 后果。终局事实可用 `QueueTerminalEvent` 记录，但不另外拟合 terminal-only V，不配任意 probe 动作训练 Q。

### 5.2 正奖励通过统一 Bellman 链向前传播

上一槽真正提交的 U 形成了本槽 C。上一条普通转移仍使用自身的 `R_prev+γ^n Q_target(X_k,π_target(X_k))`；本槽的 terminal 样本训练这个状态下的 Q，使奖励沿同一递推关系传回。与通常 actor–critic 一样，价值传播需要梯度更新及目标网络更新，不保证一条新正样本立刻改变所有前驱价值。

**不因为后来成功，就为前驱临时换成较长回报；后来没成功又保留较短 bootstrap。** 按未来终止事件选择两种 target 会引入选择偏差。例如，固定 next state 以一半概率终止得 1，另一半总回报为 0，其真值为 0.5；若终止时回填 1，未终止时仍填无条件价值 0.5，平均会变成 0.75。首版使用每条决策自身的一步／terminal target，避免该捷径。

首次 prime 槽如果已有真实 decision request，可按同一规则训练 terminal 样本；若尚处于没有控制决策的 PRECHECK，则只保存事实，不发明 request 或前驱。

### 5.3 终止与外部截断不能合并

- 真实目标终止或预先定义的吸收失败：使用实际到终止的回报，后续价值为零。
- Harness 抢占、超时、云服务掉线、日志缺失：属于中断／删失，不因此把后续价值设为零。
- 有限时域任务：剩余时间必须在状态或契约中定义；“训练程序等不及”不是任务终止。

所有虚拟吸收状态仅是学习定义，不代表机器人真的执行了填充动作。事后得到的 L／terminal 信息只用于构造 target 与样本资格，**不作为 actor 在线拿不到的额外 critic 观测特征**。提前终止后仍发生的物理保持／停止动作继续独立记账。

终局事件时间与奖励服务返回时间分开。若迟到核验表明终局已发生，而 U 的真实提交回执也已存在，两种事实都保留，不把 committed 改写成“从未提交”；按照任务终局时间划分学习 episode，终局后的物理行为归入后续处置日志。无法确定终局事件对应哪一帧时，相关 target 保持 pending，不能凭模型回复时间或猜测时间直接对齐。

**边界按实际发生顺序裁定。** 如果先超时、失联或 Harness 改写了 C，之后才完成任务，原槽已经离开本节的正常延迟决策条件；不能因为后来拿到成功标签，就追认成合法 terminal 样本。终止时刻应取任务契约要求的证据已经充分成立的时刻，不能把使用后续稳定性视频才确认的结论随意回溯到首次接触帧。

## 6. Harness 怎样接管，并产生兼容的学习数据

首版允许两种接管，但它们的数据资格不同。

### 6.1 计划式纠正：直接支持 BC＋RL

Harness 基于当前 `X_k`，调用已经具备执行能力的控制流程或生成完整纠正段；在固定期限内预提交下一槽 U。当前槽 C 不被修改，下一槽正常执行纠正。即使生成者不是 policy，其入队动作和环境转移也可进入离策略 TD。

这里不要求 Harness 是另一个成熟 policy。它可以是 GPT-6 观察与规划、几何求解、代码流程和局部控制原语的组合。进入这个 RL 接口时，必须转换成同一目标、同一动作边界、同一时间窗的 U。

对需要较长思考的 GPT-6 请求，可先进入已验证的保持状态，取得新观测，完成纠正计划与前置条件检查，再重新启动固定槽。不能假设任意一次网络大模型调用都能塞进 n 步控制预算。

### 6.2 强制抢占：先处置实际状态，再恢复训练周期

遇到必须立即纠正的情况，允许打断 C。控制流程为：撤销旧租约与排队输出、确认在途动作与停止状态、取得新鲜观测、让 Harness 处置、再建立新周期。

被打断的槽保留全部微步事实和纠正标签，但不伪装成普通固定槽 TD。首版未定义“中途改队列”的宏动作模型，因此被打断槽从普通 TD 视图隔离，不将删失当零价值。

此前转移若拥有准确的槽边界 next state 与 next queue，可按原一步目标保留；后续抢占不改变已经发生的这一步。若接管发生在边界附近，导致前驱的 next snapshot 本身不能确认，则连该前驱一起隔离，而不是猜哪个命令先发生。处理范围取决于实际不可确认的时间区间，不沿整个 episode 无限制删除。

上述隔离会减少可用 TD，尤其在接管频繁时；需要报告被删失窗口比例，不宣称它自动消除了干预选择偏差。对后来查明污染的记录，按版本追踪受影响数据视图与 checkpoint。

Harness 如果持续依据新观测逐步反馈控制，其真实轨迹仍有价值；但不能将事后微步拼成先前就选好的 U。对这部分启用微步 RL，应另行定义微步状态、动作与价值目标，不能把“日志真实”当作“任何宏转移都成立”。

回交 policy 时清除旧推理结果、旧 goal 的引用 chunk 和相关缓存。用已验证的保持动作重新填充首个 C，再基于当前观测生成第一个 U。首个保持槽允许正常记账，但不能把保持动作归功于新 policy。

## 7. 调度异常和模型版本

| 事件 | 控制处理 | 训练处理 |
|---|---|---|
| 推理提前完成 | 等待固定交接点，不提前改变 C | 满足其余条件时普通 TD 有效 |
| 推理超出预算 | 不把迟到动作塞进过期槽；执行已定义保持／停止，清空不相容计划并重新起步 | 受影响槽标记 deadline miss，不靠改一个 γ 继续当普通样本 |
| 推理中的 Harness 抢占 | 旧 epoch 结果即使随后成功返回也不能控制机器人 | 旧 request 与新动作来源分开；合法历史标签可另审 BC |
| 正反目标切换 | 在当前目标结束与队列确认后切换，废止旧目标计划与缓存 | 不跨 g 串接普通 bootstrap；共享网络不代表共享目标标签 |
| policy／normalizer 更新 | 在已确认交接点原子换版本，并重新建立上下文 | 权重改变可作为离策略来源；动作／解码语义改变需新契约或经过验证的数据迁移 |
| critic／奖励服务暂未就绪 | 原始事实先落盘，运行时按预算继续或暂停学习 | reward pending、next queue 缺失时不发布完整 TD |

前后两个槽的动作不一定来自同一个策略版本，离策略 RL 本身允许不同数据来源。但对于影响输入含义、解码空间或动力学的改变，单纯保存版本号不够。尤其是更新 VLA 表征后，缓存不能继续伪装成新模型表征；应保存原始观测以便重算，或让 learner 读取明确冻结的表征视图。

## 8. 为什么 ARLI 的“中途观测”首版不直接接入

ARLI 在较晚执行的轻量 RL 分支中使用更新的观测，具有合理的反应性收益。但本附录的普通 U 被定义为依据槽起点 `X_k` 的决策。如果 actor 实际又读取槽中才出现的画面，训练时却仍把决策时刻写在起点，便会造成未来信息泄漏和不同的转移条件。

因此首版只使用起点可用的状态、历史及承诺队列。日志可以保存中途观测，便于诊断和后续研究；不偷偷把它拼入本式 X。

未来启用中途观测时，需要另设明确模式：决策时刻移到何处、此刻还剩哪些承诺动作、RL 分支和 action expert 还有多少延迟、U 从哪一帧生效，以及奖励和 next state 如何划分。模式必须有独立的数据视图、目标推导和验收，不能直接套本附录公式。

ARLI 原实现的动作是 latent noise `w`。Harness 的实际末端／关节纠正没有自动对应的 w，因此不能直接送入其原版 `Q(s,w)`。本项目选择物理动作空间，就是为了让执行中的纠正和 BC 标签有统一接口；不能同时宣称保留了原版 latent SAC 的全部性质。

## 9. 开发者应能手工核对的六个例子

这些是**待实现的验收算例**，不是已经跑过的实验结果。

### 例 1：正常三段与一槽 TD

设 `t=100,n=6,H=20`。U 使用 proposal 索引 6–11。第一条普通转移的回报覆盖帧 100–105，next state 是帧 106 的观测与队列 `C_next=U`，折扣为 `γ^6`。U 的物理效果覆盖 106–111，进入下一条转移的回报。任何把第一条 next state 写成帧 112、却仍累计 100–105 的实现都不通过。

### 例 2：梯度只经过可选的 E

保持 X 中真实 C 不变，任意改变当前 proposal 的 C 预测和 D 预测，普通 actor Q loss 应保持不变；改变 E 则可以改变 loss。自动微分应显示这条 Q 路径对 C 预测与 D 的动作导数为零。BC 有自己的 mask，不能借这个测试禁止所有未执行标签监督。

### 例 3：下一槽第 3 步成功

为便于手算，用 `γ=0.9,n=6`，当前槽奖励全零。U 已正常提交；下一槽第 3 个控制步获得奖励 1 并终止，即下一槽的 `R_terminal=0.9^2`。下一槽起点实际接纳的 request 结果 U_next 保留，构成 target 为 `0.9^2` 的 terminal critic 样本，虽然 U_next 未物理激活。

当该状态的价值已经学到这个确定性例子的终局回报时，前一条普通 target 才通过 `0.9^6×0.9^2=0.9^8` 传回；不根据这个未来结果临时改前驱目标。第三步以后的命令没有物理执行，不能生成额外奖励、BC 真值或假观测。检查 actor mask：取消激活的 terminal 行不产生 actor Q 更新，原先真实提交的 U 则仍有正常价值学习路径。

### 例 4：建议未提交与提交后尚未执行

Harness 产生候选 A、B，只有 A 被实际控制 request 采用，并获得真实提交回执、成为 next queue。A 是普通队列动作；B 只能进入建议标签池。若 A 随后被抢占，回看前一条记录时 next queue 仍是当时已经成立的 A，不允许事后改成抢占动作 B。若真实 request 因当前 C 提前终止而未提交，只有它本身的真实结果满足第 5 节 terminal 例外；B 不因此获得 TD 资格。

### 例 5：帧 108 中途抢占

先前 U 已在 106 正常成为 C；在帧 108 Harness 强制改队列。若帧 106 的观测与队列快照准确，100–105 的一步转移保留；106 起的槽不能当“C 完整执行、下一 U 正常提交”的普通样本。若快照与接管并发而无法判断先后，则连该依赖边界的前驱一起隔离。实际 106、107、108 的动作生效情况与纠正轨迹分别保存；不可把后面的辅助成功直接贴给旧 U 或被取消的新候选。

### 例 6：晚到与换向

本次结果到帧 107 才返回，错过 106 deadline，应拒绝原槽采纳并按异常流程重启。若此时目标已从 A→B 换为 B→A，旧结果还应因 goal／epoch 不相容被拒绝。日志中一般执行索引可以准确表示这些事件，但它们不自动变为首版普通 TD。

## 10. 原论文、项目改造与待验证项

| 内容 | 证据性质 | 本项目决定 |
|---|---|---|
| SmoothRL 三段与原始动作空间价值梯度限制 | [原论文 §3](https://arxiv.org/html/2608.29768v1) | 作为分区与梯度路径依据 |
| SmoothRL 的 2n 回报、next committed、chunk-skip target | 同论文 §3、算法 1 | 保留为独立对照；不与首版 n 目标混称 |
| ARLI 已承诺动作和中途观测增广 | [原论文 v2 §4、附录 A/D](https://arxiv.org/html/2608.23831v2) | 承诺队列进入首版；中途观测模式后续独立研究 |
| 并发控制需显式处理动作与延迟 | [Thinking While Moving，ICLR 2020](https://arxiv.org/abs/2004.06089) | 队列作为状态的一般依据 |
| 共享目标条件完整动作头＋Harness BC＋一槽请求／队列 TD | 本项目推导与工程方案 | 需要实现、终局边界测试和真实采集验证，不能借原论文分数背书 |

SmoothRL 原版 2n target 使用后一状态的实际 committed context；在离策略回放中，这个 context 可能由中间的行为决策生成。忠实复现可作为实验，但不能无条件声称它等价于一决策目标对纯当前 policy 的无偏评价。本项目采用一槽目标，正是为了把当前 U 导致的队列状态变化明确放在相邻转移中；这不是只改折扣系数。

截至本轮核验，[SmoothRL 官方页](https://www.astribot.com/en/AI/SmoothRL/)未提供本轮可核验的算法仓库链接；[ARLI 官方 GitHub](https://github.com/async-rl-intermediate-information/async-rl-intermediate-information.github.io)为项目网站。两者论文可读不等于完整训练代码、许可证及松灵适配已经可用。引用的网站模板许可不能当作算法许可。

当前最重要的待验证项是：实际动作接口与时间轴能否对齐；固定槽推理预算是否可满足；共享表征是否足以支持完整动作头；Harness 能否在同样状态条件下提供有效纠正；终止边界的正奖励能否正确传回；以及关闭 Harness 动作纠正后，正反两个目标的 policy 是否都变强。协议完整并不替代这些真机证据。


## 11. v3 对照协议：不混用 Real-Time EXPO-FT 的时间语义

扩展调研补查到了此前遗漏的 Real-Time EXPO-FT 实现。它以 VLA 基础候选、较新观测和快编辑器构成另一决策过程，代码提取延迟后的动作片段，采用 filtered backup 和 RTC 一致性训练。它是有实际训练代码的强对照，不应继续描述为“EXPO 没有异步实现”。[论文](https://arxiv.org/abs/2609.18207)、[固定实现](https://github.com/pd-perry/expo-ft/blob/803381fc3b4c91a0c47904f1b688fc5e35904f50/expo_ft/agents/alg/realtime_expo_ft.py)

但两套方法并非给相同裸状态乘相同 mask：本附录在槽起点冻结 X，将旧承诺 C 纳入状态，新 U 决定下一槽；快编辑方案的决策信息、候选生成和生效时刻不同。比较前须分别固定动作坐标、决策时刻、回报区间、目标及接管处置。在本项目做 Real-Time EXPO 对照时，先忠实核对上游实际文件路径、配置与公式，再用独立协议适配共享目标／Harness，不能直接混入当前宏 replay。

引入语义动作解释器也遵守同一原则：解释器若展开的是冻结信息下的开放环动作，且请求／提交成立，可按本文规则记录；若每步反馈改动作，则先保存微步事实与反馈监督。后台运行在本地、延迟很小，都不能消除这种决策时序差异。
