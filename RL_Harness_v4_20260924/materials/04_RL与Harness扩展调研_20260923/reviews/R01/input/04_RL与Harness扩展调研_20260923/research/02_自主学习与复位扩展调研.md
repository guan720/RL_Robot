# 自主学习、复位与纠正数据：扩展调研及源码复核

核验日期：2026-09-23。本文是供人学习和选型的专项研究，不是系统实现说明。范围是低人工真机 RL、正反循环、自动纠正、失败与奖励数据。VLA 更新器和通用 Harness 的完整横向比较由同目录其他报告补充。依用户最新澄清，框架的通用性优先；松灵单臂抓放只作为首项实验场景，不以是否原生适配 AgileX 作为算法排名或排除门槛。

本文融合 [此前复位调研](../../02_自主RL调研_20260922/research/reset_autonomy.md)、[SiLRI／GAINS 调研](../../02_自主RL调研_20260922/research/deep_conrft_followups.md)、[LWD 等 VLA 调研](../../02_自主RL调研_20260922/research/deep_vla_online.md)、[自动接管复核](../../02_自主RL调研_20260922/research/reassessment_algorithms.md)。**AutoSERL、UniIntervene、SiLRI、GAINS、LWD、FARL、CRONOS 等此前已经收录；本轮重点是重新核查代码和与最新系统的兼容性，不把重新检索包装成新发现。** E2HiL、PACT、Q2RL、AutoEval 等作为补漏线索纳入；其审查深度分别标明。

## 1. 结论先行

截至本轮核验，尚未找到已经开源交付、能够直接满足“弱 VLA、共享正反策略、双向在线 RL、GPT Harness 纠正、异步动作块”的完整替代系统。这个判断针对通用学习和数据接口，而不是要求仓库已支持某个机器人品牌；也仅限定于已核验材料，不代表其他方案不存在或算法效果更差。

最值得保留的仍是**共享目标条件 policy＋示范和纠正支持的 off-policy 学习＋可靠 BC＋实际执行日志＋自动观察和恢复**这一方法形态。新论文提供了有价值的局部改进，但不能以它们各自成立，推导出组合后已经可用。

本轮对选型最有影响的四点是：

1. **SiLRI 值得做纠正权重的候选，却不是现成 VLA 基线。** 固定版本实现单步 SAC 风格动作，动作块接口明确未实现。它处理次优纠正的思路相关，但 Harness 持续给出同一个错误动作时，“低熵”不意味着“正确”。
2. **GAINS、PACT 提醒我们审查接管归因，而非直接照搬接管负奖。** 正常切换目标、观察超时和程序试验也会触发 Harness 接管；它们不能全被视为策略动作有错。异步执行时，触发前最后一条 replay 更不一定是致错动作。
3. **AutoSERL 和 UniIntervene 更适合补强 Harness 的局部能力。** 前者适合已确认物体关系的示范引导；后者适合积累纠正数据后的失败识别和恢复记忆。二者都没有公开交付本项目要求的完整无人训练闭环。
4. **LWD 是重要的真机 VLA RL 证据，但其数据和时序条件必须同时阅读。** 它支持混合经验、共享策略和在线更新的方向，不证明少量示范就能复现，也不直接解决只执行动作块中间一段的问题。

这些结论不要求替换 GPT 主观察系统。学习式进度、风险和恢复模型可以是旁路对照、低延迟辅助或后续蒸馏对象，其引入必须有单独收益。

## 2. 先把“自主”分成几个不同问题

| 问题 | 典型技术 | 容易混淆的边界 |
|---|---|---|
| 练完能否继续练 | 正反任务、目标图、reset-free RL | `env.reset()`、机械臂回零和物体恢复不是同一操作 |
| 能否避免不可恢复失败 | 可恢复性判断、安全价值、局部撤离 | 预防掉桌和把已掉桌物体捡回是不同能力 |
| 谁决定何时纠正 | GPT 观察、进度模型、风险触发 | 会识别错误，不等于能给出可靠动作 |
| 谁实际纠正动作 | Harness 工具、示范引导、恢复记忆、控制器 | 自动生成建议，不等于产生真实环境转移 |
| 谁提供奖励 | 任务谓词、GPT 评分、奖励模型 | 高进度分不是成功；未知不是失败；事后解释不是当时可见状态 |
| 如何利用纠正 | BC、偏好学习、off-policy replay、状态相关权重 | 真实遥操作转移和未执行的反事实建议不能混成同一种 TD 样本 |
| 如何长期更新 | 数据调度、版本部署、持续评估 | actor／learner 网络异步，不等于解决动作执行异步 |

对当前 A↔B 抓放，正常反向任务本身应由同一个目标条件策略学习；异常恢复只是循环之外的补救。恢复系统可以辅助两方向，却不能悄悄取代反向 RL，也不能把“救援完成”统计为被救援策略独立成功。

| [MoReFree，2025](https://github.com/yangzhao-666/MoReFree) | 学习模型和目标调度分配 reset-free 探索 | 对数据覆盖有启发；现有主要证据为低维仿真 |

| [CRONOS，2026](https://embodiedai-ntu.github.io/cronos/index.html)／[仓库](https://github.com/EmbodiedAI-NTU/CRONOS) | 在共享场景检验 VLA 持续训练、reset 预算和课程 | 提醒区分手臂姿态复位与场景复位；公开仓库仍为待发布，不是可运行真机基线 |
| [持续移动操作，2024/2025](https://continual-mobile-manip.github.io/) | 真实移动机器人持续收集与 RL | 受控场地、辅助机器人和预先布置也是成本；首版单臂无需直接复制 |

关联但不是同类 RL 更新器：

- [SOAR](https://github.com/rail-berkeley/soar) 是自动采集与目标条件 BC 的重要参照，不应改称在线 actor-critic；[GEAR](https://github.com/guided-exploration-autonomous-rl/gear-code) 主要借助偏好和目标条件学习。

- [REVOLVE](https://arxiv.org/html/2609.14633v2) 的自动恢复代码适合 Harness 研究，但其成功／纠正回流主要是 SFT，且保留人的代码验证成本。

## 4. 最相关候选的深入审核

### 4.1 SiLRI：应对不完美纠正，但纠正质量不能只看熵

SiLRI 来自北京人形机器人创新中心、香港城市大学、南开大学和北京理工大学。它从接管数据拟合行为分布，并以状态相关拉格朗日权重调节策略对纠正行为的接近程度。该行为模型由数据训练而来，并不是假设一开始就存在强上游 policy。与永久靠近弱基础 VLA 动作相比，其约束来源和权重可以更新。[论文](https://arxiv.org/html/2512.24288v1)、[官方项目](https://silri-rl.github.io/)

**源码核验。** HIL-RL 所引用的 `nuomizai/lerobot` 固定子模块为 `bd4b1356f95f0c7df4e49e16e9652bc57cd0567d`。`modeling_silri.py` 包含接管行为 NLL、单独 actor BC、状态权重和普通单步 critic 目标；`predict_action_chunk()` 明确抛出 `NotImplementedError`。编码器来自 SAC 路径，不是已经适配好的 VLA。其 optimizer 构造将 `self.actor.parameters()` 与 list 相加，存在可定位的 Python 类型问题；若走该路径需修复。某些损失直接除以接管样本数，也需防止空接管 batch。[固定文件](https://github.com/nuomizai/lerobot/blob/bd4b1356f95f0c7df4e49e16e9652bc57cd0567d/src/lerobot/policies/silri/modeling_silri.py)

上述是静态可见问题，不是宣称完成了整库运行或否定作者实验。公开 HIL-RL 有 actor、learner、奖励分类器和机器人适配，README 的 `ego_mode` 仍讨论人工复位；模拟器内置强策略也仅是仿真支路。必须分别审核“训练通信异步”和“机器人动作块异步”。[HIL-RL 使用说明](https://github.com/nuomizai/HIL-RL)、[actor](https://github.com/nuomizai/HIL-RL/blob/main/actor.py)

**迁移判断。** GPT 纠正存在两种 SiLRI 原假设未自动解决的情况：一致但错误的建议可能低熵；左右绕行等多种正确动作可能高熵。因此，纠正置信度须来自时效、场景事实、执行结果与独立核验，不能把行为分布的熵直接当成标签正确率。建议将其作为可靠 BC 基线之后的单独对照，不在首版同时引入行为模型、拉格朗日网络和新 critic。

### 4.2 GAINS：接管时机鲁棒性不等于控制延迟正确性

GAINS 研究不一致的人工接管信号，利用分布式价值和风险相关动作选择，而非假设每次接管边界完全一致。其论文明确不估计接管延迟分布；因此不能替代 SmoothRL／Learning to Act While Waiting 所处理的实际动作执行时间语义。[论文](https://arxiv.org/html/2608.15707v1)

**源码核验。** 同一固定子模块的 `modeling_gains.py` 用 quantile critic，critic 目标仍是单步 `reward + discount × next_value`。默认 actor loss 是 Q 与熵项，不能直接称作已实现本项目所需的 BC＋RL。接管奖励通过 `first_intervene_reward` 等字段进入学习；root actor 在首次接管时回标前一条记录，需要与原因和延迟一起审查。[固定核心源码](https://github.com/nuomizai/lerobot/blob/bd4b1356f95f0c7df4e49e16e9652bc57cd0567d/src/lerobot/policies/gains/modeling_gains.py)、[采集器](https://github.com/nuomizai/HIL-RL/blob/main/actor.py)

**迁移判断。** 本项目至少存在“策略错误”“正常换目标”“低置信观察”“网络超时”“候选程序试验”等接管原因。给所有首次接管统一负奖，会教策略避免某些系统事件，而非避免错误。即使确为策略错误，GPT 看见旧图后触发，最后入库的动作也未必致错。应保存原始事件、观察时刻、实际执行时间和原因，显式构建训练标签；分布式 Q 不能修复错误归因。

### 4.3 AutoSERL：优先借鉴局部示范引导，保留退出条件

AutoSERL 来自中科院自动化所、北京智源、北京大学等。其主要机制是从一条示范提取引导轨迹和恢复点，偏离或停滞时自动介入，策略表现改善后退出引导。适用实验均为手中已持对象与固定目标的关系，动作是 6D 末端增量；论文奖励仍是人工二值标注。某些任务 SERL 对照在同预算下 0/50，不等于验证了“零任务成功 VLA、全抓取释放、无人工奖励”的冷启动。[论文](https://arxiv.org/html/2607.01651v1)、[项目](https://autoserl.github.io/)

固定提交 `978f11a9a25cbb6c13ad691df4e6f3156568c378` 的 wrapper 保留 SpaceMouse 按钮奖励，并用 `intervene_action` 记录替换动作。恢复分支把 list 直接 `+ 1` 作为切片上界的静态问题仍可见。README 声明 Apache-2.0，但此前固定树中未找到项目级 LICENSE；不能以徽章替代许可文件审核。[固定 wrapper](https://github.com/autoserl/AutoSERL/blob/978f11a9a25cbb6c13ad691df4e6f3156568c378/serl_robot_infra/franka_env/envs/wrappers.py)、[固定仓库](https://github.com/autoserl/AutoSERL/tree/978f11a9a25cbb6c13ad691df4e6f3156568c378)

**迁移判断。** 对已确认抓牢、障碍物关系稳定的局部搬运，示范引导是低成本候选；物体已经滑落时，末端靠近示范轨迹不能证明物体已恢复。应在物体坐标或明确工作坐标中重定位，先检查前置条件，再以闭环动作执行。引导退出必须根据相同状态类的独立成功，而非总奖励或接管次数下降。

### 4.4 UniIntervene：真正的代码已开，但发布范围要说准确

UniIntervene 由 NTU 新加坡与北京邮电大学团队提出。它学习失败征兆，检索恢复目标，再由目标条件动作模块纠正。论文五任务结果中，HIL-SERL 加模块的平均成功率是 81%→88%，人工执行动作步占比是 34.3%→14.6%。后者约降 57%，分母不是人工工时或接管事件数。π0.5 SFT 是对照之一，不能将前述结果改写为 π0.5 在线 RL。[论文](https://arxiv.org/html/2606.12372v1)、[项目](https://denghaoyuan123.github.io/UniIntervene-project/)

**发布纠正。** 项目网页曾出现 Code 占位，但真正的 [算法仓库](https://github.com/Denghaoyuan123/UniIntervene) 已发布。固定 SHA `40f461f97573383c9cc8fdba43df56f9eb5bbea1` 为 MIT，包含 NTTG、proxy value、接管挖掘、VQ1、memory、VQ2 等离线环节。README 明确不含机器人部署、HIL-SERL 集成、轨迹、checkpoint 和记忆库。组件 overfit smoke test 也不是留出真机评估。[固定 README](https://github.com/Denghaoyuan123/UniIntervene/blob/40f461f97573383c9cc8fdba43df56f9eb5bbea1/README.md)

**迁移判断。** 它可以将 GPT 已验证的常见纠正压缩成可重复执行的经验，但首版没有这些数据时，记忆不能凭空产生恢复能力。时间位置构造的成功进度伪标签需要特别谨慎：接近失败后的撤退、重新抓取和反向目标都可能打破单调进度假设。检索必须条件化目标与物体状态，不能仅匹配机械臂姿态。

### 4.5 LWD：有价值的共享 VLA 在线学习实证，成本与协议不可省略

LWD 来自 AGIBOT Finch、上海创智学院和哥伦比亚大学等。它结合分布式隐式价值学习 DIVL 与 flow policy 的 QAM 更新，在 16 台双臂机器人、8 项任务上训练共享 VLA。混合 replay 包含示范、历史成功／失败 rollout 和人工 failure play。这支持“失败、纠正、在线经验可以共同改进 VLA”的方向。[论文](https://arxiv.org/html/2605.00416v1)、[机构博客](https://finch.agibot.com/research/lwd)

但本项目应同时看到三项限制：离线数据共 652.5 小时；在线从离线训练后的 checkpoint 出发；论文把完整动作块执行后再规划，目标含 `γ^H`。这不是异步中段执行协议。QAM 的目标也仍保留参考分布约束，不能把它解释成完全不受行为支持限制。公开检索未核到可复现完整流程的官方训练仓库／权重包；HF 的论文条目不等于模型发布。[论文 §III、附录 B](https://arxiv.org/html/2605.00416v1)、[HF 论文条目](https://huggingface.co/papers/2605.00416)

**迁移判断。** 可以借鉴混合来源记录、共享策略、数据吞吐与模型版本管理。若用其学习器，则须重新定义异步队列状态、真实动作区间和目标，而不是仅把 `H` 换成实际步数。适合作为后续原生 flow 更新竞争路线；现有证据不足以认定它是当前少示范首版更低成本的替代。

## 5. 补漏候选：哪些值得进一步投入

### 5.1 PACT 与 E2HiL：值得观察，不自动升为主线

[PACT](https://arxiv.org/html/2606.03949v1) 用成功示范训练进度，再识别接管前次优片段；将纠正动作与策略候选构成偏好，修正 Bellman 目标和 actor。论文五项真机结果为平均 58.0%→82.5%，是 +24.5 个百分点。其 [匿名代码入口](https://anonymous.4open.science/r/HILRL-A1X-BC05) 尚未在本轮完成许可、固定 SHA 与入口运行核验。当前只能算方法候选。

对 Harness 的重要启发是局部归因；局限是“接管动作必然优于策略”“成功示范时间单调代表进展”都不能无条件沿用。未来观察可用于事后定位，但不能伪造未发生的转移，也不能将 heuristic target 修改宣称为真实环境奖励。需要保留原始 reward，单独记录版本化修正目标。

[E2HiL](https://e2hil.github.io/) 以样本对策略熵的影响筛除极端样本；作者页报告 RA-L 2026，并提供 [LeRobot](https://github.com/E2HiL/E2HiL-project-lerobo) 与 [A1_X](https://github.com/E2HiL/E2HiL-project-a1x) 入口。两仓库都有源码树与 Apache-2.0 标识；LeRobot README 给出采集、奖励分类器与 actor／learner 命令，A1_X README 仅标题但目录内有 SERL 代码，不应凭短 README 判为占位。尚未深审训练损失和真实部署链，不能记为已验证复现。它优化数据选择，不能替代自动观察和动作纠正。

我的判断：在双向低数据阶段，不宜立即按熵影响删除样本；罕见成功抓取与恢复可能恰是极端样本。可以先离线分析被过滤数据的方向、来源、阶段和稀有失败覆盖，再决定是否进入受控对照。

### 5.2 FARL 与 CRONOS：补齐失败预防与课程视角

[FARL](https://failure-aware-rl.github.io/) 先训练任务策略、恢复策略与世界模型，在线只更新任务策略，恢复和风险模型保持固定。需要任务、恢复、失败等数据。它研究“在探索中减少必须人工干预的事故”，与普通反向任务不同；本轮官方页仍写代码待发布。论文不是从未覆盖的异常中无监督学出可靠恢复的证明。[原文](https://arxiv.org/html/2601.07821v1)

[CRONOS](https://embodiedai-ntu.github.io/cronos/index.html) 主要提供仿真持续学习与 reset 预算实验。其价值是提醒课程可以先缩小起态变化、只校正机械臂姿态，再减少复位；这不要求拆掉共享正反 policy。应将有限人工或 Harness 引导预算明确计入，按双方向覆盖逐步扩大，而不是一开始要求所有新状态都自主学会。

## 7. 兼容性重新审核：对当前设计意味着什么

| 需求 | 文献给出的支持 | 尚不能跳过的工作 |
|---|---|---|
| 基础成功率偏低，包括零成功 | 示范支持的 HIL／off-policy 学习提供入口；纠正数据可持续增加覆盖 | 零自主成功与“没有成功示范、没有可靠纠正、全零奖励”不是一回事。后者没有现成算法保证启动 |
| 同一 policy 共享正反任务 | 多任务／目标条件学习与 LWD 等支持参数共享方向 | actor、Q、BC、奖励、检索、调度都传同一目标版本；分别统计两个方向，不假设自动正迁移 |
| GPT Harness 替人 DAgger | 实际纠正可形成 BC 及真实交互数据；接管不必来自人 | 校验动作时效、前置状态、坐标和可靠性；未执行建议没有真实 next_state |
| BC＋RL 使用失败和纠正 | HIL 系持久示范与在线回放、LWD 混合经验提供依据 | 失败回合不全丢，成功回合不全模仿；按片段真实性、质量、时序和目标决定用途 |

| 减少 Harness 纠正依赖 | AutoSERL 退出机制、UniIntervene 自动恢复有参考价值 | 评估独立 policy 和完整系统两套结果；救援完成不等于 policy 已学会 |
| 无人连续运行 | 长时循环和自动评测逐步降低人工成本 | 硬件故障、物体不可达、GPT 无可行建议等会结束自主窗口；必须如实统计，而非无限重试 |

### 7.1 建议进入方案的具体补充

1. **纠正质量与纠正分布分开。** 保存执行验证和结果标签；熵、critic 不确定性仅作为特征，不授予建议“正确”身份。
2. **接管事件不是默认负奖励。** 存 `reason`、观察时间、发现时间、动作执行区间及目标版本。只有定义明确的事件代价或经核实的错误标签进入相应学习目标。
3. **未执行建议可以长期存 buffer，但其训练类型要明确。** 它能用于 BC、偏好、候选评分或另行验证的模型学习；不能冒充环境中实际执行过的 `(s,a,r,s')`。真实遥操作数据之所以能做 TD，是它确实有执行后果。此区分不限制 data buffer 保存内容，只限制伪造学习因果。
4. **局部引导可尽早部署，学习式恢复晚于数据基础。** 前置条件清楚的路径引导先受控试验；随着 GPT 纠正形成可靠记忆，再判断是否值得训练额外恢复模型。
5. **双向课程按状态覆盖推进。** 起始可缩小位置和朝向范围，示范与纠正同时覆盖 A→B、B→A；放宽条件时记录人工和 Harness 预算。课程不是固定反向脚本替代反向 RL。
6. **按同预算验证单项改动。** 先可靠 BC＋RL，再分别测自适应 BC、分布式 Q、进度修正或样本筛选；不能一次加齐后将收益归给某一篇论文。

上述多数与现版时间轴和目标契约一致，属于强化验收条件；不需要为“更新”而重构整个系统。

### 9.2 建议学习顺序
