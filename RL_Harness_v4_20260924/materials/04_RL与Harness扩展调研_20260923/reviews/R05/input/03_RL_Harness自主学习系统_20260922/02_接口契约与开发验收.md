# 接口契约与开发验收

审阅版 v3.0｜2026-09-23｜供机器人、算法与系统开发者联合实现。

本附录把 [主方案](01_RL_Harness真机自主学习技术方案.md) 落到执行、观察、数据、训练和发布接口。**以下均为拟议设计与待执行验收，不是已运行的软件或真机结果。** 异步动作分段、价值目标与梯度推导统一以 [异步动作时间轴与学习目标](06_异步动作时间轴与学习目标.md) 为准；本篇说明应记录什么、调用什么、怎样发现接错。

先统一三个概念：正向 A→B 和反向 B→A 使用同一组 policy 参数，由目标条件区分，两向均接受 RL 更新及 Harness 观察和纠正；Harness 是 GPT-6 驱动的观察、评分、动作纠正与代码恢复系统，不预设另有高成功率上游 policy；DAgger 指在当前 policy 访问的状态上增加纠正标签并持续聚合数据，它与 BC／VLA 原生动作监督及在线 RL 共同工作。

## 1. 先看一次完整的数据流

机器人实际执行 → Gateway 记录每一步被采纳的动作 → GPT-6 根据带时序的观察包判断进展与异常 → Runtime 决定续做、纠正、换向或恢复 → 执行证据和纠正标签进入不同训练视图 → 共享 policy 和 goal-conditioned Q 更新 → 固定评测后发布同一个双向 checkpoint。

这条链同时保持三种身份：**哪个任务、哪段真实时间、谁实际控制机器人**。模型预测完成、代码调用成功、Harness 认为成功，均不能代替真实执行证据。

### 1.1 五个开发接口

| 桥层 | 负责内容 | 交付后解决的问题 |
|---|---|---|
| B1 观测与动作 | 单臂映射、时间、动作空间、命令与驱动记录 | 每次真实交互有一致物理含义 |
| B2 执行调度与控制交接 | 异步 chunk、唯一控制权、取消／保持、旧队列失效 | 每个控制帧只有一个实际动作来源 |
| B3 Harness 观察和纠正 | GPT-6 观察包、任务评分、动作建议、程序候选、执行记录 | 减少日常人工判断与接管，并产生可学习数据 |
| B4 数据与学习 | 真实转移、纠正标签、目标条件、采样与损失路由 | BC＋RL 改善同一个双向 policy |
| B5 评测与发布 | 固定评测、版本依赖、晋级／回滚、污染追踪 | 区分系统完成任务和 policy 真正学会 |

### 1.2 一套 Runtime，多项明确职责

| 组件 | 主要工作 | 权限和含义边界 |
|---|---|---|
| 本地 Gateway | 唯一驱动连接，命令检查、下发、取消／保持及回执 | 不负责语义奖励或训练；保护不依赖云端响应 |
| Runtime | 当前目标、episode、调度时刻、控制权、试验预算与故障路由 | 不让多个 GPT 角色或实验进程分别取得硬件通道 |
| Policy Server | 同一 `πθ` 根据观测、目标及异步上下文推理 | 返回 chunk 只是提案；两个方向不是各自隐含一套参数 |
| GPT-6 观察／纠正服务 | 直接理解状态与任务，给评分、纠正动作、恢复程序和诊断 | 输出绑定真正看到的历史；返回回复不等于取得控制权 |
| 本地事实采集与保护 | 相机、关节／夹爪反馈、同步、设备健康与动作边界 | 是事实来源和执行约束，不是必须另外训练的语义小模型 |
| 纠正／恢复执行器 | 执行已发布技能或受限候选，记录每一步 | 所有动作经 Gateway，候选不得修改验收判据 |
| Data Writer 与标签服务 | 先存事实，后追加评分、纠正质量与撤销记录 | 迟到标签不改写物理历史 |
| Learner | 读取固定训练视图，训练共享 policy、Q 及 target | 不控制机器人，不自行热换线上模型 |
| Evaluator／Registry | 预约同一机器人评测，记录版本与发布决定 | 不与训练 rollout 抢设备；评测试次不可任意删减 |

这些是逻辑组件，不要求每项单独部署主机。经过 [RPent 联合审核](09_RPent与Harness联合选型.md)，首选复用 RPent 的 planner、toolkit、机器人适配和记忆结构；借鉴 Zetta 候选门禁、RoboRSI 技能组织与 ENPIRE 工位契约。实体异步 Gateway 和 RL 数据桥仍须补齐，不同时运行多套主控。

工程可按 `gateway/`、`runtime/`、`harness/`、`data_bridge/`、`learner_adapter/`、`evaluation/` 分工；本次不创建空软件目录充当实现。后续代码、数据和日志仍保存在会话专用目录。

### 1.3 RPent 的具体接入位置

| RPent 组件 | 对接本系统 | 必须修改或新增 |
|---|---|---|
| Agent / Planner | GPT-6 主观察、评分与纠正决策 | 异步观察包、迟到分流、goal/rubric 版本；不能只在工具执行完后观察 |
| Toolkit | 有类型的观察／纠正／恢复工具 | 运动只发 Gateway 意图，不能保留第二条设备连接 |
| Robot adapter / EnvServer | 松灵设备与观测适配 | 真实回执、绝对帧、主动臂及标定；Franka 常量不能直接搬用 |
| VLAServer | 共享双向 policy 服务 | goal 真正传进模型；推理执行重叠及 request/commit/activation |
| Flywheel | 原始动作／提案记录起点 | 从 LIBERO 移植到真机，补失败 RL、纠正标签、持久 journal 和调度数据 |
| Memory / Flash | 复用已验证经验和恢复程序 | 记忆置信度不直接授予动作权限；候选仍经过 TRIAL 与回归 |

默认先预检 `--planner api`：官方文档声明其 Pydantic AI 路径支持 OpenAI Responses，源码确实把 Toolkit 注册为工具并传递图像内容。模型名称、provider 路由与工具结果格式需实测；这不等于已经完成 GPT-6 真机调用。[Planner 文档](https://rpent.readthedocs.io/en/latest/rst_source/usage/configure_planner.html)、[API loop](https://github.com/RLinf/RPent/blob/eb269c8a278b0ef717d61a3f55891c9ce2ec7eb1/rpent/planner/api_loop.py)

RPent 的 RPC/tool cancel 不能替代驱动取消与保持确认。其双 Franka `request_operator_verdict` 和场景复位要由本项目 GPT 评分契约及反向任务／恢复流程替换；现有固定 `_vla_instruction` 也要改成真实双向目标条件。Codex planner 的全权限默认值不是本项目对生成代码的授权，部署权限按本篇 Gateway／TRIAL 约束配置。

**持续观察的入口独立于活动工具锁。** 原 API planner 注册 `sequential=True`，Toolkit 的 active-operation 限制也覆盖只读工具。观察服务应订阅 Gateway 发布的只读图像／遥测事件，不在长 motion 所占的 Toolkit 后排队调用 observe；它不获得额外设备写权限。验收时让一个长工具保持运行并模拟卡死，确认多批带新时间戳的观测仍可送达、运行时可发起取消且本地保持可触发。模型异步工具开关不作为通过证据。[API 工具注册](https://github.com/RLinf/RPent/blob/eb269c8a278b0ef717d61a3f55891c9ce2ec7eb1/rpent/planner/api_loop.py)、[工具互斥](https://github.com/RLinf/RPent/blob/eb269c8a278b0ef717d61a3f55891c9ce2ec7eb1/rpent/tools/toolkit.py)

若暂复用 Flywheel 的成功 BC 导出，原导出器要求单次 `task_language` 唯一：正反分开导出，再由版本化 loader 保留各自 goal 合并训练，或明确改造逐 episode 目标格式。主 RL 数据桥直接读取持久事实视图，不绕成功导出器。至少用正反各一条样本验证导出／重载后语言、规范目标和奖励归属均保留。

## 2. B1：把动作、观测和目标定义在同一个接口

### 2.1 四种动作相关量分别保存

| 记录 | 含义 | 使用规则 |
|---|---|---|
| `proposed_action` | policy 或 Harness 提出的动作／轨迹 | 可能未执行、过期、被覆盖，只表示意图 |
| `a_rl` | 选定 learner–environment 边界真正采纳的命令 | 与 actor 输出、Q 输入和部署定义一致 |
| `driver_command` | IK、滤波、限速后发给驱动的目标 | 下游执行证据，不默认与 `a_rl` 同空间 |
| `measured_state` | 关节角、速度、末端位姿、夹爪实测反馈 | 构成观测及后果，不倒填为原动作标签 |

例如 learner 选择末端增量，IK 属于环境内部，则 Q 使用该边界被采纳的末端命令；不能因为机器人只移动一半，就用实测位移改写当时动作。夹爪被物体阻挡时，实际开度也不等于原闭合指令。

若限幅发生在动作接口之前，`a_rl` 记录限幅后采纳命令；若限幅属于环境内部，则保留接口命令和下游投影证据。选择哪一层均须统一。Harness 必须经过同一学习动作接口，或提供经过验证的转换；无法可靠转换的轨迹留存，不伪造可训练动作。

动作契约固定活动臂、维度、关节顺序、坐标系、绝对／增量含义、单位、归一化、夹爪编码、持续时间、下游变换及版本。另一臂使用显式禁用／保持模式；绝对关节目标填零不等于“不动”。

### 2.2 不再用“执行了前几步”描述一般 chunk

完整预测数组保存原始索引到**机器人绝对控制帧**的映射，再记录哪些索引真正被采纳。正常异步推理也会丢掉头部的过期动作，尾部又被新预测覆盖；实际执行往往是原 chunk 的中段。接管会进一步改变它。

每个绝对帧能查到来源 chunk／Harness 命令、原始索引、goal、控制代际、采纳动作、驱动记录及执行状态。块级保存 `executed_indices`／区间列表，而非只有 `executed_length`；通用日志允许多段和部分生效，learner 只支持连续 E 段时在训练视图中显式筛选。

发送成功不是执行完成。驱动缺精确回执时，适配层应说明如何界定命令生效区间及误差；无法对齐的部分保持未知，不按计划长度构造经验。

### 2.3 观测包与目标身份

相机帧、关节／夹爪数据分别保存采样时刻，再组成带 ID 的同步观测。控制超时使用本地单调时钟；跨机器记录源时钟、同步误差和接收时刻。超过新鲜度或同步容差的图像不能重打时间戳成为新观察。

policy、Q、target、replay 和 Harness 请求均携带同一目标身份，例如 `place(object_1, B)`，以及任务契约版本。语言文本可作模型输入，但目标对象、区域和成功判据由结构化任务定义统一生成，不靠任意字符串碰巧相同维持一致性。

正向成功时结束正向目标 episode，核验反向合法起态，创建新 episode 并切换 goal；共享参数不意味着跨目标延续原 Q 回报。发布同一个双向 checkpoint，两个方向的成绩分别记录。

**B1 验收重点：**任一实际控制帧都能解释目标、观测时刻、动作层、单位、来源和真实后果。

## 3. B2：异步执行与 Harness 接管

### 3.1 执行异步和训练异步分别配置

执行异步是“机器人继续动作时，下一次推理已经开始”；训练异步是“采集进程与 learner 并发”。不能用一个 `async=true` 混同。首版可采用异步执行、分批训练；后续加入持续 actor–learner 不改变真实动作归属。

默认验证固定调度间隔 `n`、动作长度 `H≥2n` 和 deadline 的模式。在时刻 `t` 请求新预测：

- **C** 是 `[t,t+n)` 已承诺由旧计划执行的真实命令上下文，不是新预测的前 `n` 个动作。
- **E** 是当前预测索引 `[n,2n)`，在 `[t+n,t+2n)` 执行。
- **D** 是当前预测索引 `[2n,H)`，本次不执行；当前预测的前 `n` 项也不产生本次物理动作。

精确状态、时间与价值定义遵循 [06 专项](06_异步动作时间轴与学习目标.md)。C 相对当前预测是已承诺上下文，但它所引用的旧计划动作确实属于物理历史，必须有真实来源。

提前完成不擅自改变固定切换时刻；错过 deadline 不把晚到结果塞进过期索引。Runtime 按冻结的迟到规则继续已有合法动作、保持或结束尝试，并记录实际选择。只有符合该学习分支时序前提的窗口才生成其 TD 样本；异常事实保留，不重标成“准时”。

### 3.2 每帧只有一个真实动作来源

Gateway 对 `robot_id` 实施设备级独占和递增控制代际。每个绝对帧只采纳一个来源；VLA 新旧 chunk 替换、Harness 纠正、恢复、主动观察、候选试验均经同一入口。不同 session 不能各自持有同一机器人。

接管顺序：封住新的 policy 动作 → 撤销未生效队列 → 处理在途动作 → 确认适合交接的保持状态 → 重新观察 → 给 Harness 新控制代际。回交也清旧队列和旧推理，基于当前观测重新启动 policy。租约取消与机器人已停止是两件事。

概念 API 如下；名称可适配，语义不能省略：

```python
ticket = gateway.submit_plan(
    lease=policy_lease, goal_id=current_goal,
    observation_id=obs_id, plan_id=plan_id,
    frame_map=absolute_frame_map, actions=action_chunk)
receipt = gateway.quiesce(policy_lease, reason="empty_grasp")
# 必须是当前代际已确认的保持凭证，而非 cancel_requested。
corr_lease = gateway.handoff(receipt, owner="harness_correction")
# 根据新观测和当前前置状态，再提交纠正动作。
```

`submit_plan` 返回接收 ticket，执行事实经事件追加。`quiesce` 区分处理中、完成和无法确认，调用方自填 `stopped=true` 不能取得控制权。本地保护不等待云端或 owner 心跳。

### 3.3 接管按实际区间重建数据

例如新预测头部已因推理延迟失去机会，中段运行一半时发现抓空，尾部未运行。日志逐帧说明：头部期间哪个旧计划在执行；中段哪些动作生效；在途动作是否完成；尾部何时因新预测或接管失效。不能把中段重命名为“原 chunk 前缀”，也不能把旧计划的物理执行归因成新动作已经执行。在含真实 C 的队列 MDP 中，当前槽 R 仍可与新决策 U 构成合法 TD，其延迟因果关系按 06 定义。

命令部分生效后制动时，保存开始／停止时间、实际持续时间和保持过程。支持变时长的分支才可使用对应目标；固定时域 learner 不把它四舍五入为完整一步。不能跨未知片段拼连续训练序列。

所有运动路径，包括 Harness 主动观察和候选试验，使用相同 quiesce 与失联机制。停止／保持策略依据控制模式与是否持物决定，不能统一断电。

### 3.4 崩溃、去重与恢复

命令意图和执行回执分别持久化。重启先提升控制代际、确认唯一驱动连接、读真实状态、处理未决命令，再恢复运动。ACK 丢失不得重放未确认增量动作；同命令 ID 重试查询原结果，不再执行一次。

软件日志不赋予物理行为事务回滚。要求的是单一入口、请求去重、未知执行不重放、旧代际失效和可审计证据。

## 4. B3：GPT-6 主观察、动作纠正与代码恢复

### 4.1 观察输入与输出

GPT-6 是首版主语义观察和纠正决策模型。输入包括当前任务、带时间顺序的图像、相关 proprio／夹爪反馈、最近实际动作与技能说明，不只发送脱离任务的单图问“成功了吗”。

按可用模型 API 发送图片序列及显式时间信息，不假设原生视频接口已经存在或验证。视频抽帧应记录采样规则、遗漏区间和来源；低帧率摘要可能漏掉掉落或瞬时接触，需要工位校准。

| 输出 | Runtime 用途 | 留存方式 |
|---|---|---|
| 任务判断、进展与异常 | 按固定判据决定完成、续做、补充观察或未知 | 绑定观察区间、goal 和评分版本 |
| 当前纠正动作 | 检查时效和前置状态后决定接管 | 数值／程序提案与实际执行分开 |
| 历史动作标签 | 不控制当前机器人，用于动作监督 | 绑定原状态、目标、接口、质量及有效索引 |
| 诊断和恢复程序 | 检索已有技能或进入受限试验 | 保留生成证据、版本、试验与发布记录 |

GPT-6 可以输出末端目标、夹爪命令、轨迹片段和代码组合，不限于语言。执行前检查坐标系、单位、作用时刻、可达范围与当前状态。输入不足时补充观察或拒答；模型能力不能替代相机标定和接口契约。

### 4.2 迟到回复的三种用途分开判定

区分观察产生、请求发出和回复到达三种时刻。请求绑定 ID、观察区间、执行事件范围、goal／episode、控制代际、任务判据、模型／提示和预处理版本。

例如正向完成且反向已开始，正向回复才返回“物体已放在 B”：可以给正向历史补标签，不能终止反向，也不能直接执行原抓放建议。早发晚到的请求不能覆盖较新的当前状态裁决。

1. **历史评分：**只标注实际提供给模型的区间和目标；迟到本身不使其无效。
2. **历史动作标签：**绑定原 policy 可见状态和目标；混入后来场景信息的动作不能冒充原状态建议。事后结局可辅助质量审核，但不能成为部署时不存在的隐含输入。
3. **当前控制候选：**核当前 goal、控制代际、观测新鲜度和前置状态；不满足则重新观察、重规划或丢弃控制资格。

三个用途各有有效性，不能用单一 `valid=true` 混同。历史标签仍有用，不意味着当前动作仍有效。

### 4.3 评分缓存不能是“最近一次分数”

缓存键包含 goal、episode／观察证据区间、任务判据、模型／提示和预处理版本。相同事实与评分定义才可复用结果。缺当前样本评分时返回 `pending` 或 `unknown`，不复用上一方向成功分，不把网络异常默认为失败。

ENPIRE 的 Gemini 奖励源码使用全局缓存，限频、缺图像或异常时返回旧 reward，缓存无目标身份。因此只能借鉴服务形式，不能直接搬入正反共享闭环。[固定源码](https://raw.githubusercontent.com/NVlabs/ENPIRE/99ee90acf65b5b18957c8382ad580db999528be3/enpire/env/forge/cap/reward/gemini_reward.py)

终局成功按事件 ID 去重。反复询问同一放置不能增加终局奖励次数；持续停留目标区怎样计分由固定奖励定义决定，不由缓存刷新频率决定。

### 4.4 固定判据不等于额外训练一个小模型

首版 GPT-6 按固定 rubric 判断对象、目标、释放与稳定，本地事实提供证据。前期用留出片段、必要的独立传感器或离线人工审计校准误报、漏检、拒答和延迟，不要求每次在线等人确认。额外小奖励模型仅作为后续成本、速度或可靠性对照。

程序生成者不能修改 rubric、目标或正式评测实例来过关。同模型多角色认可不是独立地面真值。正式评测保留独立审计，人工建设和事后审查单独计时。

连续 reward 可由 GPT 进展标签异步生成，先验证收益；“有小数”不等于信息更多。势函数 shaping 两端须同版本、同目标和正确折扣；见过未来结局的整回合评分不能伪装成因果状态势，不任意插值未知中间状态后称为逐步真值。

### 4.5 纠正／恢复的执行资格与数据质量

Harness 可调用抓放原语、生成动作参数、重规划和恢复代码。技能包声明调用范围、前置状态、结束条件、动作接口、超时、尝试预算及版本。要求的是可执行能力，不是事先准备完整高成功率策略。

新代码进入 `TRIAL`，接口／静态检查后可在预设范围和预算内自动试验，不默认逐次人批。固定核验和回归通过后发布。候选不能修改自身保护、评分或预算；仿真和回放可淘汰明显错误，不能代替新物理行为验证。

高层 `regrasp()` 必须关联低层真实动作与观测；首尾截图不足以生成中间 RL 样本。普通 B→A 是共享 policy 的训练任务，异常复位是使起态重新可用的额外过程；改变目标时切数据边界。

执行可靠性、动作可表达性、policy 可观察性和训练内化分别检验。Harness 的额外深度或状态可帮助系统，但 policy 缺信息时不能保证可模仿；也不能仅因最终纠正成功把整段标成优质 BC。

## 5. B4：共享 policy 的 BC＋在线 RL 数据接口

### 5.1 保留事实，再生成不同用途的数据视图

| 数据对象 | 长期保存内容 | 训练用途 |
|---|---|---|
| 真实执行日志 | policy、Harness、初始化遥操、保持／恢复的实际动作和后果 | 物理事实、质量审查、符合所选 MDP 的 TD 与监督来源 |
| 真实调度事件 | 决策请求被 Runtime 接纳、结果提交、物理激活、C/E 来源、槽位及异常 | 构造首版延迟 MDP 的真实转移，三个阶段不能混成“执行过” |
| 纠正标签池 | 已执行或未执行的 Harness 动作建议，原观测、goal、质量与有效索引 | BC／一致性／flow 等动作辅助目标，按选定动作头实现 |
| 标签账本 | GPT 评分、进展、成功、质量、未知与撤销记录 | 版本化 reward／监督视图；追加而非覆盖物理事实 |
| 训练视图 manifest | 事实记录、标签版本、过滤规则、归一化、采样和 mask | 固定一轮训练输入，可从任一样本反查原始证据 |

初始成功示范保护分区不被环形 replay 覆盖。失败、实际纠正与纯建议均可长期保存；内存 replay 只是有限采样缓存，不是唯一存储。相同实际纠正在多个用途视图出现时用同一 ID 关联，不算成多次真实交互。

“未执行”要区分三类：历史遥操在采集当时已执行；Harness 影子查询只有动作标签；被真实 Runtime 在决策时接纳的请求是延迟 MDP 的真实决策，即使当前旧动作提前完成任务，使请求结果最终无需物理激活。最后一类必须有事前请求、冻结状态与运行参数的证据，不能事后给任意建议补一个 admission 就变成 TD。

### 5.2 共享参数必须贯穿 policy、Q、target 和采样

首版拟议主学习器为 **VLA 表征＋可学习的完整动作头＋goal-conditioned Q＋Harness 动作监督**。动作头直接生成学习动作空间中的完整命令，不硬性以冻结 VLA 参考动作作为偏移中心。首版初期冻结 VLA 表征；如需开放表征更新，先按算力、可复用代码和独立消融验证，再升级配置及缓存／回放版本，不与首版默认为同一模式。

工程借鉴 ConRFT 的价值引导／监督训练、HIL-SERL 的混合来源回放与接管、RLT 的表征利用；这是需实现和验证的组合，不称作上述任一原版现成能力，也不称作原版 SmoothRL。EXPO-FT 可作有条件工程对照，其原生 VLA、edit 和数据入口需单独适配。

两方向使用同一个 `θ` 和同一参数发布版本。观测／历史、goal、已承诺队列及调度信息进入一致的 actor/Q/target 状态。不能 actor 看语言而 Q 不看目标；同一位置在 A→B 和 B→A 的价值不同。正反分层采样、防止单方向占满 batch，并各自报告覆盖和梯度影响；不通过维护两个隐含独立模型掩盖共享训练退化。

### 5.3 默认 TD 以真实 Runtime 决策请求为起点

在固定 `n` 的首版中，状态 `X` 包括观测／历史、goal、当前已承诺 C、调度 phase／配置。Runtime 在决策时接纳请求，并冻结 X、goal、权重、随机种子和未来槽位；其实际在途计算产生动作 U=E。必须区分 `request_admitted`（请求已接纳）、`result_committed`（结果按时提交下一槽）、`physical_activated`（该槽开始物理执行）。三者是独立事件，不能事后根据成功或失败才决定请求是否存在。

普通非终局槽中，C 执行得到 `R_n`，结果必须按时提交且下一状态满足 `C'=U`，目标为：

```text
y = R_n + γ^n × bootstrap_valid × Q_target(X_next, π_target(X_next))
```

这是本项目拟议延迟 MDP，不是 SmoothRL 原论文 `2n` 目标改名。普通槽自身所需事实完整即可定稿，不等待后一个槽最终成功或接管。`γ` 的时间单位、prime 阶段和请求动作的条件在 [06 专项](06_异步动作时间轴与学习目标.md) 统一规定。

若当前 C 在 L 步发生真实终局，事前已经接纳的请求可让原在途计算完成，以其真实 U 配当前槽终局回报 `R_L`，不 bootstrap、不物理激活结果。这里结果仅落日志，不是重新观察后重算动作。终局与非终局使用同一事前 admission 原则，**不依据下一槽未来是否终止来覆盖前驱 target**，也不训练额外终局筛选 V/probe。无真实请求的影子查询仍没有 TD；初始 prime 等无决策请求阶段只保存事实。虚拟张量填充须标非执行。

如果 Harness 中途改变 C、deadline miss、换 goal 或未知执行破坏本槽契约，隔离该宏 TD 并保留逐帧事实、可用监督，flush／reprime 后重新采样。下一槽后来被接管，不改已完整记录的前一正常转移；仅在前驱边界快照也无法确定时一并隔离。非终局超时不冒充 `done=1`。未来事件不得成为当时 X 中的预知信息。

### 5.4 Q 梯度、动作监督和执行 mask 各管不同的事

| 标记／输入 | 说明 | 不能代替什么 |
|---|---|---|
| `execution_indices` | 原预测中真正生效的机械动作位置 | 不等于动作质量，也不等于队列接纳 |
| `request/commit/activation` | 事前请求接纳、结果提交、物理激活的三类证据 | 不同分支所需证据按 06；无真实请求的标签不能训练 TD |
| `td_valid` | 当前转移符合状态、动作、目标、时域与反馈定义 | 不是整回合成功 flag |
| `q_action_gradient_mask` | Q 引导只对当前 actor 可控制的 E 求动作梯度 | 不能对历史 C 或丢弃 D 冒称当前决策梯度 |
| `supervision_mask` | 哪些纠正动作是可信且可学习标签 | 与是否物理执行、是否位于 E 不同 |

Q 将 C 作为状态上下文，不能把历史 C 偷换成当前网络重新预测的前几步。D 不进入本次价值动作；actor 的 Q 更新不能奖励从未入队的 D。BC 可使用质量合格的历史或查询标签，因此监督 mask 有自己语义，不应一律截成 E。回归检查需要验证这些 mask 实际进入计算图，而不只是保存在 batch。

纯影子查询标签有动作但没有其真实决策转移，仍可长期进入 BC／flow 辅助分支。不能给它配 policy 原动作产生的后继状态，也不能为兼容旧 replay 填假 reward/next state。这与事前真实 admission 的终局决策样本不同。构造动作窗口按真实帧、goal、episode 和来源边界，不把数组邻接当物理连续。

对于 flow／一致性动作头，只有最终 loss mask 可能不足：未标注位置还可能进入加噪和 token 交互。要么使用完整可信窗口，要么验证未知动作在输入、注意力、目标和推理中的处理。不能复制最后一帧或填零后只屏蔽 loss 就宣布兼容。

### 5.5 正反、接管与恢复的边界

同目标下 policy→Harness 纠正→policy 可以保留同一任务 episode，同时新建来源段。接管不自动表示任务失败，传感器故障、观察补充和正常纠正也不等于负奖励。只有契约定义的真实终止才使用终止语义。

换向则结束旧目标、清理旧 goal 的控制队列和推理结果、重新 prime。GPT 的旧结果只可按原目标归档，不能改写当前评分缓存。异常恢复若改变目标同样切边界，不能让正向 Q 继续 bootstrap 到反向奖励。

本方向成功不等于下一方向起态可用：物体在 B 边缘仍可能难抓。先检查下一任务的 `init_set`，必要时整理并计入额外恢复成本。循环按实际状态路由，不按奇偶次数盲切。

**B4 阻断条件：**Q 看不到 goal／队列上下文；样本没有真实事前 request 及该分支要求的提交／时序证据；查询标签带上他者动作后果；C/D 获得错误 actor Q 梯度；奖励版本混杂；图像历史跨缺口；监督质量仅凭 GPT 自称可靠。冻结对应视图和发布，保留事实修复，不删除失败记录。

## 6. B5：评测、版本与发布

### 6.1 一个双向版本包

包绑定共享 policy、Q/target 与优化器、观测处理、normalizer、动作契约、执行调度配置、任务契约、Harness 程序、GPT 模型／提示／rubric、奖励视图、回放索引和评测协议。原始路径不能代替内容身份；只换权重而不换匹配预处理不算有效回滚。

表征更新后旧 embedding 缓存失效，应重算或隔离。改变执行 `n`、deadline 或队列输入也改变学习条件，不因 action shape 一样就继续混用旧数据。具体可转换数据由版本化 adapter 明确声明。

发布在双方可交接的边界进行：暂停接收新命令、确认状态、清旧推理和队列、原子切换相容包、重新观察并 prime。不能在一个正在执行的 chunk 内悄悄换模型或 normalizer。

### 6.2 三套结果、三种评测资料

| 结果 | 测什么 | 保留的共同条件 |
|---|---|---|
| policy 独立能力 | 关闭 Harness 任务动作纠正，分别评估同一 checkpoint 的正反成功和耗时 | 底层保护、事实记录及固定任务评分仍存在 |
| policy＋Harness 系统能力 | 允许纠正／恢复的任务产出、吞吐和调用成本 | 记录帮助时长与动作占比，不能冒充独立能力 |
| 自主学习能力 | 持续有效采样、更新、评测，在线人工分钟与中断 | 停机等待和只采集不更新不能算持续学习 |

开发诊断集用于修改方案；晋级集允许按计划反复比较，但记录选择历史；最终保留审计集不反复用于调参。保留集失败若交给 Harness 修复，就转为开发资料，下一次独立审计换新实例。

真机起态以实测位置／姿态分层和交错运行控制差异，不以同 seed 号冒称完全复现。困难复位、拒绝起态与中止试次均按预定义协议留在记录中。阈值、试次预算和允许回归在试验前确定，不临时试到过线才停止。

GPT 主评分仍需独立留出证据审核假阳性；同模型换角色复核不算独立真值。离线人工审核与前期示范如实计成本，无须把它变成每次 runtime 的在线人工确认。

### 6.3 标签撤销后追踪到权重

错误评分或纠正标签撤销时，沿 manifest 找出受影响样本、训练视图、checkpoint 及其后继版本，暂停晋级并评估是否回退可信版本重训。重标 replay 不会自动清除已经写进权重的影响。

软件回滚后重新观察和恢复物理场景，不认为 Git 或 checkpoint 回滚能撤销运动。评测和训练采集使用同一设备仲裁，不能因是测试程序便绕过 Gateway。

### 6.4 服务故障分别处理

| 故障 | 暂停什么 | 允许的后续行为 |
|---|---|---|
| learner／训练 GPU 失败 | 参数更新和发布 | 冻结包可在预算内采集，明确记作学习暂停 |
| GPT 观察／评分不可用 | 新语义判断、依赖它的换向和训练视图 | 仅在预先声明的已覆盖范围继续，否则保持／停止；不假定有备用小模型 |
| 代码生成不可用，但观察可用 | 新候选演化 | 可调用已发布技能；未知异常超预算就中断 |
| 控制、观测或 owner 不可信 | 自主运动和新任务 | 本地保持／停止、证据对账；不等云端批准 |
| 存储／事实记录失效 | 新学习采集并按契约结束运动 | 保护已有日志，不能继续生成无因果证据的训练样本 |

## 7. 开发顺序和验收场景

建议先 mock 队列／驱动，接真实观测，再做范围明确的动作。先让冻结 policy 与 Harness 跑通时序和数据，再训练一次共享 checkpoint，最后扩大持续循环。每个阶段分别验收执行正确、数据正确和学习有效，不以“服务能启动”替代三者。

以下全部为**待实现、待执行**的验收。逻辑门槛要求可确定；误判率、时延和预算数值从工位预检与任务需求确定，不借论文参数直接填空。

| 编号 | 注入或检查 | 必须出现的证据／失败处理 |
|---|---|---|
| T01 | 交换单位、关节序、绝对／增量定义 | 接口拒绝错误契约；不能静默驱动实体 |
| T02 | 旧图像、异步状态、缺夹爪反馈 | 明确失效／降级，不重打时间戳伪造新观察 |
| T03 | IK／限速改变请求，接触使关节未达目标 | 提案、`a_rl`、驱动、实测四层可区分；不倒填实测动作 |
| T04 | 同帧两个 session／policy／Harness 争控制 | 仅一真实来源，另一请求明确拒绝或等待 |
| T05 | 新预测头部过期、E 执行、D 被替换 | 绝对帧到原 chunk 索引正确；头尾不伪装已执行 |
| T06 | policy 返回早、准时、迟到、乱序 | 按固定 deadline 调度；迟到未准时插入，无旧动作复活 |
| T07 | E 中间接管，另有一条命令在途 | receipt 与驱动吻合，部分生效不取整，受影响宏 TD 隔离 |
| T08 | 在纠正、恢复、主动观察、TRIAL 分别触发故障 | 同一 quiesce／保持生效，无路径绕过保护 |
| T09 | ACK 丢失、重复提交、Gateway 重启 | 不重复运动、不重放未知增量；旧代际失效 |
| T10 | 固定窗口的正常队列推进 | 事前 request、准时 commit、当前 C、`X_next.C=U`、真实 `R_n` 对应；三种事件不混淆 |
| T11 | 当前 C 终局而请求结果未物理激活 | 仅原事前请求的在途计算产生 U，target 为本槽终局回报；无事后新请求、前驱覆盖或终局筛选模型 |
| T12 | 当前窗口非终局超时或接管 | 不用 `done=1` 伪终止；不兼容宏样本隔离，原始帧保留 |
| T13 | 分别扰动 C、E、D 并检查计算图 | Q 读真实 C；actor 的 Q 动作梯度只作用当前 E；D 不入价值动作 |
| T14 | 可信标签位于非 E 位置、部分标签缺失 | BC mask 按质量独立生效；未知值不经输入／attention 污染有效监督 |
| T15 | Harness 影子建议，policy 执行另一动作 | 标签持久入监督池，但没有虚构事前 admission 或他者后继状态 |
| T16 | 间断纠正帧及环形 buffer 保存重载 | 按真实时间和 goal 重建；数组邻接不变成连续 chunk |
| T17 | 相同状态换 A→B／B→A 目标 | 同一 θ 对目标有正确条件依赖，Q/target/样本均接收目标；检查两方向实际梯度与行为 |
| T18 | 完成正向后换反向，旧 VLA/GPT 回复才到 | 控制 flush／reprime；历史标签归正向，反向缓存和动作不被覆盖 |
| T19 | 正向成功，但 B 位置不适合反向抓取 | `init_set` 拒绝启动，整理或记录中断，不用成功 flag 盲切 |
| T20 | GPT 请求乱序、超时、缺图像 | 历史区间正确归属，当前裁决不回退，pending/unknown 不变旧 reward |
| T21 | 同一成功画面多次查询、重复回调 | 一次终局事件只记一次；奖励频率不随轮询变化 |
| T22 | GPT 输出合法数值动作或使用过期坐标 | 前者可通过接口执行，后者重新观察／拒绝；不一律禁数值，也不免检查 |
| T23 | 候选代码尝试改 rubric、预算或直连驱动 | 门禁拒绝；合规候选可在 TRIAL 自动试验，不要求逐次人工批准 |
| T24 | 相同 θ 正反交替训练，单向样本占比上升 | 分层采样和双向评测暴露退化；无隐含独立参数冒充共享 |
| T25 | 仅开启训练并发或仅开启执行并发 | 配置、日志和时序分别可测；前者不被称作已实现异步动作调度 |
| T26 | 同形状但 normalizer／n／rubric 版本冲突 | 训练视图和发布检查拒绝；不以 shape 一致掩盖语义不同 |
| T27 | 撤销已用于训练的成功／纠正标签 | 可追踪受影响权重及后继发布，必要时回退重训 |
| T28 | Harness 更强但 policy checkpoint 固定 | 系统表现提升、独立能力不变，报告不声称模型学会 |
| T29 | 困难起态被拒或候选难以复位 | 分母和拒绝记录完整；不删困难试次晋级 |
| T30 | 发布中断、服务故障、资源耗尽 | 相容旧包或明确停止；学习暂停、采集暂停和运行中断分别记账 |

T17 不要求随机初始化时换 goal 就有高成功率；首先测试 goal 确实进入全部计算图、标签和 target，然后用已知小样本任务验证其条件化行为。维度检查不等于目标语义已正确。

进入自主窗口前需填写：型号／动作定义、控制保持与停止时间、图像同步容差、固定 `n` 与 deadline、迟到处置、双向 init-set、GPT 请求／超时预算、评分 rubric、纠正试验范围、示范保护与采样、发布试次与回归门槛、日志高水位及降级规则。填写依据是测量和任务要求，不是模型名或机构声誉。

首个完整交付应演示：同一 policy 正向尝试 → Harness 识别并纠正 → 真实队列／动作与查询标签分流 → 反向同样尝试与更新 → 任一训练样本可追溯 → 一个共享 checkpoint 接受双向独立评测。学习尚未提升时，如实报告只完成数据／执行链。

## 8. 供实现者查阅的最小记录清单

下面不是最终协议或必选传输格式，而是联调时不能缺少的信息；大图像与动作数组用引用，避免每条事件重复整包。

| 记录 | 核心信息 |
|---|---|
| `ActionPlan` | plan ID、模型版本、goal/episode、观测 ID、生成／截止时间、原始 chunk、绝对帧映射、代际 |
| `ExecutionEvent` | 绝对帧、plan/原始索引或 Harness 命令、采纳动作、驱动证据、生效区间、来源、部分／未知状态 |
| `DecisionRequest` | 事前 admission、冻结 X/goal/权重/随机种子/未来槽，结果 commit 与 activation 的独立回执、next 队列与异常 |
| `HarnessObservationRequest` | 请求 ID、图像／状态时间区间、执行事件范围、目标、rubric、模型／提示／预处理版本 |
| `HarnessResult` | 原请求 ID、到达时间、历史评分／历史标签／当前命令各自资格、状态与证据、不确定原因 |
| `CorrectionLabel` | 原 policy 可见观测、Harness 额外信息、goal、动作契约、动作与有效索引、是否执行、质量与版本 |
| `TrainingView` | 原始记录 IDs、奖励/监督版本、TD 可用规则、BC 与 Q mask、数据切分、采样和 normalizer |
| `ReleaseBundle` | 共享 policy/Q、依赖版本、执行调度、Harness 配置、数据视图、双向评测、发布／回滚记录 |

`CorrectionLabel` 没有虚构的 next observation；`DecisionRequest` 不能事后只凭一个建议补 admission。真实决策请求、提交的动作结果与机械激活相互关联但分别记录，是异步 BC＋RL 接口成立的关键。


## 9. v3 新组件的融合验收

新增项仍为待实现、待执行。它们检查复用开源模块后是否保留本文物理与学习契约。

| 编号 | 场景 | 验收条件 |
|---|---|---|
| T31 | RPent、语义动作解释器、RLinf／LeRobot env 同时请求动作 | 三者都只能调用同一 Gateway；没有额外 ROS/CAN 写通道，reset 也经过仲裁 |
| T32 | 一个语义动作展开成若干低层命令，中途读新图像重规划 | 保存语义输入、展开前后、每次反馈与实际生效；反馈路径不冒充槽起点完整 U／普通 BC |
| T33 | 工具返回 DONE、Pause 或停止协程 | DONE 不直接写成功 reward；Pause 不直接宣告 quiesce；核对实体回执和独立任务判据 |
| T34 | 原生头／完整头／实时编辑采用不同时间协议和信息输入 | 相同任务与预算评估；按模块列视图／历史／派生状态、来源与可用时间、特征版本及计算成本；统一可获得信息或做输入消融。记录协议、normalizer、动作可达性与数据，不混 replay／Bellman；新协议另推导验收 |
| T35 | Harness 因评分未知、超时或主动观察而接管 | 保存 reason、证据区间及真正动作时段；不自动产生 failure reward／前驱惩罚；BC质量与TD资格分开 |
| T36 | 复用框架的 demo mixer、发布权重或设备模块 | 真实 transition 与纯动作标签分支分别测试；目标与队列不被 adapter 丢弃，发布只能在既定边界生效 |

版本锁必须写明具体 commit、模型 revision、依赖锁与机器人驱动。文献调研阶段的 `main/latest` 网页证据不是部署锁；若上游完整源码／许可／驱动未取得，就只借机制或接口重新实现，不把尚未取得组件写成已集成。

### 9.1 通用框架与本体 adapter

上层只依赖能力描述、观测／动作 schema、时间与控制权协议、任务 goal／verdict；不能硬编码 Piper／AgileX、固定 6/7/14 维或某种夹爪符号。adapter 显式声明坐标系、单位、关节／末端控制模式、频率、反馈与停止能力，schema 和 normalizer 纳入版本。跨本体通常要重新标定、适配动作头与采样，不承诺同一权重直接通用。新增 T37：用两个不同动作 schema 的模拟 adapter 做契约回放，检查上层不依赖厂商和维度；更换后旧 replay 默认隔离，只有通过显式且经过验证的转换才能复用。此测试验证软件边界，不冒充跨机器人实测。

T38：相同 GPT／工具／模拟本体和故障记录运行候选 Harness，分别核观察独立性、控制权、停止确认、日志完整性及替换成本。候选原生初始化不得隐式移动未参与肢体或松开持物夹爪；只有显式初始化请求可执行。此项先做回放，再确认所选 adapter 的真实行为。

执行 T38 时固定具体入口、provider、真实／模拟模式、fast mode、动作 horizon 及真实消费索引；库的某个 RTC 路径不能代表所有 run-policy 路径。记录需要替换的控制路径、观察延迟、日志缺口和适配工时，作为底座成本证据，不用单一主观总分决定。

T36 的 loss 适配同时检查 actor 类型：首版确定性完整头使用本文 Q＋BC 目标，不继承默认 SAC 的 `log_pi`、熵温度和 entropy backup；不能填一个假概率只为满足 worker 签名。若另选随机 actor／最大熵目标，须明确新的完整目标及其采样和验证，而非静默改变 06 的公式。
