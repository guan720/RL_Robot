# 训练平台、Hugging Face 与机构发布核查

核查日：2026-09-23。本文是专题证据，不是实测报告。区分 **方法、训练平台、模型、执行中间件**；它们不能凭项目名互相替代。

## 1. 先理解平台解决什么

一套算法需要 actor、critic、数据采样、真实环境和权重发布才能运行。RLinf、LeRobot、verl-vla 可复用其中多项；但“支持 VLA”“支持 SAC”“支持 RTC”三个勾，并不证明同一个配置已实现 VLA＋SAC＋真实异步 TD。最重要的审核单位是**具体模型—算法—环境—执行协议组合**。

本项目还要求 GPT Harness 的纠正标签能长期参与 BC，真机后果进入 RL，并保留共享正反目标。训练平台是承载这些定义的代码底座，不得反过来让平台默认数据格式决定物理事实。

## 2. RLinf／RLinf-USER：优先验证的训练运行时

**证据。** RLinf-USER 在 RSS 2026，有论文、开源平台和真实机器人操作文档。原文分别展示 CNN/Flow 的 RL 和 π₀ 的 HG-DAgger；因此不能把 π₀ 的在线提升直接归因为 SAC。异步训练/采样/权重同步是系统贡献，另有 RTC 执行功能。[官方 USER 页面](https://rlinf.readthedocs.io/en/latest/rst_source/resources/publications/rlinf_user.html)、[论文](https://arxiv.org/abs/2602.07837)

工程入口已具体到 `run_realworld_async.sh realworld_peginsertion_rlpd_cnn_async` 和 `realworld_charger_sac_cnn_async`，同时有 reward worker、replay、机器人资源调度与 DAgger 入口。v0.3 的发布锚点是 **0505431899574619da86f551bad70b71e0ea2177**，发布日期 7 月 15 日；当前文档可能包含该版本之后的功能，不能把两者当成相同冻结版本。[真机启动](https://rlinf.readthedocs.io/en/latest/rst_source/guides/realworld_robot.html)、[v0.3 发布](https://github.com/RLinf/RLinf/releases/tag/v0.3)、[固定提交](https://github.com/RLinf/RLinf/commit/0505431899574619da86f551bad70b71e0ea2177)

**三个影响本项目的边界。** 硬件条目仅用于限定公开证据和部署成本，不按是否支持 AgileX 排框架名次。

- 官方 Piper 文档明确当前覆盖硬件检查，**尚没有受支持的 Piper 真机任务／训练流程**。而用户只说松灵 ALOHA 类，型号仍未确定。不能直接宣布平台已适配用户机器人。[Piper 文档](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/piper.html)
- RTC 文档当前展示 π₀.₅ 在 LIBERO／Franka 的**评估**；推理重叠和延迟估计不等于训练 target 已实现本文队列定义。[RTC](https://rlinf.readthedocs.io/en/latest/rst_source/guides/rtc.html)
- SAC-Flow 有真实 Franka 插接入口，但小型 flow actor 不等于原生 π action expert；其采样概率机制也不能直接套在确定性完整头上。[SAC-Flow](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/sac_flow.html)

**判断。** 它可从“工程参考”上调为训练运行时的第一验证候选，理由是数据、真机 worker、VLA 和在线学习接口覆盖较齐。必须在 P0 完成最小适配与 replay/loss 测试才锁定；组织与 RPent 相同不是 API 已接通的证据。无需为单台机器人先搭满多机集群。

## 3. LeRobot 0.6：轻量备选与数据生态

官方 0.6 发布新增 rollout 的 DAgger 策略、reward API、数据注释等；RL 栈把 `gaussian_actor` 与 `sac` 算法分开。这适合复用机器人接入、数据与小规模 actor/learner，但不是所有 VLA 都已兼容所有 RL 算法。[官方发布](https://huggingface.co/blog/lerobot-release-v060)、[release](https://github.com/huggingface/lerobot/releases)

本次确实读到 `RLAlgorithm.update(batch_iterator)` 和 `OnlineOfflineMixer` 源码，而非只读功能表。后者混合的是**真实 transition**，没有替未执行标签生成后果。未执行 Harness 标签仍应走独立 BC 采样器。`online_ratio=0` 时当前 mixer 仍至少取一个 online 样本，不能未经测试把它当纯离线 warmup。[算法接口](https://github.com/huggingface/lerobot/blob/main/src/lerobot/rl/algorithms/base.py)、[mixer 源码](https://github.com/huggingface/lerobot/blob/main/src/lerobot/rl/data_sources/data_mixer.py)

HIL-SERL 例子把全部真实转移放 online，把干预转移另放 offline；这支持“纠正长期保留”的思路，却没有证明默认 SAC loss 自带显式 BC，也没有证明记录字段覆盖 C/E/D。[例子源码](https://github.com/huggingface/lerobot/blob/main/examples/tutorial/rl/hilserl_example.py)、[官方真机流程](https://github.com/huggingface/lerobot/blob/main/docs/source/hilserl.mdx)

**PR 审核发现。** Issue #3076 是路线讨论，不能视为完成清单。QC-FQL #1818 当前页面是 **Draft**，测试说明是仿真；该 issue 将 ConRFT 指向 #1823，但实际 #1823 是视频编码 PR，引用不吻合。因此不据此宣称官方 ConRFT 已合并。需要实际分支、文件与测试证明。[讨论](https://github.com/huggingface/lerobot/issues/3076)、[QC-FQL Draft](https://github.com/huggingface/lerobot/pull/1818)、[实际 #1823](https://github.com/huggingface/lerobot/pull/1823)

**判断。** 如果 RLinf 的依赖／适配成本超过单机收益，可选 LeRobot 的 actor/learner＋数据接口，单独实现本项目 goal/queue/loss 插件。主线在 VLA 表征后接确定性完整动作头；复用 SAC 平台时须显式替换 actor／target 目标并关闭熵接口，见技术契约 T36，不默认沿用 Gaussian actor，也不回到 ACT。

## 4. verl-vla：不能遗漏的新直接 VLA RL 对照

ByteDance 的开源项目把模型适配、工作流、trainer 与 TrainCluster 分开，提供 Pi0.5 的 TD3+BC、DSRL、RECAP 及 FPO 等入口，根许可 Apache-2.0。v0.1.0 发布为 **2026-08-19**、短提交 **4a7d8c5**；官方介绍文章页面为 9 月 9 日，不能用 URL 中日期替代发布时间。[仓库](https://github.com/verl-project/verl-vla)、[版本记录](https://github.com/verl-project/verl-vla/releases)、[官方博客](https://verl-project.github.io/posts/2026-09-02-verl-vla-v0-1-0/)

当前 README 已列 Piper 采集、任意长度干预轨迹；博客仍把进一步实体训练作为发展方向。合理结论是**已有 Piper 接入／采集，不等于有受验证 Piper VLA RL 配方**。RL 参考实验主要在 LIBERO／Isaac Lab-Arena。没有因旧博客一句话把当前代码降为“完全不支持实体”。

最贴合的官方 recipe 直接更新 π₀.₅，而不是 DSRL latent actor。示例在 LIBERO 抓碗任务由 32/50 到 40/50，采用 8 GPU、32 并行仿真环境；actor 有 BC，critic 有 CQL。它证明存在可检查的原生 VLA 更新路线，**不证明少量成功示范、零成功起点或单台真机同样高效**。[完整 recipe](https://verl-vla.readthedocs.io/en/latest/reinforcement-learning/td3-bc/pi05/libero-spatial.html)

HF 初始模型卡记录训练 100 步，但数据池有 432 episodes；“undertrained”不等于“只有几条示范”。权重许可证标 `other`，继承底模约束，不因框架 Apache 就自动相同。本次页面月下载显示 36，仅反映该模型仓库的统计。[模型卡](https://huggingface.co/Miical/pi05-libero-spatial-sft-step-100)

**判断。** 将它加入原生动作头直接训练的工程对照，不能只比较旧 JAX ConRFT 与自定义头。当前仍缺本文共享目标、真实队列 TD、语义纠正资格和实体同配置验证；也没有依据承诺用户需要 8 卡，那个数字仅属于上游示例。

## 5. Open-RAIL：动作执行组件候选

中国移动具身团队的 Open-RAIL 面向异步推理、设备适配、动作处理和 LeRobot 记录。它与 OpenRAL 是不同项目，名称还容易误搜到铁路软件。它可减少设备／模型通信开发，却不是 RL learner，也不是语义观察纠正 Harness。[官方项目](https://cmcc-tao.github.io/open-rail/)、[仓库](https://github.com/CMCC-TAO/open-rail)

当前 `pyproject.toml` 可读源码含更名 TODO，动态版本指向 `vla_rail.__version__`，注释指出对应包缺失会阻断安装。这是静态集成风险，**未实际安装确认**，不夸大为整个项目不可运行。对我们更关键的是任何平滑、插值、chunk 拼接必须在记录动作和 Bellman 定义中可见，不能接入一个黑盒 smoother 后继续沿用原动作。[配置源码](https://github.com/CMCC-TAO/open-rail/blob/main/pyproject.toml)、[README](https://github.com/CMCC-TAO/open-rail/blob/main/README.md)

## 7. 开源与影响力：本次实际能确认什么

LeRobot 有 HF 官方维护、论文和大规模机器人／数据生态；RLinf 有系统论文、具身论文及多种真机入口；verl-vla 有 ByteDance 官方文档、独立仓库和可复现仿真配方。这些提高维护与实现可达性的可信度，**不是用户机器人成功率或第三方复现次数**。

## 9. 对设计的具体建议

1. 将训练运行时明确为 **RLinf 首先验证、LeRobot 轻量备选**，方法与平台分别验收；保留单一实体 Gateway，避免 RPent 和平台 env 同时直写机器人。
2. 原生动作头实验增加 **verl-vla Pi0.5 TD3+BC**，异步原生／编辑方案再与 Real-Time EXPO-FT 对比，避免只在旧 ConRFT 与新建头间二选一。
3. 每个复用组件先验 action/goal/时间/数据/loss 语义；当前软件功能矩阵不能代替该测试。
4. 将这些比较移到独立调研报告。技术方案只保留最终组件职责、首版主线、候选切换门槛和实现流程。


## 10. 补充：固定源码与默认 target 的实际差别

通过提交页及固定 blob 页核到以下完整 SHA：RLinf `7b3d874945454acfd0785c7c4837a0ad795c391d`；LeRobot `fbb811fca92504439792b97d216f0d00c2268382`；verl-vla `c1de826c7c9256e4d9b6900091e4b0e243d16f5e`；Open-RAIL `64650ecab2e8f7c3d20bcc1689cc9ddd160b1696`。它们是此次选定文件的核查锚点，不是完整依赖锁。

RLinf 的 `fsdp_sac_policy_worker.py` 创建 replay/demo 两池，并从真实轨迹抽取 intervention 片段入 demo。读到的 `forward_critic` 中，DSRL 分支使用与 chunk 数相关的折扣及首列 reward；其他分支使用 `rewards.sum` 和一次 discount。这是其特定环境步定义，不能直接解释成本项目逐微步折扣的 queue-MDP。采用 RLinf 必须替换／扩展 target、goal/queue schema 和 BC 标签采样，而不是只修改 YAML。[固定 worker](https://github.com/RLinf/RLinf/blob/7b3d874945454acfd0785c7c4837a0ad795c391d/rlinf/workers/actor/fsdp_sac_policy_worker.py)

verl-vla 的 `sac_ray_trainer.py` 读到按 episode 收集、first-done 有效性、offline prefill 与子步 reward 求和；这提供真实的训练器骨架，但不默认等于本项目有设备接管和队列提交的因果窗口。采用其原生头路线必须另核相应 worker loss 与环境时间单位，不能仅凭 trainer 名称完成兼容性声明。[固定 trainer](https://github.com/verl-project/verl-vla/blob/c1de826c7c9256e4d9b6900091e4b0e243d16f5e/src/verl_vla/trainer/sac/sac_ray_trainer.py)

LeRobot 的上述接口和 mixer 对应 [固定算法接口](https://github.com/huggingface/lerobot/blob/fbb811fca92504439792b97d216f0d00c2268382/src/lerobot/rl/algorithms/base.py)、[固定 mixer](https://github.com/huggingface/lerobot/blob/fbb811fca92504439792b97d216f0d00c2268382/src/lerobot/rl/data_sources/data_mixer.py)。Open-RAIL 的静态安装线索对应 [固定 pyproject](https://github.com/CMCC-TAO/open-rail/blob/64650ecab2e8f7c3d20bcc1689cc9ddd160b1696/pyproject.toml)。四者各自能替换多少工程由接口预检决定，不按品牌适配或仓库热度直接排序。


## 11. 审查补漏：同平台已有十示范弱起点 RECAP

官方另有 LIBERO-10 task 8 的 π₀.₅ RECAP 配方，初始仅十条示范、4,033 帧，三轮各收集 32 条 autonomous rollout，累计 106 条。作者给出的初始评测为 8/50，最好 checkpoint 为 23/50；同最终数据池普通 SFT 对照最好 6/50。它提供更贴合低数据启动的开放参照，纠正“该平台只能从数百示范开始”的潜在误读。[官方配方](https://verl-vla.readthedocs.io/en/latest/reinforcement-learning/recap/pi05/libero10-task8.html)

局限同时记录：参考拓扑 8 张 policy GPU＋2 张 value GPU，16 个并行仿真环境；训练过程中多次停止、续跑并评估挑选 checkpoint，文档明确一次连续启动未必复现该数值，且中间轮次有显著退化。初始示范强制 positive，最终公开数据的 indicator 用最终 value 模型重算，不能当作每轮历史标签。应按数据与标签 lineage 复现，而非以 best-of-run 数字宣称无人稳定提升。
