## 1. 先列技术点

- 同一 θ 的双目标 BC＋RL；goal 必须进入 actor、Q、target、标签与奖励。
- 弱 base 下完整头、原生头、RT-EXPO 的动作覆盖与启动条件。
- request／commit／activate 分离；C 是状态，U 是下一槽决策。
- 一槽回报与 γ 的时间单位；提前 terminal、迟到评分和接管删失。
- 真实 TD、可信 BC、物理执行及 Q 动作梯度四种资格分离。
- 平台 SAC 默认 loss 与拟议确定性 Q＋BC 的差别。
- 本体和模块可替换优先；既有厂商适配只影响部署成本。

3. [RT-EXPO v1，§VII-C/E](https://arxiv.org/html/2609.18207v1)及[固定实现 803381f](https://github.com/pd-perry/expo-ft/blob/803381fc3b4c91a0c47904f1b688fc5e35904f50/expo_ft/agents/alg/realtime_expo_ft.py)：`sample_actions` 用当前观测编辑缓存延迟窗口；真机 base 用成功 episode 做 RTC-BC，仿真不限成功。

## 3. 问题、反例与定位回答

**Q1：物体在 B 时，正向成功价值会不会被反向目标复用？** 技术01 §5（90–109）、技术02 T17/T18：规范 goal 贯穿 Q/target/replay；换向结束旧 episode、刷新队列，同一 checkpoint 双向发布。不跨目标 bootstrap，未用固定 reset 冒充反向 RL。通过。

**Q2：零成功能否推出必须重学完整头，或完整头必然启动？** 技术01 §9、§10.2（223–277）：均未如此推断；先做原生／完整头 BC 与编辑覆盖检查。总报告 §4.3 亦纳入十示范 RECAP。通过；动作自由度不能证明冷启动优势。

**Q3：既然 RT-EXPO 有异步代码，能否直接复用其 replay 配本文 target？** 技术06 §11（329–337）、总报告 §4.2：不能。快编辑读取的决策信息和生效时间不同；已要求各自协议推导与独立训练视图。源码也确认其当前观测路径，未将完整头预设为赢家。通过。

**Q4：U 尚未物理执行，为何能配当前 C 的奖励？** 技术06 §2–3（65–148）：真实 admission 选出 U，正常 commit 产生 `X_next.C=U`；当前 R 来自 C，U 的影响通过下一状态传播。回报覆盖 t…t+n−1，next 为 t+n，折扣 γⁿ，三者一致。不能另挪下一槽奖励而保留原 next。通过。

**Q5：C 在第3步成功，U 还没返回，是否只能丢失正奖励或补假动作？** 技术06 §5.1–5.2（194–219）：保留同一冻结请求的原结果，配真实 `R_L`、无 bootstrap；结果无法取得则只存事实。影子建议不能事后获得 admission。前驱维持原一步目标，经 terminal critic 传播，不按未来成功选择性回填。通过。

**Q6：取消激活的 terminal 行不更新 actor，是否仍与原状态分布等价？** 技术06 第211行明确否认，指出存活条件采样偏差，要求按目标／状态类报告筛除比例。critic 保留 terminal。接受此已披露的工程选择，效果待消融。

**Q7：先超时或改写 C，后来成功；或评分晚到，能否追认为正常 terminal？** 技术06 §5.3（223–231）：按实际事件顺序裁定，前者不得追认。迟到核验保留真实 commit；终局时间取充分证据成立时刻，不回溯到首次接触。不能定位帧则 pending。通过。

**Q8：下一槽被抢占，是否应删除所有前驱，或把它们设 done=1？** 技术06 §6.2及例5（247–257、304–306）：仅隔离破坏契约或边界无法确定的窗口；准确前驱保留其 next queue。删失不置零价值，不把救援成功送给被取消候选。技术01 第247行另要求可恢复范围内独立尝试，并承认失败覆盖不足。通过；隔离本身不保证消除选择偏差。

**Q9：未执行建议是否被丢弃，失败是否一律不准 BC／TD？** 技术01 §9–10.3、技术06 §4.2：建议长期保存，可信标签单独 BC；不能配他者后继。失败可做真实 TD，也可包含正确监督片段；接管本身不授予专家质量或失败负奖。平台专项 §3 亦要求纯标签独立采样。通过。

**Q10：Harness 每步看新图得到的 n 个动作，能否拼成旧 X 的完整 chunk？** 技术06 §4.3（182–190）、技术02 T32：不能；要建立新的决策点或相容监督分支。孤立标签不重复填 n 步；flow 部分标签还须处理加噪输入和 token 交互。DIDA 被列为另行验证的特权监督，而非一概禁用事后数据。通过。

**Q11：Q 梯度能否沿当前预测的 C/D 或被隐藏裁剪的动作回传？** 技术06 §4.1（154–163）、技术02 T03/T13/T14：Q 使用真实 C，动作梯度只经 E；BC mask 单独定义。学习边界前投影须纳入动作与优化路径，保护性不可微改写另审资格；测量位移不倒填命令。通过。

**Q12：复用 RLinf／LeRobot 会不会实际训练 SAC，却仍声称实现确定性公式？** 技术01 第227–233行、技术02 第395行、平台专项 §10：已要求修改 actor 类型、target、标签采样，明确排除默认 logπ、温度及 entropy backup，禁止假概率适配签名。与独立源码发现一致；T36 是待执行验收，当前未宣称只改 YAML 即可。通过。
