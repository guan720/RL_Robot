# RL 与 Harness 扩展调研：范围与检索地图

开始日期：2026-09-23。任务是复查可用基线与联合兼容性，普通研究；科学家知识库只读。当前技术方案是比较锚点，不是预设获胜者。本次重新开展独立审查，前次三轮通过不能抵充本次。

## 先统一两个方向的技术问题

**RL 方向。** 比较对象应分为优化算法、动作参数化、数据入口和训练运行时。SAC/TD3/离线到在线方法关注真实交互与 replay；PPO 等依赖行为分布与概率；flow/diffusion 的密度、latent steering、残差与完整动作更新分别有额外假设。BC/DAgger 解决可用动作标签的持续吸收，demo buffer 的存在不等于显式 BC。异步采集训练、推理执行重叠、真实延迟 Bellman 又是不同问题。正反共享模型必须把 goal 贯通全部学习与评价接口。

**Harness 方向。** 比较对象包括认知编排、动作工具和机器人适配、持续观察/成功评价、纠正/恢复、程序与记忆演化、事实记录/数据回流、评测发布/故障处置。高层工具组合成功、冻结 VLA 表现提升、参数学习和长期无人训练分别求证；MCP/Agent SDK 本身不是具有机器人物理闭环的完整基线。

## 固定用户条件与必要兼容性

松灵 ALOHA 类双臂平台，首任务单臂 A↔B 抓放，另一臂保持；少量遥操作示范/SFT 可用，基础成功率偏低、包括零；使用 VLA，不以 ACT 为方案；算力未定。正反共享同一参数 θ，两方向均 RL；GPT-6 驱动 Harness 替代日常人工观察、评分、DAgger 式纠正与恢复。保留可信 BC＋在线 RL，真实异步 action chunk 只执行其中有效部分。允许按可行性保留表征、重学完整头或更新原生头，不预设强专家。

## 框架族枚举与检索计划

以下是待查线索，不是已证实的可用性或推荐排序。

## 取舍与审查规则

先宽搜去重，再深审有希望改变选型的候选；同时给主线、可运行工程对照与机制参考，不能把比较不同层级的项目压成一个虚假总分。新、热门、机构强不自动取代当前实现；方法更贴合也不自动证明改造最少。

研究报告承担路线教学、候选比较与来源审计；技术方案保留最终设计、接口和实现流程。改动有证据和迁移说明，未改变的结论也给出理由。

每轮至少三名新独立审查员，先枚举技术点并重新学习 primary，再提出反例问题；任何必要缺陷使连续通过归零，修正后重新冻结。最终技术方案与调研结论在相同版本上连续三轮无必要问题才能提交。允许明确且可判定的后续实测门槛，不把未定义方法伪装成待测。开放领域无法证明绝对无遗漏，覆盖及未解决证据缺口明确记录。

## 用户补充的选型尺度

AgileX 适配不是核心标准。优先比较通用接口、跨本体边界、RL 与 Harness 兼容性、开放实现完整度及复现证据；设备适配仅估算首次部署成本。通用性指可替换组件且契约成立，不代表免标定、免重训或直接迁移同一权重。
