日期：2026-09-22。审查对象：[主方案 01](../01_RL_Harness真机自主学习技术方案.md) 第 0–16 节，以及 [开发附录 02](../02_接口契约与开发验收.md)。本次只读这两份文件；没有运行软件、测试、训练或机器人。以下是设计审查发现，不是已运行实现的缺陷报告。主代理正在修订 EXPO 优先预检的条件，该已知变化不计入本次问题。

**总体判断：两文在动作因果配对、长期数据、教师与学生成绩分离、正反目标边界上已经一致；可作为研发方案。进入自动真机试验前，仍应补齐候选试验执行状态与所有运动状态的共同故障路径。资源降级、下一任务起态和标签撤销后的模型处置也需要更明确。没有发现文本规定每次候选都必须由人批准，但“审核/验证”的自动化主体尚需明示，以免实施时补出隐藏的人工审批。**

## 严重：实施前必须消除的状态机歧义

### S1. 当前图只为 POLICY 明示了可抢占故障路径

位置：主文 §7.1，图中 `POLICY→QUIESCE`、`TEACHER→POLICY/VERIFY`、`RECOVER→READY`；附录 §4、§8。

主文正文与附录已经规定 Gateway 独占、停止确认和本地看门狗，但图没有说明教师、恢复、候选试验以及为核验主动移动相机/机械臂时也能立即被抢占。若照状态图逐项实现，可能只在学生推理中检查故障，而教师或恢复工具持有 owner 长时间执行。

**建议修复：**在图外增加共同不变量：“任何拥有运动控制权的状态，都可被本地保护/观测失效/owner 超时抢占，统一进入 QUIESCE；不能确认安全保持时 HALTED。”图内至少补 `TEACHER/RECOVER/TRIAL→QUIESCE`。`VERIFY` 通常不拥有运动权；需要观察动作时走受限、可抢占的观察子过程，而不是 verifier 自行调用驱动。

**验收：**分别在教师抓取中、恢复携物中、观察动作中、候选试验中注入 owner 失联及旧队列迟到；确认执行同一 Gateway 停止协议，停止预算不因来源变化而失效。教师/恢复过程中发生任务失败时，也必须有进入 VERIFY、RECOVER 或 HALTED 的明确出口，不能停在状态机无出边状态。

### S2. 候选“验证后执行”与“验证包含真机执行”缺少独立阶段

位置：主文 §7.1 的 `CANDIDATE→TEACHER: 验证后受限执行`；§9.2 的“受限真实试验→回归→发布”；附录 §5.1 教师资格、§7.2 发布流程。

不是原理矛盾，但目前存在接口上的循环依赖：只有已验证/已发布教师可以执行；验证新代码又需要先执行它。开发者可能选择每次请人放行，或者反过来直接把未经发布的新程序授予普通教师资格，两者都偏离目标。

**建议修复：**增加明确的候选试验通道：

```text
CANDIDATE（仅离线生成/检查）
→ TRIAL_READY（满足预先冻结的自动试验规则）
→ TRIAL（唯一 Gateway 发受限候选租约并记录全部动作）
→ TRIAL_VERIFY（固定外部判据）
→ REGRESSION
→ PUBLISHED_TEACHER 或 REJECTED
```

自动规则至少检查：可用且已验证的原语集合、当前起态、动作范围、时间/次数预算、停止路径、日志与 verifier 健康。候选程序不能自行授予试验权限、修改规则或自判成功。新低层原语、未知可达范围或预算外情况不进入自动试验；记录能力缺口并中断相应流程。

**无需把域内每次 TRIAL 加上人工批准。** 前期建立规则与验证原语计为研发人工；自主窗口内满足这些机器可判条件即可自动进入试验。独立人工审计若只是离线研究，不应放进每次晋级的同步路径；若实际上必须等人核验，真实记为该发布环节尚未自主。

**验收：**一个域内候选在没有人工点击的情况下走完试验、核验、回归、发布；一个越界候选被自动拒绝且不获得 motion owner；试验失败只污染候选区，不能因 `teacher=true` 自动被纳入高权重 BC 数据。

## 重要：应明确后再进入持续自主窗口

### I1. 将任务运行、学习、代码改进的可用状态分开

位置：主文 §7.1、§8.1 unknown、§11.4、§15；附录 §2 职责表、T08/T16 和 §8 最后两段。

现文说明学习异步、阻断范围需匹配，但仍以一个 HALTED 描述许多情况。训练 OOM、云诊断不可用、奖励积压、原始记录写失败和传感器失效对运动的影响不同。全部停机会不必要地降低自主采样；全部继续则可能产生失控或不可学习数据。

**建议增加三个正交状态：**`rollout_status`、`learning_status`、`evolution_status`，以及以下降级表：

| 故障 | 当前任务/采集 | 学习/发布 | 恢复条件 |
|---|---|---|---|
| 仅 learner OOM/训练作业失败 | 已部署策略及其独立推理资源健康时，可继续当前任务与有界采集 | 暂停该训练作业，不切候选 | 资源回收、固定数据视图和续训状态检查通过 |
| 云端 Agent 不可用 | 已发布本地技能覆盖当前状态时继续；未知失败无法在预算内解决则本地保持/停止 | 已有合法数据可训练；新代码演化暂停 | API 恢复且迟到结果重新核时效；不直接恢复旧计划 |
| dense reward 服务不可用 | 事实记录与任务核验正常时可继续有界采集 | 等待标签或显式新建仅稀疏训练视图；不能逐条把 pending 变零 | 标签积压处理或切换视图完成 |
| 原始记录磁盘接近上限 | 到达预设高水位后停止接新任务，按本地协议收尾 | 可从已有固定数据训练；禁止声称新数据完整 | 持久存储恢复并对账；不可悄悄删除保护示范 |
| 传感器、Gateway 或控制停止能力异常 | 停止自主运动；当前尝试记中断 | 已冻结合法旧数据可继续离线训练，但不发布到故障实体 | 工位重新 PREFLIGHT |

资源故障可能联动：训练 OOM 若使同卡推理超时，必须升级为 rollout 故障。保持状态也应有已验证时限，不能无限持物等 API。逻辑暂停不等于安全姿态已经成立。

**验收：**分别杀 learner、断 cloud、积压 reward、填满日志配额并观察各环节状态；证明系统不会用一个故障触发不相干的模型替换，也不会在日志不可用时无限运动。

### I2. 成功、可交接起态和目标切换必须是三个独立条件

位置：主文 §7.1 `VERIFY→READY: 成功后切换目标`、§7.3、§12；附录 §6.2、T11。

正文已经明确从实物状态路由，也已说明异常恢复不等于反向任务；因此不是在批评它机械交替。需要补的是可执行守卫：**前一任务的成功集合，不必完全等于下一方向的合法起态集合。** 对象虽在 A 区，但夹爪未清空、腕部挡住观测、对象姿态不可抓，可能仍不能启动 A→B。反向 B→A 失败后停在中途，更不能默认回到 A→B 起点。

**建议修复：**将换向写成“当前目标独立核验成功→结束当前 episode→重新观察→满足下一方向 init-set→新 episode”。不满足则进入状态路由，不强行换向。init-set 至少包含对象身份/稳定姿态/可达可见、夹爪状态、机械臂可启动状态；不只检查物体中心落在哪个区域。反向失败可能同目标续做、重新执行反向、异常恢复或中断，各自保留原因。

**验收：**反向执行时把物体停在手中、掉在 A 边界、落入异常区；确认不会自动给正向发布 READY。再测试对象已释放入 A 但机器人尚挡住物体的情况，确保先完成合法交接而非直接启新策略。

### I3. 撤销错标签不能撤销已经训练进模型的影响

位置：主文 §8.3、§11.4、§15；附录 §6.1、§6.4、§7.1、T12/T17。

两文已有不可变标签与固定数据视图，足以定位错误来源。但当前只写重标/新视图，缺少“哪些已训练/已发布模型受影响”的处置。删除一条假成功或修正 reward 不会让已发布策略自动忘掉它。

**建议修复：**标签/奖励规则撤销触发依赖查询：找到使用该视图的训练作业、候选 checkpoint、已发布包。未发布候选先隔离；已发布包依据错误范围暂停自动晋升，必要时回到最近未受影响且兼容的版本，并在修正视图上重新训练或独立复核。系统必须记录处置决定，不能直接把模型标回干净。回滚后仍需重新核实真实场景。

**验收：**注入一条已用于训练且后来确认是假成功的数据；系统应能列出受影响候选/线上版本，阻止它们凭旧成绩再次发布。若影响不可界定，保守暂停发布而不是继续自举。

### I4. 被物理部分执行的一步，不能只用整数 chunk 长度表达

位置：附录 §4.3 T3 的“第 7 步完成/未执行/未知”，主文 §11.3。

附录正确地强调在途回执决定长度，但还有一个已知情况：第 7 个持续控制命令已应用，随后被停止/保持命令在其时窗内打断。此时不是“未执行”，也不一定是原定义的一个完整低层步，更不能因结果可观测就塞进固定 `γ` 的一步。

**建议修复：**在 action 时间语义中加入 `applied_duration`/实际有效时间；声明停止/保持是环境内部固定机制，还是单独记录的控制动作。若能建立相同 action 边界与时间单位的 transition，可按实际时长处理；否则保留原始因果日志并暂不进入要求等时步的 learner。不要按实际关节运动重新猜 action。

**验收：**在一个持续命令时窗中途取消，记录驱动命令、保持事件和后继观测；验证 duration/折扣/掩码一致。训练实现不支持这种时间语义时，明确隔离而不是四舍五入成完整步。

### I5. 自动教师“真正可学”的条件，建议落成一个门禁表

位置：主文 §5.2、§6.2、§9.4、§13 P2/P3；附录 §3.1、§5.2、§6.5。

现有论述完整，但分散在多节；开发团队容易只验“教师能做成”。建议将资格分成四个不同判定，避免把单个 `teacher_quality=high` 当全通行证：

1. **执行能力：**教师在学生实际失败状态上能提供有效纠正，不只是整齐初态演示。
2. **监督可表示：**动作标签与学生部署 action 层一致；有效长度完整，映射有证据。
3. **信息可获得：**教师的关键决策可由学生的图像/历史/状态辨识，或已补足观测；特权观测带来的不可辨识能力不能靠 BC 保证迁移。
4. **独立迁移有效：**在冻结留出场景撤掉教师后，相关失败确有减少；此前只能称“可供监督的候选数据”，不能声称学生已掌握。

未执行的查询标签可以通过前 2/3 类质量检查进入 actor 辅助学习，不要求先执行每一条才能使用；但验证教师在相关状态分布的有效性仍需要外部证据。以上门禁不改变“可信 shadow label 可以训练 base”的结论。

**验收：**选一个教师依赖学生看不见目标的反例，确认系统不会把 teacher-only 成功解释为训练配置没调好；提供补观测/限制适用域/保留系统依赖三种明确处置。

## 可选：提高阅读和开发对齐效率

### O1. 给暂停/停止/终止/截断加一张术语表

主文各节已经分别解释，但同一“停止”可能指硬件保持、当前任务中断、学习暂停或整个实验结束。将 `quiesce`、`HALTED`、`terminated`、`truncated`、`learning_paused` 并列，能减少跨团队误解。尤其 `terminated` 是 RL 目标边界，不等于电机关闭。

### O2. 用状态路由守卫代替一张越来越大的图

主文保留简图，开发附录增加“哪些状态能发动作/如何结束/全局故障路径”的小表即可，不必把 learner、reward worker、代码发布都塞入同一 Mermaid 状态图。这也自然支持 I1 的正交暂停。

### O3. 试验预算、发布阈值和统计规则放到一个冻结 manifest

两文都正确地不编造通用 Hz、停止毫秒或成功百分比。建议在 P0/P2 交付清单中列明必须实测并填入的参数名与责任人，防止“待定”进入实际自主窗口。包括停止/保持时间、观测新鲜度、日志高水位、各状态超时、教师调用预算、未知处理预算、每版评测试次与置信规则。

## 已通过的关键一致性检查

- **未偷偷要求永久强基础策略。** 允许少量 SFT 后低成功甚至零，同时承认必须有有效动作、示范或课程来启动学习；不保证无限失败自动产生能力。
- **学习 action 边界已修正。** 两文均明确 proposed、采纳命令、driver command、实测运动四层，不把测得运动当标签。
- **长期数据与 shadow 标签没有被误删。** 真实遥操/教师轨迹可长期用于 off-policy；未执行 `(s,a)` 可长期用于 actor 辅助训练，不能伪造 TD 后果。
- **系统能力与学生能力分离。** 固定 VLA＋Harness、纠正聚合、RL 三项对照，以及 teacher-only 参考，能发现“教师变强但学生没变”。
- **奖励与成功布尔分离。** 不允许 dense reward>0 自动切目标；pending、unknown、版本化与独立假阳性审计都有明确约束。
- **没有必需的人类逐次审批条款。** 主要缺口是候选自动试验的权责与状态尚未形式化，而不是用户还需新增授权。域外未知物理条件中断属于能力边界，应如实计入人工依赖。

修复 S1/S2 并落实 I1–I4 后，方案可以更清楚地进入 mock/回放与工位预检阶段；是否能够无人工持续学习，仍由教师覆盖、评分真值、实机可恢复性和学生独立提升的实测结果决定。
