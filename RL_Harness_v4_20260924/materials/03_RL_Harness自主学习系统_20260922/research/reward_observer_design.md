# 自动奖励、成功判定与失败观察员：技术评估和接口设计

日期：2026-09-22。研究范围为单臂 pick-and-place、少量成功示范、基础策略成功率偏低（包括零）、正反持续练习。本文为方案设计及原始来源审查，未加载模型、测时延、训练或运行机器人。GPT6 是用户提出的多模态候选观察员，其具体感知、时延与校准能力在本任务上均未验证；本文不依据型号名称推定其能可靠打分或生成可执行恢复。

## 1. 明确结论

**建议采用三层结构：任务几何与时序成功核验＋冻结的本地奖励模型＋异步大模型诊断/恢复提案。** 不把大模型每次自由输出的分数直接当在线 RL 的唯一目标，也不让它自行重写验收条件。

三层分工是：

1. 控制与任务核验层：根据真实传感器和固定任务合同检查目标物、目标区域、释放、稳定性、可达状态与控制器边界；输出通过、未通过或不确定。
2. 奖励观察层：本地冻结模型阅读时间窗口，提供进度、成功候选和失败线索；结果按版本异步写入回放。先验证 Robometer，再保留更轻的任务专用分类器作为对照。
3. 诊断层：GPT6 候选观察员按事件读取短视频、多视角、动作历史和结构化状态，解释失败并提议下一合法子目标或已有恢复技能。它不拥有直接电机控制、修改安全边界、修改任务合同、把未知强制改成成功的权限。

这是本项目拟议组合，不是某篇论文已经验证的完整系统。它可以复用 ConRFT 或 EXPO-FT 的数据更新链，也可以支持后续批量改进；奖励模块的效果不能替代学习器本身的验证。

## 2. 最贴近的两项原始工作

### Robometer：优先预检的通用奖励观察器

Robometer 结合帧进度、成功预测与轨迹间比较，作者团队包括 USC、UW、MIT、UT Dallas、Ai2、NVIDIA 等。原论文确实有真实 DROID/Franka 上 DSRL＋冻结 π0 的在线学习；**自动的是奖励、成功与阶段推进，实体场景仍由人复位**。论文通过异步回放重标避免逐步等待奖励推理，但没有由此证明任何用户硬件上的控制频率 SLA。[原论文](https://arxiv.org/html/2603.02115v1)

这一工作也提供了直接的误判案例：把目标物放在容器旁、操纵非目标物，都可能被奖励器错认为完成。在其在线样本统计中 RoboReward 的真阳性/假阳性为 6/45，Robometer 为 18/0；这是作者该批样本结果，不代表 Robometer 在新场景不会误报。[在线实验附录](https://arxiv.org/html/2603.02115v1#A5.SS2)

可用资产与边界：

- [Robometer-4B 权重](https://huggingface.co/robometer/Robometer-4B)公开，模型卡标 Apache-2.0，支持帧进度、帧成功及轨迹比较。2026-09-22 页面显示近月下载 1921 次；下载量不是机器人闭环复现次数。
- [奖励仓库](https://github.com/robometer/robometer)有训练、微调和推理入口。本轮根目录 LICENSE 原文仍未成功取到，不能用模型权重许可替代代码许可；既有 README MIT 标识与许可正文缺口应区分。
- [policy-learning 仓](https://github.com/robometer/robometer-policy-learning)的 [MIT LICENSE](https://raw.githubusercontent.com/robometer/robometer-policy-learning/main/LICENSE)已核验，包含真实机器人和异步奖励重标路线。
- [真机 README](https://raw.githubusercontent.com/robometer/robometer-policy-learning/main/docs/REAL_ROBOT_README.md)仍暴露人工开始、成功/失败按键及超时标注流程。论文实验的自动设置与仓库默认人工控制入口不完全相同，接入时必须核对哪层最终写 reward/done，不能只替换模型服务。
- 未实测本机单窗推理时间、p95/p99 延迟、吞吐或显存；不能把论文“异步”换算成无延迟。

对本任务的判断：优先作为**待校准的进度观察器和成功候选产生器**。不直接复制论文的成功概率阈值，不让一个模型概率独自证明“物体已释放且稳定”。

### RoboReward：终局评分对照，不能直接等同于连续控制奖励

RoboReward 由 Stanford/Berkeley 等研究者提出，用视频与任务文字输出终局 1–5 档进度。真实 WidowX 实验使用 DSRL 和 diffusion policy；所以它证明的是自动奖励可帮助真机 RL，不能转述成该实验已验证原生 π0.5 在线更新。论文也保留人类奖励对照，并明确前沿 VLM 会把仍悬在目标上方的物体误判为完成，或遗漏实际成功。[原论文](https://arxiv.org/html/2601.00675v1)

[8B 模型卡](https://huggingface.co/teetone/RoboReward-8B)和 [数据集](https://huggingface.co/datasets/teetone/RoboReward)可访问，模型卡许可为 CC-BY-4.0；本轮模型卡显示近月下载 516 次。模型训练数据包含自动合成/验证，评测集另有人工检查，不能称“全链条没有人工”。其原生输出定位为回合末进度，而非每个伺服周期内的平滑、校准、因果奖励。论文未提供本项目可用的物理自主复位方案，也未给本机时延保证。

对本任务的判断：可作离线评分对照或回合审查器；Robometer 更贴近时序进度与失败监控。**专用奖励模型也须在同一任务上校准，论文平均表现不能替代本机验证。** 此次不继续扩展 GRAPE 等轨迹偏好名单，因为当前决策核心是可靠终止、连续反馈和恢复路由。

## 3. 连续奖励应如何定义

首先固定方向相关的任务合同，例如 `place(object_1, region_B)`：必须是指定物体进入目标允许区域；夹爪已释放；物体在连续观察窗内保持稳定；规定的机械臂终态/下一任务可执行条件满足。区域、容差、稳定时间、允许对象和坐标版本在会话/训练轮次开始前确定。

建议分开存三个输出，而不是合并成一个任意分数：

- `task_outcome`：成功／未完成／不确定，决定是否达到目标；不确定不自动计作失败或成功。
- `potential`：有界进度势函数，辅助传播学习信号。
- `failure_state`：空抓、持物但未释放、掉落、错物体、卡住、遮挡、目标区不确定等结构化诊断，服务恢复路由，不直接等同负奖励。

若必须早期提供稀疏奖励，最小任务奖励为一次经核验完成事件；是否加入时间成本、碰撞成本，是任务目标设计的一部分，需要固定定义。安全限制主要由底层执行约束保证，不能指望负奖励阻止一次危险动作。

### Potential-based shaping 的正确边界

Ng、Harada、Russell（ICML 1999）的原始结果说明，在其 MDP 条件和一致的折扣下，添加 `F(s,s') = γ Φ(s') − Φ(s)` 可保留最优策略。它不是“任何 VLM 进度差都不会改变目标”的保证。[原始论文 Theorem 1](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)

本项目拟采用的 chunk 形式为：

```text
R_base(t,k) = Σ(i=0..k-1) γ^i · r_base(t+i)
F_v(t,k)    = λ · [γ^k · Φ_v(z_(t+k), goal) − Φ_v(z_t, goal)]
R_train    = R_base + F_v
```

其中 `k` 是实际执行的低层步数，不是原计划 chunk 长度；`γ` 是明确到这个时间尺度的折扣；`v` 固定奖励模型、预处理、阈值和任务合同版本；`z` 是时间一致的观测/状态表示。如果 learner 本身按决策步定义折扣，则需要重定义对应公式，不能再不加解释地用另一个 `γ^k`。

下面是对本项目的数学/工程推导边界，不能省略：

1. **折扣必须匹配。** 当 `γ<1` 时只用 `Φ(next)-Φ(now)`，不等同原定理形式。直接反复奖励“处于接近成功状态”，可能鼓励停留或拖延。
2. **终止边界必须闭合。** 若一个目标回合成功或真正终止后停止累积，令其吸收终态势为 0（或使用等价的明确边界修正），否则有限和残留的 `γ^T Φ(z_T)` 可能改变偏好。成功/失败终止和采集超时截断要分开；任务仍可继续的时间截断不应一概当吸收失败。
3. **正反目标变化要断开或显式建模。** `Φ(·, A→B)` 与 `Φ(·, B→A)` 不应随意跨边界相减。首版按目标回合终止/重新开始；共享持续任务则把目标和调度状态纳入状态并重新定义原始目标。
4. **奖励模型不要在同一更新周期偷偷改变。** 一批数据同时混入旧 `Φ_v` 与新 `Φ_(v+1)` 会改变训练问题。固定一轮版本；新版本离线验收后，对同一 transition 两端和所需上下文一致重标，再切换训练视图，保留原始传感器与旧标签。
5. **不要对 shaping 差值再任意剪裁或只保留正数。** 有界 `Φ` 可以控制幅度，但非线性裁剪差值会破坏望远镜相消，不能继续宣称策略不变。临时把低置信 transition 的 shaping 置零，也未必保留这个结构。
6. **部分观测与模型误差仍存在。** 经典保证建立在相应状态/MDP定义上；真实机器人短窗口可能不足以表达接触和隐藏状态。可用因果历史/信念状态做近似，但需明确近似与实测，不能将定理当作 VLM 识别正确的证明。
7. **禁止用未来帧假装当前因果势。** 对一次完整视频回看得到的评分，可能依赖之后是否成功，不能直接当时刻 t 的固定状态势。实时或离线重标都应使用约定的因果前缀；若用事后轨迹评分，另记为轨迹监督，不冒充满足上述保证的 shaping。

这也意味着：有了连续进度信号，不等于零成功策略就必然自举。若视觉奖励看不清有效抓取，或所有轨迹都没有有效关键动作，仍需示范、接管或更合适的探索/课程。

## 4. 成功核验：模型 confidence 不等于概率已可靠

首轮使用外部视角＋腕部视角（若已有）、夹爪开度/实际反馈、末端和物体轨迹联合核验。能测深度、接触或目标盘载荷时可加；未配置的传感器不虚构存在。对于桌面抓放，几何量只在相机标定、物体识别和遮挡允许的情况下可信；物体消失不能被解释为已放入目标。

至少在一组独立留出的录像上检查：

| 错误类型 | 必须包含的难例 | 为什么会伤害闭环 |
|---|---|---|
| 假成功 | 仍握持悬空、容器旁掉落、错物体、暂时经过目标 | 提前终止并给错误策略正反馈；反向策略接到非法起态 |
| 漏成功 | 遮挡后实际放好、不同姿态、光照变化 | 无谓重试、推走已放好的物体、增加复位 |
| 假进度 | 夹爪到位但空抓、只动背景、重试循环 | 不产生任务改进却持续拿 shaping |
| 失败漏检 | 夹住容器边、打滑、物体越界、状态不再可恢复 | 延迟救援，损失自主运行时间 |
| 时序错位 | 延迟帧、视角未同步、队列积压、模型回答过期 | 把上一状态判断应用到当前控制 |

应报告按关键难例分层的假成功率、成功 precision/recall、失败检测延迟、拒答率以及 p50/p95/p99 推理与端到端延迟。不要只报告平均准确率或漂亮进度曲线。

低成功率条件尤其要求关注假成功。举一个**假设算例而非模型测量**：真实成功占 1%、成功检出率 90%、失败误判成功率 1%，则发出的“成功”信号约只有 `0.01×0.9/(0.01×0.9+0.99×0.01)=47.6%` 为真。零真实成功时，任何误报都可能成为错误正样本。由此应采用严格终局核验和 `unknown/abstain`，而不是仅提高模型输出 confidence。

阈值必须在本任务留出数据标定，且与允许的误报成本相关；模型自行声称 0.99 不等于频率校准。两个相似 VLM 一致也不等于独立真值。**最终评测 ground truth 应独立于训练奖励器与生成恢复计划的模型**：首轮通过人工抽查录像或独立可核验传感器建立；后续可减少审核频率，但保留难例回归、漂移监测和随机抽查。

## 5. 异步接口与数据一致性

以下是待实现的 schema，不是现成已运行代码：

```json
{
  "transition_id": "unique-id",
  "episode_id": "episode-id",
  "goal_id": "object_1_A_to_B",
  "task_spec_version": "immutable-hash",
  "policy_version": "checkpoint-id",
  "controller_source": "policy|human|recovery_skill",
  "observation_ids": ["synchronized-frame-ids"],
  "start_time_ns": 0,
  "end_time_ns": 0,
  "planned_action_ref": "action-chunk-id",
  "executed_action_ref": "actual-prefix-id",
  "executed_steps": 0,
  "terminated": false,
  "truncated": false,
  "reward_status": "pending|validated|abstained|invalid",
  "reward_version": "model+prompt+preprocess+calibration-hash",
  "r_base": null,
  "phi_before": null,
  "phi_after": null,
  "r_shaping": null,
  "success_decision": "pass|fail|unknown",
  "failure_code": "none|empty_grasp|held_not_released|drop|occluded|stuck",
  "evidence_refs": ["image-or-sensor-record-id"],
  "independent_eval_label": null
}
```

控制进程不等待大模型；观察服务按 transition/episode ID 写回标签，learner 只读取符合当前奖励版本和有效性规则的数据。晚到结果不能直接终止已经进入下一方向的回合，更不能把恢复动作归到原策略。`pending` 不自动变成 0 奖励；可以等待合格重标后入训练队列，或采用事先定义的仅稀疏奖励训练视图，避免一个 batch 中奖励定义随服务速度变化。

每次写回必须核对任务版本、观测时间窗、相机标定版本、图像缺失、控制者、实际执行长度和目标边界。原始日志保持不可覆盖；所有重标追加版本。训练样本索引与持久化录像可分层存储，避免一直把完整图像累积在内存。

当观察器不确定：先用短暂保持、退到已验证观察位或补拍等合法行为改善观测；无法消歧则请求人。不能用“模型没回答”奖励策略，也不能在同一动作执行中等待不确定时长的网络响应。

## 6. GPT6 候选观察员怎样参与自主恢复

它应接收**事实、任务合同与可调用技能表**，输出结构化提案。例如“目标物仍夹持，目标区域可达，建议调用 carry_and_release(target_B)”；提案必须附观测证据、前置条件和停止条件。首版只允许在已验证技能集中选择/参数化：重新观察、退离、打开空夹爪、重新抓取、将已持物搬到允许区域、普通反向技能、请求人工。

允许模型生成新恢复程序时，先进入离线候选区，经接口/范围检查、录像回放或仿真验证、受监控真机测试后才纳入技能表；不能因为它解释通顺便立即在真机执行。主任务已授权的自主范围内可以自动选择已有技能，但模型不能自增动作上限、自改允许工作区或把“放到旁边”重新定义为成功。

诊断输出建议字段：`failure_hypothesis`、`evidence_refs`、`uncertainty_reason`、`proposed_skill_id`、`goal_parameters`、`preconditions`、`postconditions`、`max_attempts`、`escalation_reason`。由确定性调度器检查是否仍匹配当前实物状态和版本，再执行；恢复完成后由独立成功核验层确认。

该机制可减少人类逐次分析失败的劳动，但诊断错误、恢复技能覆盖不足、物体不可达和安全停机仍可能要求人。跨失败自行写代码再执行属于后期扩展，不能计作首版已经达到的 RSI 能力。

## 7. 最小实施与验收顺序

1. **离线观察基准：** 从已有示范/失败/接管视频建立固定任务合同和独立标注，重点采齐“似成功但未释放”等难例；对比规则、小型任务分类器、Robometer、RoboReward，GPT6 候选仅在同一视频上盲评，不提前假定谁赢。
2. **影子运行：** 观察器只记录，不影响奖励或控制；测错报、漏报、未知率、延迟和服务丢失。纠正数据用于校准/微调，不混入未标注独立测试集。
3. **先接自动成功候选与异步标签：** 终局由独立合同核验；确认实际 learner reward/done 包装链没有被人工按钮或旧 wrapper 覆盖。
4. **再加冻结版本 shaping：** 同任务、同数据/人工预算对比稀疏成功奖励与 shaping，检验成功、错误动作重复和回报钻空子；不同时更换策略、奖励器和恢复算法。
5. **最后接恢复调度：** GPT6 只提议受限技能；记录每次建议正确率、恢复成功率、重复救援数、主动人工分钟与待命分钟。收益应以实物任务和人工成本衡量，不以模型给自身的分数衡量。

保留原则：奖励模型帮助学习、观察员帮助诊断、调度器帮助持续练习；**可用性的判定和安全边界由外部固定合同维护**。连续奖励是一个可测试组件，不是“有多模态大模型就已经具备自学习”的充分条件。
