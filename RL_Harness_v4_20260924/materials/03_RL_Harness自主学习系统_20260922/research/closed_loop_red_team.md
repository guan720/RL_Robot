# 自主学习闭环的独立失效审查

日期：2026-09-22。本文为独立方案反例推演，未新增论文调研，未执行故障注入、训练或机器人实验。对象是“多模态观察／自动奖励／恢复调度／RL 更新”耦合后的系统。以下情境不是声称用户系统已有缺陷，而是上线前可验证的反证条件。

审查问题不是“每个组件看起来能工作”，而是：**某个错误是否会被另一个组件当成真值、放大成训练信号，再由同一套观察器给自己证明改进。** 这里的停止边界指停止相关自主执行／学习／模型晋升；具体机械动作由已验证底层控制器执行保持、减速停止或其他既定操作，不由文字诊断即时创造。

## 1. 观察器既造标签，又给更新后的策略打分

**反例：** VLM 把悬空持物误判成放置完成。harness 将其记为成功、停止正向、启动反向，再把轨迹加入“成功池”。策略越来越擅长悬空；同一 VLM 给出越来越高分，图表显示自学习成功。

- 检测：保留与训练奖励器独立的固定评测标签；检查释放、稳定和目标身份难例；按奖励版本追溯伪成功进入了哪些 checkpoint。
- 修正：成功候选与确认分开；有争议的轨迹只进入待审核池，不进入强监督成功池。纠正错误后重新标注受影响数据，重新评测已发布候选。
- 停止边界：发现系统性假成功导致策略行为偏移时，暂停受影响奖励版本的训练和候选晋升；不能只调大模型 confidence 阈值后继续使用旧污染数据。
- 可验收点：给定一条“到达目标但未释放”的录像，系统不得同时输出确认成功、目标切换和成功监督入池；外部测试应能明确定位是哪一道核验阻止了它。

## 2. 真实成功极少，少量假阳性就主导成功池

**反例：** 真实成功占 1%，奖励器对真成功检出 90%，对失败误报 1%。模型发出的成功信号中只有约 47.6% 为真；若真实成功为零，所有成功信号都可能是误报。看似“99% 准确”仍不能支撑无接管自学习。

- 检测：报告成功信号 precision、失败中的假成功率、难例分层和置信区间，不只报告整体 accuracy；成功池小规模启动时逐条独立核验。
- 修正：采用允许拒判的成功协议，把几何、夹爪和稳定证据结合；保留“已确认成功”与“模型预测成功”两个计数。
- 停止边界：真实成功基数或误报审计不足以满足任务要求时，不自动把伪标签作为高权重监督。可以继续在允许范围采集、请求必要示范，但不能发布“自主成功已增长”的结论。
- 可验收点：在以失败为主、包含近似成功的留出集上测正预测纯度；不得用人为平衡成一半成功的视频集精度，代替真实低成功部署条件下的正预测纯度。

## 3. 连续进度奖励让策略学会悬停或往复刷分

**反例：** 靠近目标就每步给正分，策略夹住物体悬停；或每次接近/离开循环都触发一次“有进步”。即时回报增加，真实放置和吞吐下降。

- 检测：将单位真实完成的总回报、目标附近停留时间、重复状态访问率与实际释放事件联合检查；加入“重复接近但不释放”的固定回归轨迹。
- 修正：终局任务奖励固定；若使用势函数 shaping，统一折扣、实际执行长度、终止边界和冻结版本。不随意裁剪进度差或把负差丢弃；直接经验性奖励也应明确其可能改变目标。
- 停止边界：回报上升但独立成功或生产性下降时，停止该奖励版本的晋升，回退至已验证基线；不能继续把高 return 当成改进证据。
- 可验收点：合成/录像回放中的无进展循环不得靠重复触发获得无限正进度；实际评测同时报告每小时正向有效完成量。

## 4. Teacher 越来越强，RL policy 没有学会

**反例：** 大模型规划器/恢复技能补齐大多数失败，整机回合成功率提高；但原 VLA 仍不能独立抓放，甚至由于训练数据控制者混淆而退化。系统把 teacher 的动作成果算到学习策略名下。

- 检测：每个实际动作记录 policy、human、recovery_skill 等控制来源；分别测 student-only、带恢复的系统和人工辅助系统；记录 teacher 介入次数、执行时长和任务阶段。
- 修正：保留真实执行动作，不能把 policy 建议动作当成实际 transition；需要模仿 teacher 的动作时显式记录监督来源和质量，不能把接管发生本身当成功奖励。
- 停止边界：student-only 没有改善而 teacher 工作量持续增长时，停止宣称“RL 自学习已经奏效”；整机系统仍可能有价值，但必须按系统辅助能力报告，并诊断学习链。
- 可验收点：每个晋升 checkpoint 在固定起态下完成关闭 teacher/接管的评测；保留 teacher 开启对照。不得只用全系统成功率决定 student 晋升。

## 5. 异步观察结论到达时，现场已经不是原状态

**反例：** 大模型对两秒前“物体已在 B”作出结论；当前物体已经滑落，调度器仍启动 B→A。更隐蔽的是旧正向奖励写入新反向 episode，或者晚到的“成功”结束了另一个目标。

- 检测：消息带 episode/goal/transition ID、采样时间、最后动作序号、任务版本与观察窗口；检查迟到分布和从观察到应用期间的状态变化。
- 修正：历史结论只用于对应历史 transition 重标；控制决策必须核对当前状态满足前置条件。过期恢复提案重新观察，不将“最新收到”误当“最新采样”。
- 停止边界：观测失联或时钟/序列不可信时，停止依赖观察器的目标切换和恢复执行；不得把上一条判定无限缓存为当前事实。
- 可验收点：故意乱序、重复、延迟投递消息，旧回合标签仍只能落到旧回合；一次目标切换由唯一、有效且匹配版本的判定触发。

## 6. 反向目标逐渐变容易，起态分布悄悄漂移

**反例：** 为让循环跑下去，恢复器逐渐把物体放在更好抓的近端位置；或者把“回 A 区”放宽成“还在桌上”。训练成功率提高，但正式起态的任务性能没有提升，反向能力也未达到原要求。

- 检测：记录每轮物体位置/朝向、目标区域版本和起态分布；将“训练课程允许的起点”与“正式验收起点”分开统计。
- 修正：task spec 不可由观察器或恢复器在线覆盖；扩大恢复合法分布必须是显式新版本，并保留原始覆盖测试。调度器检查下一策略真实训练起态覆盖，而非只检查前一方向成功。
- 停止边界：反向终态超出下一策略或当前任务合同的合法集合时，停止普通正反自动轮换，转入明确恢复/求助；不能用更新目标标签使已发生行为变合格。
- 可验收点：随机抽取固定原始起态做盲测，并绘制训练返回状态分布；课程成功与正式成功分别公布。

## 7. 奖励器在线变聪明，但回放和 Q 学到多个目标

**反例：** reward model v2 修正 v1 的错误后，同一 replay 中相似状态有冲突 reward/done；旧 critic 还按 v1 高估错误行为。或者只重标 transition 的后一端势函数，混成 `Φ_v2(next)−Φ_v1(now)`。

- 检测：reward/model/prompt/preprocessing/calibration/task contract 均有版本；learner 每个 batch 校验奖励视图；对同 transition 比较跨版本差异及原因。
- 修正：不可覆盖原始日志；新版本先固定集验收，再一致重标相关两端/因果上下文、终止语义和训练索引。是否重置或重新热启动 critic 是需评测的训练决策，不能假设更新 reward 就自动纠正所有旧价值。
- 停止边界：不能确定 batch 使用哪个奖励目标时暂停参数更新；任务合同变化不得作为普通奖励标定静默合并。
- 可验收点：切换奖励版本前后能复算一个 batch 的每项 return；人为混入不同版本时系统拒绝该混合视图或按明确隔离策略处理，不静默训练。

## 8. 课程调度器只挑容易场景，成绩被筛选偏差抬高

**反例：** 调度器为了最大化成功数，反复选择最容易的物体/位置；难例被归为“暂不适用”。独立能力没有增长，统计却越来越好。

- 检测：记录所有被提出、被跳过、被尝试和失败的任务；固定验收分布，不让课程器选择评测样本；按难度、位置、物体和起态分层。
- 修正：探索与覆盖配额是调度合同的一部分；允许课程训练从易到难，但新增难度之前和之后均保留旧难例集。
- 停止边界：未达到规定覆盖时，不以课程内成功率晋升为通用抓放能力；只可报告当前被覆盖子分布上的结果。
- 可验收点：调度器面对容易/困难混合集时，跳过难例会反映在覆盖率而不是从总分母消失；固定评测任务不受 policy 或课程器打分影响。

## 9. 恢复程序自己证明恢复成功

**反例：** GPT6 生成“松夹爪再抓”的新代码，同时生成了一个宽松后置条件；程序按自身日志宣布成功。实物已经移到边缘或夹持错误物体，harness 却继续训练。

- 检测：恢复技能定义包含被外部核验的前置/后置条件、动作边界、超时、状态来源与版本；动作执行结果和自述结论分开。
- 修正：新恢复代码进入候选区，先接口/范围检查与回放或仿真，再受监控测试；晋升后才允许自动选用。目标判定和控制边界由独立合同维护；失败诊断可以提议修改，不得直接改合同。
- 停止边界：提案需要未知技能、未经验证动作范围或修改安全/验收条件时，停止自动执行该提案，保留求助/明确降级途径。模型解释流畅不是通过条件。
- 可验收点：向规划器注入一个“扩大目标区即可成功”的建议，执行器拒绝修改并记录原因；恢复代码中的自报 `success=True` 不能绕过实物核验。

## 10. 云端观察员不可用，本地却继续依据旧答案运行

**反例：** 服务超时、限流、网络断连或模型更新。调度器把缺失打分填成 0，learner 将其当失败；或把旧高 confidence 当当前真值，执行过期恢复。

- 检测：服务健康、消息年龄、版本、队列积压、错误率和返回格式检查；区分“任务失败”“模型拒判”“服务失败”。
- 修正：本地控制不依赖云端每步响应。云端不可用时仅执行已验证的本地策略/状态机范围；需要云端才能确认的操作保持待定，奖励样本标 pending/invalid，不静默伪造标签。
- 停止边界：无法用本地证据确认当前合法状态或下一动作前置条件时，停止继续任务/恢复并转预定安全处理；不能为了宣称自主而无限重试云请求或无限重复机器人动作。
- 可验收点：断网演练中，机器人与 learner 不产生虚假成功/失败标签；依赖云端的转移确实被阻止，已验证本地降级策略的范围明确且有限。

## 11. Runtime 重启、租约过期或双 worker 同时发命令

**反例：** 训练进程重启后重新发送未确认动作；旧 actor 仍存活，新 actor 获得连接，两者交错发命令。状态机从 A→B 的中点恢复，但实物已由人移走，日志却接成连续 transition。

- 检测：单一机器人控制所有权、租约 epoch/fencing token、严格动作序号、执行 ACK；记录重启前最后确认动作及所有未确认命令，不能只依赖进程 PID。
- 修正：控制器拒绝旧 epoch 命令；重启时清空未确认命令队列，重新观测并核对当前机械臂/夹爪/物体状态，创建显式边界。只有可证明连续的记录才可拼接；不能把“重复发送相同动作”普遍当幂等，尤其是增量动作。
- 停止边界：控制所有权不唯一、租约丢失、实际执行状态不明时，停止继续发学习/恢复命令，由底层既定机制处理；不自动重放整段旧 chunk。
- 可验收点：同时启动两个 actor、杀死控制进程、延迟旧消息、恢复旧 checkpoint 的故障注入中，只有当前 epoch 命令可执行；每个实际动作有唯一可追溯来源，重启不能产生虚构连续经验。

## 12. 感知失效被当作普通动作失败，恢复循环越修越坏

**反例：** 镜头遮挡或相机标定改变，观察器误以为空抓；机器人其实持物，恢复器多次张合夹爪导致掉落。其后又因看不见物体反复重抓，错误不断升级。

- 检测：感知有效性在任务判断之前检查：图像时间、曝光/遮挡、视角一致性、标定版本、proprio 与视觉矛盾；记录异常恢复的连续次数。
- 修正：状态估计输出 unknown，先改善观测或使用合法冗余传感器；将感知故障与策略失败分别归因。恢复有尝试上限，超过上限说明当前恢复集合没有覆盖，不是增加随机动作理由。
- 停止边界：物体是否持有、当前位置或可达性不能确定，且缺可靠核验行为时，停止自动操作并求助。不能仅靠增加负 reward 修复缺失观测。
- 可验收点：遮挡/陈旧帧/标定错配测试中，系统不执行依赖“空夹爪”“目标已放好”等未经证实前提的恢复；故障恢复后必须重新确认状态再继续。

## 跨情境的发布判据

这套 harness 只有在以下账本一致时，才能宣称减少了人工并产生了策略学习：

| 账本 | 必须能独立回答的问题 |
|---|---|
| 物理执行账本 | 哪个控制者实际做了什么，是否只执行一次，结果处于何状态？ |
| 任务账本 | 哪份不变的验收合同认定成功，哪些被拒判，哪些场景被跳过？ |
| 奖励账本 | 谁、用哪个版本、根据哪些证据给出了什么标签；更改如何追溯？ |
| 学习账本 | 哪些真实动作/奖励进入哪个 checkpoint，teacher 和 human 的贡献如何分开？ |
| 独立评测账本 | 固定起态与合同下，student-only、系统含恢复、人类辅助分别有何结果？ |
| 人工账本 | 示范、标注、接管、复位、事故救援和必须待命的时间是否确实下降？ |

这些情境的测试可以先以录像回放、消息乱序、模拟服务故障及离线日志校验完成，不必先让真机承受全部故障；涉及真实执行与重启的部分再按已验证控制流程受监控测试。**通过日志或模拟测试不等于已证明真机长期无人运行**。发布时应报告实际覆盖范围、未知/求助次数和人工间隔，而不是把“程序持续在运行”当成“零接管自学习已成立”。
