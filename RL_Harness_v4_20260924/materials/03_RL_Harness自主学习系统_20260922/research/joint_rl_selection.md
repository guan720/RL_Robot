# 从最终自主学习系统反向选择 RL：ConRFT、EXPO-FT 与 STEAM

> **阶段性调研记录。最终联合选择以 [完整方案](../01_RL_Harness真机自主学习技术方案.md) 为准。后续 buffer 源码审计已修正 EXPO 必须频繁完整成功的限制：可信教师动作可经独立监督入口利用；部分 flow chunk 则仍需输入、噪声、注意力与损失的联合适配。**

核查日期：2026-09-22。范围：既有第 12 份调研、固定版本源码审计与必要原始来源。本文是方案设计和静态审核，未运行训练或真机。下述自动 teacher 接入、质量掩码和组合闭环均是本项目建议，不能当作原论文已经验证的结果。

条件：松灵 ALOHA 类双臂机器人，首任务只用一臂抓取并放置物体；最终学习策略采用 VLA，不考虑 ACT；可提供少量初始成功示范/SFT，初始策略成功率偏低，包括零成功率；目标是逐步用 Harness 接替日常人工评分、接管、恢复与值守。GPU 未确定，不预设必须全模型训练或必须冻结表征。

## 1. 结论：自动 teacher 的真实能力应当改变 RL 排序

**不能沿用“ConRFT 在人类接管下可行，所以加一个 Harness 就成为自主系统”的推理。** 人类接管原本同时供应可靠纠正动作、失败诊断、保护与部分复位。移除人后，这些供应必须分别由实际模块承担。接管接口能够接收脚本动作，只说明数据接口接通，不说明专家能力已经被替代。

本项目最先需要验证的不是哪种 RL 理论更强，而是：**Harness 从策略实际失败状态出发，能否产生可执行、可验证、有学习价值的纠正行为。** 由这个能力反向选择：

| 实测的 Harness 能力 | 整体首选与备选 | 为什么排序改变 |
|---|---|---|
| 只能判成败、复位和重新开始；还没有可靠纠正 primitive | 先补齐一个可验证的局部恢复/自动示范来源；保留初始 SFT 为采集策略。暂不宣称任何候选构成无人工接管闭环 | 自动复位增加尝试次数，却没有补上 HIL 的有效动作来源；三种方法都不能保证从重复失败中产生缺失技能 |
| 能从实际失败状态恢复并持续产出经验证的完整成功，且现有 π 系推理/数据/控制链可用 | **EXPO-FT 优先进入首轮 RL 对照；自动纠正 SFT 必须同步比较** | 成功数据能更新原生 VLA 的 base 分布，补上仅靠候选/局部编辑难以跳出弱初始策略的缺口；保留现有模型体系可能比重建 Octo 更省成本 |
| 能提供可信的局部纠正，完整成功仍少；确实需要摆脱旧动作附近搜索 | **ConRFT 机制更匹配，但采用按质量分流的 BC 对照；接受官方 Octo 路线或明确自研适配成本** | 完整动作头接受 Q 指导与局部动作监督，不必等整回合成功才直接利用纠正；必须解决自动 teacher 质量和混合回放 BC 污染 |
| 已有覆盖失败、恢复、成功的混合数据，允许“采集一批—训练一批”，在线学习并发成本较高 | **STEAM + CFGRL 可升为主要批次更新方案**；与纠正 SFT 同数据对照 | 最终系统不一定需要逐步在线 actor-critic；这里的数据质量归因比持续 Q 更新更关键，但评分能力与示范覆盖必须通过本任务验证 |

以上均为基于机制与工程依赖的条件判断，不是跨论文性能排名。若现有 π 链路并未实际跑通，不能因名称熟悉就默认 EXPO 工程成本更低。若已经采用 Octo/ConRFT，则相应迁移成本也会改变选择。

**当前信息不足以指定唯一、无条件的最终算法；可以明确指定第一项工作：验证自动 teacher 和数据闭环。** 这个验证只需有限的原语、固定任务与有限失败状态，不需要先建设完整通用多智能体系统。

## 2. RoboRSI 提供什么，尚未证明什么

RoboRSI 把技能组织成任务族、复合技能、原子任务和基础技能，按实际调用路径诊断、修订、验证并复用代码，轨迹也可回流到学习策略。它的公开说明同时明确：真机保留必要的安全监管与方向调整，自动 reset/结果判断在说明中明确覆盖仿真。因此，博客不能作为“真机自动接管教师已解决”的证据。[RoboRSI 官方博客](https://lab.noematrix.ai/blog/2-roborsi/)

本项目可以吸收其代码与模型双通路，但需把三个能力分开验证：

1. **恢复供给**：恢复后能继续练习，而非仅生成一份合理的程序。
2. **学习供给**：恢复过程能被记录为模型可学的观测—动作，且动作在该状态确实有效。
3. **独立验证**：结果由实际物理状态支持，不能由生成该技能的 Agent 的口头自评直接作为奖励。

代码能力与模型能力不会自动互相转化。代码把任务救回来，可以使系统可用；只有被记录、正确归因并进入有效优化目标的经验，才可能使 VLA 本身变强。

## 3. 用自动 teacher 替代人，必须先明确它教什么

### 最小可行的供给层

对于桌面抓放，建议先实现一个窄范围、可检查的恢复库：

- 从抓取失败后的可达桌面位置重新定位、抬起、调整姿态并重抓；
- 物体已抓住时重新接近目标、放下并退出；
- 在明确工作区域内把物体送回某个**覆盖训练初始分布**的位置；
- 对遮挡、检测冲突、物体出界等未覆盖情况停止本轮，不伪造恢复成功。

这些原语可以由脚本、运动规划/MPC、另一个已验证 VLA 或组合控制器提供。最终学习模型仍可保持 VLA；辅助控制器的价值在于提供补充行为和恢复条件。不能预设“LLM 会写程序”就等同于“具备可靠感知、抓取和接触控制”。

每个原语应有适用前提、观测输入、动作执行记录、后置条件、超时和失败返回。先测试它面对**主策略真实失败状态**的效果；只在整齐摆放的预设状态成功，不能证明能承担接管。

### 四种数据价值应分流

| 数据类型 | 对学习的合理用法 | 禁止的混淆 |
|---|---|---|
| 原始动作真实执行且奖励可信，最终失败 | 可用于相应目标的 off-policy critic；可用于混合质量数据建模 | “失败”不等于每个动作都无用；也不等于可无条件 BC |
| 经验证的局部纠正，最终回合仍失败 | 可作为局部 SFT/BC 监督；与真实上下文一起训练 | 不能因最终失败删除所有纠正；不能把仅有动作来源标记当作质量证据 |
| 自动接管后最终成功 | 标记 assisted success；提取有效段，审计前缀与切换处 | 不能把整个回合归功于 learner；也不能自动认定所有前缀动作优质 |
| 尚未执行的 Agent 计划、候选代码、想象恢复轨迹 | 用于候选测试与诊断；通过真实执行再转成经验 | 不能直接写入真实 transition 或当作已成功专家轨迹 |

单独恢复初始场景也有价值，但其目标通常不同于正向任务；不能把反向回收动作当成正向专家动作。正反共享表征是可测假设，方向数据必须有正确目标条件。

## 4. 三种候选在完整闭环中的角色

### ConRFT：完整动作头可以学习，HIL 优势不能无条件保留

原方法保留 VLA 表征并训练 consistency 动作头；离线阶段结合 BC 与 Q，在线阶段保留示范池并混合在线经验。公开 online BC 目标覆盖混合回放，而非天然只监督优质接管。论文也明确提醒：有接管的训练成功曲线可能高于策略自身成功率。[ConRFT 论文](https://arxiv.org/html/2502.05450v2)

对本系统的判断：

- **适合之处**：若自动 teacher 能给出局部有效动作，却不常把整回合完成，可以直接提供学习信号；完整动作头也避免把探索永远限制在初始参考动作附近。
- **必要改造**：保留真实 off-policy 经验供 critic 使用，另维护可信动作池/质量掩码供 BC。Agent 接管标志仅记录来源，不代表专家资格。初始真实示范保留固定采样份额，避免被大量低质量自动轨迹淹没。
- **须对照验证**：质量掩码会改变原配方，不应声称已有 HIL-ConRFT 结果为其背书；过强过滤也可能扔掉有用动作，造成覆盖不足。
- **否决条件**：teacher 在主策略失败状态无法纠正、判定器不可靠、或团队无法承担 Octo/JAX 与机器人接口适配时，不应因 HIL 名字而把它排第一。

固定源码审计基线：[ConRFT 固定版本](https://github.com/cccedric/conrft/tree/a779fde7fa5db5a469960a8490c100f35b41b49e)。用 π0.5 表征重建同类完整动作头属于新适配，并非官方现成配方。

### EXPO-FT：成功数据供给充足时，上升为更自然的整体首选

方法将学习分成 Q/编辑策略与 base VLA：有界 edit 由 Q 优化，base 使用原有监督训练目标；Q 梯度不穿过整套 base。小规模初始示范、真实成功奖励和 HIL 都属于论文设置。[EXPO-FT 论文](https://arxiv.org/html/2605.25477v2)

既有固定源码审计发现，实际主配置默认 `actor_success_only=True`，base 主要接收成功回合；经接管救成的整回合可以进入成功池，失败回合的优质局部纠正默认不等同于 base 监督样本。[batch processor](https://github.com/pd-perry/expo-ft/blob/803381fc3b4c91a0c47904f1b688fc5e35904f50/expo_ft/data/batch_processor.py)、[replay buffer](https://github.com/pd-perry/expo-ft/blob/803381fc3b4c91a0c47904f1b688fc5e35904f50/expo_ft/data/replay_buffer.py)

对本系统的判断：

- **可靠自动 teacher 会改变其劣势**：即便当前 learner 经常失败，teacher 也可能带来现有 base 很少生成的成功行为。经监督更新后 base 分布能移动，因而“局部 edit 约束”不是整体系统唯一的能力边界。这不保证一次更新就能迁移，也不消除 Q 的分布外风险。
- **无可靠 teacher 时，缺陷仍在**：只有自动重试和稀疏成功判定时，候选与局部 edit 可能长期缺少有效行为，成功池不能靠评分器自动增长。
- **需要的接入**：初始示范保留、可信纠正局部池、实际执行 action chunk、切换处有效长度 mask、独立成功验证。先保留官方成功回流配方作对照，再单独评估“失败回合的可信纠正也监督 base”。
- **否决条件**：长期只增加失败轨迹、teacher 没有带来新增可信成功或纠正，或成功池主要依靠误判增长。此时不应仅调大残差/把所有回放送进 base 来掩盖监督缺口。

### STEAM + CFGRL：适合经验已经丰富后的自动筛选与批次更新

STEAM 用专家成功示范的时间结构训练进展估计集成，给混合数据做局部质量标注，再用 CFGRL 更新 VLA。它估计的是基于时间进展的代理优势，并非标准 Bellman Q 优势；评分依赖真实前后观察，不产生缺失动作。论文抓放实验使用 50 条专家示范与 594 条策略 rollout，不能据此承诺极少示范即可成立。[STEAM 论文](https://arxiv.org/html/2606.29834v1)

官方实现位于 RLinf，公开了优势训练与策略优化链路，代码具备批次改进的实际基础；仍需对齐本任务数据格式、选定模型、质量阈值和训练资源。[官方文档](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/steam.html)、[固定 CFGRL 配置](https://github.com/RLinf/RLinf/blob/b023deb7e90ceadfe18e0a528e862e3c630f7e0a/examples/offline_rl/config/cfg_rl_openpi.yaml)

对本系统的判断：

- 当 Harness 持续产生成功、失败、重试、纠正混合轨迹，STEAM 对局部质量归因正好有用，且训练可以与真机采集分时运行。
- 当 Harness 的自动 teacher 能解决“动作从哪来”，STEAM 可承担“哪些片段值得学”；若需要减轻持续在线 actor/critic 调度，这一整体方案可能比 ConRFT/EXPO 更容易维护。
- 初始示范非常少且与真实失败状态距离大时，不能先把其打分作为真值。集成保守性无法保证全部分布外情形可靠；“失败数据中排名靠前”也不等于动作合格。
- **否决条件**：局部进展分数与独立物理检查明显不一致，或仅增加整理后的数据集却未改善部署策略。此时退回简单可验证筛选 + SFT，而非继续叠加评分模型。

## 5. Harness—数据—梯度之间的最小契约

这是三条候选都应满足的系统前提，与具体算法无关。

1. **记录真正执行的动作**：观测时间、实际发给机器人并被执行的命令、执行后观测、奖励、终止/截断、持续时间。若代码只暴露 `pick()` 名字却不暴露内部控制记录，不能直接拿这个名字训练低层 VLA；需展开记录，或另定义高层 option 学习问题。
2. **记录来源与版本**：主策略、接管脚本/MPC/其他 VLA、人类初始示范分别标记；保留 learner 版本、代码版本、评分器版本、技能节点和切换原因。来源与质量是两个字段。
3. **处理动作切换**：接管时撤销未执行的旧 chunk，保存实际执行长度，不把旧预测尾部当事实。跨控制器的 chunk 需拆分或保留来源与有效 mask，避免把“本应执行”当“已经执行”。
4. **处理任务切换**：正向 A→B、反向 B→A、恢复、重新初始化分别记录目标。最简单实现是每次目标切换结束当前目标回合并另起一个；若设计为统一 goal-conditioned 连续过程，则 goal、mode 和折扣语义必须明确进入状态/目标。禁止将反向任务的 Q 直接当成正向任务的后继值。
5. **区分真实 TD 与模仿目标**：同目标下脚本产生的真实 transition 可以供 off-policy 学习；跨多步控制器的回报、变长持续时间和接管终止仍要匹配所用 TD 定义。BC/SFT 则额外要求动作值得模仿。
6. **分开代码归因和模型归因**：技能节点调用失败先用执行证据定位，Agent 的诊断只是待检验解释；不能因为下游抓取失败就确定上游感知正确，也不能把后续脚本救援的系统成功全部标为策略独立成功。
7. **分批冻结版本**：每个采集/比较窗口固定评分器与已发布恢复代码，候选修改在隔离窗口测试再替换。否则奖励、环境、teacher、learner 同时变化，无法知道谁带来了提升。

对于目标区域抓放，初版终局判定可以要求目标物体进入区域、夹爪释放并退出、经过短暂观察仍稳定。具体传感器与容差需根据硬件确认。目标区域视觉判定、接触/夹爪状态、时间稳定性可相互校验；不能仅把“夹爪在目标附近”当作物体已放好。LLM Reviewer 适合做诊断和生成待验证假设，不应单独掌握奖励真值。

## 5A. 融合兼容性是硬门槛：不能只因模块各自有效就接受组合

标记：**N 原生支持**仅指已审代码能力；**A 薄适配**指数据/接口转换，不改变学习目标；**M 实质修改**指要改变数据契约、采样或训练/任务语义，必须独立验证。任何组合尚未经过本项目真机复现。多标签表示同一行含不同层次工作。

| 兼容项 | ConRFT 固定版本 | EXPO-FT 固定版本 | 必须通过的验收 |
|---|---|---|---|
| 自动接管 transition 入口 | N：训练入口可用 `info["intervene_action"]` 覆盖原动作并标记接管；A：脚本/MPC provider 输出同一规范的实际动作；M：新增 teacher 类型/质量标签与采样逻辑 | N：采集入口保存环境返回的 `real_action` 与动作来源，接管时清理未执行 chunk；A：脚本/MPC 返回相同契约；M：多来源/质量采样不等于原来的 human 布尔标记 | 用可追踪的动作序列证明 replay 与真正执行命令一致；不得仅替换 `is_hil` 名称就声称自动专家已就绪 |
| 动作空间与频率 | N：当前头输出单步完整 7D，原硬件是 Franka；A：坐标、尺度、夹爪和固定控制周期对齐；M：若换成不同维度、变长 chunk 或新表征，超出薄 adapter | N：原生 VLA chunk 和实际执行 prefix 的 Q 路径；A：script/MPC 的实际低层动作转成与 VLA 相同的坐标/绝对或增量定义、归一化与频率；M：异步宏动作/变时长控制需改 chunk/TD 语义 | 同一真实动作正反变换一致；关节空间不能直接套 DROID Cartesian 统计；频率改变后每步位移、动作窗口和折扣含义必须匹配 |
| learner 观测与 teacher 特权 | N：固定相机、Octo 表征和本体输入；A：可对齐已有观测；M：新增必要感知时需重建输入/缓存 | N：多视角与本体输入；A：对齐模型数据变换；M：新增感知/动作模态需改模型接口 | teacher 可以用规划或额外推理，但如果纠正依赖 learner 不可观测的关键状态，或使用 learner 无法控制的动作，不能直接承诺 BC 可学；检验同观测下互相矛盾的动作标签 |
| teacher 数据如何监督动作 | N：接管进入 demo 路径，BC 原目标覆盖混合数据；M：按可信质量掩码/重新分池监督 | N：成功回合可以进入 base 池；M：失败回合中的可信局部纠正加入 base、移除错误前缀或增加 token mask | 来源字段与质量字段独立；按片段审计动作监督，不把自动 teacher 全量当 expert |
| 正反目标与 critic | N：当前示例单任务，critic 无 goal 条件；A：两独立 learner/replay/reward，外层调度；M：共享多目标 critic | N：任务配置与语言条件接口存在；M：不能据此假设一个 Q 已接受正反 task 条件，需查输入/回放目标路径；保守用独立实例 | 正反奖励和终止不能串接；若共享，必须在网络输入、训练样本和 TD target 中证明 goal 一致 |
| 奖励、成功与终止 | N：稀疏成功设置；A：同步替换为已验证的二值终局检测；M：dense shaping 或新截断语义必须拆出独立 `success`、`terminated`、`truncated` | N：成功标签控制 base 成功池；A：同步可靠终局判定；M：引入非零 dense reward 后应改写依赖回报判成功的数据入口 | 正奖励不必成功，负奖励也不必终止；成功 flag 必须贯通环境 wrapper、writer、replay 与调度器 |
| LLM/视频异步评分 | 未确认支持迟到奖励的完整一致性协议；同步等待可由 A 实现；M：pending episode 队列、最终标签提交/失效处理需新增 | 同左，且成功池必须等待最终可信标签；M：迟到修改不能只更新日志而不更新成功索引 | 用 episode/event ID 绑定评分；未定标签不当作失败 0，也不先当作成功；保持动作所见状态与评分对应时刻 |
| 接管片段和图像历史 | **静态高优先级疑点**：只把间断接管点插入 memory-efficient demo buffer，邻接图像重建可能跨越真实时间间隔；未运行复现 | N：真实动作回填 chunk；静态边界：Q 有有效窗口处理，base 全 H 步未见同等执行尾部 mask | ConRFT 用唯一帧序号核对 obs/next_obs/proprio/embedding；EXPO 核对 prefix 与 episode 尾部，不能学未执行或重复填充尾部 |
| 版本与 replay 恢复 | N：固定 Octo 表征有缓存路径；M：encoder 更换后缓存需失效/重算，脚本/奖励版本审计字段需扩展；现有 checkpoint 恢复不等于完整优化器续训 | N：actor/learner 与回放组件存在；A/M：固定主库和 OpenPI 依赖 SHA，扩展 skill/reward/model 版本与持久化契约 | 旧数据是否仍对应同一动作、奖励和观测语义；模型更新期间不能让相同字段悄悄改变物理含义 |

ConRFT 的间断图像疑点来自“episode 末只插接管点”与 buffer 按相邻存储位置恢复图像历史的组合，属于静态风险，尚非已复现 bug。[训练入口](https://github.com/cccedric/conrft/blob/a779fde7fa5db5a469960a8490c100f35b41b49e/examples/train_conrft_octo.py#L195)、[图像回放实现](https://github.com/cccedric/conrft/blob/a779fde7fa5db5a469960a8490c100f35b41b49e/serl_launcher/serl_launcher/data/memory_efficient_replay_buffer.py#L61)

EXPO 的实际动作、chunk 回填和训练 batch 路径可审查，但“给任意 MPC 一个接口”仍需额外核对动作变换、归一化和 prefix 有效长度。[采集入口](https://github.com/pd-perry/expo-ft/blob/803381fc3b4c91a0c47904f1b688fc5e35904f50/train_pi_robo.py)、[回放实现](https://github.com/pd-perry/expo-ft/blob/803381fc3b4c91a0c47904f1b688fc5e35904f50/expo_ft/data/replay_buffer.py#L305)、[batch 组装](https://github.com/pd-perry/expo-ft/blob/803381fc3b4c91a0c47904f1b688fc5e35904f50/expo_ft/agents/alg/batch_utils.py#L20)

**非零 dense reward 的集成门槛：**若某个入口沿用 `if reward` 换向或 `episode_return > 0` 判成功，加入任意非零进展分数都会改变其原先二值奖励假设，可能错误换向或污染成功池。必须枚举实际启用的 wrapper/writer 路径，把 task success 独立贯通后再使用 dense reward。具体默认入口的条件行需以最终选定 SHA 和实际 wrapper 链确认，不能因论文采用二值奖励就假定所有 adapter 已兼容。当前推荐初版保留独立可靠终局成功信号，代理进展先用于诊断/筛选；若用作 shaping，另做效果和投机行为对照。

**否决规则：**上述动作记录、观测可学性、成功标记、跨 goal 终止、分段回放五项有任一未通过，暂停把相应组合评为“可接真机自主学习”。先完成接口回放和最小更新验证，再讨论算法效果；这不要求先做长期真机试验才能排查基础契约。


## 6. 最小实施路线与切换边界

### 阶段 A：先验证自动纠正供给

固定一个物体、有限工作区、清晰目标区，覆盖常见的抓空、偏位、已抓未放、放置偏差。保存主策略真实失败状态，检查 teacher 是否能恢复、是否提供有效动作、是否能返回可继续练习的状态。

这一阶段交付 teacher 成功/失败分布、人工例外原因、数据有效率和后置条件误判记录。**不以 learner 起始成功率达到某个统一百分比作为启动门槛。** 门槛是有没有可信学习信号、是否能执行有界练习。

如果只有复位可靠，先保留其降人工收益，同时明确“自动纠正尚未补齐”；不能将恢复次数增加当成技能已经获得。

### 阶段 B：先建立最简单的模型改进对照

使用初始示范和 teacher 的可信动作做增量 SFT/纠正模仿，并在固定初始分布上测试。失败回合中的可信局部纠正也可进入训练，不必只保留整个成功回合。

这样做不是否定 RL，而是测量“自动数据供给本身能带来多少收益”。如果 SFT 已达到目标可靠性且数据成本可接受，增加 RL 未必值得；若停滞、需要信用分配或必须利用大量非专家交互，再用 RL 检验增量价值。

### 阶段 C：按阶段 A 的结果，只集成一条主要 RL 路线

- 完整可信成功持续产生、现有 π 链路成熟：EXPO-FT。
- 局部可信纠正为主、全动作重学有优势且 ConRFT 栈适配可承担：ConRFT，原配方与质量 BC 改造分开验证。
- 混合经验已经丰富、批次更新合适：STEAM + CFGRL，可作为主要方案而非永远排在在线 RL 后面。

GPU 未确定时，先测一次推理显存与延迟、一次预定更新的显存与耗时，再选择并发在线还是回合/批次更新。分时执行降低峰值并发要求，但不会自动减少模型本身的训练显存需求。

### 阶段 D：再放开代码自改与反向策略学习

先让 Harness 在固定接口内选择已验证恢复原语；通过数据供给与学习闭环后，再允许其提出新版组合代码。每次发布需验证原来的状态覆盖与新增失败类型。

正反学习按物理状态与独立预算调度：正向一直失败时也要有反向策略的独立数据来源，不让反向永远等不到启动；同样不能仅因正向超时就盲目发送反向指令。反向的作用先是回到覆盖范围内的可练习状态，后续再检验是否提升正向表征或操控能力。

## 7. 最小公平对照与可证伪标准

### 三个必做实验臂

| 实验臂 | 保持一致的部分 | 检验的问题 |
|---|---|---|
| A：固定初始 VLA + Harness，不更新模型 | 同一初始策略、恢复代码与独立评分器 | 单靠代码与接管，系统改善多少 |
| B：Harness + 可信纠正 SFT | 同样初始示范、采集/人工预算，利用可信局部纠正 | 自动经验回流是否已足够 |
| C：Harness + 条件选中的 RL | 同样初始模型或明确披露模型变化、实际机器人/人力预算 | RL 相对 B 是否增加独立策略能力或降低成本 |

若数据池成熟，再加入 STEAM 与 B 的同数据对照。不要一开始为所有算法重建整套真机工程。

先用固定收集批次比较数据利用与训练效果，再做在线预算相同、初始物理状态分布匹配的实验。在线算法会改变采集分布，不能声称后者是完全同数据比较；若更换 VLA backbone，则结论属于系统方案对照，不能只归因于 RL 算法。

至少分别报告：

- 关闭额外 teacher 接管的 learner 独立成功率；
- 开启 Harness 的系统任务成功率；
- 自动 teacher 接管次数与动作占比、自动恢复耗时；
- 人工操作分钟数、必须现场待命的分钟数、人工例外次数；
- 单位机器人时间内有效正向尝试量、独立成功量；
- 算法与代码更新次数、GPU/LLM 开销；
- 判定器假成功、漏成功和未覆盖失败，使用固定保留集及抽样人工事后核验。

事后标注用于科研审计，不等同于在线人工接管，但其人力成本应单独计入。成功率应报告试验数、状态随机化范围与置信区间，不用不同任务的初始百分比横向排序。

### 以下观察可以推翻推荐

1. **系统成功上升，独立 learner 成功不升**：证据支持代码/teacher 变强，尚不支持模型自学习有效。
2. **同预算 SFT 与 RL 持平或更好**：首任务优先保留较简单路线；不能宣称 RL 必然更快、更省数据。
3. **EXPO 成功池增长但 learner 不改善**：审计错误前缀、辅助成功归因、切换尾部、示范占比和真实新行为覆盖，而非直接扩大训练量。
4. **ConRFT 接收更多“自动接管”后退化**：接管来源不是专家质量；检查 BC 污染和 Q 分布外估计。
5. **STEAM 分数提升而物理完成不提升**：代理进展存在偏差，暂停把它当主要筛选依据。
6. **人为值守从复位转移到处理 Harness 异常**：没有达到减少人工的总体目标，即使手动复位次数下降。
7. **反向学习只增加总耗时，未减少人工或改善练习覆盖**：正反循环设计需修改；“一正一反必然获得充分理解”没有得到支持。

## 8. 本轮取舍

应把最终目标定义成“在明确工作范围内，可靠地产生练习、可信纠正和可审计模型改进”，据此选 RL。当前最值得推进的不是无条件沿用 ConRFT，而是：

**先验证窄范围自动 teacher；完整成功供给充足时优先 EXPO-FT，局部纠正为主时优先评估 ConRFT 的质量分流改造，混合数据丰富且允许批次更新时认真考虑 STEAM。自动纠正 SFT 始终作为公平基线。**

如果没有可执行、已验证的恢复 primitive，三者都还只是学习器，尚不是自主学习系统。这是当前整体可行性的首要依赖，不应被机构声誉、公开代码或更复杂的 Agent 编排替代。
