# R01 独立学习与审查：异步 VLA、RL 与 Harness 接管

审查日期：2026-09-23。审查员：`r01_async`。输入为本目录 `input/` 冻结的 v1 主文、接口、证据与 README。本报告未阅读其他审查员的报告，未修改主文，未运行机器人、训练或声称复现论文。

**结论：FAIL。** 旧稿已有很好的控制租约、实际动作与监督数据分流设计，但没有把推理与执行重叠纳入 learner 的状态、动作、价值目标和梯度路径。仅把“执行前缀”改称“执行区间”，或再加一个 mask，不足以完成这次修订。

## 1. 本轮先枚举的关键技术点

1. 推理发起、推理结束、计划开始时间、真实采纳与物理生效，是否使用同一时间轴；动作 chunk 三段如何对应。
2. committed 旧动作和剩余延迟是否进入 actor、critic 与 replay，目标方向是否同时进入这些对象。
3. chunk-level TD 的奖励区间、折扣指数和 bootstrap 状态是否严格对应所选异步 MDP。
4. Q 的输入动作与 actor 产生有效梯度的动作是否同一组量；是否误对 committed／discarded 段赋予当前动作价值梯度。
5. Harness 接管发生在推理中、执行中、部分控制步时，旧结果失效与样本有效性怎样同时处理。
6. BC／flow 监督 mask 与 TD／Q 梯度 mask 是否区分；未执行建议可否保留且进入恰当损失。
7. 动作变换、平滑、IK、投影及 latent steering 是否改变 learner 动作语义。
8. 固定延迟预算的超时、提前结束和随机抖动是否有确定分流；收集和部署是否同 runtime。
9. 原始论文实际实现与一般原理能否分开；代码公开、许可、真机实验是否被过度概括。
10. 选用现有 EXPO／ConRFT 后，改动究竟是接口适配还是需要重新验证的方法变体。

## 2. 本轮实际学习的原始来源

### 2.1 SmoothRL：本轮新获得的信息

实际阅读 [正文 §3、算法 1、实验 §4 与局限 §5](https://arxiv.org/html/2608.29768v1)。方法使用固定延迟预算，将旧 committed 动作放进 critic，价值梯度只经过当前真正执行区间；不是把整个 proposal 当一次环境动作。其原始实例仍是冻结 π0.5、RLT 式有界残差和参考动作 BC，不能据此声称解决任意弱策略的动作覆盖问题。实验仍有人工标奖、介入与复位。

实际访问官方项目入口，经页面重定向到 [Astribot 官方项目页](https://www.astribot.com/en/AI/SmoothRL/)。保存了本轮 HTML；本轮核验页面链接只有论文等，未找到可审计算法仓库／算法代码许可。搜索出现的 `JenAlchimowicz/SmoothRL` 是 2023 年同名项目，不是本论文实现，不能借它的 MIT 许可。

### 2.2 Learning to Act While Waiting / ARLI：本轮新获得的信息

实际阅读 [v2 正文 §4、附录 A 与 D](https://arxiv.org/html/2608.23831v2)。其实现用 DSRL-SAC 学噪声 `w`，并在 RL 状态中加入推理期间的已承诺动作和较新的中途观测；附录明确把一个噪声向量重复到 chunk 各位置。原始 learner 的动作是 latent noise，不是任意物理纠正动作。论文理论还依赖数据覆盖、open-loop consistency 等条件，不能当弱基础策略必然成功的证明。

核验 [官方项目页](https://async-rl-intermediate-information.github.io/)、[对应官方 GitHub](https://github.com/async-rl-intermediate-information/async-rl-intermediate-information.github.io)。仓库 README 标题明确为 Project Website，列出的 `scripts/static/index.html/serve.py` 是网站资产；CC BY-SA 4.0 说明针对网页模板，不构成 RL 算法源码许可。本轮未核到公开 ARLI 训练实现。论文引用的 [DSRL π0 官方仓库](https://github.com/nakamotoo/dsrl_pi0) 不是 ARLI 已公开的证据。

### 2.3 交叉核验

阅读 [Thinking While Moving，ICLR 2020 原论文入口与摘要](https://arxiv.org/abs/2004.06089)，确认“并发执行需要修改决策表示与 Bellman 建模”有独立前序依据，不能仅视为 HTTP／进程异步实现。

以上是本轮真实重新访问的材料。方法学判断来自原论文及本轮对旧设计的独立分析；未采用搜索结果中的二手摘要作为技术证据。

## 4. 必要修法：先固定一套能被实现的语义

### 4.1 三段不是三个数字，而是一张因果时间表

建议主文加入一个小例子：在帧 100 取观测，预算 `n=6`、规划 `H=20`。帧 100–105 继续执行上一 chunk，当前 proposal 的索引 0–5 已失去执行机会；106–111 才执行当前 proposal 索引 6–11；112 之后被更新结果覆盖。因此“前面未执行”指**当前 proposal 的这些预测未执行**，不是机器人在那段时间没有动作。

日志至少绑定 `inference_id`、`observation_frame`、`policy_version`、`goal_id`、`scheduler_version`、`owner_epoch`、计划帧索引到绝对控制帧的映射，以及每帧实际来源。不得用“实际长度=6”取代“实际执行索引=6..11”。这直接关系到训练标签，而非纯调试信息。

### 4.2 选定并公开一种异步 RL 目标，避免混用两篇论文

若复用 SmoothRL 的固定预算目标，必须在主文说明本项目的**拟议实现**：

`C_t = 在 [t,t+n) 实际发出的旧动作`；`E_t = 在 [t+n,t+2n) 实际执行的新动作`。

critic 评价 `(观测/表征, 目标, C_t, E_t)`；actor 的 Q 路径只使用新执行区间的输出，`C_t` 是条件且停止梯度，discarded 输出不参与该 Q 路径。奖励与 bootstrap 按这个 **2n** 跨度构造，不按 E 长度 n，也不按生成长度 H。目标样本必须在后继状态及其 committed context 可用后才就绪。

这只是选用该论文目标后的具体契约，不是说所有正确异步 RL 都必须使用 2n。若采用每 n 步决策、显式将队列作为环境状态的另一 delayed-MDP 目标，也可以，但必须单独推导状态更新、奖励区间与 bootstrap；不能保留当前同步公式再声称等价 SmoothRL。

ARLI 则作为“中途观测刷新和并发状态增广”的参考，不能把其 latent SAC 目标与 physical-action BC 直接相加称原版复现。共享状态条件应包括目标、必要视觉历史、旧动作／队列、剩余时延及调度模式。图像状态仍可能是部分可观测；不能宣称添几个字段就严格恢复完整物理 Markov 状态。

### 4.3 接管覆盖后，重新判断哪一种训练资格仍成立

Harness 接管可采用同一物理动作边界，持续记录纠正动作。控制租约旧逻辑保留，但取消必须同时使在途推理、reference chunk、缓存、next committed 及对应未完成 TD 聚合失效。回交后从当前实测状态重新建立异步周期。

对于固定完整窗口 learner，遭遇停机、owner 改变、目标改变、超时或局部未知动作的窗口，不能默默补齐成“正常窗口”。建议先保留所有微步事实，将不满足该 learner 契约的窗口隔离；其中可信纠正动作仍可进入 BC／flow 监督。若要把反馈式多步 Harness 执行轨迹直接组成宏动作 TD，应审核它是否满足所用目标的 open-loop／因果条件，不能因每一微步都真实便自动证明任意重组 chunk 的有效性。可选的微步 critic 必须另外定义，而非假定已有。

### 4.4 区分四种 mask 与两类动作空间

除现有 `execution_mask`、`td_valid_mask`、`actor_label_mask`，新增 **Q-value-gradient 适用区间**。前者表真实日志，中者决定数据资格，后者是监督质量；Q 梯度范围由当前 actor 与执行窗口的因果映射决定。BC 可监督未执行的可信标签，这与“未执行不能获得真实动作 TD”并不矛盾。

ARLI 的 `w` 与物理 `a` 必须分别持久保存，且确定性解码器／版本、RTC 配置与执行记录要可追溯。没有精确相容 latent 时，Harness 动作只能用于另设物理监督分支或 base 更新，不得编造 latent 值入原 Q。base 更新改变解码动力学后，旧 latent replay 是否仍相容也必须重审。

### 4.5 调度、平滑与测试要与训练目标一起发布

首版可选择固定预算与受约束连续拼接，明确 deadline miss 时保持/停止、日志标记、恢复新周期；不直接照搬论文 n 值。若保留 temporal blending，需把混合结果作为执行边界动作，记录来源权重，并给每个参与 chunk 正确梯度，或明确该路径不做原版 value-gradient 更新。纯物理控制保护依然可以存在，但被改写动作的数据资格不可掩盖。

需新增验收：正常三段、早到等待、迟到丢弃、推理中接管、执行中接管、中途目标切换、normalizer／权重切换、next committed 尚未就绪、平滑后 action 不相等、可学习区间之外扰动不改变 Q actor 梯度。硬件时延待测属于合理的实现门槛；缺少这些目标语义本身才是设计 FAIL。

## 5. 对选型的独立意见

本轮不支持“EXPO 仍保持首选，只补接管 mask”，也不支持“原版 SmoothRL／ARLI 更贴近异步，因此直接替换”。应先选择 **共享目标条件 physical-action policy＋质量受控 BC 与离策略 RL＋明确定义的异步状态/目标** 的训练契约，再核 EXPO、ConRFT 或新动作头哪条路径改动最小且证据最充分。

SmoothRL 为异步动作建模提供直接参考；ARLI 提醒使用更近观测与已承诺动作。原版 SmoothRL 的参考锚与有界残差、原版 ARLI 的 latent 先验，均不能消除用户已指出的弱基础策略覆盖问题。允许本项目使用它们的原理而重构动作头，但应标“项目改造方案”，不能借用原论文成功率作改造后背书。

## 6. 本轮结果与下轮复核条件

**R01：FAIL。必要设计问题未关闭。** 下轮应在冻结修订稿中复核 A01–A12，至少检查能否从同一个示例重建：机器人真正动作、当前更新的目标、Q 输入、TD reward/discount、actor 梯度区间、Harness BC 标签、接管后回交的首个周期。

本次结论不是说总体方向不可行；它指出异步动作机制是此次联合设计的核心接口，不能仅作为运行时细节。已存在的原始事实记录、持久标签池、控制租约和真假 transition 分流可继续使用。
