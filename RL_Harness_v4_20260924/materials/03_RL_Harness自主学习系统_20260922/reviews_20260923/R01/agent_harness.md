# R01 独立审查：GPT-6＋Harness 的观察、纠正与自主运行

审查日期：2026-09-23。冻结输入：本轮 `input/` 下主文档、接口附录、证据文档与 README；没有阅读其他代理的本轮意见。本文不修改主方案。

**结论：FAIL。** 原版包含有价值的控制权、历史标签、候选试验与真实记录设计，但 GPT-6 被放在辅助诊断位置，“教师”术语掩盖 Harness 的实际职责，正反共享策略的任务切换没有贯穿观察和评分协议。至少须修复下列 H01—H06 后重新审查。此结论评价文档设计，不代表已运行任何机器人实验。

## 一、先枚举本轮技术要点

1. 主观察模型与底层设备保护如何分工，GPT-6 是否承担用户要求的语义观察主体。
2. 一个 Harness 如何给出任务状态、纠正动作、恢复代码和训练标签，是否隐含另有强策略。
3. 正反方向共享 policy 时，任务目标如何进入观察提示、奖励、纠正与数据。
4. GPT-6 与 VLA 都有异步延迟，历史判断能否错误地改变当前场景。
5. 大模型直接生成动作与动作执行接口之间的时空、单位和状态契约。
6. 连续奖励与终局成功的区别，以及查询限频、缓存与未知结果的语义。
7. 基于访问状态的数据聚合怎样成为 BC＋在线 RL，而不被“是否真实执行”一刀切排除。
8. 代码候选如何自动试验、发布和撤回，是否又引入逐次人工批准。
9. GPT-6 自评、自我生成代码和自我标奖是否存在共同错误来源。
10. 无人工接管与模型独立能力提升如何分别验收。
11. 真机运行、源码支持与论文叙述的边界。
12. 主文是否让开发者首先理解闭环，而不是先理解多个不同“教师”。

## 三、审查问题、回答与判定

### Q1：GPT-6 是主观察系统，还是只在其他评分器之后偶尔诊断？

**原版回答：后者。** 主文 0 把它写成候选诊断／代码模型；8.1 先安排规则、小分类器或 Robometer，GPT-6 只处理较慢分析。README 也先把大模型定义为较慢诊断。这与用户要求的 GPT-6＋Harness 主语义观察不一致。

**判定：H01，高严重度，必须修正。** 首版可明确 GPT-6 接收有任务和时序上下文的观测包，直接输出完成判断、进展、异常解释、接管建议和动作／程序候选。底层反馈、设备保护与固定判据是事实输入和执行约束，不是额外强制添加的语义小模型。Robometer 等仅保留为后续成本/时延优化或对照。

“主观察模型”不意味着它必须以关节控制频率被调用，也不等于每个回答都被当作事实。需要允许拒答、观察补充和观测域校准；这不否定其主角色。

### Q2：通篇“教师”是否清楚地等价于 Harness，而没有引入强上游策略的前提？

**原版回答：不清楚。** 文中“完整任务教师”“Teacher/Skill Executor”“教师资格”“学生/教师”占主叙述，并列列出可靠策略、代码和规划器，开发者很容易理解成还必须准备一个专门 teacher policy。

**判定：H02，高严重度，必须修正。** 改为“VLA policy”“Harness 观察”“Harness 动作纠正”“Harness 异常恢复”“纠正数据池”等直接表达。首段说明：使用 DAgger 的访问状态标注与数据聚合思想，标注和接管由整个 Harness 提供，不预设另一个高成功率 policy。旧源码类型名只在适配说明里保留并解释，不应该成为系统的核心术语。

### Q3：Harness 生成动作能否充分覆盖用户的 BC＋RL 意图？

**原版回答：原理大体覆盖。** 6.2/6.3、附录 B3 已允许实际纠正和未执行动作标签；两者持久保存，并区别 critic 转移与 actor 辅助监督。DAgger 不等于人类介入已写明。但主叙述仍用“首版固定自动教师”，把本应统一的 GPT-6＋Harness 方案变成了多个外部能力候选。

**判定：与 H02 一起修正；不是另一个算法缺陷。** 保留“实际动作有真实后果、查询动作没有”的数据区别，明确 BC/flow 是所选 VLA 的监督实现；不要为了顺应用户把未执行建议伪造为 TD。让同一 Harness 可以观测、给建议、接管执行、检查后果和固化恢复程序。

### Q4：共享 policy 的正反目标，是否同时进入 GPT-6 观察和结果归属？

**原版回答：没有完整贯穿。** 12 节首版仍是独立双 policy/head，主图是“正反策略服务”，共享目标条件模型被放到后期。虽有目标边界数据字段，主观察链没有说明同一个“物体在 B”如何分别代表正向完成和反向起点。

**判定：H03，高严重度，必须修正。** 同一个 `πθ(o,g)` 承担 A→B 和 B→A，两向都采集在线 RL 与 Harness 纠正。每个观察请求和反馈绑定 `goal_id / episode_id / task_contract_version`；成功判据按当前目标求值。目标切换使待处理的当前控制建议失效，但不使历史评分自动失效。反向不是只用于无梯度 reset 的外部脚本，异常恢复才单独区分。

### Q5：VLA 持续执行时，GPT-6 的迟到回复如何处理？

**原版回答：部分充分。** 7.2 与附录 4 已有过期建议禁止执行、可以变为历史标签；然而只讲“计划过期”，缺少异步观察回复在“当前指令／历史标签／历史奖励”三种用途上的具体判定，也没有双向换目标的例子。

**判定：H04，高严重度，必须修正。** 观察包至少绑定请求 ID、观测区间、对应执行事件范围、目标、控制代际和模型/提示版本。返回建议若要控制当前机器人，应基于新鲜状态重验前置条件；历史任务判断只能标注它见到的区间，不能标在返回时刻。顺序为请求 A 后请求 B，不保证 A 先返回；旧请求不得覆盖较新裁决。主文应给出“正向完成后反向已经启动，正向评分才返回”的正常例子，解释保留历史评分而拒绝旧动作。

### Q6：GPT-6 限频或网络异常时，是否会把旧 reward 广播给新状态？

**原版回答：有 pending 概念，但没有针对真实可复用实现的缓存防护契约。** ENPIRE 的现有 VLM 奖励缓存恰好提供具体反例：正向 YES 后，如果反向在限频窗口启动，原代码会返回上一任务的 1.0；异常也重复旧值。

**判定：H05，高严重度，必须修正。** GPT 输出是按观测和目标键控的异步标签，不是每步读取的“最新分数寄存器”。缓存只复用相同输入版本的结果；没有该样本评分时保持 pending/unknown。训练样本直到满足所用 loss 的反馈条件才进入相应视图。终局成功事件要去重，不能因多次轮询同一成功画面生成多次奖励。

### Q7：固定任务核验和“独立校准”是否意味着另建一套昂贵小模型？

**原版回答：文字容易让人如此理解，但没有必要。** 固定判据可由同一个 GPT-6 按固定 rubrics 执行，底层夹爪/释放/时间信息作为输入。离线留出集与少量人工审计或独立传感器用于验证其判定，而不是每次在线需要人工二次批准。

**判定：H06，中严重度，必须澄清。** 主方案应明确“固定任务契约”指不可随优化更改的定义，不是必须另训分类器。另一个 GPT 角色看同样证据不构成统计独立的地面真值。奖励模型提示、版本和输入字段冻结，程序生成者不能改评分 rubric；正式验收可保持阶段性的独立离线审核，不计成在线接管，但人工成本应另记。

### Q8：能否直接让 GPT-6 给连续 reward？

**原版回答：可以扩展，但 v1 把主要位置给了专用进度模型。** 连续数值不自动比二值更可信；主文已有势函数、终止边界与因果状态限制，值得保留。

**判定：原则 PASS，随 H01/H05 改角色和接口。** GPT 可输出进展、子目标事实和奖励候选。训练 dense reward 可以异步重标，不必控制周期同步调用。若声明势函数 shaping，应只使用截至状态时刻的因果信息，不能把整回合看到结局后的“事后进度”伪装成在线状态势；暂未评分的中间片段不做任意线性插值并宣称已获每步真值。

### Q9：GPT-6 直接生成动作是否应被禁止，或是否可直接执行？

**原版回答：正确避免直接硬件写入，但“必须经已验证技能”容易过窄。** Code as Policies 支持程序与参数化动作输出这一方向，并不需要另有强 policy。

**判定：原则 PASS，建议补一段。** 模型可以生成末端目标、夹爪指令、轨迹片段和代码组合；候选通过统一的 frame、单位、作用时刻、可达范围和命令语义检查，再由网关执行。不能因为是数值输出就禁止，也不能因为模型强就跳过标定与状态时效。若仅以像素定位而没有可靠深度/平面模型，应如实说明需要补充观测或可执行接口。

### Q10：新恢复程序是否每次等待人批准，阻断无人闭环？

**原版回答：不需要。** 状态机已有 CANDIDATE→TRIAL→VERIFY_TRIAL，在预设范围、静态门禁、唯一网关和有限试验预算下自动运行；最终发布、回滚与物理恢复分开。

**判定：PASS，保留。** 不能用“还没通过真实验证”禁止一切候选真实试验，也不能让候选先取得成熟纠正技能资格。静态检查和影子回放只验证其各自覆盖内容，不能冒充新物理行为已经安全有效。

### Q11：评分、纠正和代码进化同属 GPT-6，会不会共同把错误自证成成功？

**原版回答：已有独立核验与固定评测，但需在主观察替换后重新保持这些约束。** 同模型多角色隔离有助组织，不是独立证据。

**判定：PASS，修订时不得删除。** 保留失败录像、原始执行事实、固定任务判据、完整试次分母、独立 policy 评测以及版本撤销影响追踪。纠正数据的质量不单凭“出自 GPT-6”或“最终回合成功”决定。观察提示不应默认接收 learner 的希望结果、待晋级候选排名等无关诱导信息。

### Q12：方案是否已经能区分系统代做成功和 policy 真实改进？

**原版回答：能。** 无辅助、辅助系统、自主学习能力分别定义，动态纠正模仿对照及总人工分钟均存在。

**判定：PASS，保留并调整术语。** “去掉 Harness”不应理解成去掉硬件保护和记录；准确写作“关闭 Harness 的任务动作纠正，保留共同的底层保护、记录和固定评测”。正反能力分别报告，同时给出同一共享 checkpoint 的双向成绩与循环吞吐。

建议新增最小验收例子：

- 正向结束、反向启动后正向 GPT 结果才返回：保留正向标签，不修改反向当前评分或动作。
- 两个 GPT 观察请求乱序完成：最新当前状态裁决不被较旧结果覆盖，历史证据仍保存。
- API 超时/无图像：样本保持未知；不得重复上一任务成功分。
- 重复提交同一成功事件：只形成一次终局奖励和一次统计。
- GPT 产生有效数值动作：经时空接口检查执行后有真实转移；只作建议时仅产生标签。
- 同一共享 checkpoint 执行 A→B 与 B→A：两向都可被 Harness 纠正并进入同一受目标条件化的学习流程。

**最终判定仍为 FAIL。** R01 的主要价值是发现原有组件虽然分别合理，但整体没有按用户指定的共享策略、GPT 主观察和 Harness 自动纠正方式耦合。修订后应重新从实现契约审查，不能只做关键词替换。
