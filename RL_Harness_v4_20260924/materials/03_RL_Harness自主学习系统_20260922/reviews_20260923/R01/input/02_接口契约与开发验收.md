# 接口契约与开发验收

审阅版 v1.0｜2026-09-22｜供人类开发者实现与评审。

本附录承接 [主方案](01_RL_Harness真机自主学习技术方案.md)，把控制、教师数据和学习回流收敛为五个桥层。**以下 API、目录、状态与验收均为拟议设计，不是已提供的可运行软件；测试尚未执行。** 不预设松灵具体型号、控制频率、GPU 或最低显存。

## 1. 先固定集成边界

优先对 **Zetta 的 Harness 骨架做技术预检**，复用其会话、诊断、候选和评测发布结构；本地唯一 Robot Gateway 保持对实体设备的独占。ENPIRE 提供工位、执行转移与学习接口参照；RoboRSI 提供技能经验组织参照。只设一个实验编排者，不把三套主控同时接到机器人。

Zetta 本轮固定提交为 `1fee179644d52c32fa5a7728751cf0853a29b9c0`。公开后端目前是仿真，论文冻结 VLA；整体许可证正文尚未核实。可先审接口与做独立 mock；正式复制、修改、分发其代码前先核清可复用条件。真机保护、停止协议、教师轨迹回流都属于本项目新增能力，不能从类名或配置项推断已经实现。[Zetta 固定版本](https://github.com/air-embodied-brain/Zetta-Embodiment/tree/1fee179644d52c32fa5a7728751cf0853a29b9c0)；[本轮源码审核](research/autonomous_teacher_harness_survey.md)

预检不通过时保留已有真机 runtime，在同一套接口下独立实现必要编排。更换骨架不改变五个桥层的验收条件。ENPIRE 当前单步 RL 接口仅作协议参考，不能未经适配承载 VLA 长动作块。[ENPIRE RL 接口设计](https://github.com/NVlabs/ENPIRE/blob/main/enpire/env/docs/RL_PIPELINE_DESIGN.md)

| 桥层 | 交付内容 | 通过后才能做什么 |
|---|---|---|
| B1 观测与动作 | 单臂映射、时钟、动作空间、采纳命令与驱动证据 | 在声明边界内解释真实交互 |
| B2 控制所有权与取消 | 设备独占、租约、可确认的停止/保持、旧队列失效 | 在学生、教师、遥操之间交接 |
| B3 教师与逐步记录 | 可执行技能、状态适用域、接管轨迹与独立教师标签 | 把纠正变成可追溯训练数据 |
| B4 数据与学习器 | 持久真实池、持久教师标签池、质量视图与算法适配 | 训练候选策略，而非只让教师代做 |
| B5 评测与发布 | 固定测试协议、证据、版本切换与回滚 | 判断学生学会，并发布新版本 |

“Critic”一词容易混淆：Zetta 式执行监控器负责发现异常；RL critic 估计价值；成功核验器判断任务事实。三者分别命名为 `execution_monitor`、`value_critic`、`task_verifier`，不共享一个含义不清的 `score` 字段。

## 2. 拟议工程目录与进程职责

目录只是开发组织建议，本次没有创建这些软件模块。后续代码、数据、运行记录仍全部留在本会话目录内。

```text
03_RL_Harness自主学习系统_20260922/
  implementation/
    contracts/          # 工位、动作空间、任务、数据和评测契约
    adapters/           # Zetta、现有驱动、一个选定 learner 的适配
    gateway/            # B1/B2：实体唯一控制入口
    runtime/            # 单一实验编排、episode 与控制来源状态机
    teachers/           # B3：已发布技能、候选技能、标签查询
    data_bridge/        # B3/B4：事实日志、标签、训练数据视图
    evaluation/         # B5：冻结测试、晋级与回滚
    tests/              # mock、故障注入、数据契约和真机验收脚本
  runs/                 # 执行证据、标签、版本 manifest、测试结果
  datasets/             # 持久真实转移与教师标签；不等同内存 replay
  registry/             # 不可变 checkpoint/技能/奖励版本登记
```

| 进程/服务 | 主要职责 | 权限边界 |
|---|---|---|
| Robot Gateway，本地 | 持有唯一驱动连接；命令校验、下发、取消、保持与回执；记录动作事实 | 唯一可写机器人通道，固定 `robot_id`；不生成奖励、不做训练 |
| Runtime/Orchestrator，本地 | 控制 episode、方向、预算、owner 交接与故障路由；接入 Zetta 预检通过的模块 | 只经 Gateway 发意图；不允许另起第二条驱动链 |
| Policy Server | 用固定模型包推理；返回带观测身份的动作块 | 无驱动凭据；模型推理结束不代表动作已执行 |
| Teacher/Skill Executor | 调用已验证控制原语；给出纠正或查询标签 | 同样无直连硬件权限；所有运动进入 Gateway |
| Observation/Verifier 服务，本地优先 | 同步采样、传感器健康、固定任务核验 | 可发布事实与未知状态；不能改验收目标 |
| Data Writer＋Reward Worker | 前者持久化事实，后者异步追加奖励/质量标签 | 原始事实不可改；标签可撤销并以新版本追加 |
| Learner | 从固定数据视图训练，登记候选 checkpoint | 不热替换线上模型，不移动机器人 |
| Evaluator/Registry | 预约同一个 Gateway 做评测；登记结果、晋级或回滚 | 不能与训练 rollout 同时占用实体设备 |
| Agent 诊断/代码服务 | 异步分析失败并生成候选 | 不能独立取机器人 owner，不能直接发布代码或改成功定义 |

这些是逻辑职责，不要求每项一台主机。设备网关、硬件看门狗和必要的停止/保持能力必须本地可用；其余可按资源合并进程。软件急停接口不能替代机器人的物理保护链。

## 3. B1：动作与观测必须先说清“是什么”

### 3.1 四种量分开保存

| 名称 | 例子 | 在学习中的含义 |
|---|---|---|
| `proposed_action` | 学生或教师提出的归一化末端位移/关节目标 | 候选意图；可能过期、被取消、被接管替换 |
| `a_rl`：选定 learner/env 边界真正采纳的命令 | 环境接口采纳的末端位移与夹爪目标 | 真实 RL transition 的 action；定义必须与 actor、critic、部署一致 |
| `driver_command` | IK、限速、滤波后向驱动发送的关节目标/速度 | 下游执行证据；不默认与 `a_rl` 同空间 |
| `measured_state` | 编码器关节角、估计速度、末端实际位姿、夹爪实测开度 | 观测与后果；**不是回填 action 标签的来源** |

例如 learner 输出末端 `Δx`，IK 与限速位于环境内部，则 `a_rl` 是该接口真正采纳的 `Δx`；驱动关节目标另存，关节实际位移进入下一观测。不能因为机器人只移动了请求的一半，就用测得位移倒填为当时“选择的动作”。夹爪因夹住物体没有完全闭合，也不能把实测开度当作策略原本下达的闭合目标。

若限幅发生在选定 action 边界之前，`a_rl` 应是该边界接收的限幅后命令；若限幅属于环境内部，保留边界命令并把投影作为环境行为记录。两种建模均可，但训练、采集、部署必须使用同一边界。**不能一概要求 critic 使用最底层驱动命令。** 若决定改学投影后空间，actor 输出、critic 输入、归一化、采集和部署应整体改版。

接管时未执行的学生建议不能占据教师 transition 的 `a_rl`。教师必须在同一个学习动作接口提交实际被采纳的动作。若一个教师原语只会直接发关节命令，而当前 learner 学末端 delta，首选让教师经过相同动作接口；否则需验证可因果重建的映射。无法可靠映射时，保留真实原始记录，但不给它伪造 learner action，不进入该 learner 的 TD/动作监督视图。

### 3.2 动作契约的最小内容

动作契约固定单臂索引、动作维度、关节顺序、坐标系、绝对/增量语义、单位、归一化、夹爪编码、控制周期/持续时间、下游变换及版本。另一臂的禁用或保持模式要能在日志中核验，不能依赖调用方记得“别动”。

一个动作块还要标明：起始观测、生成时间、有效期、计划长度、允许执行前缀、实际采纳长度、下游执行长度、未决状态与掩码。`accepted` 只是接收；只有结合驱动状态和后继观测确认了因果对应，才能形成可训练的真实 transition。驱动不提供精确应用回执时，需在适配层声明如何界定一次 action 生效区间，不能把发送成功等同完成。

### 3.3 观测契约与时间

每个 observation 保存相机帧、proprio、夹爪反馈、各自采样时间及合成 observation ID。采用本机单调时钟判断延迟和控制超时；跨机器同时保留源时钟与同步误差，不靠墙钟字符串排序。

按实测定义允许图像/状态不同步范围和新鲜度上限。超过门槛时返回不可用于当前控制的 observation，而非沿用旧帧却更新时间戳。动作转换需要的标定、坐标和状态必须可追溯；标定变化开启新契约版本。

**B1 阻断条件：**驱动动作语义、单臂映射或单位不明；action 层无法对齐；观测时序无法支撑所选粒度；持物/释放缺少可用核验。先解决这些，再讨论 RL 超参数。

## 4. B2：唯一 owner、取消与回交

### 4.1 设备级租约与真实停止是两件事

Gateway 对同一 `robot_id` 只接受当前 lease/epoch 的命令；不同实验 session 也不能各自独占同一实体。唯一驱动连接与系统权限确保其他进程无法绕过它。重复发送同一 command ID 只能查询同一个执行结果，不能再次产生物理动作。

暂停先封住新命令与排队动作，再处理在途动作。**取消推理、取消队列、控制器已保持、机器人状态适合交接**要分别确认。已发生的物理运动无法撤销；调用返回 `cancel_requested` 不等于已经停止。长动作块与整个恢复脚本不能封装成无法中断的单个硬件步骤。

Gateway 按当前控制模式和持物状态进入经验证的保持/停止方式；失联时不能统一用“断电”处理。系统在实测中确定最大停止延迟和允许在途执行粒度，并写入工位契约。未能确认停止时禁止发给教师新 owner。

### 4.2 控制 API 示例

以下是概念 API，名称可由现有协议适配，不要求照抄实现：

```python
lease = gateway.acquire(robot_id, owner="student", expected_epoch=40)
ticket = gateway.submit_chunk(lease, observation_id="o120", chunk=actions,
                              action_contract="armA-ee-delta-v3", command_id="c17")
receipt = gateway.quiesce(lease, reason="empty_grasp", request_id="q18")
# receipt 必须确认队列失效、在途结果、保持状态以及最后执行位置。
teacher_lease = gateway.handoff(receipt, new_owner="teacher:regrasp-v2")
```

`submit_chunk` 是异步接受请求，返回 ticket；真实执行通过事件与回执查询。`quiesce` 必须区分确认完成、仍在处理、失败/未知。`handoff` 只消费当前 epoch 下有效的停止凭证，并签发新 epoch；不能凭客户端自报的 `stopped=true` 交接。

紧急保护可由本地独立看门狗触发，不等待 owner 心跳。其触发也应产生事件，待系统可用时对账。

### 4.3 一次被打断的动作块

假设学生生成 20 步；确认已执行 6 步时发现抓空，第 7 步可能已经在途：

| 时序 | 系统动作 | 数据与边界 |
|---|---|---|
| T0 | 基于 `o120` 提交 chunk，学生 epoch=41 | 保存 20 步 proposed；尚不写成 20 条真实 transition |
| T1 | 前 6 步获得执行证据，第 7 步在途 | 已确认片段逐步落盘；第 7 步保持 pending |
| T2 | 请求 quiesce，禁止新学生下发并清排队余项 | 第 8–20 步标 cancelled；旧推理迟到结果失效 |
| T3 | 驱动报告第 7 步实际状态，并确认保持 | 完整执行则长度为 7；完全未执行则为 6；部分生效则记录生效区间与停止过程，不能强行取整；未知则停止交接并对账 |
| T4 | 取得新鲜 `o_after_stop`，签发教师 epoch=42 | 教师必须基于新状态规划，不能沿用 T0 抓取坐标 |
| T5 | 教师执行重抓 | 每步有同层 `a_rl`、driver command、观测、技能和来源记录 |
| T6 | 教师确认稳定持物，按同一协议回交 epoch=43 | 同一正向任务可继续原 episode；切 source segment 并清学生内部旧 action queue |

不能简单写死“检测发生时已执行 6 步，所以 transition 长度就是 6”。被打断时到底执行了多少，由 Gateway/驱动证据确定。无法恢复在途动作身份时，本轮按中断处理；原始证据保留，但相关训练样本隔离。

若一步命令已生效一段时间后被制动，保存 accepted command、开始／停止时间、实际持续时间与新观测。支持变时长的学习接口才能使用相应时域 target；不支持时保留完整前缀并隔离部分步，不跨缺口串出下一条训练序列。暂停／保持期间若状态变化，也要记录控制来源，不能把等待前后的画面当成无时间流逝的同一时刻。

`quiesce` 对学生、教师、恢复程序、候选试验和主动观察统一生效。所有拥有运动租约的路径共享同一保护与失联处理，不能只在 policy 模式检测故障。迟到教师输出禁止直接控制当前场景；若能准确绑定历史观测且通过质量审核，仍可进入历史教师标签池。

### 4.4 重启与断连

启动时提升或重新建立不可与旧进程混淆的控制代际，获取设备级独占、确认旧控制连接失效，读取真实状态并处理未决命令；在完成前不恢复运动。命令意图先持久化，执行回执追加；崩溃可能发生在两者之间，因此恢复时查询实际状态，**不自动重放未确认的增量命令**。

不能宣称事务日志提供物理 exactly-once。目标是唯一执行入口、重复请求去重、未知状态不重放、旧 lease 不再写入，以及对每次不确定执行保留可审计记录。

## 5. B3：区分可执行教师与动作标签教师

### 5.1 教师资格与调用范围

每个教师技能包声明：适用物体/姿态/可见性、调用前条件、结束条件、最多尝试、允许原语、版本和观测依赖。首版优先经过真实失败状态验证的短技能；代码审查通过只表示进入试验候选，不自动取得教师资格。

新程序先取得 `candidate_trial` 资格，使用单独的受限试验租约与预算；静态门禁、原语能力范围和本地保护允许后，可在既定工位范围内自动试验，不默认每次等待人批准。试验通过独立核验及回归后才登记为已发布教师。越出预设能力范围则停止或回退，不能由代码修改自己的门禁。候选轨迹先保留，动作监督资格另判。

执行可靠性、动作在 learner 中可表示、学生可观察必要信息，以及训练后的迁移效果分别登记。可执行恢复程序可以不适合教学；纯动作教师则可以提供未执行标签，但须证明标签来源可靠、状态对应及接口相容。

教师可分为任务纠正、普通反向任务和异常复位。对同一状态的三类行为可能选择不同动作，必须携带不同目标/角色。大模型给出语言、计划或参数后仍需由可执行技能实现；未执行的建议只进入查询标签流程。

技能执行期间，记录器持续工作。`regrasp()` 这样的高层工具调用应关联一组真实低层片段；只记录调用前后截图与“成功”文本，不足以训练中间动作。采样间隔必须匹配 learner 的 action 粒度；缺帧不靠插值凭空补齐 RL transition。

### 5.2 两条持久通路，不丢掉遥操经验

**实际遥操作、自动教师和学生的有效交互全部长期保留在真实事实日志/数据池。** 即使最终失败、某段不适合 BC，或内存 replay 淘汰了样本，原始轨迹仍按数据保留策略持久保存。内存 replay 只是采样缓存，不是唯一数据存储。

**未执行的 `(observation, teacher_action)` 单独长期保存到 teacher-label pool。** 保存查询时的学生观测、教师额外可见信息、目标、教师版本、动作契约、有效掩码和质量状态。通过验证后可以进入 actor 辅助监督；没有真实后果的标签不能进入真实 critic TD 池。

若教师输出 20 步预测 chunk，但只确认当前一步标签可信，只有对应动作监督 mask 为有效；不能以重复末步或零填充伪造完整未来轨迹。固定长度 learner 必须真的使用 mask，或只使用适配后可表达的片段。

对 flow VLA，最终 loss mask 还不充分：整块动作可能先进入加噪输入与 token 交互，未标注尾部仍影响有效位置。需核选定模型版本的动作输入、噪声、注意力和推理一致性；首版优先完整可信 chunk，部分标签分支未通过此项不得启用。完整历史教师轨迹可按真实连续窗口构造 chunk；孤立单步不能直接复制为全块。[OpenPI 参考代码](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/models/pi0.py)

教师建议的置信度需要在相关状态分布校准。教师看不到/不会时应拒答；低置信不是负样本真值，高置信也不是成功证据。

## 6. B4：数据视图与 learner 的接入契约

### 6.1 四类存储与用途

| 数据对象 | 保存内容 | 可供 learner 使用的条件 |
|---|---|---|
| `real_transition_store` | 学生、遥操、程序教师实际采用命令和真实后果；包括失败 | action/obs/goal/时序有效，奖励视图完整；算法允许其行为来源 |
| `teacher_label_store` | 已执行或未执行的教师动作标签，引用原观测与真实片段 | 标签质量与可学性合格；进入 BC/flow 等 actor 辅助损失 |
| `label_ledger` | 奖励、进度、质量、成功及撤销记录 | 追加新版本，不覆盖事实；未知/待定不是零奖励 |
| `training_view_manifest` | 原始记录集合、标签版本、过滤规则、归一化和采样配置 | 固定后开始训练；任何样本可反查具体命令和证据 |

已执行教师动作同时支持真实池与标签池时，用统一 transition ID 关联，不复制成两次真实交互。成功池是按独立验收与来源生成的视图；教师辅助成功可以是有效成功训练数据，但统计口径仍是 system-assisted。

### 6.2 目标、episode 与段边界

同一正向任务的学生→教师→学生通常保留 `episode_id`，每次交接开启新的 `segment_id` 与来源标记；不必为了换 owner 伪造终止。实际碰撞、任务失败、任务成功、时间限制、观测失效和人为课程截断分别记录，不压成一个含糊 `done`。

正向成功后切 B→A，应结束正向目标的轨迹，创建新的目标 episode。异常复位若改变目标，也要切边界；不能让正向 Q 跨越复位动作后，继续 bootstrap 到反向成功奖励。独立模型可通过独立流保证目标身份；共享模型必须有足够的目标条件。

换向前单独检查下一方向的 `init_set`。本方向成功不等于下一方向可开始：目标区内的边缘放置可能无法再抓。失败后根据实物状态继续、整理或停止，不按奇偶计数换向。教师回交同目标也须检查学生的 re-entry 条件。

`terminated` 表示该目标的真实终止，`truncated` 表示外部截断；超时能否 bootstrap 依任务 MDP/有限时域定义，在 learner adapter 中统一处理。监控器接管属于删失，不自动证明学生若继续一定失败。

### 6.3 三种 mask 分开

- `execution_mask`：原计划中哪些命令真的被采用并完成可识别执行；不是教师优劣判断。
- `td_valid_mask`：哪些真实片段有正确配对的 action、后果、目标与奖励，可训练 critic。
- `actor_label_mask`：哪些动作标签通过质量/可学性审核，可训练 imitation 辅助项；未执行标签也可能有效。

不能用一个 `is_success` 同时承担三者。实际失败动作可以是有效 TD 样本；未执行专家建议可能是有效 BC 样本；受辅助的成功轨迹不一定每一步都值得模仿。

### 6.4 chunk 与奖励的时间语义

若 learner 以宏动作更新，奖励累计与折扣必须依实际执行长度 `k` 或实际时间定义。低层等时步情况下：

`target = Σ(i=0..k−1) γ^i r[t+i] + γ^k × bootstrap_valid × Q_target(next_obs, next_action, goal)`

这里的 action 是选定边界的真实采纳动作序列，不是原始长计划。动作块中途 owner 改变时优先拆段；padding 必须被算法正确屏蔽。若算法只支持固定完整 chunk，要么补齐合法适配，要么明确丢弃其训练资格并保留原始数据，不能假装已经兼容。

奖励服务只按记录 ID 追加标签；`pending` 样本等待完整视图或进入事先声明的仅稀疏视图。势函数版本升级要同时重算两端与相关 bootstrap 边界。跨奖励版本训练前生成新的固定数据视图，禁止一个 batch 悄悄混入新旧目标。

### 6.5 按 learner 分别验收

ConRFT 的质量受控 BC/一致性监督、EXPO-FT 的成功数据 flow 更新，以及未执行教师标签辅助通路，均需针对各自实现核实。局部有效纠正不必达到整回合成功才保存；若原 learner 仅吃完整成功池，应新增明确的 actor 辅助数据入口，不把片段冒充完整成功。

| learner | 真实转移的主要更新 | 纯教师动作标签的路径 |
|---|---|---|
| EXPO-FT | critic 与 edit；合格成功数据可更新 base | 新增 actor-only batch 到 base flow 监督；绕开当前顶层对 critic 字段的耦合，不向 Q 编造后果 |
| ConRFT | critic、Q 引导与原一致性 BC | 从完整 transition batch 拆出教师 BC 分支；不改变标签缺少真实后果的事实 |
| HIL-SERL 已审 SAC | demo/online 转移训练 Q，actor 按 Q／熵改进 | 原版没有显式教师动作 BC；需要新增目标，不能只改插入字段 |

以上为静态代码审核后的拟议接入。具体入口与 SHA 见 [buffer 审计](research/teacher_buffer_code_audit.md)。

off-policy critic 可以使用来源明确的真实教师/遥操转移，但 target policy 仍要定义清楚；混合系统后续回报不自动等于纯学生回报。PPO 等 on-policy 实现不能给教师动作填学生 logprob 后当原生采样；如要采用，须另设计分流或修正，本附录不宣称统一 loss 已解决该问题。

**B4 阻断条件：**一个抽样 TD 样本追溯不到真实采纳动作；未执行建议带上了学生后继观测；动作空间不一致；mask 未进入实际 loss；目标或奖励版本冲突；训练成功池只有教师自我确认。停止受污染视图的训练，保留事实并修复视图，不删除失败证据。

## 7. B5：把“系统做成”与“学生学会”分别发布

### 7.1 不可变版本包

一次训练/发布登记 checkpoint、动作/观测处理、任务契约、控制变换、教师技能、执行监控器、奖励器、数据视图、learner 配置和评测协议的版本/哈希。原始路径不能代替内容身份。若只想比较 learner，固定教师、奖励和工位；若比较恢复代码，固定 VLA。

奖励模型或 VLA 表征改变可能使原监控器输入分布失效。它们不能因为接口维度没变就跳过联合兼容检查。回滚也要恢复相容的处理器、动作契约及依赖，不能只替换权重文件。

### 7.2 三套账与发布门槛

记录并分别报告：纯学生固定测试集能力；允许教师/恢复的系统能力及开销；自主训练窗口中的有效交互、人工分钟和中断。测试起态按物体位置/姿态/遮挡等预先分层，冻结抽样规则；不因候选难复位就剔除相应试次。

自动核验器是运行时裁判，仍需独立留出证据审计它的假阳性。离线人工审查不伪装为零前期人工。一次候选的部署决策至少回答：学生是否进步或达到预设目标、关键失败是否恶化、教师成本是否可接受、版本兼容是否成立。阈值、样本预算和允许的回归幅度应在试验前写入评测协议；本附录不凭空指定统一数字。

开发诊断集、允许反复比较的晋级集、最终保留审计集分别管理。晋级集不得声称完全未见；保留集一旦用于调代码／模型就转为开发资料。物理初态用实测分层和交错运行控制差异，不以相同 seed 宣称完全复现。

候选先登记，再加载到独立推理实例做静态/回放检查，最后在可交接状态切换。首版不在动作块中间换模型，不把旧模型的未执行 action queue 带入新版本。评测结果与发布记录绑定，未通过的候选不能因 Agent 判断“看起来更好”直接晋升。

发现奖励或教师标签错误时，撤销相应视图资格，并按训练 manifest 追溯已使用它的 checkpoint 及后继版本。暂停受影响版本晋级，必要时回到最近可信包重新训练；不能认为重标 replay 自动消除了已进入权重的污染。

### 7.3 不同闭环独立降级

| 故障 | 暂停什么 | 还能做什么 |
|---|---|---|
| learner／训练 GPU 失败 | 参数更新与候选发布 | 已验证冻结策略可在资源预算内继续采集；明确记作学习暂停 |
| 奖励服务暂不可用 | 要求该标签的训练视图；必要时暂停换向 | 留存事实，使用预先声明的独立稀疏视图或本地核验；不默认零分 |
| Agent／代码服务失联 | 新诊断、候选代码演化 | 在已发布技能覆盖范围运行，超预算则停止，不无限等待 |
| 控制、观测或 owner 不可信 | 自主运动和新任务 | 本地保持／停止、证据对账；离线分析可继续 |
| 存储满或事实日志失效 | 新学习采集；按契约停止新运动 | 保护已有日志、受控结束或保持；不继续产生无法追踪训练数据 |

## 8. 开发顺序与故障注入验收

先 mock 驱动、后接真实观测、再进行受控运动；先冻结 VLA 验证教师与数据链，再进行一次可审计更新，最后接持续正反练习。执行能力、数据质量和学习收益分开验收，不要求一次联调全系统。

下表全部是**待实现、待执行的验收项**。其中“零次旧命令执行”“无伪造 TD”等是逻辑正确性门槛；时延和误判率门槛由工位预检测量、任务预算与独立数据确定。

| 编号/桥层 | 注入或检查 | 应看到的证据 | 阻断边界 |
|---|---|---|---|
| T01/B1 | 故意交换关节顺序、单位、绝对/增量配置 | 命令在接口校验时被拒；带原契约版本错误码 | 任一错误配置能悄悄驱动实体，禁止运动联调 |
| T02/B1 | 注入旧相机帧、状态时间错位、缺夹爪反馈 | observation 标失效/降级原因，控制和 verifier 不伪装正常 | 旧帧被重打时间戳继续操控，禁止自主运行 |
| T03/B1+B4 | 请求动作被 IK/限速改变；关节因接触未达目标 | `a_rl`、driver command、实测状态三者均可区分，训练边界不漂移 | 用实测位移或错误空间回填 action，阻断训练 |
| T04/B2 | 两个 session、教师和遥操同时争同一 robot_id | 只有一个当前 owner 下发；另一请求明确失败/等待 | 任意双写通道，禁止真机接管 |
| T05/B2 | 延迟旧推理直到新教师 lease 已生效 | 旧 epoch 结果拒绝，驱动无相应命令 | 旧 chunk 在新 owner 后执行一次也不通过 |
| T06/B2+B4 | 第 7 步在途时打断 20 步 chunk | cancel receipt 与驱动日志吻合，尾部取消，长度/TD mask 正确 | 未确认停止便交接；计划长度冒充执行长度 |
| T07/B2 | 提交重试、ACK 丢失、Gateway 重启、网络断连 | 同 command ID 不重复运动；不确定执行隔离；旧 lease 失效 | 重放增量动作、双 Gateway 存活或未知状态自动复工 |
| T08/B3 | 教师工具执行时故意丢中间采样/日志写入 | 明确缺口与不可训练段；按本地策略停止接收新任务/运动 | 只凭首尾观测补造中间动作与奖励 |
| T09/B3+B4 | 查询正确教师动作但让学生继续原动作 | 教师标签持久存在，`executed=false`；actor 可读，TD 读取不到 | 标签被配学生后继状态送入 critic |
| T10/B3 | 在遮挡/边缘/错误物体等教师域外状态调用 | 教师拒答或转入可验证观察/停止；固定验收不放宽 | 教师只改目标、换物体或自报成功后进池 |
| T11/B4 | 正向接管后继续；再切反向和异常复位 | source segment 与 goal/episode 边界正确，Q 不跨目标串接 | 反向奖励强化正向错误动作 |
| T12/B4 | 混入旧奖励版本、pending 标签、错误 success | 新视图拒绝不兼容样本；撤销可追踪；unknown 不默认为零或成功 | 学习器无法说明本 batch 的奖励定义 |
| T13/B4 | 满足 input shape 但屏蔽动作、TD/BC mask 故意错开 | 小数据离线检查证实无效位置不贡献相应 loss，有效查询标签可贡献 actor 辅助项 | mask 只被保存却未用于 loss |
| T14/B5 | 教师越来越强但冻结学生不变 | system-assisted 提升、student-only 不变；报告不宣称学生学习 | 两种成绩混报，禁止算法晋升结论 |
| T15/B5 | 课程只挑简单初态；候选难复位的试次缺失 | 固定评测分层与实际抽样记录暴露偏移/缺失 | 删除困难试次才满足发布阈值 |
| T16/全链 | Cloud 不可用或大模型建议晚到下一 episode | 已发布本地技能在预算内继续，或本地保持/停止；过期建议只留离线分析 | 等云时机器人持续执行旧队列、迟到标签终止新任务 |
| T17/B5 | 模型包/预处理不匹配、发布中断、回滚失败 | 旧版仍可用或系统停在可交接状态；包校验失败明确 | 线上处于混合版本仍执行 |
| T18/B2+B3 | 在教师、恢复、观察、候选试验四类路径触发本地故障 | 同一 quiesce/停止协议生效，候选无发布教师权限 | 任一路径能绕过保护或自行放宽试验权限 |
| T19/B3+B5 | 本方向成功但下一方向抓取起态不合法 | 独立 init-set 核验拒绝启动，整理或记录中断 | 成功 flag 直接触发另一方向运动 |
| T20/B4+B5 | 撤销已经训练过的错误成功／教师标签 | 受影响数据视图、checkpoint 与后继发布可追踪隔离 | 仅重标 replay，继续无条件发布受污染参数 |
| T21/B4 | 只改变未标注 chunk 尾部填充值／噪声，检查有效位置；再检查推理语义 | 明确输入/attention/loss 如何处理未知尾部；未通过只用完整可信 chunk | 仅 loss mask 就宣称部分 flow 标签适配成立 |
| T22/B4 | 间断接管帧 10、30、90 入池；环形覆盖及保存重载 | 以帧 ID、episode、source segment 核对图像历史、next、动作与长度不被存储邻接伪造 | 将数组邻接误当真实时间连续；不得跨缺口重建 chunk |
| T23/全链 | 独立停 learner、Agent、评分服务或耗尽存储 | 状态与降级表一致，有效采集／学习暂停分别计账 | 采集不停却丢日志，或停学仍宣称持续改进 |

对于所有阻断，处理范围与证据相匹配：控制/感知不可确认时停止自主运动；标签污染时冻结相关训练视图和发布；单条可定位坏样本可隔离。不能用“安全停住”充当自主学习已完成，也不能为延长无人记录隐藏中断。

进入自主窗口前，工位 manifest 中不得仍留空的参数包括：机器人同学确认停止／保持时间、控制边界及观测新鲜度；任务同学确认各方向 init-set、核验容差、unknown 的观察与退出预算；教师负责人确认调用范围、试验次数与超时；学习同学确认动作／奖励时间单位、示范保护和 batch 路由；评测负责人确认每版试次、晋级规则与最终审计时点；系统同学确认日志高水位和服务降级预算。上述参数均由预检和任务需求确定，不使用文献数字填空后直接自主运行。

首轮交付验收不以“代码能启动”结束。至少要演示：一次真实学生失败→可确认接管→教师逐步轨迹持久保存→真实池和未执行标签池分流→一个训练样本反查完整证据→候选在无教师条件下被独立评测。学习效果尚未出现时，应如实报告已完成的是基础链路。
