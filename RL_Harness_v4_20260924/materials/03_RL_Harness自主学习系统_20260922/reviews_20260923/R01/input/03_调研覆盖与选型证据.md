# 调研覆盖与选型证据

更新：2026-09-22。用途：供开发者核对方案依据、开放范围和兼容性，不替代主技术方案。本附录整理本会话已经完成的论文、项目与源码审核，补核了少量关键原始链接；未安装框架、训练模型或操作机器人。

项目约束：松灵 ALOHA 类双臂平台，首项任务仅使用一臂抓放；VLA 学生可能几乎不会当前任务，可采少量示范并进行人工接管；不采用 ACT；希望减少纠正、复位和现场值守。机器人具体型号与 GPU 尚未确认，不能把“松灵”直接等同于论文中的 PiPER，也不能预设部署算力足够。

## 1. 怎样读这些表

**核验深度**分为：关键链路静态深审、源码抽查、论文／项目预筛。静态深审仅覆盖标明的链路，并非全仓审计或运行复现；“有真机实验”描述作者证据，不表示本项目已验证。

**采纳层级**分为：必做基线、优先技术预检、条件候选、机制参考、暂缓部署。层级服务于本项目，不是论文质量排名。源码可读、许可证明确、任务数据／权重齐全、实体驱动完整、独立复现充分，是不同条件；未知处明确保留未知。

当前统一选择是：**Zetta 骨架优先技术预检，但许可未清前不能无条件 fork；机器人只保留一个物理执行 runtime。先做自动纠正 SFT／DAgger 基线；已有 π 系模型链路时，优先检查 EXPO-FT＋持久教师标签桥，可信未执行建议也可通过新增监督通路利用，不硬要求频繁完整成功。ConRFT 保留为完整动作头需求、π 路线迁移限制或实测效果支持时的条件备选；混合经验积累后考虑 STEAM。**

**联合审查新增门槛：**EXPO 的教师标签路线不等于任意单步标签已能训练原生 π 动作块。部分标签须核带噪输入、未知尾部、注意力和推理语义，不能只乘输出 loss mask；首版优先完整可信 chunk。若教师只能提供单步且此适配不可达，ConRFT 单步完整头的可行性相对上升。[审查依据](research/final_joint_review.md)

### Zetta 为什么上升为首个预检对象

固定审核版本为 `1fee179644d52c32fa5a7728751cf0853a29b9c0`。已读的代码证明它具有真实协议约束，不只是一张架构图：会话绑定、操作序号、互斥执行、结构化恢复和版本 gate 都可以减少重复建设。[执行入口](https://github.com/air-embodied-brain/Zetta-Embodiment/blob/1fee179644d52c32fa5a7728751cf0853a29b9c0/rollout_runtime/workers/env_worker.py#L1409)、[版本契约](https://github.com/air-embodied-brain/Zetta-Embodiment/blob/1fee179644d52c32fa5a7728751cf0853a29b9c0/zetta/evolution/models.py)

不能直接迁移的部分同样明确：已开始的 env step 不能被现有取消逻辑打断；逐步 schema 不保证实际动作和 teacher 来源齐全；物理关节保护并未实现；仿真的 seed／状态摘要不能直接充当真实复位身份。[取消实现](https://github.com/air-embodied-brain/Zetta-Embodiment/blob/1fee179644d52c32fa5a7728751cf0853a29b9c0/rollout_runtime/workers/env_worker.py#L2789)、[消息契约](https://github.com/air-embodied-brain/Zetta-Embodiment/blob/1fee179644d52c32fa5a7728751cf0853a29b9c0/rollout_runtime/api/messages.py)、[评测代码](https://github.com/air-embodied-brain/Zetta-Embodiment/blob/1fee179644d52c32fa5a7728751cf0853a29b9c0/zetta/evolution/gating.py)

因此选择的是“**优先核查可复用骨架**”，不是“论文已替用户完成真机工程”。详细桥层与反证见 [Harness 补充审核](research/autonomous_teacher_harness_survey.md)。

### 本组最重要的选择依据

要先验证教师是否能在**学生实际访问的失败状态**给出有用动作。自动复位后做一条整齐示范、为学生打分、生成技能调用文本，都不自动满足这个条件。

监督学习可以使用未执行但可信的教师动作标签；真实 RL replay 必须使用实际执行动作与真实后果。教师接管后的后续状态由教师诱导，应如实标记，不能称为全部来自未接管学生的轨迹。一个“teacher=true”字段不足以表示动作质量、任务目标与时间对齐。

因此先比较“固定 VLA＋Harness”与“Harness＋可信纠正 SFT／DAgger”，再检验 RL 的额外收益。选用自动门控、只标接管片段时，应明确是选择性纠正聚合，不继承原始全状态 DAgger 的全部理论条件。详见 [教师与 DAgger 调研](research/harness_teacher_dagger_survey.md)、[教师—RL 兼容性审核](research/teacher_rl_compatibility_review.md)。

### EXPO 与 ConRFT 的条件选择

选择不应依赖统一的起始成功率百分比。关键是教师能供应哪一种可信数据，以及哪条模型和数据管线已经成熟。**本节纳入最新教师 buffer 审核，修正“EXPO 必须先获得频繁完整成功”的过强门槛。**

- **现有 π 推理／SFT 链路成熟，能够获得可信完整轨迹或可信 shadow 动作标签：**优先预检 EXPO＋独立持久教师标签通路。其 base flow-matching 本身不需要教师动作的 reward/next_obs；当前上层 batch 仍与 critic 字段耦合，必须拆出 actor-only 转换与采样，不能填假后继。局部短建议还需部分动作 mask，完整可信 chunk 则更容易对齐现有监督目标。
- **需要独立完整动作头，π 路线接口或资源不合适，或者实测 ConRFT 更有效：**再选择 ConRFT。它已有 consistency BC，但也需把纯标签从 transition batch 分离；“局部纠正多”本身不再构成优先迁移 Octo 的充分理由。
- **已有丰富混合经验，允许采集与训练分时运行：**认真比较 STEAM＋CFGRL 与同数据纠正 SFT。不能把“批次更新”当成永远低于在线 actor–critic 的选项。

真实 replay 与教师标签库可以使用一个底层存储，但必须独立分型和采样：前者供 TD，后者供 BC／flow-matching；历史真实 demo 可以复用，未执行建议不能借用学生真实动作的后果。持久标签库还需保护初始示范，不能假定环形 demo replay 永远保留所有数据。[EXPO actor 与调度代码](https://github.com/pd-perry/expo-ft/blob/803381fc3b4c91a0c47904f1b688fc5e35904f50/expo_ft/agents/alg/expo_ft.py#L665)、[HIL-SERL SAC loss](https://github.com/rail-berkeley/hil-serl/blob/c32939bccb65f3b8c43a9f9add3d322d4ab0264a/serl_launcher/serl_launcher/agents/continuous/sac.py#L137)

这三者均未替代自动教师、物理复位或独立评分器。最新数据语义以 [教师 buffer 源码审核](research/teacher_buffer_code_audit.md) 为准；另见 [联合选型](research/joint_rl_selection.md)、[ConRFT 实现审核](../02_自主RL调研_20260922/research/conrft_implementation_audit.md)、[EXPO 实现审核](../02_自主RL调研_20260922/research/expo_implementation_audit.md)、[UniSteer 可达性审核](../02_自主RL调研_20260922/research/unisteer_feasibility_audit.md)。

## 6. 影响力怎样审计，哪些结论没有证据

本附录主要采用可追溯的正式发表、作者机构、源码开放范围、具体复用链条与真机协议评价可信度。DAgger、ThriftyDAgger、RLIF、HIL-SERL、ConRFT、MEDAL++ 等有正式会议／期刊线索；2026 年的新预印本与作者宣布接收状态分别记录，不能把机构名当成复现担保。

本会话曾保存带日期、提供商和条目范围的 [影响力快照](../02_自主RL调研_20260922/03_影响力与开放性快照.md)，但不据不同来源的单条引用数制作总排名，也不在本附录重新拼出不可比数字。GitHub stars 不等于复现团队数，下载量不等于真机使用者；已关闭 issue 不等于算法性能复现成功；官方示例跑通也不等于满足本任务的无人值守目标。

以下断言目前都不成立：

- 所列源码已经全部在用户机器人上运行验证。
- Zetta、RoboRSI 或 ENPIRE 已经交付“任意弱 VLA＋通用自动教师＋RL＋自主复位”的完整产品。
- 自动生成恢复代码就已获得物理恢复能力。
- 教师把系统救成，就证明学生策略本身提升。
- 不同论文的初始／最终成功率可以不考虑任务、示范、人工预算与评测协议直接排序。

最先应通过的是动作、观察、奖励／终止、目标和版本五种语义的一致性。正向、反向和失败恢复的数据须带清晰目标；未执行的 chunk 尾部不能写成真实转移；复位与故障接管不应自动变成任务失败奖励。先用可追溯小样本证明链路，再决定在线更新或分批更新，最后扩大自主运行时间。
