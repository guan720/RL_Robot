## 1. 先枚举本轮技术点

1. SmoothRL 的 C/E/D 分段、固定推理预算、价值动作梯度、原论文 2n bootstrap 与原始动作空间实例。
2. ARLI 的冻结 decoder、latent 动作、已承诺动作和较晚观测，以及与首版起点信息集的差异。
3. Thinking While Moving 的并发 Bellman：旧动作继续执行，新动作计算不是阻塞环境。
4. 本项目一槽延迟 MDP 的 X、U、next queue、奖励区间和折扣单位。
5. request admitted、result committed、physical activated 三阶段是否混同；终局后取得原请求结果是否伪造行为动作。
6. 终局早发生晚确认、提交回执已存在、先超时后成功、稳定证据尚不充分的时间排序。
7. 正常前驱遇到下一槽终局或接管时，target 是否偷看未来、替换后继队列或制造零价值。
8. 边界附近接管、目标切换、旧 epoch/goal 结果与 prime 槽的处理。
9. C/E/D 对 actor 的动作梯度、BC 标签和物理执行资格是否独立；共享参数和 mask 的边界。
10. 现场能否从记录复建时序、输入、动作和训练视图；未知执行、奖励 pending 与异常选择偏差是否如实保留。

## 3. 本轮采用的信息集与记号

在槽起点 t_k，信息集 F_k 包括当时已经收到的观测与历史、目标/任务契约、真实 C_k、控制租约/epoch、固定调度配置。实际请求另外冻结权重、预处理/normalizer 和随机性；U_k 必须是这些已冻结信息的函数。槽中才到达的新图像、成功判定、接管结果，不属于 F_k。请求虽在之后完成计算，不等于读取了之后的信息。

对合法普通窗口：X_k=(h_k,g_k,C_k,ξ_k)，实际旧队列 C_k 产生本槽物理变化；请求结果 U_k 成为 C_{k+1}。样本的 R_k 覆盖本槽 n 步，next observation 与 next queue 是同一边界的事实。target 为 R_k+γ^n Q_target(X_{k+1},π_target(X_{k+1}))，其中 target actor 输出再下一槽动作。

信息闭合不等于已证明完全 Markov：遮挡、接触和隐含速度仍可能要求更多历史/估计。06:97–101 已保留此边界；本轮不将其作为文档承诺过度。

## 4. 问答、反例与逐项判定

### Q1：当前槽执行旧 C，为什么能训练 Q(X,U)？

答：U 的即时环境作用是改变后继队列，物理回报在下一槽体现。检查 06:79–85、107–128，状态转移与折扣自洽。

手算：令 n=1、γ=0.9、标量位置 x，物理演化 x'=x+C，下一队列 C'=U。即时奖励 r=C。则 Q(x,C,U)=C+0.9 V(x+C,U)。取 C=2、U=5，当前奖励应为2，未来的5通过下一状态学习。若把当前奖励替换成5，却仍以(x+2,5) bootstrap，就会重复/错位使用未来效果；冻结稿禁止此做法。**PASS。**

### Q2：项目目标是否只是把 SmoothRL 的 2n 改成 n？

答：不是。原论文算法1跨两段收集回报并在 t+2n 使用实际 next committed；项目在 t+n 把当前 U 明确写成后继状态中的队列，target actor 只选择再下一槽动作。06:130–134、322 与 07 §10 明示这一差别。

反例：t=100,n=6，若只收100–105奖励，却拿112的观测 bootstrap，即便折扣写γ^6也不成立；若收100–111奖励，仍拿106的状态 bootstrap，又重复未来区间。冻结稿例1可以判掉两种实现。**PASS。**

### Q3：request 存在但 U 未激活，是否一概没有 TD？

答：不能一概否定。普通槽要求真实准时 commit 和 C_next=U；当前 C 真终止时，原先已接纳且输入冻结的请求可以形成 terminal 样本。影子查询没有事前 admission，不能借此进入 TD。依据 06:63–95、194–211。

反例：F_100 下同时生成 A 与 B，但只有 A 的控制请求事前被接纳。C 在第3步终止。A 的原在途计算后续返回，可配本槽终局回报；B 不能因为数值类似或也预测成功就取得相同真实请求的后果。若 A 结果丢失，也不能拿 B 顶替。**PASS。**

### Q4：终局后等待原 U，是否引入未来信息？

答：是否泄漏取决于计算输入，不取决于计算结果到达时刻。冻结输入、权重和随机性的同一次在途计算可继续，仅撤销执行资格；终局后重拍图或换模型生成的新 U 不可替代。06:198–200、07:205–213 已明确。

反例：t100请求固定seed=7；t103目标完成；t104 learner发布新权重；t105原请求返回。保存原权重结果成立；使用新权重重算并把结果挂到旧 request 不成立。若系统无法证明原结果身份，应隔离而非猜测。**PASS。**

### Q5：终局晚确认，而 U 已提交甚至发生终局后的机械动作，如何记账？

答：按任务证据充分成立的事件时刻切学习 episode，同时保留真实 commit/activation 事实；终局后的运动单独归档。奖励服务到达时刻不是终局时刻。06:227–231 专门覆盖此项。

时间线：t100请求；固定判据所需证据在本槽第3步结束时已充分成立；t106已有真实U提交/激活；t110评分回传。若γ=0.9、只有第3步奖励1，本槽target=0.9²=0.81，不能改成γ^10，也不能删去t106回执伪造“从未提交”。反例另一支：若稳定性证据一直到t108才充分，不能把首次接触t102回溯成终局；它与前一支不是同一事件序列。**PASS。**

### Q6：先超时后成功，能否追认 terminal TD？

答：不能。按最先破坏契约的事件分类。06:231、263–268，07:219–223 明确把超时、失联、接管和真正终局分开。

时间线：t100接受请求；t106结果未返回，deadline miss并保持；t108保持/恢复动作促成成功；t110迟到结果到达。旧槽普通协议已在106失效，后续成功不能把它升级成合法terminal。反之，若真实终局证据在103已充分成立，106之后计算结果只作日志，不能把终局后撤销物理执行资格误称为终局前超时。判定依赖事件时刻及证据，事件无法定位则pending。**PASS。**

### Q7：下一槽第3步终止时，正常前驱怎样得到正奖励？

答：下一槽自己的实际请求构成 terminal critic 行，前驱保持普通一槽目标；通过 critic 和target网络更新传播，不依赖未来终止事件临时选择target。依据06:213–219、294–298。

手算：n=6、γ=0.9，前槽全零，后槽第3步奖励1且终止。后槽target=0.9²=0.81。确定性算例中价值学到后，前驱target=0.9⁶×0.81=0.43046721=0.9⁸。若未来一半终止回报1、一半总回报0，则无条件V=0.5；终止时回填1、否则用V=0.5，会得到0.75。乘γ⁶后错误值0.39858075，正确值0.2657205。冻结稿的统一递推避免这个特定选择偏差；不声称有限函数逼近一定学准。**PASS。**

### Q8：下一槽被接管，是否必须删掉全部前驱？

答：不必。前驱已完成的一步事实不因未来行为改变；保留当时真实 next snapshot。被接管槽隔离，不能把中断当零价值。依据06:146–148、246–256、304–306。

时间线：t106确认C_next=U，t108强制改成H。100–105前驱可保留；106槽不再满足C全槽执行。反例：如果t106的队列提交、快照和接管并发，无法知道快照对应U还是H，则前驱本身的后继不确定，必须一并隔离。不能用t108看到的H倒填t106，也不能不看证据沿整个episode删除。**PASS。**

### Q9：保留正常前驱是否等于已经评价了“含未来 Harness”的真实系统？

答：不是。其bootstrap定义是目标policy在相同队列条件下的价值；首版未建立任意中途接管的宏动作模型。隔离虽阻止假转移，但可能造成动作/困难状态的选择偏差。01末段、06:250–254和07:221–223承认这些限制。

反例：困难状态90%被接管，只有容易状态形成完整槽。即使正常池TD误差很小，也不能推出全部在线运行已无偏评价，更不能把救回成功计为独立policy成功。冻结稿要求报告隔离/接管比例并保留policy独立评估；这是明确的设计边界与实验gate，不是缺少定义却声称已实现。**PASS。**

### Q10：C/E/D 的梯度边界能否由一个执行 mask 代替？

答：不能。真实C是状态，当前动作变量只有E；D不进入价值动作，BC仍有独立标签资格。06:154–180给出计算图和四类含义，07:217另声明C内终局行的actor采样规则会改变状态分布。

手算：构造Q(C,E)=C+2E，loss=-Q。真实C固定时∂loss/∂E=-2；当前proposal的C预测、D预测未进入Q，故对应输出导数为0。若将proposal的C预测填入真实C位置，会产生-1的错误动作梯度。共享网络参数更新可能改变C/D输出数值，不代表这两路获得了该Q动作导数。终局行不作actor Q更新是已声明采样规则，不冒称无偏完整policy gradient。**PASS。**

### Q11：ARLI 的中途观测可以直接拼入当前首版 X 吗？

答：不可以。首版把U绑定F_k；更晚可见信息若要用于决策，必须另设决策时刻、剩余承诺、延迟和target划分。06:272–280已定义为独立扩展；这与ARLI实际在更晚分支选择latent的原理相容。

反例：t100物体静止，t103随机滑落，Harness据t103图像生成救回动作。把救回动作当t100普通同信息标签，会把t100不可见扰动偷偷带进标签定义；若声称那是实际U_100，更伪造了行为事实。原始纠正可保留，特权BC可单独建模；首版没有把它无说明混入。**PASS。**

### Q12：A→B 完成后共享参数，能否跨到 B→A bootstrap？

答：不能。目标是状态/奖励语义的一部分；共享θ和Q参数并不合并两个任务的终局。02:259–265、06:266要求结束旧目标、废止旧计划并重新prime。

反例：正向已经成功1，下一方向回程也成功1；若正向非终止继续bootstrap到反向，将价值从1变成1+γ^m，奖励语义改变。另有旧goal的U在换向后返回，即使动作shape相同，也应因goal/epoch不匹配拒绝，而非写入新队列。**PASS。**

### Q13：prime 和发布更新是否会伪造策略贡献？

答：首个C可来自已验证保持动作。存在真实请求时按相同定义训练请求U；尚无请求的PRECHECK只保存事实，不虚构请求/前驱。权重与normalizer在交接边界原子切换，表征缓存重算或固定视图。见06:219、256、267–270，02:273–277。

反例：初始保持时物体已满足目标，系统尚未提交任何policy请求；不能捏造U并记一次policy成功。另若同形状normalizer把数值0.5从5毫米改成5厘米，仅保存版本字符串不能让旧动作转移继续同义；冻结稿要求视图隔离或经验证迁移。**PASS。**

### Q14：现场记录是否足以复建上述时间线？

答：按设计要求足够定位必需证据；最终消息格式与真机采集尚待实现。02:87–95、142–146、354以后，06:21–34、65–85要求原始观测/源时钟、绝对帧映射、采纳命令/部分生效、事前request、冻结输入与seed/权重、commit/activation、next queue、奖励/标签版本及视图依赖。

复建方法：先固定训练视图版本→由request定位X/goal/C与权重→从原始索引重建U和绝对帧→核对准时commit及边界队列→按逐帧反馈重建R及异常先后→按终局事件时间裁分→再赋TD/BC/actor资格。若只有executed_length=6，没有原chunk索引，则不能区分0–5与6–11；若ACK丢失，则不能重放增量动作来“补证据”。冻结稿明确拒绝这两种补造，也要求未知/pending不发布完整TD。**PASS。**

## 5. 未实测 gate 与必要问题分开

尚需开发验收的内容包括固定n/deadline可行性、真实日志持久化与事件排序、原请求身份保持、原始数组复建、边界并发重放、自动微分mask、target数值、延迟终局的视图回修、标签撤销与checkpoint依赖。02的T10–T13/T16/T20/T26和06的算例为其验收入口。本轮没有代码或真机证据，不能把这些gate写成通过。

但冻结稿已给出方法选择、正常/terminal/隔离分支和可判定反例，且明确未实测，故“尚未运行”本身不构成本轮必要问题。有限历史的状态充分性、异常隔离的选择偏差、完整动作头冷启动和共享双向收益也均为已声明边界，未被包装为数学或实验保证。

本轮未发现：错误的来源归因、未定义却直接承诺可用的目标、时间线自相矛盾、靠未来成功覆盖普通前驱、用户条件被隐式改为成熟外部策略等必要缺陷。无需为本专项修改冻结稿。
