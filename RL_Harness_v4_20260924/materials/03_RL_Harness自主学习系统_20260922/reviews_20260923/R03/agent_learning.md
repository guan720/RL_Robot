# R03 独立学习兼容性审查

审查对象：`R03/input/` 六份冻结 Markdown；只写本报告，不读取其他轮次或本轮其他审稿结论。判定针对设计的可实现性与数据到 loss 的一致性，不将尚未训练、尚未真机验证本身判为失败；连续通过次数不参与判断。

## 先枚举关键点（打开原始证据前）

1. 同一组 θ 的正反目标要贯穿 actor、critic、target、数据 loader、评分和发布。
2. 完整动作头与弱策略／零成功率可以相容，但需明确可用初始化数据、动作与监督粒度，不能靠纯零奖励自行产生正确行为。
3. 队列状态必须含真实 C；U 只选下一槽 E；C/D 不能获得当前 actor 的 Q 动作梯度。
4. 普通／终局 TD 必须属于同一事前决策定义；终局正奖励应沿统一 Bellman 链传播。
5. 示范、真实动作、纯查询纠正应持久保存并拥有不同 loss 资格，不能用伪造后继塞入统一 replay。
6. 同信息集纠正与特权／事后纠正应分支定义；DAgger／DIDA 不自动保证 GPT 纠正正确或可模仿。
7. 单步反馈纠正不能重复制成固定 n 步标签；部分标签必须有真正可执行的损失路径或明确暂不使用。
8. ConRFT 的完整头、HIL-SERL 的 demo buffer、RPent 的 Flywheel 分别能提供什么，必须沿源码主链核查。
9. 完整抓放能力要在无 Harness 动作辅助下评测，不能用运输、接触或恢复由 Harness 代做的系统成功替代。
10. 同一 checkpoint 双向晋级，动态 Harness-DAgger／BC 与 BC＋RL 使用公平的数据、纠正与交互预算。

## 反例驱动问答

下列 `01/02/06/07/09` 均指本轮 `input/` 下对应文件，位置为冻结稿行号。每项的 PASS 表示设计已给出可检查的处理方式，不表示对应测试已经通过。

### Q1：换 goal 是否真的能改变同一个 policy 和 Q，而非只改日志？

**位置：**01:85–106；02:87–93、219–225、333、348；09:56–60。

**反例：**物体在 B，同一画面一行目标 A、一行目标 B；loader 把二者覆盖成一个全局 task。ConRFT 的 `create_batch_tasks(tasks, config.batch_size)` 就是迁移时需要改的具体位置；RPent 也有 requested_prompt 与 effective_prompt 不同的真实路径。

**回答：PASS。**文档要求规范 goal 贯穿 actor、Q、target、replay、rubric，并要求 T17 检查计算图与小样本条件化行为，已超出“改字符串”层面。

**最小修法／落实点：**无需阻断性修文。实现时移除单任务全 batch 覆盖，从每条样本读取 goal；让正反各一行经过真实 loader，再检查 actor/Q/target 输入、标签与梯度。建议在 07:89 附近补出 ConRFT 训练入口 415–432 的覆盖位置，便于开发定位。

### Q2：零成功率与完整动作头冷启动是否存在可达学习路径？

**位置：**01:5、34–38、208–218、271–281；07:39–51、143–151；06:169、237–243。

**反例：**重新随机初始化动作头，只有零奖励随机失败数据，Harness 又不给任何可信动作。此时“完整动作空间”不创造抓取先验；critic 没有改进方向。

**回答：PASS。**稿件未把零初始成功率等同零信息：允许少量示范、失败中的正确片段、可信同协议纠正，允许保留可训练原头或用示范初始化。P1/P2 要求基本可控或可靠局部纠正，07 明确拟合失败时调整路线。它没有声称无纠正、无有效探索时 RL 必能启动。

**最小修法／落实点：**按现有冷启动门槛，用同一头拟合两向可信动作并检查闭环；不能只展示训练 loss 下降。若本工位实际拿不到合格标签，该实施分支不能进入自主学习，而不是把缺失信息写成“待调超参数”。

### Q3：同步历史示范能否直接成为队列头的普通 BC／TD？

**位置：**01:138、222–225；07:117–131；06:41–63、169–190。

**反例：**历史遥操在看见新图后立刻动作，却给它补一个空 C，宣称其动作是提前 n 步选出的 U；图像和动作顺序真实也不能使这个新定义成立。

**回答：PASS，但只在稿件明示的范围。**历史示范可作与原输入／时刻匹配的预训练；没有可恢复队列不能进入本宏 TD。首版队列头的直接监督另有同 X、同 C、同时间窗的完整 U 路径。不能将“历史可预训练”扩写成“当前队列 BC 可以无条件直接吃”。

**最小修法／落实点：**无需改队列理论。锁定实现配置时，明确历史预训练阶段和队列训练阶段各自的输入格式与参数迁移；没有真实 C 的历史行不能伪装成普通队列 BC。用同协议采集的完整 U 完成延迟模式适配，这已是 06:169、239 的定义路径。建议把这个阶段边界在 P1 配置中写得更直白。

### Q4：当前槽执行旧 C，当前 U 尚未执行，配 R 是否错误归因？

**位置：**06:41–103、111–148；01:184–194；07:175–201。

**反例：**相同图像与 U，旧 C 一次正接近物体、一次正离开；若 Q 不看 C，就会混合不同后果。另一个错误是用帧 100–105 的回报却把 next state 写到 112。

**回答：PASS。**这里动作 U 先改变队列，`X_next.C=U` 是可观测环境后果；物理奖励晚一槽出现不破坏增广转移。普通 target 对应同一 n 步边界，而非把下一槽奖励偷移过来。并发 Bellman 文献支持建模方向，具体一槽实现仍是本项目定义。

**最小修法／落实点：**按 T10 和 06 例1逐字段核对 request、commit、C、next queue、奖励帧与折扣。不能将相同 tensor shape 当作同步 learner 已兼容的证据。

### Q5：旧 C 先完成任务，正奖励是否仍能传回真正选出 C 的前驱？

**位置：**06:192–231、294–298；07:203–217；02:327。

**反例：**终止后取消全部计算，随后丢弃所有未激活 U 的行，稀疏成功标签便没有对应 terminal critic 样本。另一个反例是仅在下一槽成功时给前驱回填实得奖励，未成功仍 bootstrap，按未来事件选择 target。

**回答：PASS。**保留事前真实请求的冻结结果，以该请求的 terminal TD 训练 Q；前驱继续统一 bootstrap。手算例 `n=6, γ=0.9, L=3`：终局为 `0.9²=0.81`，学到后前驱传回 `0.9⁶×0.81=0.43046721`，时间折扣相符。终止行的 actor Q 更新被明确关闭，并承认这改变 actor 采样分布。

**最小修法／落实点：**T11 需同时检查日志保留与参数更新链；只验证 terminal flag 不够。若原请求结果不可恢复，保持事实并隔离，不能补任意 probe U。未发现需新增终局模型的缺口。

### Q6：DAgger 查询未执行，是否仍有真实的 loss 入口与持久性？

**位置：**01:120–136、220–228；02:205–217、243–257、331–332、365–369；09:38–46。

**反例：**Harness 建议动作 B，但机器人执行 A；为了塞入 replay，把 A 的 next observation 和 reward 配给 B。或者只保存在有限环形 replay，初始示范被新失败覆盖后就丢失。

**回答：PASS。**稿件将纯查询保存为 CorrectionLabel／独立监督视图；不制造 next observation。初始示范保护分区、事实长期保存、内存缓存与归档分开，真实动作与纯标签共享 ID 去重。可信完整 U 可以直接进入 BC，TD 资格另判，不会因未执行便全部删掉。

**最小修法／落实点：**按照 T15/T16 从持久存储重载，展示查询标签产生 actor 监督梯度且不产生 critic TD；保护分区经过 replay 绕回后仍存在。RPent 原 recorder 必须新增追加落盘，这已在 09:44 明示。

### Q7：DIDA 能否为后来才看到的纠正提供原理依据？

**位置：**01:130–138；06:182–190；07:225–231。

**反例：**相同早期画面和 C，在执行中受到向左或向右的随机扰动；晚到教师给相反纠正。把未来画面藏入训练输入产生部署信息泄漏；反过来宣称这类标签绝对不能模仿也过强。

**回答：PASS。**稿件区分首版同信息集 BC 与 DIDA 式特权扩展，没有把其教师能力假设视为本项目事实。特权标签长期保留，但首版不自动混入普通 BC；可观察性、多模态、信息差被明确列为扩展问题。

**最小修法／落实点：**新增分支时才定义延迟学生输入、教师额外信息和监督分布；不能只把 `valid=true` 打开。现有主线已有同信息集完整 U，故此扩展尚未实现不构成主线 FAIL。

### Q8：单步反馈纠正是否被冒充完整 n 步学习动作？

**位置：**06:165–190、237–255；02:257、330；09:109–113。

**反例：**n=6 时，Harness 只在帧 108 看到抓空并标一个闭爪动作；复制为六帧，或与后续根据新观测生成的五步拼成 `U_106`，都改变了决策信息与时间。flow 头即使最后遮 loss，未知输入也可能通过 token 交互污染有效位置。

**回答：PASS。**稿件明确禁止复制和倒拼；首版完整 U 可以直接监督，孤立微步保留且暂不进入不相容分支。这里未承诺所有存下的单步纠正都立即有训练资格。有限研究范围内，选择完整窗口路线是定义明确的实现路径，不必先发明部分 flow loss。

**最小修法／落实点：**在动作头配置中选择直接 n 步 E 还是 H 步输出并固定标签索引；没有实现并验证的部分标签分支保持关闭。需要吸收孤立微步时必须另给模型输入／加噪／损失定义，不能用“待测相容分支”默认宣称已吸收。

### Q9：ConRFT 能否原样承担本方案的 BC＋RL？

**位置：**07:69–73、85–91；02:221–257；01:212–228。

**反例：**直接复用 ConRFT 在线 sampler，混合 batch 中的自主失败动作同样进入 `x_start=actions` 的 consistency 重建；再声称“只模仿可信 Harness 标签”。此外它的单步 7D shape 与缺 goal/C 的 critic 不能因接口名字相似自动变成队列头。

**回答：PASS（须按稿件改造，不能原样复用）。**文档声明独立可信监督资格、拒绝无条件克隆失败，并将 goal-aware critic、chunk/queue、独立纠正采样列为本项目改造。源码抽查支持这些迁移边界。

**最小修法／落实点：**给 BC 与 TD 分别构造 batch/权重，避免 consistency 分支仍读取整份混合 replay actions；保持完整原始动作空间但新增真实 goal/C。建议将这条“原版重建覆盖混合 batch”的具体风险补进 07:89，属于增强开发提示，不是现稿相反地授权了错误做法。

### Q10：HIL-SERL 的 demo buffer 是否已实现 Harness-DAgger 动作监督？

**位置：**07:93–95；02:211、221–223；01:241–242。

**反例：**删掉一条 demo 的 action，只保留同一个 observation，默认 SAC actor 的直接监督目标并没有失去一个“专家动作回归项”，因为该项根本不存在；demo actions 主要作用于 critic。

**回答：PASS。**源码 `policy_loss_fn` 采样当前 policy 动作后算价值与熵；稿件已准确指出 demo 回放不等于 BC，并要求新增 Harness BC。将真人接管源换成 GPT 不会自动改变 loss。

**最小修法／落实点：**在实现中用查询 label 的 perturbation/梯度检查证明显式 BC 被调用；不能只检查 demo buffer 大小增加。既有 T14/T15 与 07 的改造要求已覆盖。

### Q11：RPent 失败数据、双向数据与完整任务是否能经学习桥正确流通？

**位置：**02:43–60；09:38–46、56–60、98–113；01:259、283–300。

**反例：**让 Flywheel 成功导出器承载全部 RL：零成功初期没有数据；正反 task_language 不同会被拒绝。另一个反例是 Harness 全程运输，VLA 只抓住物体，系统成功率上涨却宣称完整 policy 学会。

**回答：PASS。**现稿明确失败 RL 直读事实视图，不绕成功导出；成功 BC 若暂复用则分向导出后保留 goal 合并。完整抓放由同一 policy 无动作辅助评测，运输不能从测试任务删除。静态源码和 RPent 论文的分工均支持这些必要改造。

**最小修法／落实点：**以一条正向、一条反向、一条失败、一条纯查询作持久化到 loss 的联调例；同时执行完整任务无辅助评测。来源中有 proposal 不代表已有本项目 query-label learner，这一点不能在接入时省掉。

### Q12：双向共同发布与动态 BC 对照是否足以防止虚假 RL 收益？

**位置：**01:38、87–106、289–298；02:271–291、340、344、350；07:99–113、143–149。

**反例：**挑正向最好的 θ1 和反向最好的 θ2 合报；或给 RL 在线纠正，BC 只用最初示范；或 RL 用更容易复位的起态并把困难试次删除。

**回答：PASS。**稿件要求同一个 checkpoint 双向过各自门槛，动态 BC/DAgger 获得同样纠正、示范和交互预算；起态分层交错、拒绝与中止记录、预先规定试次数和回归容忍均有明确要求。数值等待工位预检不等于门槛未定义。

**最小修法／落实点：**正式实验登记每组初始化、可用纠正信息、交互／标注预算、优化计算及评测起态；同数据离线对照和各自在线收集的同预算对照分别命名。现稿已有公平性约束，实验尚未执行不判 FAIL。

### Q13：接管导致的样本隔离会不会掩盖困难状态无法学习？

**位置：**01:202、232、292；06:245–255；07:219–223；02:323、328。

**反例：**每次接近失败立即接管，坏状态全部隔离；Q 只在顺利窗口拟合，评测却把辅助救回算成 policy 成功。即使每条保留转移时间正确，样本选择偏差仍存在。

**回答：PASS，覆盖仍是实测风险。**稿件不把隔离宣称为无偏估计，要求按目标／状态／触发原因报告隔离和接管比例，保留可恢复范围内独立尝试，并以关闭动作纠正的表现决定退出辅助。需要微步 RL 时另设目标，未把它隐含计入当前学习能力。

**最小修法／落实点：**不能仅报总 replay 条数；报告每向合格 TD/BC 与接管删失率，并检查困难区域是否有可学习纠正或自主重试。若没有，应报告该区域尚未学会并调整采集方式，而非扩大本稿的性能结论。
