# R05 独立审查：RPent 联合选型与 GPT Harness 自主闭环

2026-09-23。审查人：独立 Harness 审查代理。

首先核对以下关键点：

1. RPent 论文里的冻结 VLA 组合能力，不能冒充完整 policy 已经通过在线 RL 学会任务。
2. GPT 图像输入、工具调用和结构化输出的支持，不等于本工位成功评分、三维定位或纠正已经可靠。
3. 观察不能排在长 motion 的活动工具锁后；取消工具不能代替驱动保持确认。
4. 不同进程、会话和试验只能共享一个实体 Gateway；旧任务和旧控制代际的结果必须失去运动权限。
5. 人工 verdict、纠正标签、复位、代码试验、发布与故障处置要逐项替代，不能把人移到后台后声称无人运行。
6. 事实先持久化，失败、实际纠正和纯查询分开；正反导出必须保留各自目标。
7. 程序生成者不能改评分、事实或预算；memory 的 verified 不能授予执行或监督资格。
8. 评估必须包含完整任务、同一 checkpoint 的双向无动作辅助能力，以及全部人工和计算成本。
9. 对 RPent 与 RoboRSI 使用同一证据尺度，区分已有代码、计划改造和待实测效果。

**结论：PASS。实际独立问题／反例 18 组；确认缺陷 0 项；必要修改 0 项；可选措辞澄清 1 项。**

这里通过的是六份冻结设计稿的来源、逻辑和 Harness 闭环契约审查。它没有授予真机运行资格，也没有证明 GPT 的工位能力、纠正质量、学习增益或无人时长。文档已经把这些列为预检、实现和实测门槛；不能仅因尚未执行便判 FAIL。本次也没有为满足轮次要求放宽缺关键契约即 FAIL 的标准。

## 十八组问题、反例与裁定

### Q01：是否把冻结 VLA 的系统增强误写成在线学习证据？

**来源：**S1、S2。论文的方法是固定原语、冻结 VLA、记忆与逐回合工具反馈；联合奖励微调和技能扩张仍是边界。

**冻结位置：**09:22、28、32、111–113；01:24、253–259。

**反例：**解析程序完成运输，VLA 仅闭合夹爪，系统成功率提高；训练后的完整 policy 其实没有改善。

**回答：**稿件已明确区分论文、当前仓库与本项目改造，并要求完整任务无动作辅助评测。将 RPent 作为认知和工具骨架有可核模块依据；没有由机构、发布时间或 RLinf 组织关系推断 learner 已兼容。

**必要修法：**无。保留现有证据边界。**PASS。**

### Q02：GPT 的模型接口能力是否被等同于工位观察能力？

**来源：**S8 支持图像输入、工具调用和结构化输出，视频未列为支持模态；S3 另要求工位标定。

**冻结位置：**01:110–116、126、158；02:150–163、185–201。

**反例：**JSON 格式完全正确，却把遮挡中的物体错判为已经稳定释放，或把像素坐标当三维位置。

**回答：**稿件采用带时间的多图、本体和执行证据，要求校准误报、漏报、拒答和时延，允许 unknown；动作需坐标系、单位与标定。图像接口可用仅支持可接入判断，准确率与纠正能力必须另测。

**必要修法：**无。**PASS。**

### Q03：长 motion 或卡死工具是否让观察服务一起失明？

**必要修法：**无；该待执行验收不可删。**PASS。**

### Q04：实例内锁能否防止跨进程双 owner？取消回执是否被误当实体停止？

**必要修法：**无。**PASS。**

### Q05：正向旧回复能否污染反向控制；取消后是否误删合法历史结果？

**来源：**S4 的合作式取消边界；反例由该边界与并发换向推导。

**必要修法：**无。**PASS。**

### Q12：纠正成功是否意味着它能直接成为延迟 policy 的 BC 标签？

## 人工工作逐项替代核对

| 人工工作 | 冻结方案中的自动主体与闭环 | 仍需保留的真实边界 |
|---|---|---|
| 观察 | 锁外事实流→带时间 GPT 请求→版本化结果→Runtime | 初始标定和工位能力校准；缺证据返回 unknown |
| 成功评分 | 固定 rubric、事实引用、终局去重、目标绑定 | 留出审计可有人参与并计成本；没有每回合人工确认 |
| 纠正标签 | 原决策快照→动作建议→质量与信息集审核→持久 BC 视图 | GPT 自称可靠不够；不能承诺所有标签可用 |
| 执行接管 | 同一 Gateway→quiesce→新观察→新代际→受限纠正 | 本地保护独立于 GPT；未知执行不能假交接 |
| 正常复位与异常恢复 | 共享反向 policy＋init_set 核验；额外恢复独立记账 | 不可达或超预算状态结束自主窗口；实际人工必计介入 |
| 代码试验 | 受限候选→静态／接口检查→自动 TRIAL→固定核验／回归 | 候选不能改约束与评分；不要求逐次人批 |
| 发布 | Evaluator／Registry 的双向评测→同一包边界切换 | 预定门槛和数据身份必须冻结；未过门槛不发布 |
| 故障 | 按服务故障类型暂停、保持、回退、对账或结束窗口 | 等待不计持续学习，必要人工和停机如实统计 |

上述替代在设计层没有发现隐含“必须有人完成、但未计账”的步骤。它仍依赖本工位能达到声明的观察、纠正、保持和恢复覆盖；这一依赖已经被放在进入自主窗口前的实测门槛中。当前允许进入实现与预检，不允许把本文 PASS 写成真机已完成无人自学习。
