# R05 独立审查：共享 VLA、BC＋在线 RL 与数据

审查日期：2026-09-23。审查对象仅为本轮 `input/` 中 01、02、06、07、09、README 六份冻结 Markdown；没有读取其他轮次或其他审查结论，没有修改正式文档或科学家知识库。外部证据采用原论文及下列固定 SHA 源码。本审查是设计和静态源码核验，没有运行训练、仓库测试或机器人。

**结论：PASS。确认的实际设计问题 0 项，必须修正项 0 项；另列 2 项非阻断验收细化建议。** 该结论只覆盖本报告的学习与数据范围，不代表组合算法已有效，更不代表真机验收通过。

## 1. 阅读原始来源前先列出的关键点

1. 用户条件不变：松灵 ALOHA 类平台、先单臂 pick-and-place、另一臂保持；已有弱 VLA，允许少量示范/SFT，起步成功率可以为零，不用 ACT，不预设强上游 policy。
2. 正反任务必须共用同一组 θ，并且两向都真正进入 RL；goal 必须被 actor、Q、target 的计算消费，不能只存在于日志或函数参数。
3. GPT Harness 替代日常人工纠正，但不自动继承原始 DAgger 的可靠专家假设；完整任务能力最终要内化到 policy。
4. 纯查询标签可以永久保留并训练 BC；其梯度通路必须独立于 TD 资格，不能伪造 reward、next state 或 admission。
5. 真实示范的永久归档、保护性采样和某种特定 RL 目标的资格是三件事；历史同步数据不能补假 C。
6. 下一槽完整 U 的同信息集监督、特权/事后监督、反馈式微步纠正必须分清；不能把若干后见动作拼成早先选择的 U。
7. 完整动作头必须有零成功起步的可行建设路径；可表达所有动作不等于自动具备探索或运动先验。
8. 共享模型共同发布、分向回归、负迁移诊断、同预算动态 BC 对照，必须约束最后的结论。
9. 失败、接管、超时和拒绝起态不能在训练或评测中消失；隔离不兼容 TD 不等于消除删失偏差。
10. 撤销标签必须追到已训练权重和后继版本，不能只修改 replay。

## 2. 独立学习的原始来源

### 2.1 论文原理

- **S1：DAgger。** 重新阅读 [正式论文](https://proceedings.mlr.press/v15/ross11a/ross11a.pdf) §2、§3及算法 3.1。其核心是访问状态上的专家动作标注、数据聚合和再训练；行为混合概率与专家查询不是同一件事。纠正动作不必实际执行才有监督价值。原文的 no-regret/专家假设不能直接保证会出错的 GPT 标签有效。对本项目的判断是：允许 Harness 当标注来源，同时要求质量核验和独立能力评测，这种借用边界成立。
- **S2：DIDA。** 重新阅读 [正式论文](https://proceedings.mlr.press/v162/liotet22a/liotet22a.pdf) §5、算法 1、式 3 和非整数延迟讨论。它用当前状态的无延迟专家标签训练读取历史状态与动作历史的延迟策略；所学目标受条件信念及信息缺失限制，确定性模仿也有表达局限。因此事后标签并非原理上非法，但必须声明为相应模仿问题。其高效无延迟专家假设不属于本项目已有条件。
- **S3：并发控制。** 阅读 [Thinking While Moving 原文](https://arxiv.org/html/2004.06089v2) §3.4–3.6、式 5–9。旧动作在新决策计算期间继续影响状态和奖励，需要把并发信息纳入价值定义；仅为同步 Q 的 loss 加 mask 不足。原论文的截断动作模型与本项目固定槽队列不是同一实现，原文收缩性结论也不能自动外推到部分可观测的 VLA＋Harness 系统。

## 3. 十二组反例问答

以下“冻结位置”均指本轮 input 内文件及行号。“无必要修法”表示设计已经阻断反例，实施时仍须执行其验收。

### Q1：日志的 goal 改成 B→A，网络却仍读固定指令，能算共享双向学习吗？

**答：不能。** RPent S6 提供了真实可发生的反例，ConRFT S4 还说明 critic 的形参可以完全不进入网络。冻结位置：01:87–106；02:225、333、348；09:56–60。设计要求同一 θ、actor/Q/target 真正消费目标，并用小任务检查条件化行为，不能只测 shape 或期待随机初始化立即成功。**判断：通过；无必要修法。**

### Q2：某条 Harness 建议没有任何 TD 数据，为避免空 batch 将它跳过，是否仍满足“query 可 BC”？

**答：不满足。** S1 的访问状态标注不以该动作已经执行为前提；S4 的原始训练入口又确实需要改造。冻结位置：02:243–257、330–331、365–369；06:165–190；01:216–228。这些位置已要求独立监督视图、监督 mask 和真实梯度，且禁止填假 reward/后继。**判断：通过；无必要修法。** 可将“TD batch 为空但 query BC 产生非零 actor 梯度、没有该标签的 critic TD 梯度”补成更直接的验收算例，见建议 A。

### Q3：最早的十条真实 demo 还在硬盘，但新失败占满 batch；或者 demo buffer 环绕把原始记录覆盖，是否算长期保留示范？

**答：前者缺采样保护，后者缺事实归档，二者均不符合设计。** S5 的环形结构提示不能把 buffer 名称当永久保存保证。冻结位置：01:223–228；02:213–217、350；07:95–105、123–131。设计分别规定持久事实、初始示范保护、按方向/来源/质量采样和有效样本预算，且不要求永久固定采样比例。**判断：通过；无必要修法。**

### Q4：同步遥操作轨迹确有真实后果，给每条记录加 C=0，便可进入异步宏 TD 吗？

**答：不能。** S3 表明遗漏旧动作会改变价值问题；S2 的延迟监督重组也不等于获得本项目真实入队事件。冻结位置：01:138、223；07:123–131；06:138–148。本版只允许可真实重建的时序进入该宏 TD，历史示范可按相容输入/动作时间作 BC。**判断：通过；无必要修法。** 缺 C 的旧 demo 如何具体初始化新头属于实施配置，见建议 B；不能以“用于 BC”免除输入语义检查。

### Q5：Harness 在 107 帧才看到滑落，然后用该纠正监督 100 帧策略；是否所有这样的监督都应删除？

**答：不是。** S2 明确支持某类延迟/特权模仿，但它不是普通同信息集标签，也不是同一动作的真实 TD。冻结位置：01:130–138；06:182–190；07:225–231。本版保留原 policy 可见信息与 Harness 额外信息，首版暂不自动混入，未来需单独验证可预测性和多模态。这是明确范围选择，不是错误禁止事后学习。**判断：通过；无必要修法。**

### Q6：Harness 每一步都看新图像，成功重抓后把六步拼成在原 X 下预提交的 U，可以同时做 BC＋宏 TD 吗？

**答：不能这样声称。** S2/S3 的条件化对象都是明确的；事后拼接改变行为信息集。冻结位置：06:188–190、237–255；09:111–113；01:120–124。同信息集完整 U、反馈微步、部分监督分支已经区分；孤立动作不能重复填满 n 步，flow/diffusion 不能仅在最终 loss 遮罩未知值。**判断：通过；无必要修法。**

### Q7：初始 policy 成功率为零，重新训练完整头是不是必然更容易？方案是否暗中仍需要一个强专家？

**答：没有这种保证，也不能补入强专家假设。** S4 仅提供可复用的价值/监督结构；S2 的无延迟有效专家不能被移植成项目既有条件。冻结位置：01:5–7、26–38、208–218、273–281；07:40–48、143–151；06:239–243。可行建设路径是用用户允许的可信示范或保留可训练原头初始化，先核双向拟合；建立具有可验证局部能力的 Harness，再在真实固定槽决策点采集完整 U 与队列日志，进行 BC＋RL。失败时检查接口/表征/数据，再比较保留原生头，文档允许该回退。没有有效纠正、奖励或探索时仍可能启动失败，已明确限定。**判断：通过；无必要修法。**

### Q8：正向 checkpoint A 最好、反向 checkpoint B 最好，把两者分别部署能算同一共享策略通过吗？

**答：不能；平均成功率掩盖某一方向退化也不行。** 这是用户约束及共享参数优化的直接要求，S4 的单任务实例不能替代此验证。冻结位置：01:15、22、87–106；02:225、271–277、340；07:99–105。文档规定共同包发布、分向门槛、最低覆盖与退化诊断；独立模型只能作消融。**判断：通过；无必要修法。**

### Q9：BC＋RL 比“只用开头示范的静态 BC”好，就能证明 RL 的额外收益吗？

**答：不能。** S1 本身就是随访问状态更新的监督基线。冻结位置：01:38、296–298；07:143–151。本版已经要求同纠正、示范和交互预算的动态 Harness-DAgger/BC 对照，并接受 RL 没有增益的结果。不同训练方法诱导不同状态分布，公平原则应以预先确定的资源与评测协议落实，不能把“同预算”误写为真机轨迹逐点相同。**判断：通过；无必要修法。**

### Q10：凡是要失败就立即接管并删除该宏窗口，剩下 Q 很好，能证明原 policy 已学会困难状态吗？

**答：不能。** S1 要求关心 policy 访问分布；S5 的真实干预转移经验也不证明任意队列接管都兼容本目标。冻结位置：01:202、232、285–294；06:247–255；07:219–223；02:287–289、345。文档保留事实与独立可信 BC，明确报告删失比例、触发原因及困难区域覆盖，并在可恢复范围安排独立尝试。隔离是避免错误 TD 的选择，不是宣称统计无偏；零覆盖时不能宣称困难状态被 RL 学会。**判断：通过；无必要修法。**

### Q11：Harness 的运输原语越来越强，抓放系统成功率上涨，但 policy 仍只会局部接触，是否达到完整任务学习目标？

**答：没有。** S6 的工具组合能力与参数学习是不同证据。冻结位置：01:259、285–298；02:279–287、344；09:109–126。本版已要求完整 pick-and-place 无动作辅助评测、成熟纠正回流与自主重试，不准删除运输阶段后换评价对象。何时能够退出动作辅助是实验未知项；文档没有把它当成既定事实。**判断：通过；无必要修法。**

### Q12：一个错误成功标签已训练十次，只从 replay 删除它，继续发布其后继 checkpoint，是否完成撤销？

**答：没有。** 这是优化器已经把标签影响写入参数的直接后果；S4/S5 的更新链说明改未来输入不逆转旧更新。冻结位置：01:228、265–267；02:293–297、343、366–367。文档要求 manifest→样本/视图→checkpoint→后继版本追踪，暂停晋级，评估可信版本回退重训，并说明物理动作不能软件撤回。**判断：通过；无必要修法。**

## 4. 非阻断验收细化建议

**A：补一条纯 query 的最小梯度算例。** 构造一个与输出不相等的可信标签，TD 集合为空；验证 BC 可独立更新 actor，没有该标签的 critic TD 梯度，也没有建立假转移。测试时可暂固定 target 同步以隔离计算图；正式训练按声明的同步规则维护 target，并不因为同步就意味着产生了 TD 资格。再撤销该标签，确认缓存、预取 batch 与新 manifest 均不再采样。02 已有损失分流、计算图验证及撤销要求，故这是把既有契约合成容易执行的算例，不是新增必要原理。

**B：实施配置明确历史 demo 到新头的冷启动入口。** 可选“在原观测/动作语义的兼容监督入口初始化，再以真实固定槽数据适配”，或直接新采集同协议示范/完整 U。旧数据缺失的承诺队列不冒充真实 C；当前真实保持槽可以记录保持 C，但不能用它反填过去。01/07 已允许多种初始化并要求输入匹配，06 已给出保持、重新建决策点的路径，故不要求设计审查先证明哪个初始化一定成功。
