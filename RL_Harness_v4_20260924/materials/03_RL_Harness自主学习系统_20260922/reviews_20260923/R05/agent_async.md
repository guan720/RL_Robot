# R05 独立审查：异步控制与 RL

审查日期：2026-09-23。审查对象仅为本轮 `input/` 的六份冻结 Markdown；未读其他轮次、其他审查者报告或知识库，未修改正式稿。下面先列技术点，再列独立阅读依据和反例问答。本文是设计与官方源码静态审核及手算，**没有实施训练、仿真或真机实验**。

## 1. 先列关键技术点

1. 用户要学的是同一个低成功率 VLA 的正反完整任务，Harness 纠正应回流 BC／RL，不能由两个隐含独立策略或永久代做替代。
2. 当前推理的 C 预测没有执行，真实 C 来自旧队列；E 是当前动作，D 不进入其价值动作。
3. 一槽增广状态是否同时包含观测历史、目标、真实承诺队列及必要调度状态；增加队列不能替代物理可观察性。
4. request、commit、activation 是否可独立追溯；计算完成时间晚于动作决策信息冻结时间是否改变定义。
5. 一槽奖励、下一边界状态和折扣是否对齐；与 SmoothRL 原版 2n 目标是否明确区别。
6. 真实任务在 C 内提前终止时，是否存在合法原请求动作及 terminal TD，使成功奖励沿统一 Bellman 链传回。
7. 终局事件时间、证据充分成立时间和评分返回时间是否区分；不能靠迟到成功把先前失效协议洗成正常样本。
8. 同边界提交、终局、超时、抢占的顺序；顺序无法证明时应隔离什么范围。
9. prime、换目标、回交、换版本是否清理旧队列和旧结果；不能跨正反目标 bootstrap。
10. actor Q 梯度、物理执行、TD 准入和 BC 监督四类条件是否独立。
11. 同信息集的完整下一槽纠正与执行时反馈微动作是否区别；部分 flow 标签能否穿过加噪输入与 token 交互。
12. 删失及 actor 终局筛样改变什么分布；不能把已声明的有偏工程规则误判为未定义，也不能宣称它给出无偏的全运行价值。

## 3. 一槽定义的独立推导

先在理想物理 Markov 状态 `s` 下考察固定槽，令 `X=(s,g,C,ξ)`。在协议未破坏的非终局分支，当前槽的物理演化由 C 产生，随后队列赋值为 U，故其转移可分为“在 C 下的 n 步物理转移”与 `C'=U`。对该分支：

`Qπ(X,U) = E[R_n + γ^n Qπ((s',g,U,ξ'),π(s',g,U,ξ'))]`。

如果 C 在第 L 步先产生真实任务终局，则该次环境结果为 `(R_L, absorbing)`；当前请求 U 的后续激活被取消，不要求 U 曾经物理执行。U 来自事前冻结输入及随机性的同一个真实请求，计算可以稍后完成。这是延迟动作过程中的一个合法结果，不是为动作建议编造物理轨迹。

这套推导成立的边界是：C 没有被中途重写；U 没有读取未来信息；正常分支准时提交；动作接口一致；奖励和边界快照正确。在视觉历史替代 s 时是近似状态；经过结果相关删失后，训练分布也未必等于这个理想核。冻结稿已经分别声明这两点，不能把上述代数推导扩大成真机收敛保证。

## 4. 反例问答与裁定

以下均为本次独立构造，未沿用正文的 `t=100,n=6,H=20` 数字。每项裁定都针对六份冻结稿的整体约束。

### Q1：当前 U 尚未机械生效，配当前 C 的奖励是不是伪转移？

**反例。** 设 `t=240,n=4,H=13,γ=0.8`，240–243 执行真实旧 C；本次 proposal 索引 4–7 对应 244–247，8–12 为 D。当前槽第二步奖励 0.3，其余为零；下一状态 Q 值暂为 0.5。若把 U 的物理执行回报挪来，时间轴将重叠。

**回答。** 当前 `R=0.8×0.3=0.24`，正常一步 target 应为 `0.24+0.8^4×0.5=0.4448`；next state 是 244 边界的观测和 `C'=U`。当前 U 的环境作用是改变队列，物理奖励随后经价值链传递。不能把 next state 改成 248 仍保留这一回报与折扣。

**冻结位置与裁定。** 06 §2.2–3.3（65–148 行）、02 §5.3（229–241 行）已明确。反例未推翻正文；必要修改 0。

### Q2：同一图像但旧队列不同，增加 C 真能解决价值混叠吗？

**反例。** 相同物体画面与关节位置，一个队列未来四步闭夹爪抬升，另一个队列未来四步张开退回；给二者相同新 U，未来抓取结果不同。

**回答。** 缺 C 的 `Q(h,g,U)` 会混合两个条件。正文的 `Q(h,g,C,U,ξ)` 能区分本例；但若相同 h、C 对应不同且不可见的滑移速度，仍可能混叠。后者要求历史／状态估计／额外传感器，不是“队列加进去便完全 Markov”。

**冻结位置与裁定。** 06 §2.1、2.4（45–61、97–101 行），07 §10.1（192 行）已限定。没有隐藏的完全可观测性保证；必要修改 0。

### Q3：真正完成任务的 U 会不会因下一槽提前终止而失去正奖励？

**反例。** `n=4,γ=0.8`。槽 240 的 U 正常提交为槽 244 的 C；244 起点实际接纳请求 B；C 在该槽第二步获得终局奖励 3。B 还在计算，没有机械激活。

**回答。** 保留 B 的原在途计算结果，生成 `Q(X244,U_B)←0.8×3=2.4` 的 terminal critic 样本，无 bootstrap。等这个状态的价值和 target 网络得到更新后，240 槽的零奖励 target 经 `0.8^4×2.4=0.98304` 传回。这个数也等于奖励相对 240 起点延后五步的 `3×0.8^5`。B 不是造成成功的物理动作，队列价值定义不要求作此归因；上一槽真实 U 仍有正常学习链。

**冻结位置与裁定。** 06 §5.1–5.2（198–219 行）、02 T11 已覆盖。没有正奖励闭合缺口；必要修改 0。

### Q4：终局前只有请求，能不能给所有 shadow 建议复制同一个 terminal 后果？

**反例。** 300 起点只接纳 policy 请求 P，同时离线询问 Harness 备选 H1、H2；C 在 302 结束前终局。P 输出稍后到达，H1 数值碰巧更好。

**回答。** terminal 行只使用 P 的真实结果；H1/H2 没有行为 admission，不能进入 TD。P 若已被取消且结果无法取得，只保留终局事实，不用 H1 替代 P；也不能事后再次观测生成 U。冻结状态、权重和随机性证据使“保留原计算”可与“补动作”区分。

**冻结位置与裁定。** 06 §2.2、5.1、9 例4；02 §5.1、5.4。必要修改 0。

### Q5：按未来成功为前驱回填奖励，是否只是更快的 n-step 学习？

**反例。** 固定同一个 next state，后续以概率 0.3 得回报 2，以概率 0.7 得回报 0.4；价值为 0.88。若只在成功分支回填 2，在另一分支仍 bootstrap 0.88，则期望变成 `0.3×2+0.7×0.88=1.216`，不是 0.88。

**回答。** 这是根据未来事件选择不同估计量导致的偏差，不是预先固定时域的 n-step 目标。正文不这么做：前驱始终使用自身一步目标，终局行按当前请求关闭。延迟正奖励传播速度属于 target 更新与函数逼近问题，不能用这个捷径修补。

**冻结位置与裁定。** 06 §5.2（215–217 行）、07 §10.3（215 行）。必要修改 0。

### Q6：评分迟到时，已经发生的 commit／activation 是否会与 terminal 相矛盾？

**反例。** 槽 `[600,604)` 内，固定判据所需证据在 603 已充分成立；U 于 602 获得真实队列提交回执，604 物理激活；GPT 历史评分 610 才返回。

**回答。** 任务终局按 603 的证据事件划分，不能用 610 作事件时间；同时保留 602 的 commit 及 604 的实际动作，不把真实 commit 改成从未提交。604 之后的物理行为进入后续处置日志。若只有 606 才出现判据必需的稳定证据，就不能把终局回溯到 603 的第一次接触；若事件帧不能确定，则 target pending。

**冻结位置与裁定。** 06 §5.3（229–231 行）、02 §4.2–4.4（167–191 行）已有明确回答。必要修改 0。

### Q7：同边界 deadline、终局、抢占相撞，是否能靠“成功优先”绕过失效？

**反例。** `[720,724)` 的末端记录同为墙钟 7.240 秒，分别考虑三条真实顺序：A，任务终局证据先成立，再撤销动作权限；B，先 deadline miss，保持控制后才成功；C，先 Harness 改写 C，再放置成功。另设 D，只知道三个粗时间戳相同，没有顺序或队列快照证据。

**回答。** A 在原请求可追溯时可成为 terminal；B/C 的首个破坏协议事件已发生，不能追认原槽为正常 terminal；D 不能猜先后，相关宏 target 保持未知／隔离，必要时隔离依赖该不明边界的前驱。实际事件顺序是裁定依据，不要求用墙钟相同强行规定“成功赢”。具体串行化实现属于既有验收应实现的证据能力。

**冻结位置与裁定。** 06 §5.3（231 行）、§6.2（249–253 行），07 §10.4（221 行），02 §3.2、T04/T06/T07。规则已闭合；必要修改 0。

### Q8：下一槽被抢占，是否必须把上一槽也删掉才能因果正确？

**反例。** `[800,804)` 完整，804 边界快照明确 `C=U800`；Harness 在 806 首次改写 C，807 放置成功。

**回答。** 800→804 转移已经成立，应保留原 next queue；804 槽被抢占，从首版宏 TD 隔离，807 的成功不能倒贴为原 U804 的正常后果。若接管恰在 804，致使边界快照来源不可确认，则依赖该快照的前驱也隔离。隔离范围根据证据缺口，而非事后整回合成败。

**冻结位置与裁定。** 06 §3.3、6.2、9 例5；02 §5.3。必要修改 0。

### Q9：prime 的保持动作能否伪装成新策略成功，或导致首个 terminal 无法训练？

**反例。** A，在 PRECHECK 阶段物体已满足目标，没有 policy request；B，已用保持动作建立 C0，并于 900 接纳实际请求 U0，保持槽第二步满足终局。

**回答。** A 只保存事实，无 U、无虚构前驱。B 可用真实 U0 构造本槽 terminal critic 样本，但不能声称保持动作由新 policy 生成；同样不能凭空补上一条使 U0 获得物理成功信用的前驱。

**冻结位置与裁定。** 06 §5.2（219 行）、6.2（257 行），02 §5.3（239 行）。必要修改 0。

### Q10：共享 θ 会不会把正向奖励传给反向，或让旧输出复活？

**反例。** 正向 epoch=18 在 1002 终局，经保持与起态核验后，1008 建立反向 epoch=19；正向推理及评分于 1010 才回来。

**回答。** 历史评分只能归正向；旧推理因目标／代际失效而没有控制资格。正向 terminal 不 bootstrap 到反向，反向以同一个 checkpoint 的新 goal、新队列 prime 开始。共享参数带来的迁移或冲突靠采样及双向独立评价检查，不改变目标 episode 语义。

**冻结位置与裁定。** 02 §2.3、4.2、5.5、T18；06 §7；01 §5。必要修改 0。

### Q11：C/E/D 只做一个执行 mask 足够吗？

**反例。** `n=3,H=11`，旧 C 全为合法非零命令，新 proposal 前三项故意置为另一组数，E 保持不变，D 设为极大值；若 critic 读取 proposal 前三项，Q 会随从未采用的头部改变。

**回答。** 应固定 X 内的真实 C，critic 的当前动作参数只有 E。改变当前 proposal 的 C/D 输出不应直接改变本轮 Q loss；E 可以改变。BC 是否监督某个位置由可信标签决定，不能用这个 Q 测试把所有非 E 监督禁止。共享参数更新间接改变其他输出不等于错误的 Q 动作梯度。

**冻结位置与裁定。** 06 §4.1–4.2、9 例2；02 §5.4、T13/T14。必要修改 0。

### Q12：Harness 在 E 执行期间看到滑落后给出的正确动作，为什么不能直接当原 E 的 BC 真值？

**反例。** policy 在 1100 选取未来 1105–1109 的五步 E；Harness 在 1107 看到随机向左滑落，并给出一条右移微动作。若滑落向右则应左移，而 1100 的可见输入相同。

**回答。** 这条标签混入了部署在 1100 无法取得的信息，且只是一微步；既不能改写真实 U，也不能复制五遍变成完整下一槽标签。可以长期保存为显式特权模仿候选，或在新状态重新建立决策点，不能默认进入首版普通 BC。纯历史查询若使用同一 X、C、目标时段并生成完整可信 U，即使未执行，也可以 BC。正文没有断言所有事后标签在理论上不可用。

**冻结位置与裁定。** 06 §4.3（184–190 行）、07 §10.5、09 §5 末段。必要修改 0。

### Q13：反馈式 micro 轨迹是真实的，拼成 macro 不就能训练 Q 吗？

**反例。** Harness 在 1200 看图后向前一步，1201 看新图后侧移，1202 接触后回撤；事后恰好凑齐三步且最终成功。

**回答。** 三步不是在 1200 冻结信息下选出的开环 U，未来反馈决定了后两步。不能套用当前固定槽宏动作转移，不能给最初状态编造完整的预提交 request。逐帧记录应保留；另立微步状态、控制模式、动作和价值目标后才可启用 micro RL。现有首版明确选择不做这个分支，并非留下不知如何解释的混合 replay。

**冻结位置与裁定。** 06 §6.2（247–257 行）、02 §3.3、5.3，01 §3 第5项。必要修改 0。

### Q14：部分 flow 标签只在 loss 末端乘零，真的不会污染有效监督吗？

**反例。** 五步标签只有第 2、3 步已知；未知位置填零后一起加噪并进入全 token 交互，最终只对第 2、3 步算 loss。已知位置的预测仍可以依赖那些任意填入的零。

**回答。** 末端 mask 不能证明监督相容。首版可选择完整可信动作窗口；若要接部分标签，需验证未知位置的输入、加噪、注意力与推理处理。当前不能接的标签保留候选，不以复制最后一帧补成完整纠正。该取舍缩小可用 BC 数据量，但定义明确。

**冻结位置与裁定。** 06 §4.3（190 行）、02 §5.4（257 行）及 T14，07 §5.3。必要修改 0。

### Q15：删掉被接管槽，再保留前驱 bootstrap，是否就得到纯 policy 的无偏 Q？

**反例。** 某类 X 有 80% 的物理分支触发 Harness 接管，只有容易的 20% 留在正常池；另一个 X 全部留下。即使两个池里每条转移都是真实记录，前者的条件分布已经变了。若所有坏后继只被接管，从数据上也无法辨识无 Harness 时的后续价值。

**回答。** 不能宣称无偏。保留前驱是物理与队列事实成立，不是对缺少覆盖后继的价值估计作保证。正文明确要求按目标、状态范围和触发原因报告删失，保留可恢复范围的独立尝试；若要把接管区真实后果放进 RL，需另审带模式的目标。首版没有把 Harness 救回的成功当作 policy 成功。

**冻结位置与裁定。** 07 §10.4（221–223 行）、06 §6.2（253 行）、01 §9（232 行）。这是已声明的数据覆盖和有偏估计风险；不是待补的动作／target 定义。必要修改 0。

### Q16：把 C 内终局行排除于 actor Q 更新，会不会还是未来事件筛样？
