## 1. 先枚举关键点

1. 用户研究对象是同一个目标条件 θ，正向和反向都学；另一臂暂不参与；不是两个方向分别保存最优参数。
2. 少量示范/SFT 可以使用，初始成功率可以为零；没有外部强教师，也不使用 ACT。完整动作头取消弱 base 附近的残差限制，但不保证更容易探索。
3. DAgger 借用的是 learner 访问状态上的纠正聚合；Harness 标签的可靠性、可观察性和动作表达必须另验，不能移植原专家假设。
4. 事实持久存储、采样资格、BC 梯度、TD 梯度和模型发布是不同环节。保存动作或保留 demo buffer 不自动等于产生 BC。
5. 普通异步监督标签是同一 X、goal、承诺 C 下，针对下一执行槽的完整 U。孤立 micro 标签、反馈式轨迹和未来信息标签不能悄悄变成这种 U。
6. 历史同步示范只按其真实时间和输入语义使用；没有队列和真实请求证据不能补成当前宏 TD。另有兼容监督路径才能训练当前队列头。
7. 纯查询完整纠正允许长期 BC，但不具有虚构的 reward/next state。实际控制请求、提交、物理激活则有各自的真实环境语义。
8. goal 必须贯穿 actor、critic、target、BC、reward、replay 和评估；仅写 planner prompt 不足以成立。
9. actor 的 Q 动作梯度只经 U/E；监督 mask 独立于 TD、执行和 terminal mask。
10. 共享更新的负迁移、接管删失的覆盖偏差和完整任务的无辅助表现，都需要单独衡量。
11. 撤销标签不仅影响今后的 replay，还要追踪依赖的 checkpoint；发布必须是同一双向版本包。

### Q02：十次抓空都有真实动作和负奖励，把它们全部加进 BC 是否符合“失败数据有用”？

### Q03：同一 X、C 的完整可信纠正没有执行，能否留下来学习，还是被 td_valid=false 一并清掉？

### Q05：少量旧同步示范只有 (h,a)，没有已承诺 C，是否已经被承诺能直接训练首版 (h,g,C,ξ)→U？

### Q06：抓空后只得到帧 107 的一个后退 micro 动作，把它重复六次作为帧 100 的 U，是否能扩大纠正覆盖？

## 4. 对“保存了数据但实际没有梯度”的专项复核

本节是对冻结文字的可执行含义做检查，不宣称已有训练代码。用两个独立集合表达现稿要求：D_T 是满足队列契约的真实 TD，D_B 是输入/时间/质量相容的动作标签。D_B 可含 demo、实际纠正、纯 query；D_T 可含失败。它们可以共享物理记录 ID，但不需要拥有相同成员或相同 batch schema。

现有文字要求的分流可写成：

```text
critic：在 D_T 上计算其合法 terminal / nonterminal TD 目标。
actor Q：在规定的 D_T 状态分布上，经 U/E 求梯度，应用 actor Q 资格。
actor BC：在 D_B 上，用可靠标签及独立监督 mask 求梯度。
发布：同一候选 θ 接受正反完整任务的无动作辅助评测。
```

简单反例足以检验错误实现：保留一条可信完整 query 标签，令该行 `td_valid=false`，关闭 Q 与 continuity 项；在回归实例 `πθ(X)=θ=0、U_H=1` 中，只要该标签已被采样且 BC 权重大于零，BC 对 θ 的梯度应非零。增加大量未获 BC 资格的失败数据不能把它自动改成失败动作克隆。这个检查不需要为 query 制造 reward 或 next state。它是 T14/T15 与 07 数据到梯度预检的组合，不是新增一种研究算法。

源代码比较加强了这个检查的必要性：C1 的原 batch 契约需要 rewards/next observations，C2 的 actor 原来没有动作回归。冻结稿已经要求新增独立监督通路，因此不能据此反推冻结方案也只有原版入口。反过来，如果实现最终未新增，这将是明确的实现验收失败。

## 5. 边界、可选说明和最终判定

下列两条有助于后续实现，但本轮不计必要问题：

1. 在具体 learner 选定后，把上一节的 D_T/D_B 分流写成 sampler/update 伪代码，并把 query-only 梯度例子单列测试。这可减少实现者机械沿用 ConRFT/HIL-SERL batch 契约的风险。当前文字已经定义其所需语义，未发现与之相反的承诺。
2. 实施前为历史同步示范选择一个具体预训练/迁移 adapter，并用一个样本展示观测、goal、时间、队列可用性与输出索引。没有通过 adapter 验证的旧数据继续归档；队列头以同协议完整 U 初始化和学习。当前没有承诺所有旧示范直接兼容，因此不因该实现选择尚待预检而宣告设计错误。

未定义的能力仍保持未定义：任意 feedback micro 的宏 TD、任意部分 flow 监督、特权 DIDA 分支、同步历史到队列 TD 的通用转换、动态延迟与中途观测扩展。本报告没有替它们补出一个新方法，也没有把延期误读为已经兼容。

**最终：审查反例 14 组；确认必须修订的实际问题 0 项；必要修法 0 项；可选实现说明 2 项；结论 PASS。** 通过的是冻结设计的共享策略/数据/BC＋RL 语义审查。完整动作头冷启动、纠正有效性、TD 覆盖、双向独立能力及无人窗口仍须按既定门槛实现和验证。
