## 1. 先枚举技术点，再学习原始证据

独立审查先确定以下技术点：一槽延迟动作 MDP；C 是当前执行的旧队列、U 是下一队列；request／commit／activation 的因果身份；C/E/D 动作梯度；低层解码与保护投影；真实终局的请求结果；终局与超时／抢占的顺序；迟到奖励与事件时间；目标换向；边界接管与前驱 bootstrap；BC 与 TD 资格；未来信息和部分标签；actor 按终局结果筛样；删失后的 critic 覆盖与独立策略评价。

## 2. 问题驱动复核

### Q01：当前奖励由旧 C 产生，配当前 U 是否错归因？

**冻结位置：**06:42–85、105–134；02:227–239。**来源：**[S3 §3.5](https://arxiv.org/html/2004.06089)、[S1 §3.3](https://arxiv.org/html/2608.29768v1)。

**反例：**取 n=2、γ=0.8。当前 C 的两步奖励为 2、3；U 入下一队列，下一槽第一步得 5 并真终止。若为了让 U 配自己的奖励而把下一槽的 5 挪到本槽，却保留本槽 next state，就会重复／错位计奖。

**判断：通过，数学已核。**文档的一槽目标给 `2+0.8×3+0.8²×5=7.6`，与物理时间轴直接折扣完全相同。固定 n 下，正常增广转移可写为 `P_n(h'|h,C)` 与确定性赋值 `C'=U` 的组合；U 的价值经下一状态传递。不要求 U 当槽已经物理执行。前提是其余状态与环境近似满足文档声明的条件。

### Q02：加上队列是否足以宣称已恢复严格 Markov 性？

**冻结位置：**06:45–51、97–101；07:188–192；02:75–89。**来源：**[S3 §3.6](https://arxiv.org/html/2004.06089)、[S2 §4 与附录 D](https://arxiv.org/html/2608.23831v2)。

**反例：**两次截图、本体状态、C 一样，但低层积分器状态、夹持滑移或未观测物体速度不同；执行同一 U 的结果可以不同。单独增加版本字符串也不能还原它们。

**判断：通过，边界准确。**06 明确不把 X 自动当作完整物理 Markov 状态，并要求必要历史／控制状态、固定动作契约。实际充分性属于状态估计与真机验证，而非已证收敛。未发现把这种近似包装为严格保证的陈述。

### Q03：request admission 会不会把任意未执行建议变成真实 TD？

**冻结位置：**06:63–95、136–148、300–302；02:217、229、255、369。**来源：**[S3 并发决策定义](https://arxiv.org/html/2004.06089)。

**反例：**同一 X 上产生 A、B 两个建议，只 A 属于真实控制流程。若终局后给 B 补 request ID，再配同一个 reward，数据量和行为身份都会被伪造；即便两者数值相同也不能修复这个历史事实。

**判断：通过，设计契约明确。**冻结稿要求事前真实接纳与冻结信息，正常分支还要求 commit／next queue。影子 B 只有监督资格。动作在控制请求后才算完不是逻辑问题：只要 U 由冻结 X、权重与明示随机性确定，它可以视为计算延迟的行为决策；不能临时读取新场景更改它。

### Q04：C 中提前终局、U 未激活，terminal Q 样本是否合法？

**冻结位置：**06:192–219；02:239、T11；07:203–217。**来源：**[S3 Bellman 分解](https://arxiv.org/html/2004.06089)、[S2 数据动力学条件](https://arxiv.org/html/2608.23831v2)。

**反例：**请求发出后第 2 步终局，计算第 4 步才结束。若重新观察成功画面再计算 U，U 就可能透露成功结果；若计算取消却填全零动作，则行为动作凭空产生。

**判断：通过，数学与契约相符。**允许继续同一冻结在途计算，撤销其执行资格，保存 `Q(X,U)←R_L`；真实结果无法取得则隔离。终止由当前 C 的环境后果决定，动作延迟并不要求已被选中的下一动作必然激活。也没有据此声称 U 导致成功。

### Q05：终止与 deadline／失联／改队列相继发生，是否会幸存者追认？

**冻结位置：**06:221–231、261–268；07:213、221；02:241、T06/T12。**来源：**[S1 固定预算前提](https://arxiv.org/html/2608.29768v1)、[S3 并发时间语义](https://arxiv.org/html/2004.06089)。

**反例：**n=6，先在槽尾超时进入保持，第 8 步在保持过程意外完成放置，第 12 步才收到“成功”。不能把成功倒灌成正常 terminal。反过来，第 4 步已经满足终局全部证据，结果第 8 步才算完，则计算超过原 deadline 不应抹掉已发生的合法终局。

**判断：通过，两个顺序均有规则。**06:231 和 07:221 依最先破坏协议的事件裁定；06:198 支持终局后只为日志完成原计算。无法确定边界顺序的片段隔离。验收仍须实现，不能仅测“迟到结果被拒绝”而遗漏第二种顺序。

### Q06：迟到终局标签能否正确处理此前真实 commit？

**冻结位置：**06:144–148、227–231；02:165–183、293–295。**来源：**[S3 奖励／状态的时间定义](https://arxiv.org/html/2004.06089)。

**反例：**终局证据实际在帧 105 已充分，但 GPT 到帧 110 才答复；U 已在 106 真实提交。把 commit 删除成“从未入队”会伪造物理历史；以回复到达帧 110 作为终局又会把后续动作错误计入原任务。另一个情形是直到 109 的稳定性视频才满足任务条件，不能回溯到首次接触 104。

**判断：通过，契约可执行。**保留提交事实，按充分证据成立时刻切学习 episode；不确定事件帧则 pending。已训练后才撤销标签还须追踪 checkpoint，02 已规定。当前不保证 GPT 一定能精确定位事件；这是已声明的观测与评分实测门槛。

### Q07：边界接管是否必须连此前整条 episode 都删掉？

**冻结位置：**06:146–148、245–255、304–306；02:134–146、241。**来源：**[S3 增广状态转移](https://arxiv.org/html/2004.06089)、[S2 数据动力学条件](https://arxiv.org/html/2608.23831v2)。

**反例：**U 在 106 已成为 C，108 被 Harness 抢占。把 100–105 的 next queue 改成 108 的纠正 B 会倒填未来；把此前所有历史删除又会丢掉已经完备的一步事实。若接管恰好与 106 快照竞争，保留那个不确定快照也错误。

**判断：通过，局部隔离范围正确。**准确的 106 快照使前驱转移保留，108 所属宏槽隔离；边界不确定才扩大到依赖该快照的前驱。保留前驱不是宣称其 bootstrap 在样本稀缺处必然准确，后者见 Q12。

### Q08：C/E/D 的梯度检查会不会误禁网络内部耦合，或漏掉动作变换？

**冻结位置：**06:150–163、290–292；02:64–77、243–257；01:204、216–218。**来源：**[S1 §3.3–3.4](https://arxiv.org/html/2608.29768v1)。

**反例：**把当前预测的 C 段代替真实旧 C，Q 将优化不存在的前缀；另一个实现先将 actor 输出 u 投影为 P(u)，部署执行 P(u) 而 Q 却只读 u。相反，E 与 D 共用参数，训练 E 后 D 数值改变，本身不证明 D 获得非法 Q 动作梯度。

**判断：通过，计算图定义明确。**真实 C 是固定条件，Q 动作变量只有 U；共享参数联动已被明确区分。变换位置、采纳动作和可微路径须一致，不可微保护改写另审资格。实际 C→E 连续性损失、单位与硬边界要在动作契约锁定后实现；文档已定义其对象而未冒称跑过梯度测试。

### Q09：目标换向或版本发布会不会保留旧回报链？

**冻结位置：**06:257、266–270；02:91–93、259–265、271–277；01:87–91。**来源：**[S3 固定 MDP 的 Bellman 语义](https://arxiv.org/html/2004.06089)。

**反例：**同一 B 区画面，正向已完成、反向刚开始，旧 GPT 成功回调和旧 VLA E 同时到达。若只以图像哈希缓存 reward，反向会被终止；若在 next state 用新 goal bootstrap，正向就吸收反向的价值。

**判断：通过。**goal／episode／epoch 明确贯穿，换向关闭旧任务、清队列并 reprime；历史评分保留旧身份。权重可为不同离策略来源，但动作／normalizer／调度语义变更需要新契约或经过验证的转换，不能靠保存版本号混用。

### Q10：BC 资格能否独立于物理执行，又不偷用未来信息？

**冻结位置：**06:165–190；02:249–257；07:225–231；09:111–113。**来源：**[S2 决策信息时刻](https://arxiv.org/html/2608.23831v2)、[S4 actor 源码](https://raw.githubusercontent.com/rail-berkeley/hil-serl/c32939bccb65f3b8c43a9f9add3d322d4ab0264a/serl_launcher/serl_launcher/agents/continuous/sac.py)。

**反例：**在 107 才观察到物体向左滑，生成向右纠正；将它作为 100 时刻已决定的完整下一槽 U，会把不可见随机扰动折叠入普通标签。单步纠正复制 6 次也不等于完整槽真值。flow 模型若把未知位置补零后参与注意力，最后只 mask loss 不能保证已知标签干净。

**判断：通过。**首版同信息集完整 U 的规则清楚；特权／事后监督另设模式，未执行建议可以 BC 但不能借他者后继做 TD。部分标签的模型兼容性没有被“保存 mask”冒充。源码也说明有示范 replay 不自动有 BC，故新增监督路径是必要实现工作，冻结稿已明确要求。

### Q11：删去 C 中终局的 actor 行，真的只是无害优化吗？

**冻结位置：**06:211、298；07:217；01:198、216。**来源：**[S4 在 replay 状态上更新 actor 的实现](https://raw.githubusercontent.com/rail-berkeley/hil-serl/c32939bccb65f3b8c43a9f9add3d322d4ab0264a/serl_launcher/serl_launcher/agents/continuous/sac.py)。

**新反例：**两个状态 A、B 原始采样各半，共享一个参数 θ。A 的旧 C 以 0.9 概率终局得 0，否则后续价值为 `10θ`，故完整 `∂Q_A/∂θ=1`。B 总存活，价值梯度为 `−0.5`。全部状态的平均梯度是 `+0.25`。若按实际终局删除 A 的 90% 行，保留行归一化后的梯度变为 `(0.5×0.1×1−0.5×0.5)/(0.5×0.1+0.5)=−0.363636…`，方向反转。即便终局事件不依赖当前 U，也不保证共享参数更新不变。

**判断：通过，但必须保留有偏解释。**07:217 已明确这是工程采样规则、不声称无偏完整 policy gradient，并要求记录分布。规则本身已定义，不能因本反例就说“方法未定义”；同时不能把它升级为等价性结论。建议把此数值例加入将来的 actor 采样消融，观察它与 BC、共享双向梯度冲突的叠加。此建议不是本轮必要文档修订。

### Q12：隔离抢占和超时是否足以让 critic 代表全部自主行为？

**冻结位置：**06:249–255；07:219–223；01:202、232；02:T12、6.2。**来源：**[S2 附录 D 的动力学与支持条件](https://arxiv.org/html/2608.23831v2)。

**新反例：**固定 X、C、U，在随机接触扰动坏的一半轨迹中触发接管并隔离；好的一半正常产生成功反馈。只在合格窗口学习会估计有选择条件的转移，而非原始无辅助动力学。即使前驱事实完全正确，其 bootstrap 所查询的危险状态也可能没有可用 Q 训练行。

**判断：通过，已有明确边界。**冻结稿没有声称隔离能消除选择偏差，且要求按状态域／原因计数，在可恢复范围保留独立尝试。它仍是有统计局限的拟议 learner；独立能力是否提高必须由无动作辅助评测回答。若未来要利用被抢占区 RL 后果，必须另定义控制模式与目标，不能仅说“更多数据待测”。首版未宣称已覆盖该扩展。

### Q13：ARLI 的中途观测、latent Q 与本项目完整动作头能否直接拼接？

**冻结位置：**06:272–280；07:133–139、196–199；01:194。**来源：**[S2 §4.1、附录 A.1](https://arxiv.org/html/2608.23831v2)。

**反例：**actor 实际读到 t+4 图像，却把输入仍登记为 t；或者把 Harness 的末端动作写进 ARLI 的 w 字段。另一个情形是旧 decoder 下 w 产生抓取，新 decoder 下同一 w 产生别的动作，却混用同一 latent replay。

**判断：通过，扩展没有偷渡。**首版只读起点信息，原始动作直接作为 U；中途观测需要另定决策点和剩余 commitment。latent／物理动作不混用，decoder 改版的语义问题已声明。因此当前方法不能继承原 ARLI 的全部理论与实验性质，文档也没有这样宣称。

### Q14：终局正奖励通过统一链传播，是否还残留选择性多步回填？

**冻结位置：**06:213–217、294–298；07:215；02:T11。**来源：**[S3 Bellman 递推](https://arxiv.org/html/2004.06089)、[S1 原版 2n target 对照](https://arxiv.org/html/2608.29768v1)。

**新反例：**相同 next state 有 0.3 概率终局得 1、其余回报为 0，真实值为 0.3。终局时替换前驱为 1、未终局时保留无条件 0.3，平均变成 `0.3+0.7×0.3=0.51`。偏差不依赖原文 0.5／0.75 的特例。

**判断：通过，数学已核。**当前规则不按未来结果选前驱 target，终局行只训练当前真实请求的 Q，再由固定 Bellman 链传播。没有立即收敛保证；在缺覆盖、有限函数逼近与目标网络滞后时，传播速度和准确度仍待测试。原版 SmoothRL 的 2n target 被作为独立对照，没有改名混用。

## 3. 实际完成的验证与最终判断

实际执行了 Python 纯数值核验，没有写测试代码或数据到其他文件：

| 独立核验 | 结果 |
|---|---|
| 一槽延迟 TD 与直接物理折扣回报 | 均为 7.600000000000001 |
| 终局筛 actor 行的共享梯度反例 | 全状态 +0.25；筛选后 −0.36363636363636365 |
| 按未来成功选择前驱 target | 正确值 0.3；混合目标 0.51 |

**已验证的数学：**在所声明固定槽、冻结决策与准确队列条件下，一槽奖励和折扣对齐；未来终局选择前驱 target 会偏；终局筛 actor 行可改变梯度方向。这里只验证代数与反例，不证明真实视觉状态完整或神经 Q 收敛。

**已明确的设计契约：**请求、提交、生效三类事件；真终局与外部截断；事件时间与回复时间；局部接管隔离；goal／版本边界；TD／BC／动作梯度的独立资格；扩展模式不得隐式混入。

**待实验：**固定 n 的可行性、事件定位准确率、C→E 连续性、完整头拟合、真实 TD 密度与删失偏差、actor 筛样实际影响、终局奖励传播、两方向无辅助提升。上述项目都有已定义对象或规则；它们不是已通过的实验。
