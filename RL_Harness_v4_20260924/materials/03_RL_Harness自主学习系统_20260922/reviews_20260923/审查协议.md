# 2026-09-23 联合方案审查协议

用户要求：先深入学习并修正五项评审意见；每轮启动多个审查代理，各自枚举技术要点、独立学习原始来源，再提出问题审查。发现必要问题后补学、修订，直到连续三轮无问题才交付。

本协议仅审核研究设计，不执行科学家知识库更新，不宣称真机实证。

每轮冻结主文、开发附录、证据综述和快速入口，保存 SHA-256。至少三名独立审查代理覆盖异步动作/RL、共享目标/BC+RL、GPT-6/Harness运行时；可以变换交叉角度。代理先列关键点，打开原始论文/官方文档/代码进行本轮独立学习，再提出至少六个有依据的问题，并逐项对照冻结文本回答。不能只读前轮意见后勾选。

必要问题指概念错误、与用户需求冲突、数据或梯度语义不成立、开发所需关键契约缺失、事实证据不足却作既定结论、影响正确性的文档矛盾。任一必要问题使本轮 FAIL，连续无问题计数归零；补学和修改有明确出处及修订位置。合理且明确的实施前验证门槛不因尚未实测就自动 FAIL，但不能以“待测”掩盖尚未定义的方法。可选改进若实际改变技术方案，也须再冻结并重审。

PASS 要求全部代理无未解决必要问题，主代理复核来源与问题回答，无交叉遗漏。连续三轮应针对同一技术文档版本通过，保持新一轮实际学习记录和不同问题视角；任何技术内容变化重新开始计数。最后的状态汇总、链接索引生成与审查处置记录不改变被审技术定义。

记录结构：`Rxx/input_manifest.json` 与 `input/` 为冻结输入；`agent_async.md`、`agent_learning.md`、`agent_harness.md` 为独立记录；`result.json` 为总判定；必要时 `remediation.md` 为补学修订。总状态保存在 `status.json`。三轮通过只表示对冻结范围和所提问题的设计审阅，不是穷尽性证明或独立实验室认证。
