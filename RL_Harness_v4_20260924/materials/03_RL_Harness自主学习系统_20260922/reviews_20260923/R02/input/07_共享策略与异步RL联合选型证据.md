# 共享策略与异步 RL：联合选型依据

**2026-09-23｜开发者审阅补充｜基于原始论文与固定源码的静态审核，未运行训练或真机实验**

本轮选型对象不再只是“哪篇 VLA RL 论文更好”，而是一个确定的工作方式：**同一个共享参数 policy，按目标执行 A→B 或 B→A；两方向都接受在线 RL；Harness 观察并纠正，将可信纠正聚合为 BC 数据；机器人在推理期间继续执行旧动作，因此训练必须适配真实异步执行。**

结论是：**主拟议路线采用“共享目标条件 VLA 表征＋完整原始动作头＋Harness BC＋固定推理预算下的队列增广离策略学习”。** 执行区的处理参考 SmoothRL；首版 Bellman 目标采用单决策队列增广定义，不照搬原论文的双窗口目标，具体区别见第 10 节。这比继续围绕弱 base 做固定幅度修正更贴合本项目，但它是一项需要实现和验证的改造，不能宣称已经有完整开源成品，也不能宣称工程量小于 EXPO。EXPO 保留为有明确源码基础的实现参考与条件回退；原 SmoothRL、ARLI、ConRFT 和 HIL-SERL 分别提供异步目标、延迟状态、动作头与纠正学习、真机回放工程的依据。

## 1. 为什么改变之前“先选 EXPO”的结论

之前优先 EXPO 的理由，是现有 π 推理与监督链可以复用，且其 base 监督更新容易接入新的纠正数据。这个理由仍成立，但不足以决定最终系统。

新增约束改变了比较：同一模型必须同时学习两个方向；Harness 可能提供短片段纠正；初始动作可能离正确行为很远；生成的动作块通常只有中段真正执行。已有 EXPO 代码的“VLA 前缀候选＋有界 edit＋固定前缀 Q”并不能直接覆盖这些条件。另一方面，ConRFT 的完整动作头也不是现成的异步动作块 learner。

因此要区分三个问题：

| 比较维度 | 应回答的问题 | 不应替代它的证据 |
|---|---|---|
| 方法匹配度 | 能否表达目标条件、真实异步动作、可信纠正与偏离弱初始策略的改进？ | 论文是否更新、机构是否知名 |
| 现成代码复用 | 哪些数据、网络和执行链已公开且可以检查？ | “论文说可扩展”“有 GitHub 链接” |
| 实质改动与验证成本 | 哪些只是 adapter，哪些会改变状态、动作、目标函数或模型表达？ | 把几个方法名称相加后称为成熟方案 |

三者分别评价，不计算掩盖差异的虚假总分。新方案的第一项更贴合要求，不代表后两项天然占优。

## 2. 主拟议路线到底训练什么

### 2.1 一套共享参数，两个任务条件

机器人只部署一个任务 policy。输入除图像、本体状态和必要历史外，还包含目标：例如“把物体放到 B”和“把物体放到 A”。两个方向共用 VLA 表征、可训练动作头和发布版本。共享不只是“两个模型采用一样的代码结构”，而是使用同一组参数 θ。

critic 和 target 网络同样需要目标条件。对于同一画面、同一动作，“更靠近 B”对两个方向的价值可能相反。仅给 VLA 换语言提示、却让 Q 看不到目标，会把这些经验混在一起。共享 goal-conditioned 价值函数有成熟的方法基础，但本项目的动作队列、任务条件和目标边界仍需自行贯通。[UVFA 原始论文](https://proceedings.mlr.press/v37/schaul15.pdf)

训练方式采用两个互补信号：

- **Harness BC：** 模仿经过质量核验、与 policy 输入和动作空间相容的纠正。既可使用真正执行的纠正，也可使用具有可信依据但未执行的动作标签。
- **在线 RL：** 用真实执行命令及其实际后果训练价值与动作改进。失败样本可以发挥作用，不要求每次都形成成功回合。

BC 在这里是动作监督的总称。具体可使用适配动作头的回归、consistency 或其他明确的监督目标，不能把不同模型的损失直接拼成一个通用函数后宣称已兼容。Harness 负责产生、记录与审核纠正，系统并不假定另有一个已经很强的上游 policy。

### 2.2 完整动作头解决什么，又增加什么风险

完整动作头直接输出学习接口定义的动作序列，不把可输出动作强行限定为弱 base 动作附近的小邻域。底层关节、速度、可达性和控制约束仍然存在；“不贴近弱参考动作”并不意味着取消物理约束。

它的优势是 Harness 的原始动作可以直接作为监督目标，不必先反演为 VLA 的 latent noise，也不必证明纠正落在固定残差幅度内。其代价是动作头需要从已有表征和少量数据重新建立运动映射，可能丢失预训练动作头中的控制先验。表征若不足以分辨抓取位置或夹持状态，换成完整头也不会自动补齐信息。

因此冷启动要先证明：两方向的可信动作能够被拟合、动作单位和帧定义正确、闭环输出可执行。可选初始化包括保留原有可训练头、用可信示范训练新头，或在其有效范围内蒸馏原策略。不能把任意弱 base 的所有输出都当正确答案。多种合法动作方案也不应被简单平均成一条不合法轨迹。

“BC＋RL 更稳妥”是合理工程选择，不是无条件保证。错误纠正、高度重复的少数片段、过强 BC 权重都可能压制探索。初始数据和高质量新纠正应得到保护，同时记录质量、覆盖和采样次数；权重变化必须能追溯，而不是让新奖励或新的 Harness 版本悄悄改变学习目标。

### 2.3 异步原则必须进入训练

首版采用固定推理预算和明确的窗口调度：在新动作块生成期间，机器人继续执行已承诺动作；新动作块只贡献约定的执行区；未执行尾部被后续结果替换。value gradient 只针对本次可训练动作模块提交到下一槽的执行区，不能作用于旧承诺前段和被丢弃尾段；critic 则必须知道影响其所评估时间段的已承诺命令和执行语义。这个动作分区原则来自 SmoothRL；本项目进一步选择第 10 节的队列状态与 Bellman 定义。[SmoothRL 原始论文](https://arxiv.org/html/2608.29768v1)

从 ARLI 借鉴的是“让 learner 知道推理等待期间发生了什么”的状态设计，而不是默认采用其整套 latent steering。已承诺队列、观测年龄和必要的较新观测不能只写入日志；它们要在选定数学定义下进入网络和 target 构造。[ARLI 原始论文](https://arxiv.org/html/2608.23831v2)

固定预算也不是要求实际延迟永不变化。系统需要测量截止时间内的完成情况，并为超时、取消和队列不足规定明确处置。未满足首版数学条件的片段保留原始证据，不凭补零或复制动作硬塞进宏观 Q 更新。

## 3. 六条路线分开比较

| 路线 | 方法匹配度 | 本轮核到的可复用代码 | 实质改动与限制 |
|---|---|---|---|
| **主拟议完整动作头路线** | 直接面向共享 goal、Harness 原始动作 BC、偏离弱 base 和异步执行区 | 复用已有 VLA 表征/数据链；ConRFT、EXPO、HIL-SERL 的部分组件可参考 | 完整 chunk 头、goal-aware Q、固定预算异步 target、数据 builder 和测试属于本项目改造；不是现成开源算法 |
| **原 SmoothRL** | 异步 chunk 的实际贡献与原始动作空间干预最相关 | 已核论文；官方项目抓取未成功，本轮未取得完整训练实现和代码许可 | 论文实例仍使用冻结 base＋RLT 类有界修正；替换成完整头和 Harness 数据源后不能原样继承其实验结论 |
| **原 ARLI** | 延迟状态和中途观测的处理最相关 | 已核原论文、官方项目；本轮未固定作者完整训练仓库 | RL 动作为 latent noise；Harness 物理动作不能直接写成 latent action；更新 base 又会改变 latent 的物理含义 |
| **EXPO-FT** | 有 base 监督＋真实交互 Q/edit，可复用 π 链；但默认有界编辑不保证补齐缺失行为 | 已固定并阅读 actor、critic、replay 和 sampler | 增加 goal、committed context、中段 credit、独立 Harness 标签与部分监督；不能只换 runtime 而保持同步前缀目标 |
| **ConRFT** | 完整动作头与 BC＋Q 是直接依据，支持离线到在线 | 已固定训练和 loss 源码；公开实例使用 Octo 与 7D 单步动作 | 增加 goal-aware critic、chunk/queue 条件、异步目标及纠正独立采样；保留 π 表征还涉及模型接口改造 |
| **HIL-SERL** | 真机混合控制、离策略回放和工程生命周期有价值 | 已固定并审查默认 SAC、单臂 hybrid 与训练入口 | 非现成 VLA learner；已审默认 actor 没有显式 BC，demo 用于 TD 不等于原生 DAgger；异步 chunk 还需重构 |

**主拟议路线更直接满足需求，EXPO 更有现成源码落点。** 应通过一组小而必要的接口、梯度和数据预检决定首轮实现，不用“更直接”掩盖从单步到动作块、从单任务到共享目标、从同步到异步的研发成本。

## 4. 代码核查如何改变判断

### 4.1 EXPO：语言条件存在，不等于 Q 已具有目标条件

固定代码里，VLA 采样 batch 包含 tokenized prompt；critic 字段只抽取相机和 proprio。其动作处理取 `:replan_steps`，TD 使用固定 `discount ** replan_steps`。这说明原代码的语言能力与多目标价值学习不能画等号，固定前缀训练也不能直接承载任意中段执行。[batch_utils.py](https://github.com/pd-perry/expo-ft/blob/803381fc3b4c91a0c47904f1b688fc5e35904f50/expo_ft/agents/alg/batch_utils.py)、[expo_ft.py](https://github.com/pd-perry/expo-ft/blob/803381fc3b4c91a0c47904f1b688fc5e35904f50/expo_ft/agents/alg/expo_ft.py)

EXPO 的 base 监督与 Q/edit 已有可复用的分工，但其 replay 用顺序真实记录回填动作块、构造后继。独立的 Harness 动作标签应走 actor 监督视图，不能插进这条序列后借用下一条记录作其后果。[replay_buffer.py](https://github.com/pd-perry/expo-ft/blob/803381fc3b4c91a0c47904f1b688fc5e35904f50/expo_ft/data/replay_buffer.py)

### 4.2 ConRFT：已有完整头，不等于已有完整异步方案

ConRFT 的 actor loss 明确包含 consistency 重建和 Q 改进；但固定文件的动作形状检查是单步 7D。`forward_policy` 接收任务信息，而 `forward_critic` 虽有 `action_embeddings` 形参，实际调用没有使用它，仅把 observation 和 action 送入 critic。因此共享正反训练必须检查下游真正消费的 goal，不能看见字段名就认定兼容。[固定 loss 与网络入口](https://github.com/cccedric/conrft/blob/a779fde7fa5db5a469960a8490c100f35b41b49e/serl_launcher/serl_launcher/agents/continuous/conrft_single_octo_cp.py)

### 4.3 HIL-SERL：有 demo buffer，不等于已有 BC

已审默认 SAC actor 在回放状态上采样自己的动作，优化价值与熵，并不回归 replay 中的示范动作；真实示范主要通过 critic 提供有信息的后果。因此，要用于本项目必须新增明确的 Harness BC 通路，并解决 VLA 与异步动作块接口。[固定 SAC](https://github.com/rail-berkeley/hil-serl/blob/c32939bccb65f3b8c43a9f9add3d322d4ab0264a/serl_launcher/serl_launcher/agents/continuous/sac.py)

## 5. 共享正反学习必须共同满足的契约

### 5.1 物理循环连续，任务回报不能串线

一次 A→B 成功后，场景可以直接用于 B→A，但正向目标的回报在其任务终局结束。反向新建逻辑任务，目标、核验和动作队列切换到 B→A。不能为了保持物理循环而让正向 Q 自动吸收后续反向成功奖励。

共享 θ、共享 Q 参数和共享 target 参数不改变这条规则。每个样本有其明确目标；bootstrap 按该目标的正确终止/截断语义构造。若只是同一目标下的 Harness 纠正，保留真实控制来源与实际后果；其救回不能计为 policy 单独成功。目标切换时旧方向的在途推理结果必须失效，不得继续进入新方向队列。

### 5.2 一个回放系统，按目标、来源、质量采样

底层可以统一存储，采样至少同时区分：

- 目标：A→B、B→A，各自有最低覆盖和有效样本预算。
- 来源：初始示范、policy 真实执行、Harness 真实纠正、Harness 未执行标签。
- 质量：可信动作监督、仅有真实 TD 后果、待核标签、不兼容执行片段。

每目标分别统计有效 TD/BC 数、重复抽样比例、损失尺度和无辅助能力。比例可以随覆盖调整，不必永久固定 50:50，但不能让更容易成功、动作更多的一侧饿死另一侧。初始示范长期归档与保护不等于其采样权重永久不变。

共享更新后只能发布一个版本包，正式指标仍分别报告两个方向。晋级要求两个方向都满足各自已定义门槛和回归容忍，不能只看平均分。一方向退化时先检查目标条件、样本覆盖、奖励尺度和优化冲突；独立策略可用作诊断消融，不悄悄替代主方案。

### 5.3 三种 mask 不能混成一个 valid

| mask | 回答的问题 | 典型反例 |
|---|---|---|
| 执行贡献 mask | 这次实际命令中，哪一段由当前可训练动作输出贡献？ | 未执行尾段不能接受该次真实后果的 value gradient |
| BC 标签 mask/质量 | 哪些动作位置具有可信纠正标签？ | 可信但未执行的完整建议可以监督；执行过的错误动作未必值得模仿 |
| 终止/折扣 mask | 该目标和时间定义下是否允许 bootstrap？ | 监控暂停不必是任务失败，反向新目标也不能无条件延续正向回报 |

只在最终 loss 乘一个 mask，不能修复上游错配的观测、动作时间索引、flow 输入、未知尾部或 target 状态。

## 6. 长期数据怎样保留，怎样获得训练资格

用户提出保留 DAgger/遥操作类数据参与在线 RL 是合理的。原始 DAgger 的关键是访问状态上的纠正聚合，而非指定人类或某种上游模型。[DAgger 原始论文](https://proceedings.mlr.press/v15/ross11a/ross11a.pdf)

不过，**数据被长期保存，不代表它对每一种 RL 目标都具有相同资格**。特别是首版队列增广 Q 需要对应决策请求、执行窗口、已承诺命令与正确后继：

| 数据 | 长期保存 | 可立即用于什么 | 进入首版异步宏观 Q 前还需什么 |
|---|---|---|---|
| 历史真实示范，只有图像/状态/动作序列 | 是，保护原始记录 | 与模型输入匹配的 BC；必要时保留作其他明确目标的离线数据 | 从真实日志恢复完整时间、队列和窗口语义；恢复不了就不能补假 queue 直接进入宏观 Q |
| 在目标异步执行协议下采集的真实示范/纠正 | 是 | 可信段 BC；完整兼容窗口的 TD | 核 goal、实际命令、窗口、奖励和后继均已确定 |
| Harness 在历史状态提出但未执行的建议 | 是 | 经质量核验的 BC/动作辅助目标 | 没有该动作真实后果，不能伪造转移；保留为动作标签视图 |
| policy 的真实失败交互 | 是 | 兼容窗口的 critic/价值学习 | 不因为真实发生就默认成为 BC 正例；不跨缺口拼接窗口 |
| 取消、超时或异步上下文不完整的真实片段 | 是 | 诊断；其中独立可信标签可供 BC | 首版宏观 Q 默认隔离；只有明确的新目标设计或补齐真实上下文才可解锁 |

“历史真实示范有真实后果”是必要事实，但未必足够满足特定异步算法。也不能给历史同步轨迹虚构零延迟/空队列，并把它说成按当前协议采集。若确实要设计一个支持不同调度模式的 learner，需将模式作为状态、动作和 target 的一部分重新论证；首版不默认具备这种能力。

## 7. ARLI 为什么作为机制参考而不是默认主 learner

ARLI 在 latent-noise 空间学习，物理动作由被冻结的 VLA 生成。因此“当前 Harness 选择了一个物理动作”不意味着知道它对应哪个 latent；不能直接把关节/末端动作写进 latent replay 的 action 字段。未知 latent 的真实纠正仍可保留作原始动作 BC 或其他明确设计的数据，不需丢弃。[ARLI 论文与官方项目](https://arxiv.org/html/2608.23831v2)、[官方项目页](https://async-rl-intermediate-information.github.io/)

另一处兼容性在 base 更新：旧 decoder 下某个 latent 导致真实结果，并不证明新 decoder 下相同 latent 也有该结果。若选原 ARLI 路线，应在 RL 阶段冻结 base，保存 decoder 版本，并在 base 改版后隔离旧 latent replay；重新采集、按严格条件重建或另设模型才可能继续使用。真实物理命令、原始图像和有效 BC 标签仍应保留。

主拟议路线直接在原始动作空间建模，避开这类 latent 动作语义变化，但仍不能忽略 normalizer、表征、调度协议和动作接口改版。表征更新后旧缓存要重算；动作意义或环境契约变化后的样本需要重新判定资格。

## 8. 用哪些预检锁定最终实施路线

| 预检 | 主拟议路线应证明什么 | 不通过后的合理调整 |
|---|---|---|
| 双向条件动作拟合 | 同一头能利用目标与表征拟合两方向可信纠正，动作模式可执行 | 检查表征/目标输入；比较保留原生 π 头或 EXPO 的监督路线 |
| 数据到梯度追踪 | BC 读取真实标签；TD 只读完整兼容窗口；执行 mask 精确控制 value gradient | 先修数据和目标，不用真机试错掩盖因果配对问题 |
| 固定调度复现 | 同一日志能重建 committed、execution、discarded 和 bootstrap context | 固定预算与窗口协议；不兼容片段隔离，不静默退回同步公式 |
| 小规模闭环与同预算对照 | BC＋RL 相对单独 Harness 纠正聚合带来独立 policy 收益 | 接受 RL 未增益的结果；检查探索、奖励、BC 权重与覆盖 |
| 共享模型回归 | 两方向都被训练且均满足发布门槛 | 调整采样/归一化/目标表达，独立模型只作定位问题的对照 |

若完整头冷启动显著不如原生 π 的监督微调，优先采用后者是合理修正。若 Harness 主要只能提供短片段，而原生 π 的部分动作监督始终无法对齐，完整头的直接 BC 优势才更有实证支撑。最终选择应以这些预检和小规模学习结果为依据，不能预先宣称完整动作空间必然更容易探索或成功率更高。

## 10. 补充复核：固定 n 步队列增广目标

### 10.1 定义与成立理由

首版使用统一的“延迟控制请求”决策定义，区分**请求已经由 runtime 接纳**与**计算出的动作已经写入下一槽**。每个正常窗口含 n 个微控制步；窗口起点冻结观测/历史、目标、当前承诺 C、随机种子、权重、预处理和调度配置，runtime 接纳一条绑定下一槽的真实 policy 请求。请求结果 U 可在计算结束后才得到，但它只由这个冻结信息集决定，不能在事后读取未来观测改变结果。

```text
当前决策状态 X = (观测/历史，goal，当前槽承诺 C，阶段/配置)
本次决策动作 U = 这次真实延迟控制请求依据冻结 X/seed/权重得到的原始动作
当前槽实际执行 C，得到折扣累计奖励 R_n
正常分支：U 在截止时间前写入下一槽
下一决策状态 X_next = (新的观测/历史，同一 goal，新承诺 C_next=U，阶段/配置)

正常非终局 TD：
y = R_n + γ^n Q_target(X_next, π_target(X_next))
```

当前槽的直接物理奖励通常由 C 产生，而不是由正在计算的 U 产生，这不构成错误归因。U 的作用首先是改变下一状态里的承诺队列，再影响后续物理回报；value gradient 经这个延迟作用学习。不能把当前 C 的真实后果说成“U 已经在物理世界执行了一遍”。

把动作延迟放入增广状态，是已有延迟 MDP 的标准思路。Thinking While Moving 也从并发控制出发，将旧动作执行与新动作计算同时纳入 Bellman 定义。这里的 VLA、固定槽、Harness 接管与共享目标实现仍是本项目的具体设计，不是原 SmoothRL 代码即插即用。[延迟状态增广讨论](https://proceedings.mlr.press/v162/liotet22a/liotet22a.pdf)、[Thinking While Moving 原论文](https://openreview.net/pdf?id=SJexHkSFPS)

这一设计与完整动作头、弱初始 policy 兼容：动作头输出的仍是原始命令，不需要 latent 反演；BC 仍可给下一槽动作提供监督；Q 的延迟信用传递不要求 base 原本已经可靠。但是队列扩大了学习状态，延迟降低了反应上限，完整头仍需正确数据冷启动。图像/有限历史不一定构成完全 Markov 状态，不能仅凭增加队列便宣称获得严格的真机收敛保证。

### 10.2 必须保持的四个条件

1. **同一信息集：** U 对应明确的决策快照、随机种子和 policy 版本。如果生成期间又使用较新的观测进行改写，必须更新决策定义或采用明确的中途决策模型，不能仍按只依赖旧 X 的策略训练。
2. **真实请求：** 有 runtime 接纳请求的凭证、窗口和 goal epoch；正常分支另有下一槽提交凭证。没有进入控制请求流程的 shadow 建议只是标签，不能为其补造请求或队列状态。
3. **承诺稳定：** 正常 TD 窗口内 C 的实际执行与约定相符，下一槽承诺确实是 U。Harness 后来临时生成的纠正不能回填成先前请求的结果。
4. **target 同步语义：** target 的输入包含真实 X_next 及其承诺 U，target 输出的是再下一槽的动作。不能在 target 中退回“看到新图立即执行新动作”的同步模型。

必须把 `request_admitted`、`next_slot_committed`、`physically_executed` 分开记。真实控制请求在计算期间遇到任务终局，与从未提交给 runtime 的建议不同。前者可以按下面的统一终局分支保存 TD，后者没有因此取得真实请求的后果。

### 10.3 终局：同一决策定义下直接关闭，不特判回填前驱

若 runtime 已接纳上述真实请求，C 在第 L 步使该目标真正终局，即便 U 尚未提交下一槽，也可以等待该请求基于冻结信息完成计算，在数据视图齐备后保存当前决策的终局样本：

```text
当前终局样本：Q(X, U) ← R_L
terminal = true；next_slot_committed = false（若终局前确实未提交）
不 bootstrap；不声称 U 曾经物理执行
```

其中 R_L 从当前窗口起点折扣，覆盖实际 L 步。请求起点的 X、seed、权重和信息集早于终局已经固定；等待计算结果不允许重新生成一个看过终局的新动作。若请求没有实际提交、无法恢复其确定结果，或更早发生超时/接管/信息集改变而破坏协议，保留原始事实并隔离，不补一个虚构 U。

**修正已被否定的旧建议：不使用 `QueueTerminalValue`，也不在“下一槽恰好终止”时特殊回填上一条 target。** 后一种写法即便不训练独立 V，仍可能有未来事件选择偏差：假设相同下一状态有一半概率终止得 1，另一半后续总回报为 0，真 V 为 0.5；若终止时把前驱 target 改成 1，未终止时仍使用 V=0.5，平均就变为 0.75。统一使用当前请求的普通 terminal/nonterminal 分支，避免这一捷径。

首版可选择不从这些“C 中已经终局”的样本计算 actor Q 梯度，但 critic 必须保留其真实回报。这是明确的工程采样规则，不宣称它等价于无偏完整 policy gradient。终局由固定目标定义确认；超时、传感器故障和 Harness 接管不能冒充物理任务终局。

### 10.4 接管、超时与数据选择偏差

C 被接管、实际命令不完整或推理超时造成该窗口不满足契约时，首版隔离相应宏观 TD，保留真实微步记录和独立可信的 BC 标签。按最先破坏协议的事件分类；不能在先超时/接管后又因为最终成功而改用正常终局分支。不能把接管后发生的未来动作拼回先前的预提交队列。

隔离可以防止错误转移，却不会自动消除统计偏差。若困难状态总被接管、某类动作总被拒绝，训练池会过度代表正常窗口。必须按 goal、状态范围和触发原因报告隔离比例、纠正/超时频率，并把这些事件计入系统评测。不能拿“正常窗口 Q 学得很好”证明全部真实运行已得到无偏评价。需要利用被接管区域的 RL 后果时，应另设计并审核带控制模式的目标，首版不默认做到了。

### 10.5 BC 的时间对齐：首版规则与可研究的例外

最容易出错的样本是：在 t 时刻开始预测 t+n 的动作，却把 Harness 到 t+n 看过新画面后临时给出的纠正，未经说明就当作 t 时刻已经知道的答案。首版采用简单规则：记录纠正对应的决策快照、承诺队列和目标执行时间；优先训练在相同信息集下生成的下一槽动作标签。执行时纠正仍可长期保留，不因暂不满足提前决策 BC 的资格而删除。

**不过，“事后或特权纠正绝不能监督延迟策略”也是过强结论。** DIDA 的原始研究使用较新的无延迟动作标签来训练依赖过去观测和动作历史的延迟策略。这类监督可以成立，但需要显式定义延迟/特权模仿问题，并承认可观测性、随机扰动和多种合法动作带来的不可消除误差。[DIDA 方法 §5 与算法 1](https://proceedings.mlr.press/v162/liotet22a/liotet22a.pdf)

本项目首版暂不自动把所有此类纠正送进提前决策 BC。这是降低标签混叠的工程选择，不是证明它们在原理上无效。以后开放该通路时，要保存当时 policy 真正可见的信息，禁止把未来观测偷偷作为部署输入；评估标签可预测性与闭环效果。它也不会因此获得 TD 后果，未提交控制请求的 shadow 建议与真实请求转移仍须分开。
