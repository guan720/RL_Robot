## 1. 先枚举本轮独立学习和审查的关键点

1. SmoothRL 原文的 C/E/D、固定预算、2n 回报和梯度截断，是否被误写成当前一槽算法。
2. 当前状态中 C 的作用，以及当前奖励来自 C、当前 U 只改变下一队列，是否仍构成合法 Bellman 递推。
3. request、commit、activate 是否只有名称区别，还是有可核验的不同事件与准入条件。
4. 当前 C 提前终局时，尚未激活 U 的 critic 样本是否真实、是否泄漏未来。
5. 终局正奖励如何传回前驱，是否按未来成功选择不同 target。
6. 抢占、超时、迟到核验和数据删失，是否错误归零或改写历史队列。
7. Q 动作梯度、物理执行 mask、TD 资格和 BC mask 是否被混用。
8. ARLI 的中途观测、latent 动作与冻结 decoder 是否被错误搬进物理动作头。
9. 部分动作监督与事后/特权 BC 是否被过度禁止或未经建模直接接入。
10. 共享 goal 是否真实进入 policy、Q、target、奖励及换向边界。
11. RPent 的动作维度、固定 VLA 指令和解析动作分工，是否被错误当作松灵单臂完整任务能力。
12. 所有未实测项是否被清楚保留为实施门槛，而不是借论文成绩背书。

## 3. 审查问答

### Q01：当前一槽目标是否冒用了原 SmoothRL 的 2n 结论？

**位置：**06:119–134、312–324；07:7、173–199；01:180–194。

**答：通过。** 本轮重读 SmoothRL 后确认：原文在有效 C+E 的 2n 区间累计回报，当前稿明确改为每 n 步一个队列决策。06:134、322 和01:194都明示区别。不能要求此项目为了与原论文一致而退回2n；也不能把当前改动称作仅改一个折扣指数。[原文 §3.3](https://arxiv.org/html/2608.29768v1)

**尝试的反例：**直接保留 n 步回报，却把 next state 设成 t+2n，或用行为策略在中间生成的新 commitment 冒充目标策略选择。冻结稿06:288直接禁止前者；其相邻队列递推避免了后者的这次跨越。没有发现必要修正。

### Q02：R 来自旧 C，为什么可以与本轮 U 构成 TD？

**位置：**06:42–85、105–128；02:223–233；01:184–192。

**答：通过。** 在拟议环境中，本轮动作首先是“把下一承诺队列设为 U”，不是“立即执行 U”。在正常分支可写为：物理状态在当前 C 下推进 n 步，队列分量确定性变为 U。于是 `Q(X,U)=E[R_C+γ^n Q(X_next,π(X_next))]` 合法；即时奖励不依赖当前动作并不违反 MDP 定义。并发 Q 要读取先前动作这一出发点也与 Thinking While Moving 式(8)–(9)一致。[并发 Bellman 原文](https://arxiv.org/html/2004.06089)

**独立手算/实际数值核算：**取 n=1，状态只含 C=c，即时奖励 r=c；本轮 U=u，后续 policy 恒取 p。则 `Q(c,u)=c+γu+γ²p/(1−γ)`。γ=0.9、c=0.3、u=0.7、p=0.2时，直接式与 `c+γQ(u,p)` 均为2.55，残差为0。此为审查用代数算例，不是项目 learner 测试。

**边界：**06:99明确图像/有限历史仍可能不充分；本结论不把队列增广当真机完全可观测性的证明。

### Q03：request 接纳但 U 尚未算完，会不会只是事后补一个行为动作？

**位置：**06:63–75、196–200；02:225、235、358、365；07:175–201。

**答：通过。** 冻结稿要求真实控制请求在槽起点成立，冻结输入、goal、权重、随机性和槽位；原计算可以较晚得到数值，但不能读取后来的图像或新参数。这里可以把 U 看成已确定信息集与随机性的函数。事后新增请求、重采样多个结果择优、给影子建议补 admission 均不符合文字契约。

**反例：**成功后重新以“物体已在B”的图像生成一个零动作，再声称它是起点的 U，会产生未来信息泄漏。06:198、07:196与213已排除。没有必要修正；实施时需验证原在途计算和冻结版本的真实身份。

### Q04：C 内终局、U 从未物理激活的样本能训练 critic 吗？

**位置：**06:192–211、221–231；01:198；02:235与T11；07:203–217。

**答：通过。** 这是延迟动作 MDP 中，当前决策遇到吸收终局的样本。U 没有机会改变后续物理状态，因此 target 仅为本槽实际终局回报，不要求强行构造 next queue。稿件没有将这件事表述成“U 导致 C 成功”。

**反例：**同一 X 下 C 已确定将在第2步终止，任意 U 的真值都应相同；把 U 是否被激活作为 critic 样本硬过滤条件，会系统性丢失这类终局事实。冻结稿保留真实请求结果；结果确实不可得时仅留事实，不伪造 U。06:211还明确该类行不做 actor Q 更新。这是有边界的设计，未发现定义性错误。

### Q05：正奖励能传回吗；是否存在“未来成功才改前驱 target”？

**位置：**06:213–219、294–298；07:215；01:200。

**答：通过。** 当前终局行训练当前 Q，前驱仍用正常 Bellman bootstrap。γ=0.9、n=6，下一槽第3步奖励1，则终局 target=0.81；在该价值已学会时，前驱为 `0.9^6×0.81=0.43046721=0.9^8`。本轮实际数值核算一致。

**反例：**同一后继状态一半概率得到终局1，另一半后续回报0；只在终局时把前驱改为1，其余仍用无条件0.5，会得到平均0.75。冻结稿明确禁止这种按未来事件选 target 的捷径。目标网络更新会带来传播延迟，稿件也没有许诺单条正样本立刻传遍前驱。

### Q06：后一个槽被抢占，前一个完整槽还保留，会不会伪造未执行的后果？

**位置：**06:140–148、245–255、300–306；02:237；07:221–223。

**答：通过，但有已声明的覆盖限制。** 前一个槽的后果是“正确的边界观测＋队列已变成 U”，这件事可在后续抢占前真实成立。以后抢占不能倒改这个历史队列。受抢占槽不是原固定槽转移，因此隔离；边界本身不可确认时前驱一起隔离。该处理与本稿的队列动作定义一致。

**反例：**106帧 U 已成为C，108帧切到 Harness，不能用108后的纠正段重写106的C；也不能宣称100–105从未完成。两种错误都被06:251、306排除。

**剩余风险：**若106状态每次都会被接管，Q 在这些状态缺乏合格后继，保留前驱不会自动补齐覆盖。01:232、06:253、07:223已经承认并要求监测，因此属于待实验的外推/选择偏差，不构成未披露的正确性保证。

### Q07：超时后又成功、晚到终局核验，是否会改变事件先后？

**位置：**06:221–231、259–268；02:107、163–179、235–237；01:160。

**答：通过。** 冻结稿以最先破坏契约的实际事件分类，区分任务终局、服务返回时间、超时和接管。奖励未知保持 pending，不取0；超时本身不自动令后继价值归零。迟到核验不能篡改已存在的 commit 回执。

**反例：**deadline先错过，机器人保持后才稳定放置；若将原槽追认成合法正常terminal，便删掉了调度失败。06:231明确禁止。若释放后还需要稳定性视频，终局取证据充分时刻，不任意回溯至首次接触，避免把后见信息提前用于边界。

### Q08：Q 梯度与物理执行 mask 是否仍有混淆？

**位置：**06:150–163、171–180、290–292；02:239–251、T13–T14；07:50–56、107–115。

**答：通过。** 规范定义是 `Q(h,g,sg(C),πθ(X),ξ)`，本次动作变量只有U/E；C是状态，D不进入本次价值动作。06明确区分计算图动作路径与共享参数更新后其他输出变化，因此没有要求共享网络的C/D数值永久不变。这个区别保留了 SmoothRL 原始动作空间梯度思想，但执行资格以本项目队列模型为准。[原文的梯度与动作一致性讨论](https://arxiv.org/html/2608.29768v1)

**反例：**把当前网络预测的C前段塞入critic，会改变本来不可改变的旧队列；只在loss末端乘物理mask，不能修复这种输入错误。稿件的T13和06例2覆盖该反例。07表格的“执行贡献”简写应按02/06的完整定义读取，而不能理解成“只有后来实际激活才允许保留先前队列TD”。

### Q09：未执行标签和部分动作标签的 BC 规则是否正确？

**位置：**06:165–190；02:247–253、T14–T16；07:123–131、225–231。

**答：通过。** 未执行建议没有自己的真实TD后果，但可以是可信监督。固定n步头不能把单步标签复制n次；flow/diffusion也不能只在最终loss加mask而让未知标签先污染加噪输入和attention。冻结稿已将这些条件写成所选动作头的实现门槛。

**反例：**未知夹爪标签填0后送入全chunk去噪输入，即使最终对该位置loss置0，其他位置仍可能受它影响；文字已明确不接受。相反，未执行完整建议若输入、C和执行时刻相符，也不应被物理mask全部删掉。没有必要修正。

### Q10：DIDA 是否证明事后标签一律非法；当前稿是否误引？

**位置：**06:182–190；07:225–231；01:130–138。

**答：通过。** 独立重读DIDA算法1与§5.3后，确认其专家可看较新状态，而学生依赖过去状态和动作历史；这不能被概括为“所有未来信息监督都是泄漏”。真正禁止的是把学生部署时拿不到的信息伪装成输入，或把后来的动作伪装成早先已选择的行为。稿件把首版同信息集BC与特权监督扩展分开，符合该区别。[DIDA 原论文](https://proceedings.mlr.press/v162/liotet22a/liotet22a.pdf)

**反例：**同一旧观测在随机扰动后需要向左或向右纠正；强行做确定性均方回归可能得到危险的平均动作。稿件01:136、07:229已承认可预测性和多模态限制，没有借DIDA许诺任意GPT纠正均可内化。

### Q11：ARLI 的中途观测是否被偷塞进起点 X？

**位置：**06:272–278；07:54、175、196；01:194。

**答：通过。** ARLI在后段噪声策略启动时使用更新观测，依赖推理结构和剩余延迟；这种观测对于它的实际决策时刻可用，却相对本项目槽起点属于未来。当前首版明确不接这条路径，未来接入须重定义决策时刻、承诺剩余段、奖励与生效窗口。[ARLI §4.1](https://arxiv.org/html/2608.23831v2)

**反例：**100帧起点发请求，104帧看到滑落后修改U，却仍以只含100帧信息的X训练。06:274、278及07:196已禁止。07:54的原则性“较新观测”并未推翻后续明确的首版限定，没有发现必要的跨文档矛盾。

### Q12：ARLI 的 latent Q 能否直接吸收 Harness 的关节/末端动作？

**位置：**06:280；07:133–139；01:244、247。

**答：通过。** ARLI/DSRL选择的是冻结动作生成器输入噪声；物理动作不是已知latent标签，decoder改变也可能改变同一latent的后果。当前稿选择原始动作头，并清楚说明这不是原ARLI性质的完整保留。[ARLI §3–4及局限](https://arxiv.org/html/2608.23831v2)

**反例：**把7维末端纠正写进latent replay的action字段，或者更新decoder后仍把旧latent当同一环境动作。稿件均禁止；保留物理命令和原观测作为BC/其他视图，不等于可以伪造latent逆映射。

### Q13：共享目标会不会在 Q、target 或 RPent 内部丢失？

**位置：**01:85–106；02:83–89、215–221、T17–T18；07:27–31、89–105；09:56–60。

**答：通过。** UVFA为目标条件价值提供原始依据，但是否真实消费goal仍是本项目数据流问题。[UVFA 原文](https://proceedings.mlr.press/v37/schaul15.pdf) 本轮独立核到RPent固定源码真正送入模型的是固定 `_vla_instruction`，而非planner的 `prompt`；09准确指出了该缺口，并要求修改。01、02、07没有把“字段存在”当实现完成。

**反例：**画面中物体在B，g=B应终局，g=A则是下一任务起态；若Q不见goal，或者正向bootstrap进反向奖励，会混合两种价值。冻结稿要求结束旧episode、清旧队列、重新prime，并在T17检查实际计算图和条件行为。此处是明确的待实施要求，不因未运行就判FAIL。

### Q14：VLA 输出、学习动作、驱动命令和实测位移是否保持同一物理语义？

**位置：**02:60–73、T01–T03；06:59–61、101、163、267–270；09:64、100–102。

**答：通过。** 冻结稿没有假设动作维度通用。独立核到RPent双Franka分支校验20维chunk，所以“复制现有双臂动作即兼容松灵单臂”确实不成立；09已明确要求新适配，02要求固定单位、坐标、主动臂、持续时间与下游变换。[固定源码](https://raw.githubusercontent.com/RLinf/RPent/eb269c8a278b0ef717d61a3f55891c9ce2ec7eb1/robots/dual_franka/tools.py)

**反例：**末端请求移动2cm，因接触只移动1cm，不能将Q行为动作改写成1cm；另一臂绝对关节目标填0也不是保持。02:69–73直接排除。投影在学习边界前时要贯通优化路径，在环境内部时保留接口命令和下游证据；没有发现暗中混用两套动作定义。

### Q15：Harness 的原语成功是否会被冒充为完整 VLA 学会任务？

**位置：**01:253–259、283–300；02:275–287；09:22、107–122。

**答：通过。** 本轮重读Harness VLA原文确认，解析工具承担运输、定位和释放等工作，冻结VLA偏向接触原语。当前稿明确把这种系统能力与完整pick-and-place policy能力区分，并要求关闭动作纠正后测双向全任务。[Harness VLA 原文](https://arxiv.org/html/2607.08448v1)

**反例：**Harness永远完成运输，policy仅学会夹爪动作，却用整个系统成功率声称完整policy变强。01:259、09:109与02的三套评测直接排除。完整动作头是否能从现有表征学会，仍是冷启动预检，稿件没有宣称已经证明。

## 4. 可选建议，不计必要问题

### O1：收紧02中“旧计划后果配给新动作”的措辞

**位置：**02:132，相比06:128和02:225–233。

**误读反例：**实现者单看02:132，可能理解为“R来自旧C就不能出现在以U为动作的TD中”，从而删掉合法的当前槽R。可是本稿定义的queue-MDP本来就这样构造TD，并通过C状态解释即时奖励。

**可选改法：**改成“不能把旧计划的物理执行归因成新动作已经执行；在含真实C的队列MDP中，仍按06构造当前槽R及下一队列状态”。本轮不判必要问题，因为02后文和06已完整、明确地给出规范算法，02:132的上下文本就在描述物理执行索引。

### O2：终局actor过滤建议保留一个小型消融

**位置：**06:211；07:217；01:198、216–218。

**研究反例：**相同X下，C有一定概率在本槽终止。若critic已经学习包含终止概率的期望Q，而actor仅从实际未终局行采样，会进一步改变不同X的权重；不能把它称作原始状态分布上的无偏actor梯度。07:217已经明确不做这种等价声明，所以不是定义错误。

**可选改法：**实现时记录actor有效状态分布，并对“全部合法状态参与actor更新”与“排除取消激活terminal行”做简单对照；控制误差和外推后再决定默认值。此建议属于优化与稳定性研究，不要求为本轮设计PASS补真机结果。
