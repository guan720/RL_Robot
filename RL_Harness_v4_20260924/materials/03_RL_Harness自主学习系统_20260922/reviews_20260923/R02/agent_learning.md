# R02 独立审查：学习、数据与联合选型

日期：2026-09-23。审查对象仅为 R02/input 冻结的 README、01、02、06、07、09 六份文件；未阅读其他轮次报告或知识库，未修改正式文档。本报告中的行号均指本轮冻结输入，不指后续修订。审查为设计、原始论文与固定源码核对，未安装算法、运行训练或操作真机。

## 1. 本轮先枚举的技术要点

1. 单臂 A↔B 使用同一组 actor 参数；goal 贯通 actor、critic、target、BC、reward、replay、Harness 和评测。
2. 正反物理循环与逻辑 episode 分开；共享参数不允许跨目标串接 Bellman 回报。
3. 初始成功率可以为零；完整原始动作头用于摆脱固定小残差表达限制，但不自动解决探索或恢复预训练控制先验。
4. 原始数据长期保留与训练资格分开；历史遥操、真实纠正、失败交互、纯查询、终局取消激活请求不是同类数据。
5. 区分 C/E/D、request/commit/activation、物理执行 mask、TD 准入、BC 可信标签 mask 与 actor Q 梯度区间。
6. 首版状态为 X=(h,g,C,ξ)，冻结起点信息；U 是下一槽动作，当前奖励由旧 C 产生，信用经 C_next=U 传递。
7. 真实控制请求遇当前 C 提前终局时，保留原请求结果供 terminal critic 学习；不得给影子建议补造 TD。
8. 首版 BC 必须至少有完整、同信息集的 (X,U_H) 正向通路；孤立动作和反馈式纠正不能凭数组拼接变成完整 n 步标签。
9. 晚信息或特权纠正并非原理上禁止，但普通首版 BC 与 DIDA 类扩展必须分开；不能让未来信息进入部署输入。
10. actor 明确使用价值改进、质量 BC 与连续性项；Q 动作梯度只经过当前可选 E，终局取消激活行按首版规则排除 actor Q 更新。
11. 双向采样、示范保护、标签撤销、数据视图与模型依赖必须可追溯；共享发布不能挑两份各向最佳权重。
12. RPent 的动作／提案记录与成功 SFT 导出不能冒充现成在线 RL；完整 pick-and-place 能力必须由关闭 Harness 动作纠正的评测证明。
13. 实测阈值、延迟预算、BC 权重和是否获得 RL 增益可以留给预检；状态、动作、监督资格和 target 的定义不能用“待测”代替。

## 3. 必要问题审查问答

### Q1：shared goal 是否真正进入 Q、target、BC 与 reward，而非只有语言 prompt？

**回答：PASS。** 01:87–89 明确贯通 actor/Q/BC/reward/replay；02:87、221 规定结构化身份与一致网络状态；06:45–56、82、122–123 的 X 显式含 g，target 使用同目标 X_next；02:T17（329、344）要求计算图与行为检查。07:31 和 09:58–60 还明确指出已有源码中的“有 prompt 日志却没换实际 VLA 条件”的陷阱。

反例：画面中物体在 B，动作是原地释放。若 g=B 应终止成功，g=A 应是未达目标；裸 Q 会把两种标签平均。当前契约明确拒绝这种实现。UVFA 提供价值按目标定义的依据，不能用形状检查代替 goal 的实际消费。

### Q2：正反切换会不会将后续反向成功回传给正向 Q？

**回答：PASS。** 01:89–91、02:89、259、06:266、07:91–93 一致要求旧目标终局关闭、新目标重新 prime，不跨 g bootstrap。两方向 reward 的事件与评分版本也各自绑定。

反例：A→B 已放好，随后 B→A 成功产生第二个正奖励。若正向 transition 的 next_state 指到反向 episode，正向价值会计算两次任务收益。按当前定义，前向已 terminal，不允许该拼接。迟到前向评分只标前向历史，02:165–175 已给出处理。

### Q3：双向都接受 RL，且同一 checkpoint 双向发布，是否只是口号？

**回答：PASS（设计级）。** 07:99–105 规定方向、来源和质量分层，各向覆盖与梯度统计；02:221、269、273、T24（336）规定共享 θ、同一包及边界发布；01:106、289–296 给出双向独立成绩和必要对照。反向不是永久 reset 脚本，01:15 已明说。

反例：正向训练到 θ_1，反向另外训练到 θ_2，再用路由器按 goal 切模型，可得到高双向系统成绩但不是共享策略。该实现不符合当前契约。数值采样比与回归容忍需工位预先确定，不能因尚未填百分比而判设计不成立。

### Q4：完整头优先于弱 base 附近编辑，有充分依据吗？会不会把零成功率误当作完整头必胜的证据？

**回答：PASS。** 07:42–48 只主张表达原始纠正更直接，同时承认丢失动作先验、信息不足、少数据与多模态平均风险；07:143–151 给出与原生 π／EXPO 比较后回退的门槛。01:210、247 也不保证完整头更好。

反例：正确重抓动作距 base 输出远超编辑范围，固定小编辑不能表达；反过来，base 仅有小偏差、示范极少时，重建完整头可能更差。文档同时保留两种反例，推荐属于“优先验证的表达形态”，不是已证明的优越算法。ConRFT 与 EXPO 原始代码支持这些实现边界，不能替代该工位的同预算对照。

### Q5：actor 目标是否包括真 BC 与价值改进，而不是把 demo 进 replay 就称 BC＋RL？

**回答：PASS。** 01:212–218 明确双 Q／目标网络／确定性 actor，actor 包含 -Q、BC 和连续性项；06:154–169 规定 Q(h,g,C,U,ξ) 与可信纠正，C 停梯度，E 承担价值动作梯度；07:83–85 已正确指出 HIL-SERL 默认 actor 无 BC。

反例：沿用 HIL-SERL SAC loss，把示范混入 critic replay，却不计算动作监督，即未实现 BC；或者把新预测的前 n 步当 C 并让其梯度穿过 Q，会训练当前无法控制的动作。现有必要验收 T13/T14（02:325–326）能够发现。双 critic 的聚合、各损失系数是实现配置，不改变已写明的学习信号分工。

### Q6：历史 teleop／DAgger 数据长期保存后，能否直接进入当前队列 TD？

**回答：PASS。** 01:138、223，07:123–131 区分“采集时确实执行过”和“满足当前宏 MDP”。能复原必要时间／C／窗口才可转入队列 TD；复原不了，保留为时间语义相符的 BC 预训练数据，不补假空队列。02:211 保护初始示范不被环形缓存覆盖。

反例：旧同步轨迹 (o_t,a_t,o_t+1) 中 a_t 立即生效；新 learner 却把它放入 U，设 C=0 并把 o_t+1 当下一槽状态，会把两种动力学混为一谈。当前规则禁止这种转换。

限制：历史 BC 预训练到新增队列条件头的具体 adapter 仍须选型预检；文档没有声称所有旧样本可直接训练每个分支，因此这一实现工作不构成必要缺陷。

### Q7：Harness 未执行查询是否能持续训练？是否伪造环境后果？

**回答：PASS。** 06:169、02:207、251、365 给出独立标签池及 BC 资格，06:75 禁止事后补 admission；01:225 和 07:127 不给纯建议他者动作的 reward/next_state。

反例：policy 抓偏后掉物，Harness 离线建议正确重抓；将该建议与掉物后继配对做 Q 会把错误后果归给纠正。当前规则只允许该建议形成合格监督标签。DAgger 支持未执行标签聚合，但不凭空产生其动作转移。

### Q8：当前 C 提前终局、U 尚未激活时，是否错误丢失正奖励或把建议伪装为真实动作？

**回答：PASS。** 06:194–219 给出事前真实请求、冻结输入／权重／随机性、原在途计算结果 U、target=R_L、无 bootstrap；结果不可追溯就只保留事实。02:235、T11（323）与之相符。06:211、298 明确首版该行不做 actor Q 更新，奖励经正常 Bellman 链传向前驱。

反例一：终局后重新看场景生成 U，再补请求，是伪样本，已被禁止。反例二：只在下一槽成功时给前驱直接回填成功，其余情况继续 bootstrap，会按未来事件选择目标，06:217 给出 0.5 被抬成 0.75 的数值反例。当前方案没有使用这条捷径。

非阻断文字差异见 N1：07 对 terminal actor mask 的“可选择”应与首版固定口径统一。

### Q9：BC 训练粒度是否有可落地默认定义，还是只说“mask 掉缺失标签”？

**回答：PASS，适用范围明确限于已定义通路。** 06:169 给出完整 (X_k,U_k^H)，U 为下一槽 n×d_a；06:188 明确孤立一步不能复制填满；06:190、02:253 规定部分标签若不能处理加噪／token 交互，留存但暂不进入该分支。06:61 允许输出 E 或输出 H 后取 E，但要求实现配置写清。因此本轮通过的是完整、同信息集动作段 BC，不是“所有短片段已能训练任意 flow 头”。

反例：n=6 只确认第 2 步标签，将其他五步填零并只在 loss 末端 mask。若一致性／flow 的输入先被加噪并跨 token 交互，有效位置的预测仍依赖伪填充值。ConRFT 的 x_start→x_t→forward_policy→重建链直接说明这个风险。当前设计显式拒绝把该做法当已兼容。

完整窗口的可取得比例、短纠正是否值得增加专用监督分支应实测；已经提供完整 U 正向路径和不兼容标签隔离规则，不属于完全未定义方法。

### Q10：较晚新观测生成的纠正，能否放回早状态训练？DIDA 是否意味着必须有外部强教师？

**回答：PASS。** 01:134–138、06:184–190、07:227–231 一致：普通首版 BC 先限定同一可见信息／队列；未来信息不得倒写部署输入；特权／事后标签保留，扩展单独建模。07:167 明确 DIDA 的有效无延迟策略假设不是本项目事实。

反例：t 时物体将以不可预测扰动向左或向右滑，t+n 的反馈纠正方向各异。把这些标签当成同一个 X 下确定且唯一的“正确 n 步动作”，可能平均出无效轨迹。DIDA 允许这样的监督问题被研究，并不消除不可预测性，也不证明 GPT 原生就是专家。

本方案的普通完整 U 标签由 GPT＋工具／局部程序在已定义 X 上形成，不将 DIDA 作为必需上游 policy，符合用户前提。

### Q11：没有强外部教师时，“可信 Harness BC”是否只是 GPT 自称可信的循环？

**回答：PASS（设计级），能力证据尚待实测。** 01:26、51、128 要求在 policy 失败状态证明局部纠正有用；02:191–197 分开执行可靠性、可表达性、可观察性和内化；02:263 将仅凭 GPT 自称可靠列为阻断；01:158、02:183–185 要求独立证据校准。方案没有把运行成功等同全部动作优质。

反例：Harness 先无效摆动二十步，最后靠抓取原语成功；把全段都赋高 BC 权重会复制浪费甚至错误。当前规则要求分段质量资格。零成功且无有效纠正／探索时可能无法启动，01:36 已直说，不作虚假保证。

局部质量标准数值与可用技能覆盖仍需工位建立；它们是任务与能力预检，不应被偷换成“另外准备一个高成功率 policy”。

### Q12：RPent Flywheel 到在线 RL 的连接是否清楚，失败数据会不会被成功导出器丢掉？

**回答：PASS。** 09:38–46 准确区分原始记录与成功 SFT 导出，明确新增失败 RL 视图、查询标签、goal／评分版本、request/commit/activation、绝对时间和独立 mask；02:51、203–213 与数据清单 356–362 一致。官方源码确实按 is_success 筛选，training_step_count 截至首次成功，原记录器 finalize 才写盘。

反例：直接把官方 export_lerobot 输出叫在线 RL replay，既缺失败样本也缺本项目队列请求链；在初始零成功时甚至可能没有任何成功导出。当前方案明确要改造，因此未把“同属 RLinf”误当 learner 已接通。原始失败记录、BC 标签与 RL 训练视图是三层对象。

### Q13：RPent 的系统增强会不会被误认成 policy 学会完整任务？

**回答：PASS。** 09:22、107–109 与 01:259 明确原论文冻结 VLA、常把运输交给解析动作，而本项目要求完整 pick-and-place；02:279–287、T28（340）将独立 policy、系统辅助、持续自学习三套账分开。训练数据要吸收相容的有效动作，但不能用辅助后的总成功率证明内化。

反例：同一冻结 checkpoint 原地不变，仅改 Harness 运输代码使系统成功率从低变高。若关闭纠正后的全任务成功不变，则只能报告系统增强。当前评测约束能区分此情况。RPent 官方论文恰好表明其原始结果不能直接证明在线 RL 的 policy 收益。

### Q14：有些门槛尚未测定，是否因此应判 FAIL？有没有“待测”掩盖未定义方法？

**回答：本范围不因此判 FAIL。** 02:309、344–348 把逻辑验收和工位数值分开；01:273–281 给出接口、BC、纠正、目标手算和短闭环阶段；07:143–151 明确不通过后的调整。核心 X、U、普通／terminal target、BC 最小完整窗口、查询排除 TD、接管隔离、双向发布均已有定义。

反例：若文件仅写“异步 loss 以后测试决定”而没有 request/commit、R_n、X_next.C=U 与 actor 区间，就属于方法未定义，应 FAIL。本轮并非这种情况。相反，要求作者在无硬件时填一个任意 n、λ_BC 或成功率阈值，会制造虚假精确。

实现时必须锁定动作头形态、完整标签格式与冻结配置，再执行所列测试；本次 PASS 不授权省略该锁定，也不声称所有扩展已覆盖。

## 4. 跨文档非阻断澄清
