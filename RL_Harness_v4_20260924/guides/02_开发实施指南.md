# 开发实施指南

本页把已评审设计转换成接手顺序，不增加算法结论，也不替代主方案与两个附录。当前所有实施阶段均为待开展。

## 第一次接手要形成什么

先确定已有代码、设备、模型、数据和算力的真实情况。复制[项目参数模板](../templates/项目参数模板.json)到 `work/project_parameters.json`，把实测结果与来源填入；未知保留 `null`，不要从论文默认值猜设备参数。模板是交接记录，不是可直接加载的机器人运行配置。

第一批产物应包括：设备与模型资产表、动作/坐标/时间接口说明、候选路线预检记录、可回放的事件样例、当前阶段的验收清单。没有GPU或硬件时仍可实现数据结构、mock驱动、队列事件回放和手算target检查；这些结果标为回放或静态检查，不能写成真机通过。

## 按阶段实施

阶段定义来自[主方案§12–13](../materials/06_三轮递进调研与方案复审_20260923/01_开发技术方案.md#12-实现路线)，验收细节以[接口附录](../materials/06_三轮递进调研与方案复审_20260923/appendices/01_接口契约与开发验收.md)和[异步附录](../materials/06_三轮递进调研与方案复审_20260923/appendices/02_异步动作时间轴与学习目标.md)为准。

| 阶段 | 要实施的内容 | 留下的证据与继续条件 |
|---|---|---|
| P0 接口与时间 | 锁定模型/上游commit与依赖；定义本体adapter、请求/入队/生效事件；测推理、观测、保持及停止 | 接口契约、延迟分布、候选固定槽预算；先mock/回放，再在具备条件时测真实设备。不能只证明SDK连通 |
| P1 共享BC启动 | 少量双向示范；原生头优先预检，完整头参考与编辑路线按可达性竞争 | 双向基本可控或可靠局部纠正、小样本可学性、完整包推理一致性；不要求初始高成功率 |
| P2 GPT Harness | 建双向/失败/遮挡留出记录；校准评分；实现典型局部纠正和独立观察 | 误报/漏报/未知、纠正可靠性、控制权交接、观测时效的可复核结果 |
| P3 学习语义 | 日志形成BC与TD视图；实现goal、队列target、终局与接管分支 | 可手算短轨迹对照、mask/梯度/边界故障回放；不靠拼接不合法转移增加样本 |
| P4 最小真机学习 | 打通抓空→纠正→入池→更新→双向独立评估；实施H1 | 相对持续动态BC的实际增益与区间、成本和允许回归；证据不足则诊断，不提前扩大窗口 |
| P5 连续正反循环 | 自动评分、换向、纠正/恢复；按错误类型降低帮助；实施H2 | 双向独立能力、人工复位/接管/值守工时、窗口中断、困难起态和合格数据覆盖 |
| P6 可选扩展 | 增加一种异常及程序扩展，实施H3；稠密奖励和动态延迟分别消融 | 新范围的能力与成本收益、版本回退证据；当前限定任务已达标可验收，不强制先完成P6 |

架构、数据和评估契约应先统一；确定接口后，各模块可以并行开发。一次只推动已经具备输入条件的阶段，不需要先完整移植所有候选。

## 模块交接时至少对齐的内容

| 模块交接 | 需要共同确认 |
|---|---|
| Adapter → Runtime/Gateway | 动作维度与顺序、单位/参考系、夹爪语义、限幅/插值、驱动反馈、保持/停止含义 |
| Runtime → 日志/learner | 事前观测、goal、实际C、请求U、deadline、控制来源、提交与物理生效、终局/截断原因 |
| Harness → 数据视图 | 生成时依赖的信息、标签有效位置、是否后续反馈、质量依据、实际是否执行、程序与评分版本 |
| 数据视图 → Learner | BC质量、TD资格、动作参数化、normalizer、样本分组、奖励/标签版本、撤销依赖 |
| Learner → 部署/评估 | 共享双向checkpoint、全部必要模块、输入与调度协议、权重转换一致性、验收及回滚身份 |

详细字段已有 `DecisionRequest`、`CorrectionLabel`、`TrainingView`、`ReleaseBundle`、`PolicyDeploymentManifest` 等定义。不要用本表覆盖原附录的精确字段和分支。

## 当前需要实测或决策的参数

- 本体、驱动能力、参与肢体、相机/标定、动作表达、实际控制频率与停止反馈。
- 可用VLA/checkpoint/revision、GPU、推理与训练环境、底模和依赖的资产条件。
- chunk长度、固定执行槽 `n`、deadline、观测龄期、时钟误差及超时路径。
- A/B起态与目标集合、成功/失败/未知判据、纠正和恢复预算、自主窗口范围。
- 示范和纠正质量、BC/TD准入与采样、学习超参数、有效数据覆盖、候选路线预检结果。
- GPT实际接口与请求预算、评分校准门槛、程序试用条件与纠正退出条件。
- 双向部署可靠性和节拍要求、训练重复/评估试次、实际增益、允许回归、数据切分、停止规则及总成本。

这些值由工位与项目目标确定；本交付不虚构统一成功率、GPU数、训练小时或固定超参数。

## 如何记录完成状态

使用[实施进度模板](../templates/实施进度模板.md)与[单项验收记录](../templates/单项验收记录模板.md)。每项记录设计依据、实现路径/commit、输入数据/配置、实际执行环境、结果和证据位置。明确区分未实施、已实现未验证、回放通过、真机通过、失败/受阻。

原文T01–T54仍是验收依据。按当前模块挑选相关用例执行并记录覆盖，不能用格式检查或旧文档PASS替代测试。修改接口、目标或模型信息条件时，记录对数据、训练和评估的影响，并重新验证受影响部分。

如需改变设计，先在 `work/decisions/` 记录问题、证据、选择、被推翻的假设与对应验证；若形成新科学版本，注明其与v4的差异和独立审查状态。普通导航整理不改变原v4科学结论。
