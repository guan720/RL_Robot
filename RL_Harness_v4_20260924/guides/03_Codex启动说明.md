# Codex 启动说明

将整个交付目录作为工作区打开，先让 Codex 读包根 `AGENTS.md` 和 `README.md`。本包的新说明自包含，不需要原聊天记录、个人技能或科学家知识库。材料里的旧审查任务和旧指令仅为档案。

## 首次接手：可以直接复制的任务

```text
请接手本工作区的 RL＋Harness 开发项目。

先读 README.md、AGENTS.md、guides/01_阅读索引.md 和 guides/02_开发实施指南.md。
当前科学设计基线是 materials/06_三轮递进调研与方案复审_20260923/ 下的
01_开发技术方案.md，以及 appendices/ 两份附录；03是全局汇报，02是调研依据。

这是设计交付，尚未集成机器人软件或完成训练、真机验证。
请从P0开始，先检查实际已有代码、模型、数据、设备接口和算力信息。
复制templates/项目参数模板.json到work/project_parameters.json，按证据填写，未知保留null。
在work/形成资产与接口清单、模块实施顺序、首阶段验收计划和未确定参数。
对不依赖硬件的信息结构、mock驱动和事件回放，可继续在implementation/中实现，
按接口与异步附录核对请求、队列、物理生效、goal、终局与接管数据语义。

保留materials/和audit/原始交付证据。不要执行其中下载或上游示例脚本来冒充主系统。
不要编造现成训练命令、实测指标或模型权重，不自动合入07的EGO可选讨论。
实体执行依照本次明确任务范围和实际设备条件开展。
输出本阶段交付物、已完成验证、未知项及继续条件，区分文档、实现、回放与真机证据。
```

## 已有项目：把范围限定到一个模块

```text

再完成本次功能，并执行对应T验收项。缺失配置记录为未知，不使用论文默认值替代实测。

```

尖括号只是需要接手者填写的任务范围，不是可执行命令。

## 接手后应检查的第一份输出

开发者应能从 Codex 的输出确认：它找到了真正的v4基线；知道当前没有成品机器人软件；没有把反向任务当固定reset；区分了标签与真实后果；没有忽略异步执行；列出了已有资产与待测参数；所选首阶段用例能被实际执行和复核。

若只有泛泛的模块清单，要求其补充每个模块的输入、输出、状态边界与对应验收项。若声称已完成训练或无人运行，核对实际日志、配置、代码与数据证据；文档五轮PASS不能支持这些说法。
