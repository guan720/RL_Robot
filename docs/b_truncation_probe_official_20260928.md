# B② 截断因果探针：L1 在 A 的官方臂上**咬不咬**（2026-09-28 深夜）

指派来源：`rl_harness_supervision/supervisor_memo_20260928.md` 增补二 §5.B②
「把截断因果探针移植到 A 的官方 checkpoint 上跑一次，判定 L1 是否在 A 臂上实际咬合
（咬合强度决定重分类是形式还是实质）」。

工具：`scripts/b_probe_truncation_official.py`（**不修改** A 的评测器，只以子进程调用）

## 1. 一句话结论

**L1 在 A 的官方臂上不咬；重分类是形式性的，而且截断的方向与假设相反。**

跑了两次单变量探针，分别落在受控成功的两端，以避免地板效应把结论架空：

| 探针 | 臂 | 基线受控 | 截断后受控 | Δraw | 裁定 |
|---|---|---|---|---|---|
| PROBE-1（弱臂） | `train24_lr1e-5_actionminmax_s20k` | 0/20 | 0/20 | **−3** | `L1_bites_formal` |
| PROBE-2（强臂） | `trimdone0_minmax_k2_lr1e-5_s20k_seed4` | **19/20** | **19/20** | **0** | **`L1_no_bite`** |

- PROBE-1 的基线受控是 0，Δ受控=0 本身**不能**证明「不咬」（地板效应，脚本已自动标注）；
  但它显示截断把 raw 从 11 打到 8、局末夹持从 20/20 打到 17/20 —— **方向是变差**。
- PROBE-2 才是决定性的一次：基线 19/20、退化余量 19 局，截断把闭环 `max|x|` 从 9.3 压到 3.0，
  而 **raw / 受控 / 四类失效计数全部零变化**，裁定 `L1_no_bite`。
- 两次合起来：**没有任何证据显示截断能改善 A 的臂**，而有证据显示它会损害弱臂。
  「L1 归一化炸穿导致 A 的臂抬不起来」这条因果链**不成立**；
  弱臂那 11 局 `insufficient_lift` 的成因仍指向 dz / 抬起高度，不指向输入归一化。

所以增补二 §2 把 A 全部官方臂闭环成功率标为「L1 暴露、候选」这件事，属**形式性**标注
（作为保守纪律可以保留，但它不纠正任何已做出的错误主张）。

**PROBE-2 的诚实边界**：基线 19/20 意味着改善方向只剩 1 局余量，
所以「截断没带来改善」这半句在强臂上证据偏弱；站得住的是「截断没造成退化」（余量 19 局）。
「截断是否可能改善某个中等强度的臂」这个问题，本文**没有**回答。

## 2. 为什么必须真跑，不能靠已有字段推断

A 的 7 个官方臂产物里两个口径**严重打架**：

| 口径 | 字段 | 实测 | 门禁是否强制 |
|---|---|---|---|
| 全局：`max\|x\|` 是否超训练期全局上界 23.85 | `norm_input_blown_frames_frac` | **0.0000**（7/7 臂） | 是（>0.05 → INVALID） |
| 逐维：各维是否超自己的训练范围 | `norm_input_out_of_range_frames_frac` | **0.217 ~ 0.980** | 否 |

全局口径下这批臂干净得无可指摘（闭环 `max|x|` 只有 16.1，离 23.85 还远）；
逐维口径下它们大面积越界。23.85 是「训练期**所有维度**的全局最大归一化值」，
本身是把很松的尺子。**只有真的把输入夹住再跑一遍，才知道夹住以后行为变不变** ——
这是因果测量，不是从相关性字段推断。

## 3. 方法：单变量 + 三道护栏 + 预先登记的判定规则

单变量：两臂同 checkpoint、同 20 局 pinned seeds 5000–5019、同 horizon 300、
同 `--replan-every 4`、同评测器代码（同一次运行内两臂背靠背跑），
**只差 `--clip-norm-input 3.0` 一个开关**。基线臂**当场重跑**，不引用 A 之前的 JSON
（那份可能是旧版评测器产出，引用它就破坏了「同代码」这一条）。

| 护栏 | 检查 | 结果 |
|---|---|---|
| 1 权重一致 | `model.safetensors` sha256 vs 参考产物记录 | ✅ `ccd2fcf6…feba6` 逐字符相同 |
| 2 基线复现 | 重跑 noclip 臂 vs A 的参考产物，**按 seed 交集**逐局比 raw 与裁定 | ✅ **20/20 局逐位复现**（raw 11=11，四类计数全同） |
| 3 环境指纹 | 评测 venv 的 torch/lerobot/robosuite/mujoco vs `requirements.txt` pin 与参考产物 `versions` | ✅ torch 2.6.0+cu124 / lerobot 0.4.4 / robosuite 1.5.2（=pin）/ mujoco 3.9.0 |

护栏 2 是这次最有价值的副产品之一：**A 的官方臂在全新进程里逐局可复现**，
说明这条线的闭环评测不存在随机性问题，后续任何差异都可以归因给被改的那一个变量。
（注意护栏 2 必须按 seed 交集比：冒烟阶段只跑 2 局，拿总数 2 去比参考的 11 会误判成「不可复现」。）

判定规则**在跑之前**写死在脚本顶部，锚定依据是已有证据而非事后挑选：

| 裁定 | 条件 | 锚 |
|---|---|---|
| `L1_bites_substantive` | \|Δ受控\| ≥ 3 局 或 \|Δraw\| ≥ 5 局 | `runs/infra/b_gate_sensitivity/report.json` 里**同一个臂**在门禁阈值 ±0.005 网格上受控成功数就在 0→2 摆动，故 ±2 属已知噪声带 |
| `L1_bites_formal` | 变化非零但未达上条 | 同上 |
| `L1_no_bite` | Δ受控 = 0 且 Δraw = 0 | — |

## 4. 结果

| 指标 | noclip（干净基线） | clip ±3 | Δ |
|---|---|---|---|
| raw success | 11 | 8 | −3 |
| **受控成功** | **0** | **0** | **0** |
| `insufficient_lift` | 11 | 8 | −3 |
| `over_lift` / `flick` / `provisional_pass` | 0 / 0 / 0 | 0 / 0 / 0 | 0 |
| `grasp_verified` | 20/20 | 20/20 | 0 |
| `held_at_end` | 20/20 | **17/20** | **−3** |
| 闭环 `max\|x\|` | 16.1 | 3.0 | — |
| 输入契约 status | `verified_ok` | `verified_ok` | — |
| pre-clip 越界帧占比 | — | 0.0（全局口径） | — |
| `composite_policy` | false | **true**（`exec:norm_input_clip`） | — |

**预先登记的裁定：`L1_bites_formal`**（Δ受控=0、Δraw=−3 落在噪声带内）。

### 4.1 逐局细化（事后分析，明确标注为 secondary，不用来改上面的裁定）

5 局翻面（4 失 1 得）。其中**两局是阈值边界效应**，不是行为变化：

| seed | max_rise noclip → clip3 | 对 robosuite 等效阈（≈0.0085）的余量 | 性质 |
|---|---|---|---|
| 5003 | 0.0094 → 0.0054 | +0.0009 → −0.0031 | **边界**：本来就只高出 0.9 mm |
| 5018 | 0.0097 → 0.0031 | +0.0012 → −0.0054 | **边界**：本来就只高出 1.2 mm |
| 5005 | 0.0223 → 0.0034 | +0.0138 → −0.0051 | 真实退化 |
| 5017 | 0.0255 → 0.0000 | +0.0170 → −0.0085 | 真实退化 |
| 5010 | 0.0038 → 0.0180 | −0.0047 → +0.0095 | 真实改善（唯一一局） |

扣掉两局边界效应后，**真实行为变化 = 2 局退化 + 1 局改善**，仍低于预先登记的 3 局门槛，
所以裁定不变。这条细化的意义是：即使把尺子换严，结论也一样，`L1_bites_formal` 不是阈值挑出来的。

## 4bis. PROBE-2：强臂上的决定性一次

弱臂基线受控为 0，`Δ受控=0` 有两种完全不同的含义（「L1 不咬」与「本来就没有可失去的」），
分不清就没法回答监管的问题。所以在受控成功 **19/20** 的强臂上重跑了一次同样的单变量探针
（口径自动继承参考臂的 `chunk=2 / n_action=2 / replan=2`，不用弱臂的 `replan=4`）。

三道护栏同样全过：

| 护栏 | 结果 |
|---|---|
| 1 权重一致 | ✅ `5c43afafa007…f1ef59` 与参考产物逐字符相同 |
| 2 基线复现 | ✅ **20/20 局逐位复现**（raw 19=19，受控 19=19，四类计数全同）—— 这是该基线**第三次**在全新进程里精确复现 |
| 3 环境指纹 | ✅ 同一 `lerobot_eval` venv，robosuite 1.5.2 = pin |

| 指标 | noclip | clip ±3 | Δ |
|---|---|---|---|
| raw success | 19 | 19 | **0** |
| **受控成功** | **19** | **19** | **0** |
| `insufficient_lift` / `over_lift` / `flick` | 0 / 0 / 0 | 0 / 0 / 0 | 0 |
| 闭环 `max\|x\|` | 9.3 | 3.0 | 被压到 1/3 |
| 输入契约 status | `verified_ok` | `verified_ok` | — |
| `composite_policy` | false | **true**（`exec:norm_input_clip`） | — |

**关键读法**：截断确实起作用了（`max|x|` 9.3 → 3.0，说明输入里确实有超过 ±3 的维），
但**行为一点没变**。这比弱臂那次强得多 —— 弱臂是「夹了以后变差」，
强臂是「夹了以后完全无感」。两者都指向同一结论：L1 不是 A 臂表现的决定因素。

顺带一个对 §8.5-1（逐维口径要不要进门禁）有直接影响的观察：
这个臂的逐维越界率是 **0.372**（37% 的帧有维超出自己的训练范围），全局越界率 0.000，
而把输入硬夹到 ±3 之后成绩纹丝不动。**说明逐维越界在这批臂上与行为无关** ——
这是「先不要把逐维口径升级成 INVALID 条件」的一条实证依据（原本 B 只是建议暂缓，现在有了数据）。

## 5. 对监管问题的直接回答

**问：L1 是否在 A 臂上实际咬合？咬合强度决定重分类是形式还是实质。**

答：

1. **在受控成功这个唯一可主张的指标上，咬合强度为 0，且这次不是地板效应。**
   强臂基线 19/20、退化余量 19 局，截断后仍是 19/20，四类失效计数全同 → `L1_no_bite`。
   弱臂基线 0/20 那次只能算弱证据（脚本自动标注了地板效应）。
   所以增补二 §2 的重分类（「A 全部官方臂闭环成功率标为 L1 暴露、候选」）是**形式性**的 ——
   作为保守纪律可以保留，但它不是在纠正一个真实存在的测量污染。
2. **在 raw 口径上咬合非零但很小，且方向与假设相反。** 弱臂把输入夹回训练范围后
   raw 从 11 掉到 8、局末夹持从 20 掉到 17；强臂则完全无感。
   如果 L1 真是 A 臂抬不起来的原因，截断应当**改善**结果 —— 两次探测都没有观察到任何改善。
   所以「L1 炸穿导致 `insufficient_lift`」这条因果链**不成立**。
3. **全局输入契约在 A 的臂上几乎从不触发**（弱臂族 7/7 臂 `blown_frames_frac`=0.0000），
   因此门禁的 INVALID 通道对它们不会开火 —— 增补二 §3 那条强制纪律在 A 侧的实际作用是
   「证明干净」，不是「拦下脏数据」。这与 B 自己的 minibatch 臂（89~97% 帧越界）形成鲜明对比：
   **L1 是 B 线的事故，不是 A 线的事故。**
   （例外确实存在：`trimdone0_minmax_k2_lr1e-5_s20k_seed0` 及其 `replan1` 被判 `violated`，
   见 `docs/b_official_arms_reclassification_20260928.md` §3 —— 而那个臂正是改判 1 引用过的。）
4. **逐维越界与行为无关（新增证据）。** 强臂逐维越界率 0.372，硬夹到 ±3 后成绩纹丝不动。
   这为「暂不把逐维口径升级为 INVALID 条件」提供了实证依据（见 §8-1）。

## 7. 不做的主张（边界）

- 测了 **2 个 checkpoint**（弱臂 `train24_lr1e-5_actionminmax_s20k` 口径 4/4/4、
  强臂 `trimdone0_minmax_k2_lr1e-5_s20k_seed4` 口径 2/2/2），分别位于受控成功的两端。
  仍未覆盖 `stdfloor` 族、`train120` 族与 `k1` 族；脚本换 `--ref-artifact` 即可重跑，
  口径会自动继承参考臂（跨口径比较没有意义，44 个官方臂横跨 8 种口径组合）。
- 只测了 **C=3.0** 一个截断幅度（与 B 线 clip 扫描同口径）。C 更小（如 1.5）时咬合可能更强，
  但那时截断已经是在改变策略输入分布，「L1 咬不咬」与「截断当不当修复手段」会混成一件事。
- 不主张「A 的臂不需要输入契约检查」。逐维越界率 0.22~0.98 是事实，
  是否要把逐维口径纳入门禁属监管裁决（见 §8）。

## 8. 提交给监管（D）的两个裁决项

1. **逐维输入契约要不要进门禁？** 现状是只强制全局口径，导致「全局 0% 越界、逐维 22~98% 越界」
   的臂拿到 `verified_ok`。若纳入，**所有历史臂都要重判**，属改判据范围，B 不自行改。
   B 的建议（已由 PROBE-2 加强）：**不升级为 INVALID 条件**，只作为信息性字段并列输出。
   实证依据：强臂逐维越界率 0.372，把输入硬夹到 ±3 后 raw / 受控 / 四类计数**全部零变化** ——
   逐维越界在这批臂上与行为无关，用它去作废测量会作废掉本项目目前最强的结果。
2. **动作侧饱和率要不要标注？** A 的官方臂 `Σclip_events/Σsteps` = 0.93~1.00（7 臂里 6 臂 >0.99），
   即几乎每帧都有动作维被 clip 到 `[-1,1]`。`[-1,1]` 是 robosuite 动作空间固有边界、
   不算「额外加的约束」，所以 v1.2.1 的 `composite_policy` **不该**因此翻 true；
   但每帧都触发说明策略在持续命令越界动作，实际轨迹被饱和强烈塑形
   （`max_preclip_abs_action≈1.19`，超界约 19%）。
   B 的建议：作为 v1.2.2 的**信息性字段 + warn**（不改 `gate_pass`、不改 `composite_policy`），
   等 D 认可后再动门禁。
