# 当前路线：从最小学习证据到 RL 与 PIPER

整理于 2026-10-09。现有实验状态来自截至 10-07 的最小路线文档；本页后续阶段是推进建议，不是已完成工作。历史转向见 [PROJECT_HISTORY](PROJECT_HISTORY.md)。

## 主问题与当前所在位置

主问题：**在固定抓放任务与评测协议下，Harness 产生的反馈/纠正数据能否提升策略自身能力，并进一步支持有真实参数更新的 RL？**

当前：Panda 单臂、π₀.₅、正反向抓放、BC/SFT、脚本专家纠正数据。已有关闭接管后的纠正 BC 结果。下一阶段仍沿用这个最小任务，避免同时增加机器人形态、任务、训练算法和执行架构。

| 路线 | 当前定位 | 何时继续 |
| --- | --- | --- |
| π₀.₅ 最小抓放 | 当前学习主线 | 先复核结果，再选一个学习问题 |
| 早期二维/三维 RL 与 ACT | 历史对照和诊断资产 | 仅复用已解释清楚的实现或反例 |
| gym-aloha 复杂 VLA、队列与账本 | 系统接口参考线 | 被主线的具体接口需求调用时 |
| RLinf-VLA | 后续训练/采样平台 | 最小 transition 和一次更新可验收后 |
| PIPER 双臂平台 | 用户正在调试的硬件目标 | 可并行做基础联调；学习任务先单臂抓放 |

双臂机器人不等于必须先做双臂交接。双臂协作是后续任务扩展，不是验证 Harness 学习收益的前置条件。旧文档中的 Genie G2 目标属于早期规划，当前目标按用户要求为 PIPER。

## 1. 先收口现有最小验证

- 补齐本地 runs，读取 S9C、S10、S11 和 MISSION_VERDICT 最终产物，确认配方、K、语言泛化结果。旧 ETA 与排队状态不能作为完成证明。
- 固定 checkpoint、normalizer、数据版本、训练 seed、评测初态、重复次数、严格/放宽判据与 K；保留逐局结果。
- 明确运行时接管与纠正数据学习的两个对照。新增学习对比均报告关闭帮助的策略成功率。
- 保留档 7H 的无纠正 BC 配方作为竞争基线；与档 8 不同数据/不同 seed 的现有结果不能直接排名。
- 侧躺、空合、接触弹射、夹持丢失分别计数，不能只用最大高度定义抓取。

出口：一张可从逐局文件复算的基线表，以及一个需要 RL 解决的具体残余问题。

## 2. 在同一任务上加入残差 RL

先冻结 π₀.₅ 基座，学习有界小残差。下列是建议的新实验要求，尚无此路线的训练结果。

| 必须明确的项 | 最小实现/验收 |
| --- | --- |
| 残差加在哪里 | 在归一化还是物理动作域、坐标系、单位、裁剪顺序；先验证零残差与 BC 执行等价 |
| chunk 与控制步 | 明确 K、残差更新频率、哪一步实际执行；取消/接管后未执行的动作不得充当 transition |
| 学习数据 | 当前/下一观测、基座动作、残差、执行动作、奖励、terminated/truncated、接管来源与策略版本 |
| 奖励与成功 | 与冻结成功判据对应；区分真实夹持、弹射和落定；奖励上涨不能代替成功率 |
| 对照 | 冻结 BC / 同预算继续 BC 或纠正 BC / BC+残差 RL；训练初态与测试初态分离 |
| 预算 | 同在线交互预算，另报示范和纠正采集成本、更新次数、墙钟成本 |
| 评测 | 多训练 seed、初态配对、重复推理；按初态考虑重复相关性，报告不确定性和失败分布 |

出口：证明确有奖励驱动的参数更新，并在关闭帮助的未见初态评测中比较净收益。接口通、loss 下降、脚本基座满分都不等于 RL 增益。

## 3. 对接 RLinf-VLA

先把现有最小环境、策略加载、动作执行与数据格式做成 adapter，完成“一次采样 → 一次更新 → 保存 → 重载 → 冻结评测”的最小闭环。

可参考仓内 [VLA runtime](a2_s4_vla_runtime_interface_20260929.md) 与 [账本数据桥](ledger_data_bridge_20260928.md)，但要核实目标 RLinf-VLA 版本、支持算法、π₀.₅ action/chunk 语义及分布式接口。当前材料不能证明平台已接通。

只有最小闭环正确后，再考虑异步队列、并行采样和吞吐优化。平台适配本身不应顺带改变任务与奖励。

## 4. PIPER：硬件联调与学习分开验收

基础联调可与仿真并行：单一 Gateway 持有物理驱动写权限，先低速验证停机、限位、超时、失联和接管。

- **动作契约**：逐臂关节顺序、角度单位、TCP/基座坐标系、控制模式、夹爪开合符号与行程；Panda 的 OSC 增量不能直接发送给 PIPER。
- **感知契约**：相机内外参、左右腕相机身份、时间戳和状态同步；模型输入预处理与采集训练一致。
- **时间契约**：控制频率、推理延迟、chunk 缓冲、过期动作处理、抢占确认及真实执行回执。
- **学习前提**：遥操作/脚本示范、可观测的成功与失败标注、复位方法、干预片段记录；列出依赖仿真真值的检测器替代方案。
- **迁移顺序**：动作探针 → 低速回放 → 单臂 BC → Harness 数据采集 → 仿真已验证的残差 RL → 双臂协作任务。

出口按阶段分别验收；平台集成完成、真机能动、抓取成功、RL 有收益是四件不同的事。

## 控制范围

新增实验应能说明：它解决哪个当前瓶颈、改变哪个变量、结果如何影响下一步。没有这种联系的模型扩容、门禁重构、多框架比较与双臂交接，留作候选，不与主线同时铺开。
